\section{Choosing an instrumental-variable method for the stated model}
\label{exec23:iv-choice}

A reusable IV component must preserve the model being estimated as well as its
numerical answer. The preceding Python comparison develops the projected-rank
and exclusion witness; it also shows why a diagnostic's number, reference
distribution and null must travel together. The resulting proposal choice for
\texttt{linearmodels} is a reference for a bounded IV comparison. Its pinned
revision is \texttt{13390eee49ea06fc42f831255ff2163f2ad13e8b}, dated
7 October 2026. The repository's package version is dynamic; equality to a
distributed 7.0 wheel or an installed environment has not been authenticated.
The inspected NCSA license requires retention of notices and conditions and
does not establish rights for every transitive dependency. Build requirements,
including Meson and Cython, differ from runtime dependency floors. An executable
bridge therefore needs a resolved environment and distribution review in
addition to the estimator contract.~\citep{exec22_linearmodels_reuse}

This reference choice has practical merit: the inspected paths expose weights,
row removal, covariance options and first-stage results that can support a
matched comparison. Its limits are equally specific. A low-level static
$k$-class estimate explicitly performs no error checking. A successful direct
inverse is not an exclusion test. The \texttt{anderson\_rubin} property uses
the LIML quantity for overidentification and has no coefficient-null argument;
it cannot be relabeled as inversion of a weak-instrument test for every
proposed effect. A proposed adapter should retain the actual sample, weight
normalization, projection conditioning, covariance design, warning state and
diagnostic null. Qualification of those fields is a future conversion task;
reference selection itself supplies no native capability. Panel, system and
GMM capabilities require their own primary technical inspections.
\citep{exec22_linearmodels_reuse}

\subsection{A Java two-stage method can address a different scientific object}
\label{exec23:iv-java}

The selected Tetrad source illustrates why searching for ``two-stage least
squares'' cannot establish interchangeable software coverage. At revision
\texttt{b89afaf952a4fd647df0}\allowbreak\texttt{d85b08102250106c6764}, dated 22 September 2026
and declaring \texttt{7.6.11-SNAPSHOT}, its package-private \texttt{Tsls}
class targets a supplied pure latent measurement model. Other measurements of
latent parents supply instrument columns. The method creates and returns a
structural-equation-model object; this is a different entry contract from a
generic observed-outcome, treatment and excluded-instrument regression, and
it does not establish a regression-discontinuity interface.
\citep{exec22_java_latent_iv_preflight}

Suppose a bank represents an unobserved service-quality construct by several
survey indicators. Fixing one loading defines the construct's scale. In the
inspected default branch, lexicographic indicator names select a fixed loading;
an explicit fixed-loading list is another branch. Renaming columns could
therefore alter the normalization under the default. A comparison must either
preserve that normalization or explicitly transform coefficients and their
interpretation. It cannot equate a latent loading with the dollar effect of a
contact merely because both are coefficients.

The source also supplies concrete conversion questions. A latent iteration
with no instrument collection is skipped, and a measurement iteration with
no auxiliary measures is skipped. The loading path forms two direct inverses.
One matrix-construction read uses \texttt{getDouble(colIndex,i)}, whereas the
inspected data interface declares case then variable, and nearby reads follow
that declared order. This is an observable source mismatch; its reachable
runtime consequences still require caller and data-layout reproduction.
The inspected matrix path delegates inversion to EJML. Its numerical behavior,
including failure signaling for singular inputs, cannot be inferred from the
wrapper alone. Section~\ref{sec:exec25-java-iv-rd} follows the concrete data
boxes and EJML delegates: storage orientation does not repair the swapped
indices, and the inverse wrapper does not preserve the backend's boolean
return. That source analysis narrows the unanswered questions to complete
caller coverage and native behavior; it does not supply an executed trial. A helper computes a residual-scaled inverse into a local array
without returning or storing it in that method. This limits what the inspected
method establishes about returned uncertainty; it is not a finding that the
whole library lacks covariance estimation.~\citep{exec22_java_latent_iv_preflight}

The next prototype should compare observed-IV and latent measurement models
separately. Its fixtures need explicit marker choices, rectangular arrays of
cases and variables, empty-instrument cases and near-singular projections. It must inspect
callers and backend behavior before attributing an executed defect. The
authenticated source header permits GPL version 3 or later, while the build's
Java 21 setting and README's JDK 25 guidance leave environment compatibility
to resolve. Generic Java/JVM and Maven IV/RD discovery remains necessary.
Neither a favorable Python reference decision nor this bounded Java inspection
closes the broader IV/RD software landscape.
