Chapter 76

Comparing assistance with credible
alternatives

An assistant should be judged against the work an analyst could already do. Evaluation
therefore needs simple baselines, tasks with defensible answers, and a record of unresolved cases
and correction costs. The following studies ask what benchmarks, retrieval, code generation
and simulated populations can establish about that comparison.


76.1     Constructed causal labels, semantic refusal and the unit
         of evaluation
The preceding chapter established what an evaluation must preserve. This chapter asks which
simpler or more established method supplies a credible comparison at each stage. Constructed
labels and literature retrieval test the reference; coding and repair studies test calculation;
factor extraction and simulated respondents test whether the inputs represent the intended
population. The final program-of-thought study returns to the full chain, where saved accuracy,
scientific meaning and executable reuse can be assessed separately.
   A causal assistant can improve the wording of an answer while leaving its decision content
unchanged. It can also repeat a familiar causal story more fluently than an analyst without
establishing that the story applies to the bank’s observations. Evaluation therefore needs to
distinguish recognizing a stipulated mechanism, identifying an effect from supplied information
and choosing a useful action. Two further benchmarks make this distinction concrete: the
published CELLO study by Chen and colleagues and the first Research Square version of
CausalReasonBench by Cherif. The former uses visual scenes and constructed graphs; the
latter uses textual scenarios and automatic reasoning scores. Their results concern their
respective tasks and historical model settings. Neither is a measurement of a causal banking
workflow. (Chen et al., 2024; Cherif, 2026)
   Consider the proposed deposit-pricing assistant. A manager asks whether a retention offer
will prevent withdrawals. A useful response must distinguish the association between receiving
an offer and staying with the bank from the effect of offering the same terms to an eligible
customer. It must also state what the information cannot establish. A benchmark that
supplies a complete causal mechanism tests whether the assistant follows that mechanism.
A benchmark that supplies only an observational vignette may instead need an answer that
preserves several possible mechanisms. Those are different questions even when the surface
wording and requested answer are identical. Constructed labels can be valuable for the first
question; their construction does not resolve the second.

76.2.3     A nonsignificant test does not certify independence

The inspected prompt instructs the verifier to infer independence when a correlation test is
not significant. That rule confuses a sample decision with a population property. It can turn
an underpowered study into apparent evidence against a correct causal mechanism. It also
treats a selected test as if it were sensitive to every form of dependence. (Zhang et al., 2026b)
   For a finite illustration, let X be a randomized binary treatment with probability 1/2 and
let an independent flip V have probability 1/4. Set Y = X xor V . The four population cell

   If an outcome contributes a stipulated USD 100 and treatment costs USD 30, the population
incremental value is 100(1/2) − 30 = USD 20 per decision. Neither the four-row sample nor its
large p value establishes this value; it is known here only because the example stipulates the
structural law. The example demonstrates the possible loss from converting a nonsignificant
finding into a zero-effect declaration. It is not a proposal ROI estimate.
   A repaired extraction should preserve the estimator, sample size, sampling design, uncertainty
interval, null hypothesis and covariates. “Did not reject this null” is an admissible extracted
finding. “Established independence” requires a different justification. For a decision, an
equivalence analysis could target a scientifically chosen negligible-effect region, with its own
design and error control. A language model may help locate those details; it cannot supply
missing power, overlap or identification by rewriting the prose.

13 October 2025 revision of Liu and colleagues’ COAT framework addresses this interface
between unstructured observations and causal analysis. It proposes and parses factors, then
uses conventional causal-discovery feedback to refine them. The paper separates COAT-MB
for Markov blankets, COAT-PAG for refining partial ancestral graphs, and COAT-ADJ for
adjustment questions. This is a useful architecture for a banking prototype whose variables
are not already settled. (Liu et al., 2025)

76.5.1    What the representation assistant contributes

In the paper’s notation, X is unstructured input, U is a set of structured target variables
and W = h(X) is a proposed structured representation. A factor instruction specifies a
deterministic map from the input to a numerical value. The initial sampling setup uses
independently drawn paired observations. COAT-MB proposes factors in rounds, parses their
values and updates a target’s Markov blanket. Its feedback selects a cluster where the existing
factors leave high conditional entropy of the target. The algorithm stops at a maximum number
of rounds or an unchanged blanket. These choices describe an adaptive search procedure; the
stopping condition does not itself certify that all relevant factors have been found. (Liu et al.,
2025)
   For the bank, a factor definition therefore needs an observable interpretation, an extraction
rule, a timestamp and a missingness convention. “Temporary income interruption” should not
acquire a different meaning depending on the desired intervention answer. If it is read from a
note written after repayment, its predictive usefulness does not make it a pre-offer confounder.
Proposed factors can be retained as hypotheses while their provenance and clock are examined.
An ordinary prediction improvement is useful feedback, but it does not decide which variables
are eligible adjustment controls.

76.5.2    The parsing assumption is scientifically substantive

The selected paper explicitly assumes faithful and Markov correspondence between a graph and
the factor distribution, with conditional independences preserved after parsing. It acknowledges
that annotation error can violate this premise. High marginal accuracy is consequently
insufficient to establish that a parsed variable can replace its true counterpart in adjustment
or conditional-independence tests. (Liu et al., 2025)

76.7.1      The target is correctness under a declared information contract

Consider a retention-offer question whose request identifies the eligible customers, the offer
time, the balance horizon and the information available before the offer. The assistant must
preserve these elements when it proposes a graph and an estimand. A useful benchmark
includes several legitimate outputs: a supported identification formula, an explicit effect set,
or a refusal that names the missing assumption or observation. Correctness is judged against
the stated graph class and information, rather than against a single preferred diagram. If the
scenario does not determine an edge direction, selecting the examiner’s favorite direction is
not the target.
   Let A ∈ {0, 1} denote the assigned assistant workflow, with the base model, retrieval access
and available tools specified for each arm. Let C = 1 mean that an answer meets a frozen
semantic criterion. Let G = 1 mean that a grader marks the answer as passing. These are
distinct binary variables. The criterion could require a correct adjustment set and an explicit
warning about an unidentified query; other criteria, such as factual grounding and valid code,
should also be reported individually. A single binary endpoint is introduced here only to
expose a measurement problem. It cannot capture every consequence of a wrong scientific
answer.
  Define pa = Pr(C = 1 | A = a), grader sensitivity sa = Pr(G = 1 | C = 1, A = a) and grader
specificity ca = Pr(G = 0 | C = 0, A = a). All probabilities refer to the same declared scenario
and answer population. By conditioning on correctness,
       qa := Pr(G = 1 | A = a) = sa pa + (1 − ca )(1 − pa ) = (sa + ca − 1)pa + 1 − ca .       (76.33)
This is an authored measurement model, not an empirical estimate from Lin’s tutorial. Random
assignment of A, consistency of the assigned workflows and an appropriate no-interference
condition can identify a causal effect on the observed grade for the experimental population.
Those conditions alone do not make q1 − q0 an effect on semantic correctness. The relation
between G and C must also be supported. (Causal banking proposal project, 2026aw)

   Compare a no-tool answer, a direct formula checker, calls to a constrained causal library and
a generated-code agent on the same frozen cases. Review source-span fidelity, temporal roles,
missing variables, graph alternatives, identification/refusal, numerical error and final decision
separately. Count invalid code, timeouts, retries and abstentions in declared denominators. A
correct final yes/no answer must not conceal an unsupported graph or a wrong estimand that
happened to yield the same sign. Blinded reference adjudication should precede scoring, and
unresolved reference disagreements should be visible.
   The comparison also needs model and tool revisions, seeds or decoding settings, raw
responses, generated programs, dependencies and all failed attempts. Question-level paired
results support uncertainty calculations that respect the shared cases. Token use, tool calls,
latency and human correction time belong in a full workflow comparison. Useful merit means
meeting a predeclared combination of decision quality, justified refusal and total cost; it is not
established by the paper’s accuracy improvement alone. These are proposed public qualification
steps, with no live-model result claimed here.


76.10.7     A proposed CLI and MCP boundary

A request should distinguish a calculation from a proposed interpretation. It should carry
the decision time, eligible population, intervention, outcome coding, horizon, source identities
and spans, graph alternatives, estimand and explicit assumptions. A calculation request
additionally needs its actual probability table or dataset and a declared sampling law. The
response should return the selected target, unresolved conditions, calculation provenance
and a typed disposition. Missing scientific information, conflicting evidence, unsupported
identification, invalid code and numerical failure are different outcomes requiring different next
actions.
   For a generated-code prototype, the proposed execution boundary permits only declared
inputs and bounded computation in a restricted environment. Generated code, dependency
identities and tool inputs must be inspectable, and network access or policy actions must
not be implicit consequences of a calculation. A formula checker or typed library call can
supply a simpler comparator with a smaller execution surface. The paper motivates evaluating
these alternatives; its use of a REPL is not evidence that this proposed interface has been
implemented or qualified. The following repository review inspects selected prompts, saved
evaluations and source rights, identifying both reusable records and defects that rule out
unchanged executable adoption. Complete artifacts, dependencies and a qualified runtime
remain prerequisites for a new comparison. (Shrestha et al., 2025)
   The resulting investment question is concrete: can constrained calculation support improve
a faithfully specified causal workflow on public cases at an acceptable total cost? A positive
result would justify a more expensive prototype or institutional study while preserving the
additional assumptions that authentic banking decisions require.

76.11.3     The example generator and the displayed graph disagree

The program prompt supplies an illustrative drug-assignment example. Read literally as an
intended generator, it draws assignment A with probability one half, then independently draws
adherence T and low cholesterol Y conditional on A. Its probabilities are

                     P (T = 1 | A = 0) = 0.79, P (T = 1 | A = 1) = 0.43,
                     P (Y = 1 | A = 0) = 0.54, P (Y = 1 | A = 1) = 0.52.

The generated outcome does not depend on adherence once assignment is fixed. Yet the
displayed DoWhy graph contains only T → Y and treats adherence as the intervention.
Assignment, which drives both generated variables, is omitted. The example also contains
explanatory text that is not valid Python inside its purported code illustration. These are
properties of the selected prompt text; the prompt module itself is a Python string, and no
failure rate for generated programs follows from inspecting it. (Rahul Shrestha and causal-

76.11.4     Reference reuse requires a different execution contract

The selected inference helper has a concrete call mismatch: its self-consistency function accepts
four parameters while its caller supplies five. Within the helper, the completion call also omits
the client required by that routine. The tree branch in the common runner is unimplemented,
with tree logic instead appearing in a separate notebook. These observations qualify the
selected source revision. They do not establish which revision or interactive notebook state
generated the saved result tables. (Rahul Shrestha and causal-reasoning contributors, 2025)
