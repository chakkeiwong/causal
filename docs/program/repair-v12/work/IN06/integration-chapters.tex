\chapter{Preserving a causal result across software boundaries}
\label{in:semantics}

\section{The unit of exchange is an analysis with meaning}

A funding service, a servicing notebook and an analyst's agent may all request
an ``effect'', while referring to different populations, actions, horizons and
units. Exchanging a floating-point number is therefore insufficient. The
proposed common object contains a scientific context, an operation, input
identities, an execution disposition and a qualified result. The local
reference implementation enforces selected parts of this contract; it does not
validate the truth of every declaration.\cite{v12_in_contract,v12_in_runtime}

For a scalar intervention query, write the context schematically as
\[
 Q=(P,\mu,a,a_0,Y,H,u,s,\mathcal T,\mathcal A,G),
\]
where $P$ is the population, $\mu$ its weighting measure, $a$ and $a_0$ the
intervention and comparator, $Y$ the outcome, $H$ the horizon, $u$ the units,
$s$ the sign convention, $\mathcal T$ the information clocks, $\mathcal A$ the
assumptions and sampling declarations, and $G$ the graph or graph class.
This mathematical notation expresses the required meaning; particular schema
fields may encode only a supported subset. The original declaration must be
retained when a narrower operation representation is used.

Changing $a-a_0$ from a ten-basis-point offer to a one-percentage-point offer
changes the question, even if the same coefficient field can store both.
Replacing customer weights by balance weights changes $\mu$. Treating a
post-decision observation as available history changes $\mathcal T$. A digest
can detect that the declared context changed. It cannot establish that the
context describes the actual banking process.

The implementation binds supplied moments and sensitivity artifacts to their
scientific context. Reusing their bytes with a changed sign, clock, unit or
target is rejected unless a new, appropriate artifact is supplied. This
prevents a consumer from reinterpreting a cached numerical object through an
unannounced schema change. It does not replace a scientific argument for the
moments or covariance.\cite{v12_in_runtime}

\section{Execution, science and qualification are different states}

A successful invocation can return unsupported identification, an empty
sensitivity set, or a whole-line confidence set. These are not necessarily
transport failures. Conversely, a timeout supplies no scientific answer even
if the requested mathematical object exists. The common response separates
invocation state, scientific disposition and qualification evidence.

This separation gives a batch operator a defensible continuation rule. A
completed negative answer can be archived and used in a report. A malformed
request needs correction. An unsupported operation needs another qualified
backend or a narrower, explicitly authorized question. A contradiction in the
declared premises needs scientific review. Automatically retrying all four
events until a finite number appears would select answers according to their
convenience.

The library's supplied-DAG back-door operation illustrates the distinction.
It can attempt an adjustment expression in its bounded domain. Failure of
that attempt does not prove general nonidentification; a different graphical
functional or additional information could be relevant. The response must
describe the actual method and its limitation. Likewise, graph syntax review
checks declared structures but does not discover their causal truth.
\cite{v12_in_runtime}

\section{Sets must retain their topology}

The local representation distinguishes unknown from empty, and permits a union
of intervals with infinite endpoints. Unknown has no asserted interval list;
an empty set has an empty list. A whole-line set has one interval unbounded in
both directions. A disconnected set keeps its components.\cite{v12_in_contract}
None should be represented by an arbitrary plotting range.

Consider the stipulated effect set
\[
 \Theta=(-\infty,-2]\ \cup\ [3,\infty)
\]
and a known monetary map $V=100\theta-300$. The image is
\[
 V(\Theta)=(-\infty,-500]\ \cup\ [0,\infty).
\]
Taking the convex hull would return the entire real line and discard a real
exclusion. Clipping the tails would falsely assert boundedness. Changing to a
loss convention $L=-V$ gives $(-\infty,0]\cup[500,\infty)$; endpoint order must
reverse when multiplying by a negative number.

If $\Theta$ has a stated coverage guarantee for $\theta$, applying a known
deterministic map preserves containment on the same event. It does not create
a guarantee for an estimated conversion factor or a randomly chosen target.
When margins, discount rates or exposure weights are estimated, joint
uncertainty or an explicitly conditional analysis is needed. Serialization
cannot make uncertain financial inputs fixed.

The same care applies to graph sets. Member identities, endpoint semantics and
evidence must travel with the alternatives. A CPDAG, PAG and selected DAG are
not interchangeable edge lists. The present schema retains declared classes
and hashed membership; its validator is not a complete recognizer or confidence
construction for arbitrary temporal equivalence classes.

\section{A contract for future numerical adapters}

Each adapter should state its accepted targets, graph classes, sampling laws,
missingness rules, numerical inputs and output uncertainty. A source package
may use an ATT where the caller requested an ATE, return pointwise intervals
where simultaneous inference is required, or approximate a set with a hull.
Those are semantic mismatches even when both sides exchange valid JSON.

The adapter must either preserve the requested meaning, return a disclosed
qualified approximation, or refuse the mapping. A proposed R, Python, Java or
C++ bridge therefore needs matched fixtures at ordinary and adverse boundaries,
including disconnected sets, weak identification and unsupported models.
Cross-language execution, licenses, data copying and complete workloads remain
qualification obligations. The existing local dispatcher is a common boundary
for that work, not evidence that those bridges already exist.

\chapter{The library, command line and MCP service}
\label{in:surfaces}

\section{One dispatcher and three access paths}

The implemented local library entry is
\texttt{causalbank.runtime\_v12.Runtime.invoke}. The JSON command line and MCP
server call the same runtime, artifact store and scientific dispatcher. This
architecture reduces opportunities for one interface to silently change an
operation's meaning, while leaving transport-specific validation necessary.
\cite{v12_in_runtime}

Nine advertised operations execute in the reference scope: capability
inspection; declared graph syntax review; supplied-DAG back-door identification;
supplied-moment Gaussian residual-test inversion; quadratic sensitivity sets;
observation timestamp diagnostics; durable reports; job status; and job
cancellation. Automatic formulation, data-driven discovery and design comparison
have no engine in this runtime. Canonical requests for unsupported methods
retain that status, and the MCP tool list advertises only implemented operations.

Moment inversion uses the supplied mean and covariance under its declared
Gaussian approximation. It is not an arbitrary estimator fitted to bank rows.
The sensitivity operation solves a deterministic inequality and labels the
result nonprobabilistic. These boundaries are essential when a general agent
selects tools by their names: ``estimate effect'' is an operation family, not a
promise that every causal question is supported.

\section{Command-line use and result handling}

From this repository's root, the installed local runtime can be invoked through
the following entry points. The first displays the interface. The second
assumes an operator-prepared canonical request whose operation field is
\texttt{graph.review}; the file is not created by the command itself.
\begin{lstlisting}
PYTHONPATH=src .runtime/in04/bin/python -m causalbank.cli_v12 --help
PYTHONPATH=src .runtime/in04/bin/python -m causalbank.cli_v12 \
  operation graph.review --input request.json
\end{lstlisting}
The operation name on the command line must agree with the JSON request.
Requests are bounded and validated. Artifact import is a separate operator
action taking JSON on standard input, with an explicit role and schema version.
The scientific request subsequently refers to an opaque artifact identity.
\cite{v12_in_runtime}

Exit status describes command execution. Completed, queued, running and
cancelled canonical responses can return exit zero. Invalid requests use exit
two, unavailable local artifacts exit three, and execution failures exit four.
A consumer must read the response's scientific disposition rather than equate
exit zero with an identified, useful or institutionally accepted effect.

The current state root is an operator launch setting inside this repository's
\texttt{.runtime} tree. A scientific request cannot choose an arbitrary working
directory or program to execute. Notebook use can call the same library
directly, but notebook authors remain responsible for retaining the canonical
response instead of displaying only a convenient scalar from it.

\section{The tested MCP protocol is explicit}

The real server uses Python SDK~1.27.0 and the legacy MCP~2025-11-25 protocol
over local standard input/output. The inspected specification requires
initialization and version negotiation, and reserves stdout for newline-delimited
protocol messages.\cite{v12_mcp_legacy_lifecycle,v12_mcp_legacy_stdio}
The local launch entry is
\begin{lstlisting}
PYTHONPATH=src .runtime/in04/bin/python -m causalbank.mcp_server_v12
\end{lstlisting}
A compatible MCP client must manage the protocol exchange; this command is not
an interactive natural-language console. Diagnostics belong on stderr.

Structured tool results carry the canonical response, with a JSON text copy for
compatible clients. Tool execution errors and unknown-tool protocol errors are
handled separately.\cite{v12_mcp_legacy_tools,v12_in_runtime} The recorded
conformance trial verifies both response representations against the library
and CLI for the selected cases.

The separately inspected 2026-07-28 specification uses a different discovery
and per-request metadata arrangement.\cite{v12_mcp_versioning,v12_mcp_basic}
The present service does not implement that protocol era or HTTP transport.
Its negotiation restricts the process to the tested legacy revision; a client
that cannot use the returned version must not assume compatibility. The name
MCP alone is too broad to specify a working consumer contract.

\section{Resources and custody are part of the interface}

The specification provides resource listing and reading operations; the
product applies a narrower local custody policy.\cite{v12_mcp_legacy_resources}
Only small reports, evidence summaries and canonical responses are exposed as
MCP resources. Raw input artifact roles are excluded, and reads have explicit
size and identity checks. A tool response can therefore point to a report
without making the underlying raw observations into model-readable resources.

This is an implemented local operator boundary. It is not multi-tenant
authentication, a remote authorization service or isolation from a hostile
operator who controls the same files. A later service wrapper needs those
additional properties, plus a policy for customer data, before a bank client
can rely on it. The current runtime itself invokes no language model and
uploads no observations.

\section{What the conformance evidence establishes}

Eleven recorded scientific fixtures compare library, CLI and real MCP outputs,
including graph review, a back-door expression, weak moment inversion,
finite/empty/whole-line/disconnected sensitivity sets, unsupported behavior,
contradicted premises and a late observation. Report submission and terminal
job queries were also compared.\cite{v12_in_runtime} These are checks that the
interfaces preserve selected results. They do not independently qualify the
scientific premises of those results.

The SDK's thread wakeup hung in the managed sandbox, including a minimal
diagnostic, while the recorded diagnostic and harness passed in the approved
local environment outside that sandbox. This is a material operating limit:
an installation plan must test the actual launch environment rather than infer
successful service operation from importable packages. The environment and
failed attempts remain part of the evidence.

\chapter{Workspace consumers and complete banking workflows}
\label{in:consumers}

\section{An inspected interface is a proposed connection}

The dated workspace inventory covers eighteen observed top-level directories
and fifty-three source records. It inspects declarations and documentation,
without executing or changing sibling projects. Three MacroFinance worktrees
belong to one project family and are not three independent implementations.
These are observations of the local environment on 12 October 2026, distinct
from the literature cutoff.\cite{v12_in_inventory}

FinMarketing, dataml and MacroFinance form the initial conformance shortlist.
BayesFilter and CardNPV supply additional numerical and value interfaces to
assess. A shortlist is a design choice based on inspected boundaries, not a
claim that maintainers have accepted this contract. Every actual connection
still needs a version-specific mapping and a complete workflow trial.

The proposed adapters reside in the causal project. Their purpose is to map
explicit consumer records to the canonical analysis, retaining the original
record and any unresolved meaning. A consumer should not need to adopt an
internal research directory structure, and an adapter must not import an
unrelated project's historical execution path merely because it is available.

\section{Funding: model authority and monetary meaning}

The funding exchange needs the action's basis and sign, the population or
exposure weights, balance units, horizon and discounting rule. It also needs
the observation law and the uncertainty carried by the numerical provider.
The intended sequence is a consumer target, a reviewed causal declaration,
supported identification and estimation, and a qualified monetary result.
Every arrow in that sequence is a proposed conformance boundary to test.

The inspected MacroFinance instructions designate BayesFilter as the numerical
authority and demote historical local filter/HMC paths. BayesFilter's selected
contracts retain model, data, coordinate and approximation identities.
\cite{v12_in_inventory} A causal-side adapter should consume the selected
authority's declared outputs and diagnostics. A successful state-space fit
does not itself establish the intervention interpretation of a funding shock.

A useful adverse fixture changes one field at a time: ten basis points to one
percentage point; USD millions to USD; benefit minus cost to cost minus benefit;
six months to one year; or known assignment to estimated assignment. The
correct consumer behavior is either an explicitly justified transformation or
a refusal requiring a different analysis. Numeric closeness on one example
cannot validate the mapping.

The current local runtime has no qualified general BayesFilter or MacroFinance
adapter. Its supplied-moment operation can demonstrate interchange of an
already declared result in a narrow law. End-to-end inference from a sibling
model, including approximation and causal uncertainty, remains further work.

\section{Servicing: source clocks and policy-value contrasts}

FinMarketing's inspected toolkit exposes JSON operations and source, feature
and target records. These are useful boundaries for retaining entity ownership
and information availability.\cite{v12_in_inventory} A servicing workflow should
declare which feature snapshot was available before each action, which later
observations update the state, and how the intervention changes decisions.
An event timestamp alone does not certify that the bank could use a feature
at decision time.

CardNPV's inspected target is historical value minus perfect-execution value,
with horizon, intervention and continuation qualifications.
\cite{v12_in_inventory} That accounting object cannot silently become a
population ATE or an alternative servicing policy's value. If a consumer asks
for a policy contrast, the adapter must identify both policies and their
information sets, then justify any relationship to the accounting target.
Reversing a sign field is insufficient when the interventions differ.

One proposed trial therefore carries an explicit observable policy through
feature construction, declaration, supported longitudinal inference and value
reporting. An adverse companion introduces information that becomes available
after an action. Another changes the continuation assumption. Both should
preserve the original request and explain the failure. The existing static
ATE translator does not implement this longitudinal exchange; its refusal is
part of the current capability boundary.

\section{Discovery and trustworthy observations}

For discovery-to-effect use, model equations, timing declarations and evidence
can help construct candidate diagrams. DynareMCP's inspected documentation
distinguishes selected CLI/in-process operation from unqualified strict stdio
support. MathDevMCP exposes mathematical-tool boundaries with restricted use
terms.\cite{v12_in_inventory} Their names do not establish transport conformance
with this service or causal identification of an imported model.

The proposed exchange retains a variable ontology, measurement definitions,
time indices, edge endpoints, graph alternatives and source anchors. A graph
result then reaches an identification operation only in its supported domain.
The conformance trial must preserve an unsupported or ambiguous result as
carefully as an adjustment expression. A mathematical simplification or a
tool trace alone is not a proof that the scientific premises hold.

Trustworthy-observation work starts still earlier. Candidate owners, selection
rules, inclusion probabilities and label audits determine what the observations
mean. A local adapter can verify that the supplied artifact is unchanged and
that declared clocks are internally consistent. It cannot infer authentic
ownership or validate gold labels from a schema. Proposed dataml and
FinMarketing exchanges should therefore carry those declarations and their
evidence instead of flattening them into a clean table without provenance.

The four workflow designs are complementary. A trustworthy observation may
feed discovery; a discovered class may restrict a policy effect; a funding or
servicing decision may determine which additional audit is valuable. The
common contract makes these connections explicit without assuming every stage
has a qualified implementation.

\section{Standalone use and a consumer acceptance trial}

The library supports local analytical code, the CLI supports bounded batch
requests, and the tested MCP surface supports compatible local clients. A
service wrapper remains proposed. All should preserve the same scientific
context and result, but their operating risks differ: notebooks can discard
metadata, shell pipelines can ignore dispositions, and agents can misread a
tool's capability boundary.

A proper consumer trial starts from the consumer's actual request and ends at
its displayed decision object. It checks the target mapping, input identities,
full uncertainty, exceptions, cancellation, replay and monetary interpretation.
Matched toy fixtures isolate semantics; realistic workloads then reveal data
copying, environment and recovery costs. Maintainer acceptance and bank use
must be recorded separately from author-operated trials.

License review precedes adoption, copying or redistribution. Several inspected
projects have internal-use, proprietary or incomplete notices; metadata alone
does not establish permission for a proposed port.\cite{v12_in_inventory} These
limits can change the integration choice even when an API mapping is clear.
The present inventory copies no sibling implementation and supplies no
distribution approval.

\chapter{Operating the local causal service and qualifying its limits}
\label{in:operations}

\section{An execution identity is larger than a request name}

A durable analysis must bind the canonical request, scientific context, input
bytes, code, schema, numerical environment, seed and budget. A repeated job
name alone cannot establish that a result is still valid. The implemented
runtime records these identities and rejects idempotency collisions involving
changed requests or execution identities.\cite{v12_in_runtime}

Artifacts use canonical JSON, content and descriptor hashes, opaque identities
and bounded local reads. Regular-file and nonsymlink checks reduce accidental
path redirection. A content hash establishes byte identity under the relevant
assumption about the hash function; it is not an authenticated endorsement of
the input's scientific accuracy. A local operator can still supply a false
declaration whose bytes remain perfectly stable.

The scientific request contains no arbitrary shell command, Python import or
network endpoint. Fixed worker entry points execute the supported operations.
This makes the scope of the local tool explicit and allows a review grant to
refer to actual operations. The current controller's trusted caller object is
not a substitute for an institutional identity and approval service.

\section{Budgets, durable jobs and cancellation}

Scientific workers have wall-time and address-space limits. The memory bound
applies to the worker, not to all memory used by the resident SDK and
coordinator. A complete operating measurement must include both. Small control
or error envelopes may exceed an extremely small requested output limit to
explain why the request cannot be fulfilled. These are disclosed boundaries of
the present implementation.\cite{v12_in_runtime}

Report jobs retain a hashed prefix of completed work identities. The local
retry rule is bounded to three attempts under the original deadline. Publication
is atomic, and replay checks request, artifact and checkpoint identities before
continuation. The recorded restart fixture kills a report worker after its
first checkpoint and completes all one hundred distinct work identities once.
This is evidence for that local workflow, not a distributed exactly-once
guarantee for arbitrary external side effects.

Cancelling an in-flight protocol request and cancelling a durable application
job are different operations. The inspected specification also recognizes
cancellation/completion races.\cite{v12_mcp_legacy_cancellation} If publication
has already completed, a cancellation response must report that terminal state.
It must not imply that a displayed result or an external action was undone.
The present service has no operation that changes a bank account or sends a
customer communication.

\section{Fault evidence and what remains unmeasured}

Nine recorded fault cases cover replay with conflicting budgets, wall timeout,
output limits, worker memory, kill/restart with checkpoint, cooperative
cancellation, changed artifact bytes, changed scientific context and changed
checkpoints.\cite{v12_in_runtime} The tests distinguish preserving a result from
merely restarting a process. An interrupted computation that silently uses new
inputs is a different analysis even if it eventually finishes.

These fixtures do not measure institution-scale availability, multi-host
recovery, adversarial tenant isolation or a service-level commitment. They also
do not show that streaming always improves elapsed time. The earlier complete
local workload comparisons retain small or absent gains; engineering choices
must be justified by the intended workload rather than by the existence of a
streaming interface.

Operational qualification should measure the complete request: artifact import,
scientific work, uncertainty, serialization, reporting and recovery. A benchmark
of one reducer omits fitting and coordination costs. The comparison needs
matched inputs, numerical tolerance and an explicit accounting of unsuccessful
requests, just as a scientific comparison needs a common target.

\section{Compatibility is a maintained scientific obligation}

A new backend release can change defaults, graph encodings, estimator targets,
uncertainty or failure behavior. A compatible JSON schema alone does not prove
scientific compatibility. The proposed adapter register should bind a version,
accepted inputs, method identity, preserved result types and matched adverse
fixtures. A material semantic change requires a reviewed successor rather than
relabeling an old qualification.

Transport migration likewise needs real client/server tests. The current legacy
MCP choice is useful for its tested environment. Supporting a modern protocol
or both eras requires a new compatibility argument, discovery behavior and
failure tests. It should not be advertised by extending a version string while
keeping the old handshake.

Ownership must also remain explicit. The causal library owns its result
contract and adapters. Numerical providers own their implementations and
scientific domains. Consumers own their target interpretation and displayed
decision. The bank owns actual data authority, assignment records, operational
constraints and acceptance. A report can connect those responsibilities; it
cannot replace their evidence.

\section{The next complete qualification}

The remaining engineering route is concrete: choose source-audited packages
and permitted integration forms, implement representative bridges, and run
matched consumer workflows across all three surfaces. The trial must include
unsupported methods, late observations, graph ambiguity, weak or disconnected
effect sets, interruption and changed-input rejection. Passing results should
name the actual supported environments and domains.

This work will close an engineering gap only in those domains. Negative
persistent-map, latent-graph and dependent-learner studies remain scientific
obligations. Independent review, authentic bank validation and measured
economics remain additional gates. A coherent runtime makes their required
inputs and outputs reviewable; it does not turn missing information into an
accepted causal answer.
