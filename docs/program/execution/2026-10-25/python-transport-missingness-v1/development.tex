\section[Python transport and missingness contracts]{Python transport and missingness: defaults, uncertainty, and the meaning of completion}
\label{sec:exec25-ptm}

A bank selecting a Python workflow for a partially observed target population must choose more than an estimator name. It must preserve the population, treatment contrast, outcome scale, observation mechanism, and uncertainty target through selection weighting, prediction, imputation and discovery. The selected primary implementations are zEpid, causallib, miceforest, statsmodels and causal-learn, pinned at or before the client cutoff. They perform different scientific jobs. A shared Python runtime makes composition possible, but does not establish that their scientific contracts compose. The following comparison uses authenticated source and exact authored laws; no downloaded package was executed.\citep{exec25_ptm_zepid,exec25_ptm_causallib,exec25_ptm_miceforest,exec25_ptm_statsmodels,exec25_ptm_causallearn}

\subsection{Transport requires the right score, not just the right odds}

zEpid explicitly separates generalizability, where the trial belongs to the target population, from transportability to a disjoint target. Its IPSW class fits selection models and uses inverse probabilities or inverse odds as appropriate. The selected fit computes separately normalized weighted means in the two treatment groups and reports a difference and ratio. A constant stabilization factor cancels in such an arm-specific weighted mean. Its documentation directs uncertainty estimation to a nonparametric bootstrap, and the selected source contains a placeholder for a missingness model. The adapter must therefore specify who is resampled, which models are refitted, and whether missing outcomes are supported by a separate qualified mechanism. The presence of sampling weights is not a proof of censoring adjustment.\citep{exec25_ptm_zepid}

The same package's GTransportFormula fits a source response model and averages counterfactual predictions over either the combined population or only the target sample. This makes a target-population choice visible. Its optional weighting must still be interpreted consistently in source fitting and target averaging. The AIPSW class adds augmentation and explicitly refuses its optional weights argument at construction. That refusal is valuable product behavior: an adapter should preserve it rather than silently drop weights to obtain a numerical answer.\citep{exec25_ptm_zepid}

Augmentation changes the role of stabilization. Let $S$ mark source membership, $A$ treatment, and write $p=P(S=1)$ and $e=P(A=1\mid S=1)$ in a simple randomized law. With $p=4/5$, $e=1/2$, $Y=A$, and a working response regression set to zero, the target effect is one. The selected AIPSW transport formula divides its residual sum by the target count. Its default sampling stabilization multiplies inverse odds by $p/(1-p)$, while the default treatment stabilization is one in this constant-probability example. Thus the supplied-nuisance population value of that selected residual is $pe/(1-p)=2$. In generalize mode, the corresponding default residual average is $pe=2/5$. With unstabilized sampling and treatment factors, the transport reference is
\[
 \frac{pe}{1-p}\frac{1-p}{p}\frac1e=1.
\]
These are authored population calculations for the displayed branches. They are not outputs from fitted package runs, and a correct outcome model can remove the residual discrepancy in this example. They show why cancellation in a normalized IPW mean cannot be assumed in an augmented residual added to a different averaging term. The proposed qualification compares all combinations of target mode, response misspecification, treatment weighting and stabilization before admitting a claimed robustness property.\citep{exec25_ptm_zepid,exec25_ptm_choice}

The economic implication is conditional but concrete. In that two-versus-one witness, 10,000 hypothetical customers valued at USD10 per outcome unit produce a USD100,000 discrepancy. This is neither an observed loss nor an ROI estimate. It defines a public prototype test whose cost can be compared with the risk of misinterpreting the result before any expensive bank experiment.\citep{exec25_ptm_choice}

\subsection{Treatment balancing is a component of a population argument}

causallib supplies reusable treatment weighting, response standardization and doubly robust components. Its selected IPW implementation predicts a probability matrix, clips entries to requested bounds, and takes reciprocals. These are useful implementation boundaries, but treatment assignment and source selection remain distinct variables with different identifying roles. Reusing a treatment-weight class for population transport requires an explicit transformation and target derivation; the API alone does not provide them.\citep{exec25_ptm_causallib}

The exact shape of a weight matrix matters. In the selected stabilized branch, prevalence is looked up using each row's observed treatment and multiplied into every column of that row. This produces the usual numerator on the observed-treatment diagonal. It is different from a counterfactual matrix whose column $a$ always uses $P(A=a)$. With prevalences $(1/4,3/4)$ and probabilities $(1/2,1/2)$, the selected rows are $(1/2,1/2)$ for an observed control and $(3/2,3/2)$ for an observed treated subject; a column-stabilized reference would have $(1/2,3/2)$ in both rows. The observed diagonal agrees, so this is not a claim that ordinary observed IPW extraction is wrong. It is a warning to specify which entries a downstream consumer interprets.\citep{exec25_ptm_causallib,exec25_ptm_choice}

Likewise, componentwise clipping need not preserve the probability simplex. Clipping $(0.98,0.01,0.01)$ to $[0.1,0.9]$ gives $(0.9,0.1,0.1)$ with sum $1.1$. Such values can be intentional bounded denominators, but should not automatically be passed as a normalized categorical distribution. The proposed result schema distinguishes original probabilities, bounded denominators, normalized sampling probabilities and final weights. Qualification must retain how many values were clipped, the changed estimand or approximation, and any downstream normalization.\citep{exec25_ptm_causallib,exec25_ptm_choice}

\subsection{Completed datasets and valid uncertainty are separate deliverables}

miceforest provides model-based chained imputation with several mean-matching choices. The selected implementation can choose observed nearest-neighbor donors, sample categorical values according to model probabilities, or skip mean matching. With zero candidates it uses regression predictions or modal classes. These choices change the conditional imputation law. For a fixed binary prediction $P(Y=1)=1/4$, a stochastic draw has mean $1/4$ and variance $3/16$, whereas modal completion returns zero with zero conditional draw variance. Other randomness from fitted models or initialization can remain; the claim is only about the selected conditional completion step. Faster deterministic completion is not automatically a valid multiple-imputation uncertainty mechanism.\citep{exec25_ptm_miceforest,exec25_ptm_choice}

The deployment contract is also concrete. Imputing new data requires stored models and candidate values; the selected method refuses when iteration data were not saved. Script-level random-state reproducibility is distinguished from record-level reproducibility, which has additional seed and data conditions. The binary fast path with record seeds calls the global NumPy seed function for each record. A CLI/MCP worker must therefore isolate and restore its random-state boundary if other tasks share the process. This is a source-level interference risk to test, not a measured concurrency failure. The neighbor query also requests all workers, making resource limits part of an execution wrapper's responsibilities.\citep{exec25_ptm_miceforest}

statsmodels offers a different MICE implementation with parametric perturbation, donor matching and analysis-result pooling. It drops rows where all variables are missing and resets the index. A bank pipeline must preserve a separate identifier and the dropped-row ledger to avoid assigning completed values to the wrong customers. The imputer permits Gaussian parameter draws or bootstrap perturbation and supplies a model contract for predictions and covariance. The selected setter stores the donor-count setting on the common object rather than in a per-variable dictionary, so a later setter can change the donor count used for other variables. This must be made explicit in an adapter instead of promising an unsupported per-variable setting.\citep{exec25_ptm_statsmodels}

The pooling implementation retains full covariance. With three two-parameter estimates $(0,0)$, $(2,2)$ and $(4,4)$, and an identity within-imputation covariance, the pooled covariance is
\[
 T=\begin{pmatrix}19/3&16/3\\16/3&19/3\end{pmatrix}.
\]
The variance of the parameter difference is two. Discarding cross-covariance would instead give $38/3$. This exact example shows why returning only marginal standard errors loses information needed by a banking contrast. The selected code uses the empirical between-imputation covariance and the factor $1+1/m$; valid analysis still depends on the imputation and complete-data models. Small numbers of imputations, inadequate donor support, singular fits and unsupported degrees-of-freedom assumptions require explicit qualification.\citep{exec25_ptm_statsmodels,exec25_ptm_choice}

\subsection{Missingness-aware discovery has its own assumptions}

causal-learn provides test-wise deletion and a missingness-correction path for conditional-independence testing. The selected missing-value Fisher test chooses complete rows for each tested variable set, inverts their correlation matrix, and uses the multiplier $\sqrt{n_{\rm test}-|Z|-3}$. It explicitly rejects zero overlap and singular inversion, but the displayed path has no preceding positive-degrees-of-freedom guard. At three rows and no conditioning variables the multiplier is zero, yielding a nominal value of one when the correlation calculation remains finite. This is an exact formula boundary requiring a minimum-information refusal policy, not evidence that a three-row dataset establishes independence.\citep{exec25_ptm_causallearn,exec25_ptm_choice}

The correction routine depends on a previously inferred skeleton and missingness-parent information. It falls back to test-wise deletion when the correction condition or usable predictors are absent. Otherwise it fits linear regressions, shuffles complete predictor rows, and adds retained residual vectors to predicted values to form virtual data. The assumptions needed to transfer those residuals to a new predictor distribution remain substantive. Heteroskedasticity, nonlinear relationships, estimated missingness parents, and the randomness of the virtual sample must be part of the qualification design. A graph learned from such a procedure is not by itself a confidence set for the customer's intervention effect.\citep{exec25_ptm_causallearn}

One dispatch detail is particularly important for typed interfaces: both accepted correction names, including the G-squared-named option, set the selected correction test to mc\_fisherz. The wrapper must not promise a categorical G-squared correction merely because the supplied name was accepted. It should resolve the actual implementation and refuse an unsupported semantic contract. Exact scientific type checking is more valuable than a superficially uniform command name.\citep{exec25_ptm_causallearn}

\subsection{Conditional reuse and public qualification}

The proposed adoption choices follow these boundaries. zEpid is a candidate for explicit transport targets and source-response models, with augmented normalization and missingness support qualified separately. causallib supplies candidate treatment-balancing components after matrix semantics and population mappings are fixed. miceforest is a candidate flexible imputation engine with declared randomness, resource and new-data contracts; statsmodels is a candidate analysis-and-pooling engine with preserved row identity and full covariance. causal-learn is a candidate missingness-aware discovery component under a specified test and missingness law. None is admitted as a universal transport or missing-data solution. A port must preserve refusal and failure behavior along with arithmetic, and an adopted runtime requires versioned dependencies and rights.\citep{exec25_ptm_choice}

Six bounded discovery queries retain returned and unreturned candidates, including substantial adjacent material that is not evidence of population transport capability. The package metadata and license files are retained separately from complete dependency clearance. miceforest declares MIT in its selected project metadata, but the selected complete tree contains no license-named file; that declaration does not close distribution diligence. Source comments naming scholarly works are discovery leads until genuine originals and inspected anchors are retained.\citep{exec25_ptm_miceforest,exec25_ptm_choice}

The public qualification program should freeze the target law, intervention, selection and observation indicators, probability conventions, imputation mask, seed scope and contrast covariance. First replay exact supplied-nuisance scores, then add fitted learners, repeated sampling, missingness mechanisms, clustering and resource failures. CLI/MCP responses should distinguish observed data, generated imputations, sensitivity assumptions, graph uncertainty and causal effects, with retained denominators for every refusal and failure. That program can justify a prototype before bank trials, while preserving the central boundary: a filled table is not evidence that the missing causal information has been recovered.\citep{exec25_ptm_choice}
