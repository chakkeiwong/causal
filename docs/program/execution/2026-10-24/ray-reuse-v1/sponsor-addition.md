## Distributed execution must preserve the scientific request

Ray is retained as a pinned source reference and conditional prototype option. The selected Core documentation and source distinguish task retries, actor state recovery, object ownership, cluster metadata durability and runtime environments. A worker returning successfully does not establish exactly-once scientific accounting, durable bank state, independent sampling units or secure multi-tenant operation. The development source identity is separate from an installed release. \citep{exec24_ray_sources}

Exact authored witnesses show a 2 USD logical mean becoming 2.40 or 3 USD after duplicate accounting, and a household covariance contribution shrinking by half when worker fragments replace household units. A stable contribution ledger rejects conflicting duplicates. Stipulated scaling and cost examples distinguish ideal 2.5 speedup from 1.43 after overhead, and 60 USD per attempt from 120 USD per accepted artifact. These are reproducible design examples, not Ray benchmarks or vendor prices. \citep{exec24_ray_contract}

Adoption remains conditional on profiling against a local baseline, a pinned environment and rights inventory, external isolation, deterministic fold and contribution identities, owner/head/worker failure tests, numerical aggregation checks and complete cost accounting. The proposal rejects a wholesale scheduler port and unrestricted code submission through an agent-facing interface. No native Ray execution or new integration capability is admitted. \citep{exec24_ray_contract}
