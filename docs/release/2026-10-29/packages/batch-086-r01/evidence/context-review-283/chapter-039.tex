\chapter{Learning relationships over time}

A funding decision has a date, an information set and an outcome horizon.
A learned temporal relationship has these attributes only if the observation
and estimation procedure preserve them. Yesterday's rate may predict tomorrow's
balance because the rate changes retention, because both respond to a shared
liquidity shock, or because aggregation conceals their within-day order. The
useful question is what the observed sequence and any intervention information
allow the bank to distinguish.

The first comparisons follow that question through R, Python, Java, native
engines, Julia, Rust and MATLAB. They distinguish temporal restrictions,
structural innovations, supplied dynamic models, predictive information and
changing mechanisms. The detailed Tigramite study examines how statistics,
endpoints, intervention contrasts and resampling can change meaning within
one package. The later studies examine discovery delegates, reinforcement and
attention-based search, evaluation truth and discrete score helpers. They
connect a method's mathematical claim to the inputs and results that an
implementation actually preserves. Throughout, the worked examples keep
monetary consequences visible while distinguishing an exact construction,
a source finding and an executed experiment.

\section{Temporal order, dynamic prediction and intervention regimes in R}
\label{exec14:r-temporal}

A treasury analyst may ask which funding action today improves tomorrow's
contribution, while a monitoring analyst asks which variables forecast tomorrow's
shortfall. The same rectangular file can support both questions, but the required
information differs. A row might be an independent institution with variables
measured at three waves, a daily observation from one institution, or an
observation under a known experimental regime. A tier orders variables within a
row; a lag relates rows; a regime describes how a mechanism changes. Giving these
objects distinct types is the first requirement for a useful R interface.

The inherited pcalg pathway covers an important part of this territory. Its
GIES interface estimates an interventional essential graph, using intervention
targets and a row-to-target index. An empty target represents observation without
intervention. The returned representative DAG is one member of the estimated
class. It must not silently become the uniquely established mechanism. Likewise,
an undirected essential-graph edge represents alternative directions across
DAGs: a plotting convention that renders it with two arrowheads does not turn
it into a latent-confounding PAG edge. FCI-JCI instead augments system variables
with context variables and explicitly selects context assumptions, including
exogeneity and, when invoked, absence of latent confounding between contexts and
the system. A month-end dummy does not establish these assumptions merely by
being supplied to the API. These are distinct statistical specifications, even
though both can combine data from multiple regimes. \citep{exec13_pcalg,exec13_latentr_primary}

\subsection{Ordering variables is different from modelling a series}

The inspected causalDisco 1.2.1 interface exposes TPC, TFCI and TGES with tiered
background knowledge. Its examples of temporally ordered variables describe a
useful cohort-wave application: measurements at an earlier wave cannot be caused
by measurements at a later wave under the declared clock. That restriction does
not supply stationarity, equal time intervals, independent observations or a
valid conditional-independence test for dependent rows. The selected TPC/TFCI
implementation wraps pcalg operations and converts their results through caugi.
The method name therefore describes a proposed workflow entry point, not a
complete uncertainty contract. \citep{exec14_rtime_causaldisco}

Two details require qualification before conversion. First, the pinned TFCI
help describes a PAG stored with class UNKNOWN because native PAG support is
unavailable, whereas the runner in that same revision requests class PAG from
the caugi constructor. The TPC help describes a PDAG while its runner requests
UNKNOWN. These are observed source/documentation disagreements; without the
matching dependency and a runtime inspection we cannot assert the actual returned
class or whether conversion succeeds. The proposed adapter should preserve the
original endpoint matrix and labels, record the effective constructor and
dependency version, and refuse an unsupported conversion. Reading an UNKNOWN
tag as an ordinary undirected graph would discard scientifically relevant
information. \citep{exec14_rtime_causaldisco}

Second, the tier-aware test wrapper returns zero without calling the underlying
test when a proposed conditioning variable is later than both endpoints. This
sentinel prevents that forbidden conditioning set from removing an edge. It is
not an observed p-value of zero. A diagnostic screen that reports every returned
number as a statistical test would misstate the evidence. The interface must
distinguish a test executed on data from a restriction imposed by declared
knowledge, just as it distinguishes an oriented arrow from a fitted coefficient.
TFCI's source places an arrowhead at the later endpoint of a cross-tier edge;
it does not thereby prove the earlier endpoint is an unconfounded causal parent.
The remaining endpoint and the equivalence-class semantics must survive export.
\citep{exec14_rtime_causaldisco}

The separate tpc 1.0 package is a useful comparator. Its API specifies a partial
node order, forbidden edges and global or tier-specific context variables,
returning a pcalg-style pcAlgo object. Its source forces particular context
adjacencies and removes others; supplied forbidden edges can override those
context constraints with a reported conflict. Thus labelling a business variable
as context can insert substantive structure rather than simply add a column to
the data. A reviewer should see the effective constraints after precedence rules,
their business rationale and which arrows follow only from those constraints.
This tpc package and causalDisco's TPC pathway have different package identities;
their names alone establish neither identical implementations nor identical
scientific behavior. \citep{exec14_rtime_tpc}

For cohort applications, we would first use such tools as comparators with
independent subjects and an explicit measurement order. Repeated accounts sharing
calendar shocks require an additional sampling argument. For example, suppose
100 banks have residual \(R_{it}=C_t\) on each of 20 dates, with independent
mean-zero, variance-one \(C_t\) across dates. The grand mean is the mean of the
20 calendar shocks. Its variance is \(1/20\), whereas an independent-row formula
using 2,000 rows gives \(1/2000\). The standard errors differ by a factor of ten.
This exact special case does not assign a universal effective sample size to
panels. It demonstrates why adding a time ordering to graph search cannot repair
a wrong replication unit. \citep{exec14_rtime_exact}

\subsection{Dynamic Bayesian networks and admissible rows}

dbnR 0.8.0 provides a different route: Gaussian dynamic Bayesian-network learning
with an explicit number of unrolled slices. Its size argument includes the
present slice, so size two corresponds to one historical lag. The structure
wrapper permits a previously folded data set through f\_dt and forwards it to
the selected search method; the reviewed wrapper does not by itself establish
the guarantees of each downstream search engine. This is a promising prediction
and lag-construction baseline. A learned DBN or a Gaussian conditional forecast
still requires causal assumptions before it supports an intervention query.
\citep{exec14_rtime_dbnr}

The data preparation source supplies a concrete safeguard worth reusing.
Ordinary fold\_dt shifts rows and removes incomplete leading rows.
filter\_same\_cycle compares the identifiers across slices, and
filtered\_fold\_dt combines folding with that filter. The integration obligation
is to select the appropriate pathway, supply the correct identifiers, and verify
the rows it produces. The selected functions do not establish chronological
sorting or equal physical intervals from timestamps. Equal bank identifiers
are necessary but insufficient for a one-day lag when days are missing.
\citep{exec14_rtime_dbnr}

Consider the deliberately small table of bank A values \(1,2,3\) on days
\(1,2,3\), followed by bank B values \(101,102,103\) on the same three days.
Positional one-lag folding produces five pairs, including the invalid transition
from bank A's last observation to bank B's first. Requiring equal bank identity
and a one-day increment retains four pairs. Conversely, two observations from
bank A on days one and three pass an identity-only filter but do not form a
one-day transition. These are exact constructions of required adapter behavior,
not reports of running dbnR or demonstrations that its documented ID filter
fails. \citep{exec14_rtime_exact}

The same source contains reduce\_freq, which averages batches whose size is
the ceiling of the requested interval divided by the current interval, with
optional identifier grouping. A physical-calendar adapter must consequently
record the achieved spacing and aggregation convention, especially when the
ratio is noninteger or timestamps are irregular. Averaging is not merely a
computational reduction: it changes the variables and potentially the estimand.
\citep{exec14_rtime_dbnr}

An exact daily example makes the change visible. Let the action \(A_t\) be
independent Rademacher variables, taking values minus one and one with equal
probability, and let the outcome be \(Y_t=A_{t-1}\). At the daily scale the
structural response is a one-day lag. With nonoverlapping two-day averages,
\[
 \bar A_k=\frac{A_{2k-1}+A_{2k}}2,
 \qquad
 \bar Y_k=\frac{A_{2k-2}+A_{2k-1}}2.
\]
Independence gives \(\operatorname{Var}(\bar A_k)=1/2\), while both
\(\operatorname{Cov}(\bar A_k,\bar Y_k)\) and
\(\operatorname{Cov}(\bar A_{k-1},\bar Y_k)\) equal \(1/4\).
Because successive action-block averages are independent, the population linear
projection of \(\bar Y_k\) on current and previous action-block averages has
coefficients one half and one half. A daily lag thus appears at both current
and previous block positions. \citep{exec14_rtime_exact}

Even the meaning of an intervention on a block average is incomplete without
its within-block timing. Increasing the first day's action by two changes the
current action average by one and the current outcome average by one. Increasing
the second day's action by two makes the same change to the current action
average, but changes the next outcome average by one instead. These perturbations
have identical aggregate action size and different response timing. A service
cannot answer an aggregate-action query with a unique response path until it
specifies which intervention is intended. The source data, aggregation map,
information clock and action policy all belong in the request identity.
\citep{exec14_rtime_exact}

\subsection{Invariant prediction: the exact scope of the guarantee}

seqICP 1.1 targets a response's invariant parents rather than returning a complete
temporal graph. Its linear API distinguishes an iid model from an autoregressive
model; lag order may be supplied or selected up to a maximum by AIC. It also
provides a nonlinear interface with an additive iid-noise model and a regression
function intended to approximate the target relation. These alternatives require
different justification. The manuals explicitly warn that reducing max.parents
below the predictor count sacrifices the stated confidence-interval coverage,
and that the default early stop when the accepted intersection is empty loses
coverage for coefficient values different from zero. The source also distinguishes
an empty intersection from modelReject, which records rejection of every tested
model. Both can display an empty parent set, yet communicate different evidence.
\citep{exec14_rtime_seqicp}

The genuine sequential-invariance original explains why these distinctions
matter. Its Definition 2.1 assumes a fixed linear Gaussian target relation with
iid innovations, and its causal interpretation additionally requires structural
independence conditions. Suppose \(S^*\) is the invariant true parent set and
\(\mathcal A\) is the family of accepted candidate sets. The estimator
\(\widehat S=\bigcap_{S\in\mathcal A}S\), with the declared empty-family
convention, satisfies
\[
 \Pr(\widehat S\subseteq S^*)\geq 1-\alpha
\]
when the relevant tests have the required level. If the true set is accepted,
its presence in the intersection ensures containment; erroneous inclusion of a
nonparent therefore requires rejecting that true set. This is a guarantee against
false included parents, not a guarantee of recovering every parent, selecting the
whole graph, or covering an intervention value with a numerical interval.
Failure to discover an edge is not a certificate that its effect is zero.
\citep{exec14_rtime_pfister}

Section 6 of that original adds the past \(p\) lags of all variables to each
candidate regression and targets instantaneous parents under a fixed linear
Gaussian higher-order Markov relation. The level statement is given as the
Monte Carlo resampling count \(B\) tends to infinity. It does not justify calling
the package's finite default \(B=100\) an exact finite-simulation guarantee.
The paper explicitly discusses lag selection and post-selection difficulties;
one proposed alternative considers multiple lag choices with a multiplicity
adjustment. AIC is a useful operational option, but its mere availability does
not remove that inferential issue. Moreover, Remark 3.2 labels the residual
permutation extension to nonlinear or non-Gaussian settings heuristic. We must
not borrow the linear fixed-lag theorem for every supplied nonlinear regressor.
\citep{exec14_rtime_pfister,exec14_rtime_seqicp}

Invariance also changes the usual conversation about stationarity. A stable
target mechanism can coexist with changes elsewhere in the system; those changes
may help rule out incorrect parent sets. Full-system stationarity is not a
universal desirable prerequisite for this route. A bank policy revision that
directly changes the target mechanism, however, can violate the very invariance
being tested. The specification should name which mechanisms may change, which
remain fixed, how blocks or smoothing comparisons are chosen, and whether
calendar shocks enter the innovation or observed predictors. An invariant
coefficient fit under an unjustified partition cannot establish that these
declarations are true. \citep{exec14_rtime_pfister}

\subsection{A funding counterexample and integration choices}

Temporal precedence and excellent prediction remain insufficient for the funding
question. Let \(C_t\) and \(E_t\) be mutually independent Rademacher sequences,
with the calendar driver \(C_t\) unobserved. In both of two worlds the recorded
action is \(A_t=C_t\). In the first world,
\(Y_{t+1}=2C_t+E_{t+1}\); in the second,
\(Y_{t+1}=2A_t+E_{t+1}\). Their complete stationary observed processes agree:
each daily pair \((A_t,Y_{t+1})\) takes
\((-1,-3),(-1,-1),(1,1),(1,3)\) with probability one quarter. Conditional
forecasting and temporal order cannot distinguish the worlds. Yet replacing
the action equation with \(A_t=1\) versus \(A_t=-1\) changes expected next-day
outcome by zero in the first world and four in the second. If the outcome is
stipulated to be thousands of dollars of funding contribution and that action
change costs one thousand dollars, the net consequences are minus one and plus
three thousand dollars. These values illustrate a missing-information decision,
not an estimate of bank return. \citep{exec14_rtime_exact}

The example is intentionally elementary. The practical implication is a typed
pipeline: separate graph candidates, predictive responses, identified effect
sets and monetary scenarios. Preserve interventions as mechanism changes rather
than row labels; retain lag direction, contemporaneous endpoints, measurement
frequency, within-period timing, regime membership and shared-calendar structure.
Return unknown when the requested effect lacks identification, and preserve
model rejection, unsupported conversion and insufficient test precision as
different reasons. A graph with plausible arrows should not bypass these checks.
\citep{exec14_rtime_contract}

Our proposed reuse choice is conditional integration of causalDisco for tiered
graph exploration, dbnR for checked lag/forecast baselines, and seqICP for a
declared target-parent invariance service. The separate tpc and inherited pcalg
paths remain reference comparators. No adapter is enabled by this comparison.
Direct adoption waits for dependency rights, pinned execution and semantic
qualification; porting is not selected because it would add a second
implementation before the original contract is understood. Declared licenses
are GPL-2 for the inspected causalDisco release, GPL-3 for dbnR and seqICP,
and GPL version three or later for tpc. Their dependency and distribution
obligations need a separate review; a process boundary is not assumed to settle
those questions. \citep{exec14_rtime_causaldisco,exec14_rtime_dbnr,exec14_rtime_seqicp,exec14_rtime_tpc,exec14_rtime_contract}

A useful first prototype can use public data for measurement conventions and
generated mechanisms for known truth. Predeclare tests for separate-series
boundaries, irregular calendars, aggregation timing, graph-endpoint round trips,
forced context constraints, all-rejected models, lag selection and finite
simulation settings. Compare a prediction-only baseline with correctly declared
and deliberately misspecified causal requests, keeping refusals and failures in
the denominator. The original R engines must actually run before we claim
runtime behavior or measured accuracy. Further screening should cover additional
nonlinear and mixed-frequency methods and the tsGFCI/Tetrad interface family;
the bounded repository-name search did not resolve that family's R route.
None of these local omissions blocks developing the remaining proposal areas.
\citep{exec14_rtime_contract}
\label{exec14:r-temporal-end}

\section{Python discovery across clocks, contexts and interventions}
\label{exec14:python-temporal}

A bank comparing discovery libraries must first say what changed in its data.
A funding-rate movement can be a decision, a response to a common calendar
shock, a change in the mechanism setting that rate, or simply the next
observation of a persistent process. These possibilities require different
inputs and support different conclusions. A library accepting several data
matrices does not, by that fact, identify an intervention; a time-series
library does not recover the physical clock from a row number. This comparison
therefore separates temporal search, context and regime search, and discovery
from labelled or partially known interventions. The proposed service should
return the relevant graph object and assumptions before attempting an effect
query. The reuse decisions below are proposed adapter and research choices,
with no enabled integration or upstream execution established by this review.
\citep{exec14_pt_contract}

\subsection{The structural object and its decision horizon}

Write a linear structural time-series model using column vectors as
\[
 x_t=B_0x_t+\sum_{\ell=1}^{p}B_\ell x_{t-\ell}+\varepsilon_t.
\]
Here $B_\ell[j,i]$ is the coefficient from variable $i$ at lag $\ell$ to
variable $j$ now. The within-period matrix $B_0$ describes an acyclic ordering,
while the lag matrices allow feedback through time. Premultiplying by
$(I-B_0)^{-1}$ gives reduced-form coefficients
$\Phi_\ell=(I-B_0)^{-1}B_\ell$ and reduced-form innovations
$(I-B_0)^{-1}\varepsilon_t$. A forecasting coefficient, a structural
coefficient and an impulse response are thus different quantities even in
this small model. Identifying the contemporaneous structure needs additional
restrictions. The DYNOTEARS paper studies independent realisations of a
stationary series with independent innovations, and discusses non-Gaussian
innovations or standard Gaussian innovations as identifiable cases. Its
within-slice acyclicity condition does not itself establish stability of the
dynamic process. \citep{exec14_pt_paper_dynotears}

For an exact banking illustration let the two coordinates be standardized
funding pressure and liquidity contribution, and stipulate
\[
 B_0=\begin{pmatrix}0&0\\1/2&0\end{pmatrix},\qquad
 B_1=\begin{pmatrix}1/2&0\\1/4&1/2\end{pmatrix},\qquad
 \Phi_1=\begin{pmatrix}1/2&0\\1/2&1/2\end{pmatrix}.
\]
The direct lagged funding coefficient in the second equation is $1/4$;
the reduced-form counterpart is $1/2$. A unit innovation to the funding
equation, with zero initial deviations, produces immediate deviations
$(1,1/2)^\mathsf{T}$. The next two liquidity responses are $3/4$ and $5/8$.
Since both eigenvalues of $\Phi_1$ are $1/2$, the infinite-horizon sum is
\[
 (I-\Phi_1)^{-1}(1,1/2)^\mathsf{T}=(2,3)^\mathsf{T}.
\]
If each liquidity unit is valued at a stipulated USD 100 and the one-time
action costs USD 60, the immediate net is minus USD 10 whereas the undiscounted
cumulative net is USD 240. These are conditional arithmetic examples. They
do not estimate a bank return, and changing the action to a sustained rate
policy, adding discounting, or allowing feedback into the decision rule
changes the target. A reusable interface must therefore distinguish an
innovation, an equation replacement and a sustained policy, and retain the
horizon and units. \citep{exec14_pt_exact}

Sampling frequency is equally substantive. Consider two stationary Gaussian
processes $X_t=\rho X_{t-1}+\epsilon_t$, with independent innovations of
variance $3/4$ and $\rho$ equal to either $1/2$ or $-1/2$. Both have marginal
variance one. If the bank retains only every second day, both satisfy an
observed autoregression with coefficient $1/4$ and innovation variance
$15/16$. Their complete stationary observed laws agree, but their one-day
impulse responses have opposite signs. Recovering the original day-level
response is therefore impossible from this coarsened law alone within this
two-world comparison. A daily timestamp declaration cannot repair information
that was discarded; the response must retain the observation frequency and
the unresolved finer-clock target. \citep{exec14_pt_exact}

\subsection{Tigramite: three distinct questions behind one ecosystem}

Tigramite offers a useful primary family of proposed adapters because its
documented graph classes distinguish PCMCI, PCMCI+, LPCMCI, RPCMCI and
J-PCMCI+. PCMCI+ combines lagged and contemporaneous search under causal
stationarity and sufficiency, while LPCMCI retains the partial ancestral
graph needed when latent confounding is admitted. Neither endpoint
ambiguity nor the restrictions of the chosen conditional-independence test
should disappear in a common wrapper. Earlier selected installed operations
are separate evidence from this static extension review.
\citep{runge2020,gerhardus2020,runtime_tigramite_scope,exec14_pt_tigramite}

J-PCMCI+ addresses multiple datasets with system variables and temporal or
spatial contexts. Its primary paper requires a joint acyclic structural
model, context exogeneity, restrictions excluding context--system
confounding, complete observation of system nodes, and a particular
context-determinism construction. A temporal context is shared across
datasets; a spatial context is constant within a dataset. This offers a
route for common funding calendars and bank-specific characteristics, but
does not license arbitrary unobserved common causes. Coding a bank identifier
or calendar as a context is a scientific assertion about the model.
\citep{exec14_pt_paper_jpcmci}

The inspected implementation makes those assertions operational: it accepts
five node classes, orients context-to-system links as exogenous, and removes
specified reverse and dummy links. A generic graph adapter must preserve the
effective constraints after these transformations, the pooled datasets, time
offsets, masks and conditioning choices. Before enabling this candidate,
generated comparisons should separately vary shared-calendar dependence,
bank-specific fixed contexts and hidden system-to-system confounding. The
last case deliberately violates this J-PCMCI+ model and should not be used
to award it a latent-variable guarantee. The raw conditional-test results
and final endpoint graph should remain distinguishable.
\citep{exec14_pt_tigramite,exec14_pt_contract}

RPCMCI answers a different question: it alternates regime learning and
causal search under a finite persistent regime structure, with stationarity
within regimes. Its paper initially develops lagged structural relations
with independent stationary innovations. A recovered regime can describe
different behaviour without representing a randomized or externally assigned
intervention. In the inspected constructor, only one multivariate series with scalar rather than vector-valued nodes
is accepted and a supplied mask is replaced by an all-false mask;
missing values have a separate flag. The adapter must either reject an
unsupported user mask or require an explicit, reviewed transformation before
calling this path. It must retain the regime count, transition limit,
annealing settings and convergence information. Regime membership should
not be exported as an observed experiment label.
\citep{exec14_pt_paper_rpcmci,exec14_pt_tigramite}

Tigramite's preserved root terms specify GPLv3 and its README declares
version 3 or later. That is useful source evidence for a reuse decision,
but a process boundary or command-line interface is not, by itself, a
completed distribution-rights analysis. The proposal should compare a
versioned adapter with the cost of independently maintaining a port and
qualifying its numerical equivalence. The immediate recommendation is
separate, explicitly scoped adapters for the different temporal methods.
\citep{exec14_pt_tigramite,exec14_pt_contract}

\subsection{CausalAI, VARLiNGAM and DYNOTEARS as contrasting baselines}

Salesforce CausalAI's inspected PC and Granger paths enumerate candidate
parents at strictly negative lags. Its VARLiNGAM wrapper separately exposes
lag-zero coefficients, preserving the dependency's target-row convention.
The time-series data helper forms lagged observations inside each supplied
array and then concatenates those slices, which avoids simply linking the
last row of one array to the first of another. However, the selected
interface has no physical timestamp argument: a missing business day and
a regular one-step transition can look identical after the caller has
formed the arrays. Its optional complete-case deletion also does not
establish an ignorable missingness law. \citep{exec14_pt_causalai}

The uncertainty interface deserves particular caution. The inspected
Granger routine fits LassoCV coefficients and then evaluates a t-tail
expression using a residual sum of squares and inverse design cross-product.
The source does not establish the additional justification needed after
selection and under dependent observations. When the cross-product is
rank-deficient, that routine substitutes a vector of p-values equal to one;
the VARLiNGAM wrapper has a similar branch. An operational refusal is then
numerically indistinguishable from a valid large p-value if the wrapper
discards the diagnostic. The proposal should preserve a separate
\emph{uncertainty unavailable} status, effective sample/design rank and
the selected model. A successful coefficient fit is insufficient evidence
for a calibrated interval or a causal graph. These are static-source
findings, with no claimed runtime failure frequency.
\citep{exec14_pt_causalai}

The inherited direct LiNGAM inspection provides a clearer starting point
for a declared linear non-Gaussian structural model: fit the lag process,
discover contemporaneous structure in its residuals, and preserve
$B[\text{target},\text{predictor}]$. Its residual bootstrap reconstructs
a sequence, unlike the generic row bootstrap, but the inspected bootstrap
loop fixes the lag-selection criterion to None. Consequently its existence
does not establish uncertainty including lag-order selection. Before an
adapter is enabled, the proposed generated study must include Gaussian
innovations, hidden common causes and persistent residuals as explicit
scope violations, alongside the eligible non-Gaussian innovation cases.
\citep{v131_sw_lingam,exec13_pydisc_lingam,exec14_pt_contract}

DYNOTEARS supplies a simultaneous optimization comparator. The inspected
CausalNex path minimizes a penalized residual loss based on
$X(I-W)-X_{\rm lags}A$ and constrains the within-slice matrix $W$ to be
acyclic. Its dataframe transformer checks numeric columns and sorted integer
indices, splits gaps larger than one, and constructs lags separately for
each resulting realisation. This is more specific than assuming that every
row is adjacent. It still admits a nondecreasing sequence with duplicate
indices: the authored sequence $(1,2,2,3,6,7)$ creates two segments and four
retained one-lag pairs, only three of which have a strictly positive unit
step. The proposed adapter must reject duplicates, define the calendar and
record every exclusion. It should also preserve raw weights, threshold
choices and optimization diagnostics.
\citep{exec14_pt_causalnex,exec14_pt_exact,exec14_pt_paper_dynotears}

The inherited maintenance review records CausalNex's discontinuation notice.
That supports retaining DYNOTEARS as a methodological and conversion
reference, while deferring default dependency adoption. A port would require
an explicit maintenance owner and equivalence tests; it is not a free
substitute for a maintained upstream package. CausalAI's inspected BSD terms
and LiNGAM's inspected MIT terms likewise do not certify their entire
resolved dependency environments. \citep{exec14_causalnex_primary,
exec14_pt_causalai,exec13_pydisc_lingam,exec14_pt_contract}

\subsection{Intervention data need a mechanism contract}

An intervention label must include the target set, mechanism type and
assignment context. To see why, let $H,U,W$ be independent standard
normal innovations, define $A=H+U$, $Y=2A+H+W$, and observe $(H,A,Y)$.
A perfect stochastic
intervention replaces the action equation with $A=\delta+Z$, where
$Z\sim N(0,2)$ is independent of the other innovations. A soft intervention
instead sets $A=H+U+\delta$. In both cases $E(A)=\delta$,
$\operatorname{var}(A)=2$, and $E(Y)=2\delta$. Nevertheless,
$\operatorname{cov}(H,A)$ is zero under replacement and one under the soft
change; $\operatorname{cov}(A,Y)$ is respectively four and five. The action
margin and its label alone cannot tell the library which graph truncation
is justified. If $H$ is hidden, the same example additionally violates a
causally sufficient observed-variable model. \citep{exec14_pt_exact}

Python GIES is a useful known-perfect-intervention baseline. The original
paper defines stochastic interventions by replacing targeted mechanisms
and requires a conservative target family: every variable remains
unintervened in at least one environment. Observational data satisfy this
particular requirement, although they do not supply all other assumptions.
The paper's interventional equivalence theory concerns graph classes under
the stated intervention family. Independent observations from several
environments are not automatically the same sampling model as repeatedly
observed banks on a shared calendar. \citep{exec14_pt_paper_gies}

The inspected Python Gaussian score centres data within each environment,
forms covariances from observations in which the target variable was not
intervened on, and checks conservative target coverage. Its output is an
estimated I-essential graph: reciprocal nonzero matrix entries denote an
undirected edge, not a two-cycle. A proposed adapter should validate unique
target indices, dataset/target alignment, environment sizes and the
effective score before preserving these endpoints. It should refuse to
present the score as an effect or confidence interval. This candidate is
attractive for a transparent generated perfect-intervention comparison;
soft targets and dependent panels need their own justified treatment.
\citep{exec14_pt_gies,exec14_pt_contract}

Unknown-target IGSP offers another route when intervention targets are
partially known. Its primary paper requires observational data and an
I-faithfulness condition relating invariance to separation; its theorem
identifies an interventional equivalence class and targets under those
conditions. The algorithm needs both a conditional-independence tester and
a conditional-invariance tester. An unknown target is therefore not
recovered merely by dropping a target column from a known-target method.
\citep{exec14_pt_paper_utigsp}

The pinned CausalDAG facade reexports external graph and learning packages,
while its older tutorial points to an implementation path absent from the
selected tree. The recovered graphical-model-learning implementation
defaults to depth four, five starts, and tuple scoring. Its default score
orders edge count and variant count lexicographically, whereas the
inspected paper defines their sum. The distinction can matter: candidate
counts $(3,5)$ and $(4,0)$ are ordered in opposite ways by these rules.
This arithmetic example does not claim those two candidates are reachable
in a particular search. It identifies a precise theory-to-code question
that must be resolved before transferring the theorem to a wrapper's
default. A public prototype should pin all three facade dependencies,
retain score mode and search restrictions, and compare oracle-level and
finite-test behaviour separately. \citep{exec14_pt_causaldag,exec14_pt_gml,
exec14_pt_paper_utigsp,exec14_pt_exact}

\subsection{Differentiable discovery: optimization and evidence remain separate}

DCDI's primary score theorem concerns a global population optimum with a
sufficient density class, positivity, finite entropy and I-faithfulness.
Its finite nonconvex optimization is not guaranteed to attain that optimum.
The inspected constructor implements perfect interventions with known or
unknown targets and imperfect interventions with known targets; the
combination of imperfect interventions and unknown targets explicitly raises an unimplemented error.
Known perfect targets are removed from the mechanism likelihood using a
retention mask, while the other implemented branches use regime-specific
parameters. These distinctions should be visible service variants, with
the original masks, regime identities and optimizer diagnostics returned
in the evidence bundle. They should not be compressed into one boolean
intervention option. \citep{exec14_pt_paper_dcdi,exec14_pt_dcdi}

ENCO provides a contrasting parameterization of edge existence and
orientation. Its documented array format indexes intervention samples by
the single targeted variable. The inspected gradient path suppresses
incoming-edge updates at that variable and treats orientation updates
separately. The primary theorem and supporting argument require informative
interventions, sufficiently accurate conditional models, suitable
regularization and the stated data conditions. The paper itself distinguishes
the extension to fewer intervention targets, for which the same convergence
guarantee is unavailable. A comparison should report actual target coverage
and cycle handling instead of treating the method's title or learned edge
probabilities as a finite-sample confidence guarantee.
\citep{exec14_pt_enco,exec14_pt_paper_enco}

SDCD is worth considering for numerical stability and its two-stage
structure. The primary paper's stability result concerns the acyclicity
constraint; its first-stage screening argument uses exact population
optimization and explicit model, faithfulness and positivity conditions.
Neither result establishes that every finite training run retains every
true parent. The inspected output helper sorts weighted edges and omits
those that would form cycles. A caller receiving only that DAG loses the
distinction between a learned low-weight edge and an edge removed to impose
acyclicity. The proposal should return raw adjacency, the retained graph,
the threshold and a record of the removed edges.
\citep{exec14_pt_paper_sdcd,exec14_pt_sdcd}

There is also a concrete input risk. SDCD's inspected dataset helper maps
unmatched perturbation labels to a sentinel, drops those entries, and
turns an empty target list into an all-ones retention mask. In the authored
two-variable example, the label \texttt{rate} gives mask $(0,1)$ but the
misspelling \texttt{raet} gives $(1,1)$. This traces the selected transformation;
it is not an observed frequency in user data. The proposed wrapper must
distinguish an explicitly observational record from an unresolved target,
validate all labels before conversion, and refuse unknown or duplicate
targets with the original input preserved. Successful optimization after
an unintended input reinterpretation would not resolve the mistake.
\citep{exec14_pt_sdcd,exec14_pt_exact}

\subsection{A bounded reuse portfolio and the next evidence}

The immediate portfolio has distinct roles. Tigramite supports proposed
endpoint-preserving temporal/context adapters; LiNGAM and DYNOTEARS supply
declared linear structural comparators; CausalAI provides an additional
interface and benchmark reference with explicit uncertainty restrictions.
Python GIES supplies a transparent known-perfect intervention baseline.
UT-IGSP adds an invariance-based unknown-target comparison once its scoring
and dependencies are reconciled. DCDI, ENCO and SDCD provide complementary
neural research comparators, each restricted to its reviewed data and
intervention contract. Direct adoption is deferred; no port is selected
merely because source terms permit modification. A port must justify its
maintenance and numerical-equivalence cost against a versioned adapter.
\citep{exec14_pt_contract}

The first prototype can use generated structural laws with known graphs,
observed intervention assignments and saved observation clocks. Separate
strata should vary lag order, contemporaneous links, hidden common causes,
shared calendars, regime persistence, regular versus coarsened sampling,
target knowledge and perfect versus soft intervention. Eligible and
deliberately ineligible cases must be reported separately. Software
acceptance cases should include duplicate clocks, unknown target spelling,
rank failure, an unsupported RPCMCI mask, an unsupported DCDI combination,
raw-to-DAG conversion and the UT-IGSP score switch. These cases test whether
the adapter preserves or refuses meaning; they cannot by themselves establish
statistical recovery. \citep{exec14_pt_contract,exec14_pt_exact}

A matched scientific comparison must then keep each method's assumptions,
search budgets and target objects explicit. A selected DAG cannot be ranked
against a PAG as though every unresolved endpoint were an error. Report
coverage of eligible requests, refusals, graph and intervention-target errors,
downstream identified effects or ambiguity, runtime and full preparation
costs. For dependent series, use a design justified for that process rather
than an independent-row bootstrap by default. Public datasets can test
ingestion and observable diagnostics; unless they supply independently
credible intervention truth, they cannot award causal correctness by
agreement between algorithms. \citep{exec14_pt_contract}

This is a developed comparison, not a complete census. The bounded search
retains unresolved families including amortized discovery, subsampled
proxy methods, periodic/nonstationary discovery, Bayesian unknown-intervention
methods and event-process methods. CUTS still needs primary identity and
embedded implementation resolution. The CD-NOD lead has a more developed
disposition in Section~\ref{exec17:other-temporal}: its primary method and
selected MATLAB paths are inspected there, with the lagged implementation
boundary and reuse rights still explicit. That resolves this source lead
without completing the wider census. For the remaining families, acquisition
must establish the original method and implementation path, classify their
clock and intervention assumptions, and compare their contribution against
this portfolio. An unresolved lead is an evidence gap, not evidence that its
capability is absent. Each comparison can be developed independently.
\citep{exec14_pt_contract}
\label{exec14:python-temporal-end}

\section{Tigramite as a temporal reference: preserving the meaning of the result}
\label{exec23:tigramite-scope}
A bank comparing deposit rates and subsequent balances needs to distinguish a conditional-dependence statistic, an unresolved endpoint, a fitted intervention response and uncertainty about that response. Tigramite offers explicitly differentiated methods for these stages. The selected January 2026 source declares version 5.2.10.1. PCMCI, PCMCI+, LPCMCI, RPCMCI and J-PCMCI+ differ in contemporaneous-link, hidden-variable, stationarity and context assumptions. The conditional-independence test adds its own restrictions: ParCorr uses linear residual correlation, whereas other tests require their own treatment. These are distinct scientific choices within one package, not interchangeable routes to a monetary effect. \citep{exec23_tigramite_reuse_source,exec14_pt_tigramite}

The proposal selects Tigramite as a method-specific reference, with a conditional route to an isolated Python worker. Prior installed-version operations remain relevant within their recorded scope, including the finite-DAG oracle comparison. A matching version string does not establish byte identity with the selected repository tree, and those operations do not qualify every delegate considered here. \citep{runtime_tigramite_scope,runtime_networkx_dynamic} The additional evidence below is static source inspection and independent exact examples, not another native trial.

\subsection{A statistic, a graph and a dollar response}
\label{exec23:tigramite-statistic}
Let $X_t$ denote a centered rate intervention in specified rate units, $Y_{t+1}$ a balance response in dollars and $Z_t$ the chosen history. Consider a stipulated linear population,
\begin{equation}
 Y_{t+1}=100+20X_t+\gamma^\top Z_t+\epsilon_{t+1},\qquad
 \operatorname{Var}(X_t\mid Z_t)=1,\quad
 \operatorname{Var}(\epsilon_{t+1}\mid Z_t)=225.
 \label{exec23:tigramite-dollar}
\end{equation}
Assume independent residualized exposure and error, an intervention-invariant mechanism, a history sufficient for adjustment, and intervention support. The residual covariance is $20$ and the residual variance of $Y$ is $625$. Thus the partial correlation is $20/25=4/5$, whereas the stipulated causal slope is 20 dollars per rate unit. A one-unit change with stipulated cost 12 dollars has net value 8 dollars. Reading $4/5$ as a dollar gain instead gives $-56/5$ dollars. These are authored population values, not observed bank returns; their disagreement demonstrates the units lost in an invalid conversion. \citep{exec23_tigramite_reference}

PCMCI labels its \texttt{val\_matrix} as test-statistic values and its optional \texttt{conf\_matrix} as intervals for those values. ParCorr fits ordinary least-squares residuals and returns their Pearson correlation. Its analytic test uses $T-d$ degrees of freedom for $d$ array rows and $T$ usable observations, returning a nonfinite p-value when degrees of freedom are insufficient. The CI base also supplies a constant-variable shortcut. An adapter must report degeneracy and invalid arithmetic rather than interpret every returned entry as scientific evidence of absence. The \texttt{run\_pcmci} signature defaults FDR to \texttt{none}, although the parameter prose says \texttt{fdr\_bh}; a profile must set this argument explicitly. The correction helper distinguishes lagged-only and contemporaneous-inclusive test families. A corrected edge p-value is not a portfolio-response interval. \citep{exec23_tigramite_reuse_source}

\subsection{Endpoint ambiguity is a substantive output}
\label{exec23:tigramite-graph}
PCMCI+ can return contemporaneous ambiguity and conflict marks; LPCMCI returns a temporal partial ancestral graph. The selected effect class accepts DAG and ADMG variants, including temporal and stationary forms, but does not enable its commented-out PAG graph types. A wrapper cannot bridge these interfaces by replacing circles or conflicts with arbitrary arrows. It must retain the compatible graph family, justify additional scientific restrictions where possible, and determine identification or set identification under those restrictions. A graph-conditioned adjustment fit does not solve that preceding problem. \citep{exec23_tigramite_reuse_source}

Even a summary frequency requires its exact definition. The default graph-summary routine chooses a modal endpoint string but, in a tie, reports the sum of tied modal counts divided by the resample count. Five resamples with one direction and five with the reverse can produce a conflict mark with reported frequency one, although none of the ten inputs contains that conflict mark. In a second stipulated ensemble, four absent links and three of each direction make absence the most frequent individual string, while adjacency has total frequency $6/10$. The alternative adjacency-first aggregation answers the latter question. These finite examples do not establish discovery failure; they show why the counts, aggregation rule and emitted mark must accompany the summary. Such frequency is neither the posterior probability of an arrow nor a calibrated graph confidence level. \citep{exec23_tigramite_reuse_source,exec23_tigramite_reference}

\subsection{An intervention prediction still needs a contrast}
\label{exec23:tigramite-intervention}
For a supplied admissible graph and valid adjustment set $Z$, the unconditional adjusted response is
\begin{equation}
 \mu(x)=\int E[Y\mid X=x,Z=z]p(z)\,dz,\qquad
 \Delta(x,x_0)=\mu(x)-\mu(x_0).
 \label{exec23:tigramite-contrast}
\end{equation}
This requires identifying graph and sampling assumptions; fitting regression does not supply them. The inspected prediction delegate aggregates predictions over stored adjustment observations. For an illustrative zero-mean adjusted history in the linear population, predictions at zero and one are 100 and 120 dollars; the contrast is 20 dollars. Calling 120 the gain includes the baseline. A caller must preserve that baseline, adjustment distribution, units, transforms and conditioning target. The effect class checks adjustment validity by default but exposes a bypass for a user-supplied set. An accepted product profile should not silently enable that bypass. \citep{exec23_tigramite_reuse_source,exec23_tigramite_reference}

The hard intervention sets an exposure value; the source's soft option adds an amount to each observed exposure. For nonlinear responses these policies differ. If $Y=X^2$ and the stipulated reference population places equal mass at zero and two, the hard zero-to-one contrast is $1$, whereas adding one to everyone's observed exposure gives
\begin{equation}
 E[(X+1)^2-X^2]=2E[X]+1=3.
 \label{exec23:tigramite-policy}
\end{equation}
Here soft denotes that additive implementation, not every stochastic intervention in causal inference. Conditional nested regression and alternative estimators need separate review. \citep{exec23_tigramite_reuse_source,exec23_tigramite_reference}

The effect bootstrap refits the selected effect procedure and takes percentiles of intervention predictions, retaining the supplied graph. Discovery bootstrap summaries instead concern graphs and statistics. Neither bootstrap code nor a nonempty interval establishes joint validity after graph discovery, graph or policy selection, or under arbitrary dependence. Specify the uncertainty target and sampling law before choosing which stages to resample. \citep{exec23_tigramite_reuse_source}

\subsection{Calendars, masks and resampling belong in the scientific contract}
\label{exec23:tigramite-calendar}
The data layer constructs lagged arrays from integer reference positions, dataset offsets and a cutoff. Its ordinary twice-maximum-lag cutoff and the effect fitter's maximum-lag cutoff can retain different observations. Masks apply to selected variable roles, separately from missing-value handling. Calendar gaps, reporting delays and multiple panels require explicit time-grid conversion and effective-sample records. The earlier inspected RPCMCI implementation replaces a supplied mask, requiring a distinct admission rule. \citep{exec23_tigramite_reuse_source}

Several static edge cases warrant native oracle tests. The selected data-layer bootstrap draws starts from \texttt{arange(n-L)} for $n$ retained positions and block length $L$. For $n=6,L=2$, these are $0,1,2,3$; the complete nonwrapping set includes start 4. Position 5 is absent from the first expression's reachable indices. This enumeration describes the inspected expression, not an executed failure or quantified inference bias. Nonconsecutive retained positions also need not be adjacent calendar times. \citep{exec23_tigramite_reuse_source,exec23_tigramite_reference}

The missing-value extension constructs later position indices without clipping before assignment. Missing position 5 in a six-position array, extended through lag two, yields $5,6,7$; the last two exceed the bounds. The source writes the used-indices attribute after its dataset loop while concatenating samples from all datasets. A multi-panel adapter must verify complete panel provenance rather than assume this attribute records every panel. These observations motivate narrow replay cases and separately reviewed patches; they do not establish that all package analyses fail. \citep{exec23_tigramite_reuse_source,exec23_tigramite_reference}

\subsection{The reuse choice and the work needed to change it}
\label{exec23:tigramite-choice}
Whole-package adoption is premature because method assumptions, graph conversion, uncertainty and these edge cases require distinct contracts. Porting to R, Java or C++ is not justified by a measured benefit here: orientation rules, tests and resampling would acquire a second maintenance burden. A selected Python worker is the candidate to test, preserving endpoints and counts, effective observations and transforms, warnings and failures, and refusing unsupported graph-to-effect requests. These requirements describe proposed capabilities.

The repository declares GPL version 3 or later and contains GPLv3 text. Setup specifies minimum dependencies rather than a locked environment; optional algorithms add packages. This records licensing evidence, not clearance of a future distribution. Process isolation alone does not settle rights. A maintainer must bind artifacts and versions; a scientific owner must choose the sampling law, target and tests; an operator must address custody, failure budgets and distribution. Comparison should include installation, search, ambiguous and failed queries, resampling, serialization, upgrade regression and human review. Reconsider integration when a permissible pinned profile passes the exact oracles and registered public or synthetic trial. Later bank experiments should be justified by prototype merit rather than required to finish this proposal decision. \citep{exec23_tigramite_reuse_source,exec23_tigramite_reference}

\section{Java temporal discovery: clocks, regimes and the meaning of a learned network}
\label{exec15:java-temporal}

A treasury analyst may have thousands of branch observations but only a few
distinct funding-shock dates. A package can turn these observations into a
lagged network without answering whether changing a deposit offer improves
next-day net funding. A Java backend must preserve three different objects:
the observation clock, the statistical model fitted to the observations, and
the intervention whose consequence matters. Confusing them can produce a
plausible diagram with an incorrect economic interpretation.

The comparison develops six repository routes: Tetrad, a modified BANJO
distribution, Weka's forecasting package, learnDBN, learnDBM and
BayesNetBuilder. The two learning repositories share substantial code; these
are not six independent algorithm families. Selected historical revisions
through 7 October 2026 support the discussion, without establishing a complete
Java census. Tetrad offers a candidate for a restricted graph adapter. Discrete
dynamic-network learners provide another modeling route, while Weka supplies
a forecasting and preprocessing comparison. Their scientific acceptance
conditions differ.~\citep{exec15_javatemporal_tetrad,exec15_javatemporal_banjo,
exec15_javatemporal_weka,exec15_javatemporal_learndbn,
exec15_javatemporal_learndbm,exec15_javatemporal_builder}

\subsection{The observation clock and the population}

Let $i$ index a branch or customer series, $t$ a physical event date, $A_{it}$
the action available at that date, and $Y_{i,t+h}$ the funding outcome at horizon
$h$. An effect for a typical customer, an effect for a typical branch, and a
bank-wide monetary total require different weights. The information set must
contain only values available when the decision is taken. A later-revised
balance cannot silently become a decision-time covariate. A lag of one row
also needs a declared relationship to the physical horizon.

Tetrad's inspected \texttt{TsUtils.createLagData} creates a matrix with $n-L$
rows and $p(L+1)$ columns from $n$ rows, $p$ variables and maximum lag $L$.
Output row $r$ at lag $\ell$ takes its value from input row $r+L-\ell$.
Temporal tiers order the lagged variables. This method has no physical
timestamp or subject-boundary argument and reserves the colon in variable
names for lag notation. An external clock and identity validator is therefore
necessary: the constructed tiers do not establish the meaning of the original
row order.~\citep{exec15_javatemporal_tetrad}

For dates $(0,1,4,5)$, positional lagging yields $(0,1),(1,4),(4,5)$. Only two
pairs represent a one-day transition. The middle pair includes a three-day
gap. Two independent series $(1,2,3)$ and $(10,20,30)$ likewise provide four
within-series transitions. Concatenating first adds $3\rightarrow10$, which
corresponds to no observed history. These are exact bookkeeping examples,
not findings about a bank dataset.~\citep{exec15_javatemporal_exact}

The adapter should construct admissible windows before dispatch or refuse a
clock it cannot represent. It should retain event time, availability time,
series identity, gap policy and aggregation rule. An inserted missing row is
different from an observed zero; carrying a balance forward is a modeling
choice. Resampling or aggregating to regular dates changes the information
supplied to discovery and needs justification. For branches sharing a market
shock, protecting series boundaries does not establish independence.
\citep{exec15_javatemporal_design}

\subsection{Tetrad: temporal infrastructure and its limits}

The inspected September 2026 Tetrad snapshot's FCI wrapper constructs lagged
data, supplies the selected conditional-independence test, and passes knowledge,
replication and other settings to the FCI core. IMaGES lags each dataset
separately, constructs component scores and invokes BOSS permutation search.
A lag parameter does not transfer every temporal-discovery theorem to every
test, sampling law and graph class.~\citep{exec15_javatemporal_tetrad}

A saved SvarFCI help page describes time order, homologous edge removal under
a repeated structure, and contemporaneous connections unless forbidden by
knowledge. It distinguishes that contemporaneous allowance from assumptions
of the research it references. The current wrapper inspected here invokes
the FCI core. The help page and wrapper cannot serve interchangeably as proof
of a specialized algorithm. The earlier static FCI review's possible-DSEP and
orientation findings remain relevant; adding lag columns does not repair
them. Qualification must match the algorithm, test, representation and
assumptions.~\citep{exec15_javatemporal_tetrad,exec14_java_latent_sources}

Graph storage requires equal care. The inspected
\texttt{TimeLagGraph.addEdge} accepts directed edges, checks selected temporal
conditions and propagates repeated edges over lags. The separate
\texttt{addDirectedEdge} delegates directly to the underlying graph without
using that validation path. A container's name therefore cannot guarantee
that every mutation enforces the same conditions. A directed time-lag
container also cannot losslessly represent an arbitrary PAG: circles, latent
confounding marks and unresolved orientations have meanings that a directed
completion would remove. Validate the actual entry point and preserve a typed
graph before creating a simplified display.
\citep{exec15_javatemporal_tetrad,exec15_javatemporal_design}

The bootstrap path contains a useful, limited repair. For tabular data and a
wrapper accepting knowledge, \texttt{BootstrapTimeLag} constructs lagged
tuples before resampling, resets the core's lag parameter to avoid lagging
twice, and restores knowledge afterward. The base class uses this preparation
on inspected single- and multiple-dataset paths. If knowledge cannot be
accepted, the helper leaves the inputs unchanged and logs a warning. This
does not guarantee the repair for every wrapper.~\citep{exec15_javatemporal_tetrad}

Original observations $(10,20,30)$ contain transitions $10\rightarrow20$ and
$20\rightarrow30$. Resampling raw indices $(2,0,1)$ before lagging fabricates
$30\rightarrow10$. Resampling already formed tuples prevents this particular
error, but does not make tuples independent or establish bootstrap coverage.
The helper's comment acknowledges residual dependence and the absence of a
block bootstrap in that path. Dependence conditions need justification for
the actual statistic, rather than acceptance from a comment.
\citep{exec15_javatemporal_tetrad,exec15_javatemporal_exact}

For a concrete law, set $Z_t=\varepsilon_t+\varepsilon_{t-1}$ with independent,
centered unit-variance innovations. The variance of $Z_t$ is two and adjacent
covariance is one. For four observations,
\[
 \operatorname{Var}(\bar Z)=\frac{4\cdot2+2\cdot3\cdot1}{4^2}=\frac78,
 \qquad \operatorname{Var}_{\mathrm{ind}}(\bar Z)=\frac24=\frac12.
\]
Enumeration of the 32 equally likely configurations of five Rademacher
innovations reproduces the first value. This discrepancy is a property of the
law, independent of faithful lag-column storage. For four branches and five
dates, suppose outcomes contain independent common date shocks of variance four plus
independent branch-date shocks of variance one. The grand mean has variance
$4/5+1/20=17/20$. Treating the 20 rows as independent gives $5/20=1/4$.
Separate within-branch bootstraps do not automatically restore the missing
cross-branch covariance.~\citep{exec15_javatemporal_exact}

\subsection{Multiple datasets, intervention regimes and weights}

IMaGES needs more than a list of matrices. The inspected one-argument
\texttt{ImagesScore} constructor is documented as selecting
\texttt{SAMPLE\_UNIFORM}, but its body selects \texttt{DATASET\_WEIGHTED}.
With component sizes $N_k$, their mean $\bar N$, and positive user weights
$u_k$, the latter normalizes
\[
 w_k=\frac{u_k\bar N/N_k}{\sum_j u_j\bar N/N_j}.
\]
The alternative uses $1/K$ on the component scores. Since scores can scale
with sample size, the two modes have different objectives. IMaGES uses the
one-argument constructor. A nonfinite component makes the aggregate undefined
rather than being silently dropped; the sample-size accessor returns the
rounded mean size, not total rows.~\citep{exec15_javatemporal_tetrad}

For component differences 100 and $-20$ with sizes 1000 and 100, the plain
average is 40. The actual equal-$u_k$ default uses weights $1/11,10/11$, giving
$-100/11$. The sign changes. This is arithmetic for stipulated component
differences, not a claim about a particular search trajectory. The sample-size
accessor gives 550 while total rows are 1100. Calling 550 the pooled count, or
putting 1100 into an uncertainty formula without a dependence argument, each
misstates the evidence.~\citep{exec15_javatemporal_exact}

Economic targets can change sign too. Suppose branch effects are 1 and $-2$
outcome units per action, with 1000 and 100 eligible customers. The
customer-weighted effect is $8/11$; the equal-branch effect is $-1/2$. At a
stipulated USD 20 per outcome unit and USD 8 per action, net values are
USD $72/11$ and USD $-18$. No action has value zero here. These are different
targets, not estimators of an unspecified common target. Score weights are
not automatically causal target-population weights; the request must declare
both and their relationship.~\citep{exec15_javatemporal_exact}

Intervention information is another distinction. The inspected
\texttt{InterventionalColumn} holds value/status column metadata. That class
alone does not show that a discovery score recognizes perfect versus soft
interventions, excludes intervened mechanisms or handles unknown targets.
Branches can differ through selection, hidden conditions or measurement.
Intervention interpretation requires regime identity, targets and types,
assignment evidence, and assumptions about unchanged mechanisms. The selected
inspection supports no universal absence claim about Java interventional
algorithms.~\citep{exec15_javatemporal_tetrad,exec15_javatemporal_design}

\subsection{BANJO: discrete longitudinal search and a reuse boundary}

The modified BANJO repository applies network search to gene expression
ordered by pseudotime. Its sample configuration chooses lag one,
discretization policy \texttt{i2}, mandatory identity edges at lag one, up to
five parents and a five-minute search budget. These are application choices.
An edge at pseudotime lag one does not mean a bank intervention acts over one
calendar day. Mandatory autoregressive edges also cannot be presented as
discoveries made without prior restrictions.~\citep{exec15_javatemporal_banjo}

The observation code demonstrates a useful series boundary rule. Usable rows
subtract the maximum lag separately for each input file. The window loop reads
only within the current file, preserving independent series. The inspected
BDe evaluator uses discrete parent-configuration counts and equivalent-sample-
size parameters. That model differs from continuous funding dynamics.
Discretization can discard magnitudes essential to a monetary decision;
category definitions, fitted cutpoints and outcome-to-money conversion need
joint review. Transformations for prospective prediction also need to be
learned using permitted training data. Using all dates to fit cutpoints would
require a different information claim.~\citep{exec15_javatemporal_banjo}

Commercial reuse is not settled by a public mirror. Source headers state Duke
ownership, a possible noncommercial license and a need to contact the owner
for commercial use. They do not establish a permissive commercial grant for
this derivative. The proposed decision is reference-only use while official
version and rights remain unresolved; direct adoption and source porting are
deferred. Independently specifying series-safe windows and explicit lag
constraints remains useful without declaring this code cleared for
incorporation.~\citep{exec15_javatemporal_banjo,exec15_javatemporal_design}

\subsection{learnDBN and learnDBM: combinations of options matter}

learnDBN declares tDBN, cDBN and bcDBN structure learning for multivariate
longitudinal observations, missing-value handling and a dynamic multinet
clustering route. The inspected revision includes an Apache2 license. The CLI
defaults to a stationary network, with an option for a separate network at
each transition, a maximum Markov lag and a likelihood or MDL score. Its
observation format places subjects in rows and time-indexed attributes in
columns. This differs materially from concatenating panel rows into one
series.~\citep{exec15_javatemporal_learndbn}

The missing-data path does not consistently honor the stationarity option.
The CLI passes literal \texttt{true} to parameter EM, missing-value filling and
scoring, even when the requested flag is false. With two nonstationary
transition networks, the filling routine therefore selects network zero
across transitions. If parameter learning is reached, its stationary branch
throws an exception because multiple transition networks exist. This is a
finding from the caller and callee, not an executed Java failure or a claim
that no earlier error could occur. The complete-data path instead passes the
actual flag to parameter learning. Support for an option and support for
missing values separately do not establish support for their combination.
\citep{exec15_javatemporal_learndbn,exec15_javatemporal_exact}

Malformed time headers can call \texttt{System.exit(1)}, which is unsuitable
inside a shared host process. The inspected parameter-EM method and outer
structural loop continue while scores strictly improve, without an explicit
iteration cap in those loops. Missing-value filling enumerates category
combinations and allocates arrays from their counts. Resource budgets and
overflow/allocation checks are therefore part of the prototype contract.
Finally, the compact graph option explicitly omits intra-slice edges. That
display cannot be the canonical scientific graph.~\citep{exec15_javatemporal_learndbn}

The engineering repair route is concrete: propagate the declared stationarity
flag through all relevant calls, or refuse the unsupported combination;
isolate process-level failures; impose termination and memory budgets; and
export the full graph with lag and intra-slice information. Native tests
should cover complete and incomplete data under stationary and nonstationary
settings. These repairs do not justify the missingness mechanism, guarantee
a global optimum, or turn a score-selected graph into a causal confidence
set.~\citep{exec15_javatemporal_design}

learnDBM is a related implementation. At the selected revisions, 15 of the
17 shared paths in the repositories' dynamic-network source directory have
identical Git blobs. Their observation classes and CLI entry points differ:
learnDBM accepts a cluster count, supplies the requested stationarity flag
to \texttt{MultiNet}, and invokes its clustering method. The learnDBN CLI
finding cannot automatically be attributed to this different caller.
Inspection of the inner class at the same learnDBM revision nevertheless
reveals a separate option mismatch: training and the inner reassignment
pass the declared flag, but the final stored reassignment calls
\texttt{computeClusters(networkPrev, true, false)}. Its stationary branch
uses transition network zero at every date.
\citep{exec15_javatemporal_learndbn,exec15_javatemporal_learndbm,rel15multinet}

This matters even when every required conditional probability is available.
In an authored two-transition example with equal component weights, let
the observed-path probabilities be 0.9 then 0.1 for one component and 0.6
then 0.6 for the other. Their likelihoods are 0.09 and 0.36, giving
normalized weights 1/5 and 4/5. Reusing the first transition gives 0.81
and 0.36, hence weights 9/13 and 4/13. The final routine samples a hard
assignment, so this discrepancy changes its sampling probabilities; it
does not imply a deterministic native outcome in every run.
\citep{rel15multinet,rel15delegatewitnesses}

Two other distinctions prevent a generic EM claim. The reassignment helper
gets mixture weights from the object's stored clustering while the loop
updates a local count array; these are not synchronized within that loop.
Its classification branch chooses the greatest trajectory likelihood
before mixture weights are applied. For weights 0.9 and 0.1 and
likelihoods 0.4 and 0.8, the likelihood-only choice favors the second
component, whereas the weighted products 0.36 and 0.08 favor the first.
The loop can switch from stochastic to classification assignment after
one hundred iterations; that switch is not a hard iteration limit.
An adapter must specify the intended mixture objective, propagate the
stationarity option and qualify the stopping and assignment behavior.
These are selected-source findings and exact illustrations, not an
executed Java failure or a proof that all clustering paths fail. Learned
clusters also need not represent externally assigned intervention regimes;
that interpretation still needs an identification argument.
\citep{rel15multinet,rel15delegatewitnesses,exec15_javatemporal_learndbm}

\subsection{Weka and BayesNetBuilder: alternatives with different outputs}

Weka's declared forecasting package version 1.0.27 dates to October 2019 and
uses GPL3 in the inspected mirror. It creates lagged and date-derived features
for regression, with CLI and graphical interfaces. The actual
\texttt{TSLagMaker} import is forecasting-core \texttt{TimeSeriesTranslate};
the similarly named generic filter is a different class. The caller copies an
attribute and applies a negative instance shift. The core translator copies
selected historical values; its base maintains a queue with offsets counted
in instances. The selected history method receives neither physical
timestamps nor subject identities. Calendar preprocessing elsewhere does not
remove the need for adapter-level clock and series validation.
\citep{exec15_javatemporal_weka}

Weka is therefore useful as a forecasting or feature-construction comparator
with explicit transformations and information availability. This does not
qualify it as a causal-effect estimator. Consider a fair binary hidden risk
indicator $U$, an independent $E$ equal to one with probability $1/4$, and
$A=U\mathbin{\mathrm{xor}}E$, $Y=U$. All four observed $(A,Y)$ cells have
positive probability. The conditional means are
$E[Y\mid A=1]=3/4$ and $E[Y\mid A=0]=1/4$. Yet setting $A$ changes no outcome
equation, so the intervention contrast is zero. With USD 20 per outcome and
USD 8 per action, the conditional proxy for net benefit is USD 2, while the
actual intervention net value is USD $-8$ in this stipulated law. Perfectly
fitting its conditional distribution would not resolve that distinction.
\citep{exec15_javatemporal_exact}

BayesNetBuilder offers parameter learning in a supplied dynamic model. Its
inspected EM entry point defaults to 1000 steps and tolerance 0.0001, computes
expected sufficient statistics and maximizes parameters, and logs when the
limit is reached without convergence. Its author's README describes graduate
research code requiring major refactoring and documentation. No root license
was identified in the selected complete-tree review; rights remain unresolved.
These observations justify a reference candidate for model-supplied EM. They
do not establish structural discovery, intervention identification or a
dependable production service.~\citep{exec15_javatemporal_builder}

\subsection{A public and generated prototype to resolve the known issues}

The immediate proposal should fund a restricted prototype. A first comparison
would retain Tetrad behind a typed adapter, consider a repaired learnDBN path
for discrete longitudinal data, and use Weka for forecasting comparison. An
exact small oracle and a conservative no-discovery decision provide further
baselines. BANJO and BayesNetBuilder remain reference-only pending rights and
version clarification. learnDBM remains disabled pending repair and native
qualification of the inspected clustering contracts. Porting is a later option
where rights, numerical
equivalence and maintenance advantages are established. Wrapping software
does not remove its rights or scientific conditions.~\citep{exec15_javatemporal_design}

Generated mechanisms can vary clock regularity, series boundaries, shared
shocks, regime changes, missingness and hidden causes while retaining known
interventions. Public observations supply realistic calendars and measurement
patterns. Documented public assignments may supply stronger causal evidence
for their stated populations and interventions. The comparison should report
window and graph fidelity, unsupported/refused requests, graph-family
retention where truth is known, justified effect-set coverage and width,
decision loss and full workflow cost. Whole mechanisms or trajectories form
evaluation units, with common-calendar clusters retained. Sources, settings,
evaluation units, replications and stopping rules must be frozen before a
final study. This is a prospective design, not an executed Java experiment.
\citep{exec15_javatemporal_design}

Remaining uncertainty has distinct remedies. Broader candidate searches,
missing originals, release matching, rights review and native option-
combination trials are concrete acquisition and engineering work. Useful graph
and effect uncertainty under hidden causes, dependence and potentially invalid
regime assumptions remains a research problem. Where two models fit the
observations but disagree about an action, the product must report an
identified set, obtain justified additional information, or decline the point-
effect claim. Another package name, larger panel or successful EM termination
does not supply that missing premise.~\citep{exec15_javatemporal_design}
\label{exec15:java-temporal-end}

\section{Native temporal and interventional engines: preserving the scientific request}
\label{exec16:cxx-temporal}

A bank considering a native discovery engine first needs to specify what is
to be learned. A graph of relationships among funding rates, balances and
market conditions is different from the response of balances to a controlled
rate change. A transition model for delinquency is different again: it can
predict the next recorded state without identifying the effect of a servicing
action. The R, Python and Java comparisons above make these distinctions at
their language boundaries. The same distinctions govern a C++ implementation,
even when its numerical kernel is fast and its graph output looks familiar.

Five initial families illuminate different parts of this choice. The C++ kernel in
pcalg implements search using known intervention targets through an R interface.
aGrUM supplies a native probabilistic-model engine, while the inspected dynamic
network helper is Python. Mocapy++ supplies dynamic-model inference and parameter
learning for structures supplied by the user. sDBN contains native temporal
structure-training paths. BayesNetty contributes a constrained genetic-network
search reference. Their capabilities overlap in representation and numerical
work, but their statistical experiments and result meanings differ.
The comparison uses cutoff-compatible source revisions and the technical
content of the original GIES paper; it does not treat repository search
metadata as evidence of implemented capability. \citep{exec16_ct_pcalg,exec16_ct_agrum,exec16_ct_mocapy,exec16_ct_sdbn,exec16_ct_bayesnetty,exec14_pt_paper_gies}

\subsection{A common banking question and two indistinguishable observed laws}

Let $X$ be a centered, standardized funding-rate decision variable and $Y$ a
centered retained-balance index. Consider two deliberately small causal models:
\[
 \begin{array}{lll}
 \mathcal W_1:&X=U_X,&Y=\tfrac12X+\varepsilon_Y,\\
 \mathcal W_2:&Y=U_Y,&X=\tfrac12Y+\varepsilon_X.
 \end{array}
\]
In each world the root variable is standard normal, the error has variance
$3/4$, and root and error are independent. Both observational distributions
are centered Gaussian with covariance
\[
 \Sigma=\begin{pmatrix}1&1/2\\1/2&1\end{pmatrix}.
\]
Consequently a better fit to this observational law cannot distinguish the
two directions. Temporal labels alone do not repair this example if both
variables describe the same decision interval and their within-interval order
has not been justified.

Now replace the equation for $X$ by an independently randomized draw with
variance four. In $\mathcal W_1$, the intervention yields
$\operatorname{Var}(Y)=7/4$ and $\operatorname{Cov}(X,Y)=2$; in
$\mathcal W_2$, it yields variance one and covariance zero. This is an
information change, not merely an extra argument supplied to an optimizer.
The known intervention must actually replace the appropriate structural
mechanism while preserving the other stipulated mechanisms.

For a finite increase from $\operatorname{do}(X=0)$ to
$\operatorname{do}(X=1)$, suppose that one unit of $Y$ is worth USD~20 and
the action costs USD~4. The net effects are
\[
 V_1=20(1/2)-4=6,\qquad V_2=20(0)-4=-4.
\]
These are exact authored examples, not bank measurements. Their purpose is to
show why a representative graph cannot silently become the bank's selected
causal truth: the same observational fit permits opposite action decisions.
Acquiring useful intervention information may be worth considering, but its
value depends on the decision and acquisition cost, not the number of arrows
that a search happens to orient. \citep{exec16_ct_oracle}

\subsection{pcalg: a native interventional kernel with an R contract}

The selected pcalg version is 2.7-12, represented by its September 2024 CRAN
source revision. Hauser and B\"uhlmann formulate independent observations with
known intervention targets; the data need not be identically distributed
across targets. Their conservative-target condition leaves each variable
unmanipulated in at least one regime. These conditions explain the local
score: observations from regimes that intervene on node $j$ do not estimate
that node's original conditional mechanism. In the paper's DREAM4 application,
uncertain-target perturbations are excluded. This establishes a limit of that
application and formulation, not a finding that all later methods fail with
unknown targets. The paper also leaves consistency of its GIES procedure as a
question; that statement must not be turned into a claim about all subsequent
consistency literature. \citep{exec14_pt_paper_gies}

The implementation preserves this experiment through several layers. The R
constructor validates target membership and row counts, sorts rows by target
index, and constructs a nonintervened-row index for each node. The C++ entry
converts one-based R vertex and row indices to zero-based indices. The score
factory distinguishes raw Gaussian, scatter-matrix Gaussian and R callback
paths. A proposed bridge must therefore preserve row identities, target
families, labels and score configuration together. Copying a numerical matrix
and an adjacency list into a nominally equivalent native routine is not a
complete port. \citep{exec16_ct_pcalg}

For node $j$, write $N_j=\{i:j\notin I_i\}$, where $I_i$ is the known
intervention target for row $i$, and let $n_j=|N_j|$. Up to constants that do
not affect the relevant search comparison, the inspected Gaussian local score
has the form
\[
 s_j(P)=-\frac{n_j}{2}\left[1+\log\left\{
       \frac{\operatorname{RSS}_{j,P}}{n_j}\right\}\right]
       -\lambda(1+|P|).
\]
Here $P$ is the candidate parent set and RSS is the residual sum of squares
on the nonintervened rows, with the configured intercept. The default penalty
uses half the logarithm of the total row count. The likelihood expression is
not a dependent-panel uncertainty correction. Overlapping time windows and
shared calendar shocks need their own statistical justification before this
independent-row experiment is claimed.

Configuration identity matters even before any temporal extension. The
manual constructor lists \texttt{intercept=FALSE}, while the inspected R
constructor defaults to \texttt{TRUE}. For a parentless response
$(8,10,10,12)$, fitting its mean gives RSS~8, whereas fixing its mean at zero
gives RSS~408. Holding the penalty fixed, the score difference is
$2\log(51)$, approximately $7.86365$. This is an independent calculation from
the displayed score, not an observed pcalg execution. The remedy is to set and
report the intercept explicitly and test both documented and actual defaults
in a future bridge. The same contract must reject fractional identifiers
before the wrapper's integer coercion, reject zero effective row counts and
nonfinite scores, and retain diagnostics for failed factorizations. The native
Cholesky and QR paths can return NaN on failure; that must not become a valid
zero effect. \citep{exec16_ct_pcalg,exec16_ct_oracle}

GIES returns an estimated interventional essential graph and a representative
DAG. Those are different objects. Its symmetric \texttt{fixedGaps} represents
forbidden adjacency, and adaptive modes can revise the set of gaps. A banking
constraint such as ``an earlier decision cannot be caused by a later balance''
is directional; representing it as forbidden adjacency would also delete a
permitted forward relationship. A bridge should require an explicit constraint
type and validate the returned graph against the requested hard constraints.
The proposed reuse route is a versioned R bridge around the existing native
kernel. A standalone C++ port remains a separate effort because the inspected
interfaces include Rcpp objects, callback support, R preprocessing and
RcppArmadillo/BH dependencies. The GPL-at-least-2 package declaration also
requires a distribution-specific rights review; a language bridge alone does
not settle that question. \citep{exec16_ct_pcalg}

\subsection{aGrUM: unrolling a model while preserving state meaning}

The inspected aGrUM dynamic helper, at its 6 October 2026 revision, checks
time-slice suffixes and selected domain sizes, creates time-indexed variables,
reconstructs parent order, and copies conditional-probability arrays into the
unrolled model. This is valuable model-construction support. It is a Python
helper over the native engine, and the inspected path does not itself learn
a causal temporal structure. An inference engine can answer questions about
a supplied model without establishing that the supplied arrows are causal.
\citep{exec16_ct_agrum}

Equal cardinality is weaker than equal state identity. Suppose the initial
slice lists states as (current, delinquent), while the repeated slice lists
them as (delinquent, current). The intended transition has
\[
 P(D_{t+1}=1\mid D_t=0)=0.1,\qquad
 P(D_{t+1}=1\mid D_t=1)=0.8.
\]
Starting current, the correct two-step delinquency probability is
$0.9(0.1)+0.1(0.8)=0.17$. If a conversion blindly reuses the numeric
parent-state positions after the ordering changes, it instead computes
$0.9(0.8)+0.1(0.1)=0.73$. For a stipulated value $100-40p$, this changes
USD~93.2 into USD~70.8, a USD~22.4 error. This is an authored conversion
counterexample motivated by the source path; it is not an observed pyagrum
runtime result. \citep{exec16_ct_oracle}

The helper's \texttt{is2TBN} checks cardinality without checking identity of
the ordered state labels. The unrolling function's particular invalid-slice
guard combines two conditions with conjunction, so some incomplete slice
sets evade that guard. This is a static control-flow observation; it does not
establish which later operation fails for every malformed model. A proposed
adapter should validate complete slice pairing, ordered state identities,
physical period, dimensions and permitted arrows before unrolling. A
deliberate relabeling needs a probability-preserving permutation of every
affected tensor axis, followed by comparison with a small independently
enumerated model. The inspected file permits LGPL-3-or-later or MIT, supported
by the same-revision license texts; dependency and distribution closure still
need checking. Conditional adoption of supplied-model unrolling is reasonable.
Calling that adoption a newly qualified discovery method is unsupported.
\citep{exec16_ct_agrum,exec16_ct_design}

\subsection{Mocapy++: latent-state modeling is a different investment}

Mocapy++ can serve a supplied dynamic model in which an unobserved borrower
state emits recorded behavior. The inspected manual, version 1.05 from January
2010, explicitly states in Section 3.7 that structure learning is absent.
Its worked source example adds within-slice and between-slice edges before
performing expectation and maximization steps. The sequence masks distinguish
observed, hidden and missing entries. A hidden entry is not an intervention,
and an EM fit of a hidden-state model does not establish that changing a
recorded action would change the hidden state according to the fitted model.
The bounded decision is therefore to reject this version as the proposed
structure-discovery backend while retaining it as a reference for supplied
DBN inference and parameter learning. \citep{exec16_ct_mocapy}

An engineering evaluation would need to justify the legacy environment and
source custody. The inspected mirror is dated February 2019; its build uses
C, C++ and Fortran, and its instructions discuss compiler-matched Boost and
LAPACK. Moreover, the root license contains LGPL2.1 text while the inspected
DBN, EM engine and example headers specify LGPL3-or-later. These observations
require per-file clarification and cannot honestly be compressed into one
unqualified package-license label. Modernizing this code may cost more than
using another permitted inference engine with the same supplied model. The
comparison should measure the cost of preserving the model, masks, numerical
behavior and diagnostics, rather than reward a port merely because its output
has the same shape. \citep{exec16_ct_mocapy,exec16_ct_design}

\subsection{sDBN: temporal training, dependent rows and output interpretation}

The inspected September 2021 sDBN revision contains a C++14 dynamic-network
training program with stationary, nonstationary and already-rolled input
paths. Lag zero means all available time steps. The stationary loader turns
$m$ wide subject records with $T$ time points and lag $L$ into
$(T-L)m$ overlapping transition rows. The node-training code excludes future
parents and parents outside the specified lag, while allowing contemporaneous
candidates. These are concrete temporal mechanisms; they do not by themselves
identify intervention effects or validate a stationary law for irregular bank
records. \citep{exec16_ct_sdbn}

For example, three independent subjects with four observations and lag one
produce nine transition rows. Suppose each subject has one independent,
mean-zero, variance-one shock repeated through its three transition rows.
The mean of all nine rows is the mean of three shocks. Its true variance is
$1/3$, whereas an independence calculation using nine rows gives $1/9$.
An exact enumeration of eight equiprobable sign-shock worlds reproduces the
first result. Overlap can increase numerical work without increasing the
independent information count by the same factor. Likewise, dates
$(0,1,4,5)$ have adjacent gaps $(1,3,1)$: a row lag of one does not specify a
constant physical interval. Preserving original subject and calendar labels
is necessary for splitting, uncertainty and transport to a future decision.
Shared calendar shocks create an additional dependence problem even when
subjects have distinct identifiers. \citep{exec16_ct_oracle}

The output path also deserves a literal reading. The regularization stage
produces allowed directed pairs. The serializer calls this array a
\texttt{skeleton}; it adds a separate directed structure and likelihood only
when a directed-search result is supplied. With \texttt{--no-hill}, the caller
passes no such result. That array should therefore retain its candidate-edge
meaning, rather than be advertised as an acyclic causal graph, an essential
graph or a partial ancestral graph. With directed search enabled, the called
header checks paths before adding edges and restricts reversals to equal-time
nodes with a cycle check. The inspected reversal branch does not explicitly
check membership of the reversed pair in the allowed list. A future prototype
must test and enforce the intended meaning of those restrictions, especially
when starting from a supplied graph. \citep{exec16_ct_sdbn}

There is a further transport issue. The CLI uses standard output for its result
when no output file is supplied. The directed-search routine also prints
diagnostics to standard output inside the result-producing call. Static tracing
therefore predicts a mixed diagnostic/result stream for that path; no native
execution was performed here. A proposed CLI bridge should use a dedicated
result file or separate channel, validate the entire result, and return a
transport failure when parsing fails. It should not silently remove arbitrary
text until something resembling JSON remains. The existing binary hot-start
serialization also motivates an explicit version and platform contract before
checkpoints cross environments. \citep{exec16_ct_sdbn,exec16_ct_design}

Reuse remains conditional. The complete inspected tree contains no README
or license file, so public access does not establish permission to copy or
redistribute the implementation. The build depends on Eigen, LBFGS,
FlatBuffers and OpenSSL, with optional MPI/MKL paths; its release configuration
enables fast-math and contains a host-specific include directory. Resolve
terms, replace that path, freeze dependencies and compare numerical behavior
with conservative compiler settings before considering a bridge. Until then,
sDBN is a source reference and prototype candidate, not an adopted backend.
Independent generated temporal examples remain possible without copying its
implementation. \citep{exec16_ct_sdbn}

\subsection{BayesNetty: constraints and failure values need precise translation}

BayesNetty's selected June 2025 source documents genetic-network modeling,
greedy search and random or jittered restarts. Its score documentation assumes
multinomial discrete nodes and normal continuous nodes. These sources make it
a useful constrained-network reference, but do not qualify a temporal or
interventional banking estimator. The input documentation gives ordered
blacklist edges. If both directions appear in a whitelist, an adjacency is
required while either orientation is allowed. A whitelist/blacklist conflict
is documented as an error. \citep{exec16_ct_bayesnetty}

These conventions differ from pcalg's symmetric gaps. In a two-node DAG
universe, a forbidden adjacency permits only the empty graph; banning only
$A\to B$ also permits $B\to A$; requiring adjacency permits either one-edge
orientation. Two whitelist lines do not represent an unmeasured common cause
with a bidirected edge. The proposed conversion must preserve the predicate
being asserted, with endpoint semantics carried separately from input-file
conventions. \citep{exec16_ct_bayesnetty,exec16_ct_pcalg,exec16_ct_oracle}

Failure values must also retain their meaning. The inspected serial search
method returns numeric zero when its initial network has a loop. Its caller
has not been traced in this comparison, so this does not establish the final
CLI behavior. It does establish why a wrapper cannot assume that every numeric
return is a successful score. The prospective contract needs an independent
acyclicity check and an explicit failure status. The GPL3 source and documented
compiler route support a conditional reference decision, with dependency,
licensing and target semantics checked before a wider integration is enabled.
\citep{exec16_ct_bayesnetty,exec16_ct_design}

\subsection{DBN++: filtering depends on model identity and the evidence clock}
\label{rel19:dbnpp}

DBN++ makes the supplied-model distinction especially clear. Its February
2016 revision describes filtering in discrete-time finite-state dynamic
Bayesian networks. The three advertised routes are variable elimination in
an unrolled network, the interface forward algorithm, and a forward algorithm
using algebraic decision diagrams. The model file supplies factors and the
mapping between slices; the evidence file supplies a sequence of observed
states. These paths do not estimate a causal structure or identify the effect
of a servicing action. They can nevertheless be useful reference calculations
when a bank has justified a particular latent-state model. The experimental
file format must then carry the ordered state dictionary and the physical
meaning of a transition. \citep{rel19dbnpp}

The first evidence time matters. Both interface implementations construct the
initial forward distribution, project it through the transition factors, and
then update it with the first observation. Let $D_t$ denote a binary borrower
distress state, let $K(d'\mid d)$ be its supplied transition law, and let
$\ell_{t+1}(d')$ be the likelihood of the next observed flag. If $p_t$ is the
current state distribution, the intended update is
\begin{equation}
 p_{t+1}(d')=
 \frac{\ell_{t+1}(d')\sum_d K(d'\mid d)p_t(d)}
 {\sum_z\ell_{t+1}(z)\sum_d K(z\mid d)p_t(d)}.
 \label{rel19:filter}
\end{equation}
Thus a wrapper must say whether its initial distribution precedes the first
evidence interval. Feeding evidence already used to construct that distribution
would be a different experiment. The denominator must be positive: an
impossible observation has no conditional distribution under the supplied
model. The inspected dense and diagram normalization methods divide without
an explicit positive-mass guard. The parser and caller also do not establish
a nonempty evidence horizon before the unrolled route accesses its first
record. Validate these conditions and return their scientific or input failure
meaning instead of a seemingly valid probability. \citep{rel19dbnpp}

Model identity is a separate concern for a persistent service. In each
\texttt{project} overload, function-static vectors retain the variable pointers
and transition factors from the first initialization. Later calls append and
remove the current forward factor but do not rebuild those retained vectors
for a different model. The shipped CLI loads one model, a narrower use than
a service evaluating several portfolios or actions in one process. Replacing
its factor objects while reusing the function can therefore retain the earlier
kernel; changing variable objects also raises lifetime and identity questions.
This is a static source finding, not an executed failure of every CLI request.
A prospective adapter needs model-scoped state and a concurrency contract.
\citep{rel19dbnpp}

An exact constructed example shows the monetary significance of substituting
the kernel. Take $P(D_t=1)=1/4$, with flag likelihoods $1/5$ in state zero and
$4/5$ in state one. Kernel A gives distress probabilities $1/10$ and $4/5$
from current states zero and one; kernel B gives $2/5$ and $9/10$. The next
distress probabilities before the flag are $11/40$ and $21/40$. Equation
\eqref{rel19:filter} then gives posterior probabilities $44/73$ and $84/103$.
Suppose, as an additional stipulated causal payoff law, a subsequent action
prevents USD~14 of loss only in the distressed state and costs USD~10 for
every customer. Its expected net value is USD~$14p-10$: approximately
USD~$-1.56$ under A and USD~1.42 under B. Reusing A when B was requested reverses
the action recommendation. The arithmetic assumes the same variable identities
and well-defined kernels; it does not predict the result of dangling pointers,
nor does a filtered probability establish the stipulated causal payoff law.
\citep{rel19dbnwitness}

The finite-state label also needs an algorithm-specific qualification. The
diagram constructor uses one Boolean variable for each domain variable and
selects its positive literal whenever a state index is nonzero. A three-state
dictionary such as current, delinquent and default is therefore not represented
injectively by that construction: indices one and two select the same literal.
For masses $(1/5,3/10,1/2)$, this Boolean mapping preserves only the combined
positive-state mass $4/5$. This demonstrates loss of state identity, not the
exact output of CUDD when supplied an invalid nonbinary evaluation input. A
future diagram route must reject this domain or implement and verify a proper
multivalued encoding; agreement on binary examples cannot qualify ternary
borrower states. \citep{rel19dbnpp,rel19dbnwitness}

The reuse decision is consequently limited to a supplied-model filtering
reference pending those contracts and numerical tests. The build points to
CUDD 3.0.0 through a host-specific directory. README and inspected source
headers declare LGPL version 3 or later, whereas the root LICENSE contains
GPL version 3 text. That discrepancy requires clarification before a
distribution decision; this comparison does not resolve it legally. Neither
a faster forward pass nor a license label supplies causal identification.
\citep{rel19dbnpp}

\subsection{EISALab/DBN: anomaly processing changes the observation experiment}
\label{rel19:eisadbn}

The July 2013 EISALab/DBN revision contains a flat-file anomaly-detection
application. Its Bayesian driver selects ordinary, robust, mixture and online
Kalman variants, Rao--Blackwellized particle filters and scale-recursive
methods from supplied model specifications. The inspected path is therefore
relevant to observation construction and state estimation. It does not
establish a causal structure learner merely because the repository is named
DBN. The wrapper calls an external batch-EM routine for ordinary Kalman
learning; the robust Kalman class's two \texttt{Learn} overloads explicitly
perform no learning. The common command-line learning option cannot be treated
as evidence that every selected filter fits new parameters. The external
numerical implementations remain outside this inspection. \citep{rel19eisadbn}

Its clock and output policies are consequential. The driver advances an
expected timestamp by a configured number of seconds and creates all-missing
records while awaiting the next observation. An optional sufficiently long
gap resets the filter and starts another training sequence; the shown reset
branch supports only the ordinary Kalman and first particle-filter choices.
The chronology check rejects any record earlier than the expected timestamp
before applying the nominal symmetric timing tolerance. A banking adapter must
therefore define positive time resolution, arrival ordering, gaps and restart
meaning explicitly. A missing interval, a delayed report and a new customer
history must not acquire the same interpretation by accident. \citep{rel19eisadbn}

The ordinary filter wrapper returns an observation, lower and upper predictive
limits, a predictive mean and an anomaly indicator. In the optional cleaned
file, a nonmissing observation flagged as anomalous is written as NA. That
policy may help isolate sensor failures, but a large genuine response to a
bank action is not a sensor failure. Consider an exact randomized example:
customer type $U$ and action $A$ are independent Bernoulli variables with
probability one half, and monetary outcomes obey
\begin{equation}
 Y(0)=100,\qquad Y(1)=100+100U,\qquad
 R=\mathbf 1\{Y\leq150\}.
 \label{rel19:cleaning}
\end{equation}
Here $R$ records retention after a stipulated anomaly rule, and all outcomes
are accurate measurements. The population treatment effect is USD~50.
Among retained treated customers only type zero remains; both retained group
means are USD~100, so their contrast is zero. At a stipulated action cost of
USD~20, the population net benefit is USD~30 while the retained-row comparison
suggests USD~$-20$. Randomization before cleaning does not justify the latter
comparison after outcome-dependent selection. This is a constructed law,
not an assertion that the external filter necessarily implements this threshold
or produced these results. \citep{rel19dbnwitness}

The defensible alternative retains the original outcome, flag, missingness
reason and transformation history as separate fields. A causal analysis must
justify any exclusion, model the measurement or selection mechanism when
appropriate, and examine sensitivity when that mechanism cannot be learned.
Prediction intervals concern the stipulated observation model; they are not
automatically intervals for an action effect. The inspected Makefile refers
to external libraries and absolute directories on the original developer's
machine, while the complete tree supplies no file named as a license or
copyright notice. These limits favor a scientific and interface reference
until dependency, rights and numerical behavior are resolved. They do not
negate the potential usefulness of anomaly detection for its own task.
\citep{rel19eisadbn}

\subsection{pdbntk: a parallel skeleton is not a fitted dynamic model}
\label{rel19:pdbntk}

The July 2013 pdbntk revision describes a parallel dynamic-network toolkit,
but the actual demonstration path is unfinished. Its executable declares
hidden-state models and allocates 40,000 sequences of length 100, then passes
a \texttt{DummyInfEngine} to the parallel driver. That engine performs an
arithmetic workload and returns one for each sequence, with an empty vector
of sufficient-statistic objects. The iteration loop repeatedly calls its
expectation routine; the maximization routine is empty and is never called,
and the convergence flag is never updated. If those loops complete as written,
the last accumulated value is 40,000, irrespective of the observations. Its
printed label \texttt{loglik} does not make it a fitted likelihood. No timing,
successful build or native execution is inferred here. \citep{rel19pdbntk,rel19dbnwitness}

The alternative junction-tree interface does not close the gap: its sequence
evidence entry returns zero and its sufficient-statistic method returns an
empty vector. A separate tabular parser checks header identities and numeric
characters but appends an empty observation map without inserting the parsed
values. These are concrete reasons to reject the inspected path as an admitted
learning backend. They do not show that the borrowed Mocapy++ and libDAI
libraries lack their own inference capabilities. The driver also shares one
inference-engine pointer across its OpenMP region; replacing the dummy with
a mutable engine would require an explicit state-ownership design before
parallel correctness could be claimed. \citep{rel19pdbntk}

For banking, an acceptable future EM implementation would need an observation
contract, actual posterior sufficient statistics, a defined parameter update,
an evaluated objective and convergence diagnostics. Those requirements concern
parameter estimation in a supplied model; successful EM would still not turn
an observational hidden-state model into an identified intervention model.
The selected build depends on Boost, OpenMP, GMP, LAPACK and borrowed native
libraries. Inspected libDAI and Mocapy headers carry distinct notices, while
the tree has no project-root license. Resolve their respective scope before
reuse. The appropriate current role is an unfinished design reference, with
no claimed bank benefit from parallelism. \citep{rel19pdbntk}

\section{Temporal discovery in Julia, Rust and MATLAB}
\label{exec17:other-temporal}

A treasury analyst can ask whether yesterday's pricing action predicts
tomorrow's retained funding, whether a common liquidity shock explains both,
or what funding would change if a particular action were imposed. These
questions require different mathematical objects. A predictive lag, a
structural lag coefficient, a supplied dynamic Bayesian network and a
distribution-change orientation rule cannot share an unqualified
\emph{causal edge} field. The languages considered here provide useful
alternatives, but the proposed product must preserve the question that each
alternative actually answers.

The comparison therefore follows six implementation families:
Associations.jl, formerly CausalityTools.jl; varlingam-rs; the MATLAB Bayes
Net Toolbox (BNT); MVGC1; TRENTOOL3; and the MATLAB implementation associated
with CD-NOD. The selected source revisions precede 7 October 2026.
Associations.jl and CausalityTools.jl are one family. The Rust crate and its
Python boundary likewise do not constitute independent algorithms.
The inspected paths support a comparison of mathematical meaning and
prospective reuse. They supply no measured runtime ranking or evidence of a
working bank adapter.
\citep{exec17_temporal_associations,exec17_temporal_varlingam,
exec17_temporal_bnt,exec17_temporal_mvgc,exec17_temporal_trentool,
exec17_temporal_cdnod}

\subsection{The observation clock precedes the choice of engine}

Let $X_{it}$ denote quantities recorded for account $i$ on business date $t$.
The index must carry a sampling interval, calendar and availability rule:
a one-step lag in daily closing balances is different from a one-step lag in
monthly averages. The closing balance can also become available after the
pricing decision. An engine that accepts an array cannot recover these facts
from its dimensions. Joining accounts into a single series can create lags
across account boundaries; treating account copies of the same market shock
as independent observations can create spurious precision. These are input
and sampling-law questions even when the numerical estimator is correct.

The proposed temporal request should consequently declare entity and trial
boundaries, timestamp alignment, units, missing dates, event and availability
times, lagged and contemporaneous variables, and regime labels. Its causal
part should separately declare the action, intervention type, outcome horizon,
population and identification assumptions. A one-time structural innovation,
a persistent policy replacing a conditional distribution, and a surgical
setting of one state coordinate have different propagation laws.
This is a proposed contract; it has not been enabled by inspecting software.
\citep{exec17_temporal_contract}

An exact generated example shows why a common calendar belongs in this
contract. For each independent day, let $U_t$ be a fair binary liquidity
condition. Let
\[
 S_t=U_t\mathbin{\oplus}E_t,\qquad
 T_{t+1}=U_t\mathbin{\oplus}F_t,
\]
where $\oplus$ is exclusive-or and $E_t,F_t$ are mutually independent
Bernoulli$(1/4)$ errors, independent of $U_t$ and other days. Interpret $S_t$
as a binary pricing signal and $T_{t+1}$ as a next-day retention event.
The joint probabilities for $(S_t,T_{t+1})$ are $5/16$ on each diagonal
cell and $3/16$ on each off-diagonal cell. Thus
\[
 \Pr(T_{t+1}=1\mid S_t=1)=5/8,\qquad
 \Pr(T_{t+1}=1\mid S_t=0)=3/8.
\]
The observed difference is $1/4$, although both interventional risks
$\Pr(T_{t+1}=1\mid\operatorname{do}(S_t=s))$ equal $1/2$.
At a stipulated USD~100 per retention event, misreading the observed contrast
as an effect assigns a spurious USD~25 per account. Neither amount is an
estimated bank value.
\citep{exec17_temporal_oracle}

The source contains predictive information about the future target:
\[
 I(S_t;T_{t+1})=
 \frac58\log_2(5/4)+\frac38\log_2(3/4)>0.
\]
Earlier target values are independent of the current day's $U_t$, so
conditioning on that history does not remove this information. Conditioning
on $U_t$ does: $I(S_t;T_{t+1}\mid U_t)=0$. Replicating the construction across
many accounts on each date does not create more independent daily shocks.
The example supplies a small exact reference for interpretation and
conditioning, not an empirical finding about a transfer-entropy estimator.
\citep{exec17_temporal_oracle}

\subsection{Associations.jl: useful information tests with explicit null laws}

Associations.jl offers a natural Julia reference for composing association
measures with embeddings and tests. The inspected project declares
version~4.7.1 and Julia compatibility \texttt{\^{}1.10.11}. Its Shannon
transfer-entropy definition is
\[
 \operatorname{TE}(S\to T\mid C)
       =I(T^+;S^-\mid T^-,C^-),
\]
where $S^-$ and $T^-$ contain selected past values, $T^+$ contains future
target values, and $C^-$ contains conditioning history. The notation defines
a conditional information target; its causal interpretation still needs an
appropriate observation model. In the calendar example it can be positive
without a pricing effect. The selected lag and embedding utilities distinguish
past from prediction lags and check manual lag lengths and uniqueness.
A multidimensional TODO in the construction path is a reason to restrict a
first adapter's supported inputs rather than assume general support.
\citep{exec17_temporal_associations}

The finite test is as consequential as the information estimator. One
inspected surrogate path returns
\[
 p_{\rm raw}=\frac{\#\{b:\widehat I_b\geq\widehat I_{\rm obs}\}}{B},
\]
with $B$ surrogate replicates and no added observation. Suppose, for an exact
illustration, that the observation and 19 continuous null statistics are
exchangeable. Each of the 20 ranks then has probability $1/20$. At
$\alpha=0.01$, the raw fraction rejects at the largest observed rank, yielding
rejection probability $1/20$. The alternative
\[
 p_+=\frac{1+\#\{b:\widehat I_b\geq\widehat I_{\rm obs}\}}{B+1}
\]
has minimum $1/20$ and never rejects at that level in this 20-rank construction.
This is an exact statement about the stipulated exchangeable experiment.
Adding one cannot manufacture exchangeability for a shuffle that destroys
the wrong temporal dependence or conditional distribution.
\citep{exec17_temporal_associations,exec17_temporal_oracle}

That qualification matters on a second inspected path. Its final
transfer-entropy statistic conditions on the combined target-history and
conditioning-history space $(T,C)$, while its specialized local-permutation
helper selects neighbours using $C$ alone. The source comment acknowledges
the analogous construction and retains target information. This is a precise
question for a proposed adapter: does the selected resampling law preserve
the complete conditional null required by the requested statistic?
The static observation establishes the conditioning-set difference; it is
not an executed calibration failure or a claim about every test in the
package. A first prototype should compare this path with complete
conditioning, including cases where source dependence on target history
remains after conditioning on $C$.
\citep{exec17_temporal_associations}

The cross-mapping path supplies another alternative. Its configuration
includes reconstruction dimension, a default negative embedding lag and a
temporal exclusion window; the selected calculation correlates actual and
predicted target values. Such a reconstruction result can motivate a dynamical
model comparison. It should retain its predictive/reconstruction meaning
instead of entering a treatment-effect interface as a monetary derivative.
The proposal is to reference and, after qualification, adapt selected Julia
tests behind typed embeddings and test-law metadata. A port would create a
second estimator and resampling implementation to maintain without yet
resolving these scientific questions. The inherited MIT notice supports
consideration of reuse, while dependency rights and the proposed adapter's
actual behavior remain separate obligations.
\citep{exec17_temporal_associations}

\subsection{varlingam-rs: structural recovery is more than fast regression}

A structural vector autoregression separates within-period and lagged
mechanisms:
\[
 X_t=B_0X_t+\sum_{\ell=1}^{p}B_\ell X_{t-\ell}+\varepsilon_t.
\]
Here $B_0$ represents contemporaneous effects and $B_\ell$ represents a direct
lagged structural coefficient. With invertible $I-B_0$, the reduced form has
\[
 X_t=\sum_{\ell=1}^{p}M_\ell X_{t-\ell}+e_t,\qquad
 M_\ell=(I-B_0)^{-1}B_\ell,\quad
 e_t=(I-B_0)^{-1}\varepsilon_t.
\]
Hyv\"arinen and coauthors give a non-Gaussian identification route under
linear, zero-mean structural VAR assumptions, mutually and temporally
independent non-Gaussian disturbances, contemporaneous acyclicity and the
relevant absence of latent confounding. These premises provide information
beyond a covariance fit; a good reduced-form forecast does not establish
them.
\citep{hyvarinen2010}

The inspected Rust path fits a VAR, applies DirectLiNGAM to its residuals,
and constructs contemporaneous and lagged edge records. Its actual lag helper
uses the algebraically appropriate $B_\ell=(I-B_0)M_\ell$.
A comment at the call site instead states an inverse. The executable helper
and an independent mathematical reference should govern a prospective
conversion; copying the comment into another language would introduce an
error. This observation is static source review, with no claim that the
downloaded engine was run.
\citep{exec17_temporal_varlingam}

For an exact illustrative two-variable system, take
\[
 B_0=\begin{pmatrix}0&0\\1/2&0\end{pmatrix},\qquad
 B_1=\begin{pmatrix}1/2&0\\0&1/4\end{pmatrix}.
\]
Then
\[
 M_1=\begin{pmatrix}1/2&0\\1/4&1/4\end{pmatrix},\qquad
 M_1^2=\begin{pmatrix}1/4&0\\3/16&1/16\end{pmatrix}.
\]
Multiplication by $I-B_0$ recovers $B_1$. The nonzero reduced-form
lower-left coefficient does not imply a nonzero direct structural coefficient
in the same location of $B_1$. Sampling the state every two days changes
the transition to $M_1^2$ and combines innovations; relabeling the old
one-day coefficient as a two-day coefficient is incorrect.
\citep{exec17_temporal_oracle}

For a unit structural innovation in the first coordinate, the time-zero
response is $(I-B_0)^{-1}(1,0)^\top=(1,1/2)^\top$.
The second-coordinate responses at horizons zero, one and two are
$1/2$, $3/8$ and $7/32$. At a stipulated USD~100 per response unit, their
undiscounted sum is USD~109.375. This is a structural-innovation calculation.
Setting a recorded state value, retaining an intervention for several dates,
or discounting future funding requires another query definition; the
calculation does not assign those alternatives the same value.
\citep{exec17_temporal_oracle}

Several source details govern the reuse decision. The selected VAR design
forms raw lagged columns without an intercept or internal demeaning.
Its order-selection criterion approximates a Gaussian likelihood using a
pooled scalar residual variance, which differs from a general multivariate
covariance likelihood. A first adapter should therefore require declared
centering and compare order selection with an independent covariance-aware
reference. A sample-size multiplier such as five times the number of variables
times the number of lag blocks is a heuristic, not a calibration theorem.
\citep{exec17_temporal_varlingam}

The edge field called \texttt{significant} compares the absolute coefficient
with a configured threshold, default~0.05. It is not a p-value or a
confidence statement. A response coefficient of USD~0.04 million per unit
equals USD~40 thousand per unit; an unchanged numerical threshold of~0.05
changes its flag after this harmless unit conversion. The adapter should
expose a coefficient-magnitude flag with units, and refuse to present it as
statistical significance. The advertised bootstrap, scalable and RCD
interfaces and performance claims remain unqualified by the selected review.
The proposal is to retain a numerical reference and test an existing
Rust/Python boundary before choosing a port. The crate's MIT-or-Apache-2.0
declaration does not settle every dependency or distribution condition.
\citep{exec17_temporal_varlingam,exec17_temporal_oracle}

\subsection{BNT: surgery on a supplied dynamic model}

BNT offers a contrasting reference: its dynamic-network constructor receives
the intra-slice and inter-slice graphs from the caller, together with node
sizes and parameter classes. The selected unrolling function repeats this
supplied topology. These operations support an explicit dynamic model; they
do not discover its graph from a bank table.
\citep{exec17_temporal_bnt}

The inspected file named \texttt{do\_intervention.m} declares the function
\texttt{mutilate\_bnet}. It deletes incoming arcs to a selected node and
replaces its conditional distribution with a root CPD containing the supplied
value. The corresponding root sampler returns that value exactly.
The file/function naming mismatch remains an environment and call-resolution
question before runtime reuse. On the ordinary forward-sampling path,
prepopulated evidence cells are skipped. Skipping a fixed value during forward
sampling is not, by itself, a general posterior sampler conditioning on
possibly downstream evidence; the chosen inference engine needs its own
semantics check.
\citep{exec17_temporal_bnt}

Consider another exact model: $U$ is a fair latent state,
$A=U\oplus E$ with independent $E\sim\operatorname{Bernoulli}(1/4)$, and
next-period outcome $Y=U$. The observed risks are
\[
 \Pr(Y=1\mid A=0)=1/4,\qquad
 \Pr(Y=1\mid A=1)=3/4,
\]
while both surgical risks are $1/2$. The same observed two-variable law
also admits a supplied model with exogenous fair $A$ and
$Y\mid A$ having those conditional risks; in that model the causal contrast
is $1/2$. Choosing a supplied graph changes the intervention answer even
though both graphs reproduce the observed table. A correct graph-surgery
operation cannot decide which graph describes the bank.
\citep{exec17_temporal_oracle}

BNT is consequently a legacy mathematical and small-model reference.
Direct adoption as the temporal discovery engine is rejected for the
inspected constructor/unrolling role, because no graph is being inferred on
that path. A permitted prototype could compare exact enumeration, posterior
conditioning and intervention in a tiny supplied model, while resolving the
callable name and engine-specific evidence handling. The inherited GNU
Library GPL version~2 text, component inventory and target MATLAB environment
need a distribution-specific review before adaptation or a port.
\citep{exec17_temporal_bnt}

\subsection{MVGC1 and TRENTOOL3: two predictive directions, two test contracts}

MVGC1 is a developed MATLAB reference for multivariate Granger-causal
inference. Barnett and Seth formulate the question through additional
predictive information and reduced versus full residual covariance.
For a scalar target, the statistic is a log ratio of reduced to full
prediction-error variance. A positive value can be scientifically useful
without being an identified effect of a bank action. The preceding calendar
example explains why measured common causes and the interpretation of the
information set matter.
\citep{exec17_temporal_mvgc_paper}

The selected MVGC1 estimator accepts variables by observations by trials,
demeans input and forms lagged regressors within trials. Its autocovariance
path checks spectral radius, residual covariance and numerical conditions,
with explicit diagnostics for unstable or truncated calculations. These
checks are valuable prospective adapter outputs. The paper also discusses
collinearity, nonstationarity, long memory, moving-average components and
heteroscedasticity; a stable fitted VAR alone does not remove those problems.
For short-window multiple trials, the described justification depends on
independent realisations of a common underlying process. Bank accounts sharing
a calendar need another dependence argument.
\citep{exec17_temporal_mvgc,exec17_temporal_mvgc_paper}

The inspected distribution routine uses an F form by default for a
univariate target and a chi-square form for a multivariate target, with
effective observations $N(m-p)$ for $N$ trials of length $m$ and order $p$.
It labels a noncentral F calculation experimental. The significance utility
offers Bonferroni, Holm and FDR variants; none validates input p-values whose
sampling law is wrong. A conversion should preserve target-row/source-column
orientation, unavailable diagonal entries, failed covariance/stability
diagnostics and the selected null distribution.
The README's v1.3 date of March~2022 and the later pinned revision are separate
identities. The newer state-space path advertised there remains outside the
selected technical review.
\citep{exec17_temporal_mvgc}

The MVGC license notice expressly grants GPLv3-or-later, even though a
repository metadata field did not identify a license. Original rights text
therefore takes precedence over that metadata for this limited finding.
The proposal is to use MVGC1 as a reference and consider a permitted MATLAB
comparator before any port. Reimplementing only the regression while losing
covariance, model-order and failure semantics would remove much of the
reason to choose this reference.
\citep{exec17_temporal_mvgc}

TRENTOOL3 instead develops a transfer-entropy workflow, with reconstruction
and interaction-delay choices, trial handling, surrogate tests and
partial multivariate correction described in its README. Its declared
implementation combines MATLAB with CUDA C/C++ components and uses FieldTrip
and TSTOOL. The selected preparation interface distinguishes sampling in Hz,
analysis windows in seconds, prediction delay in milliseconds, and embedding
delays expressed using autocorrelation-time units. A banking adapter must make
these conversions explicit. Passing the integer~1 from a daily-series
interface to a millisecond argument does not mean one day.
\citep{exec17_temporal_trentool}

The inspected one-tail permutation path counts strict surrogate exceedances
and replaces a zero fraction by $1/B$. Its two-tail path uses the smaller
tail fraction against $\alpha/2$. These conventions differ from the
Associations.jl raw-zero example; that example must not be attributed to
TRENTOOL. The source defaults for alpha, one-tail testing, FDR and a shift
test likewise describe a workflow rather than establish its calibration for
common banking calendars. Ties, trial dependence, temporal exclusion and
surrogate construction belong in a registered comparison.
\citep{exec17_temporal_trentool}

The proposed use is a reference for embedding, delay and surrogate design.
A first bank prototype should favour a bounded CPU comparison with declared
units and null laws before considering a GPU port. A repository GPL version~3
text and source headers granting GNU GPL do not by themselves settle every
component, dependency or licensed MATLAB distribution. Direct product adoption
remains deferred, as does any speed advantage.
\citep{exec17_temporal_trentool}

\subsection{CD-NOD: changing mechanisms and the actual lagged extension}

Distribution changes can add orientation information, but only under a model
of what changes. Huang and coauthors explicitly allow pseudo confounders that
are functions of the domain index or smooth functions of time, fixed within
the corresponding domain or time instance. Their assumptions also include
mutually independent disturbances, mechanism-parameter restrictions,
Markov and faithfulness conditions for an augmented graph, and no selection
bias. A calendar variable is therefore not a universal remedy for unmeasured
credit risk, rapid latent shocks or selective account observation.
Additional orientation premises appear in their Assumption~3 and Theorem~2;
an equivalence class may remain when the sufficient conditions fail.
\citep{exec17_temporal_cdnod_paper}

The paper does develop time-varying instantaneous \emph{and lagged}
relationships. Section~6.1 and Algorithm~5 reorganize $m$ processes with
maximum lag $P$ into $m(P+1)$ columns, prohibit future-to-past causes, and use
lagged common causes when testing contemporaneous adjacency. Omitting this
extension from the literature comparison would understate the available
method. Conversely, mentioning it does not establish that a particular
downloaded entrypoint implements the whole construction.
\citep{exec17_temporal_cdnod_paper}

The inspected MATLAB examples call a same-row variable-plus-context
entrypoint. It appends and standardizes the context, invokes conditional
independence tests and orients an edge $i\to j$ as
$g(i,j)=1,\ g(j,i)=0$; unresolved adjacency begins with $-1$ in both
directions. The direction helper has explicit kernel bandwidth and
regularization choices, and its final direction statistic is not a p-value.
A changing-module visualization uses kernel PCA; a plotted component is not
thereby an identified bank latent factor. No dedicated Algorithm~5 lag
assembly and temporal-tier restriction is established on these selected
paths. A prospective adapter must implement or locate those operations,
preserve endpoints and context role, and qualify overlapping lag-window
tests rather than simply relabel columns.
\citep{exec17_temporal_cdnod}

The distinction is economically meaningful when a bank changes policy.
In an exact generated example, suppose two equally weighted eras have a
centered unit-variance source, mean-zero independent noise, and slopes
$+1$ and $-1$. The pooled source--outcome covariance and linear slope are
zero, despite opposing era-specific responses. Detecting change can expose
an inadequate pooled model, but does not show why policy changed. The paper's
soft-intervention discussion first gives the classical definition with a
known, exogenous intervention affecting the designated module. It then
extends the comparison to automatically detected, continuous and
multiple-module changes, and even appearing or disappearing edges.
The classical definition is therefore not a blanket restriction on CD-NOD.
The extended analysis still requires its changing-mechanism assumptions;
a crisis-era label can simultaneously track selection, measurement and
several changing mechanisms.
\citep{exec17_temporal_oracle,exec17_temporal_cdnod_paper}

Even within the paper's richer discussion, stationary confounding does not
disappear generally. Section~6.2 distinguishes some cases with one changing
module, while the two-changing-module alternatives in its Figure~7(c),(d)
remain indistinguishable without more information. The proposed product
should return remaining graph or effect ambiguity rather than force a
direction because a direction statistic is available.
\citep{exec17_temporal_cdnod_paper}

The immediate choice is a mathematical reference for changing-mechanism
discovery and an explicit lag-construction prototype. The inspected top-level
code does not establish redistribution permission and includes a rights
reservation. Nested component licenses cannot supply permission for the
whole repository. Adaptation or direct adoption is deferred until applicable
rights are established; an original implementation based on the paper would
still require its own numerical and statistical review.
\citep{exec17_temporal_cdnod,exec17_temporal_contract}

The first prototype can use generated mechanisms with known graphs and
explicit intervention oracles. The calendar, structural-lag, unit-scaling,
rank, supplied-model and regime examples above give exact targets before
running any engine. Development should then add centered and shifted
levels, near-unstable dynamics, moving-average misspecification, missing
dates, unequal trial lengths, overlapping lag windows and unknown common
causes. Each case should state whether a graph, a prediction contrast, an
identified effect, a set or a refusal is the correct output. Equivalent
observed laws must remain ambiguous whenever the declared information
does not distinguish them.
\citep{exec17_temporal_contract}

A second stage can use permitted public observations and documented public
experiments. Observed series can test parsing, clocks, stationarity diagnostics,
failure handling and predictive reproducibility; they generally do not
provide a known intervention graph. A documented experiment supports a
causal comparison only to the extent that assignment, measurement, timing,
interference and the queried population match its design. Public accessibility
alone does not establish reuse permission or causal ground truth.
This route postpones expensive representative bank work until a narrow
prototype has demonstrated enough merit to justify it.
\citep{exec17_temporal_contract}

Before a finite performance study, freeze engines and versions, generators
or permitted data, transformations, units, train/evaluation separation,
surrogate and tuning budgets, failures, stopping rules and scoring.
Score graph endpoints and lags separately from intervention-target error,
and report availability and refusal with the denominator of every request.
Include retrieval, preparation, licenses, hardware, human assumption review,
failed runs, corrections and maintenance in cost. A faster wrong target
cannot support a bank return-on-investment claim.
\citep{exec17_temporal_contract}

The six-family comparison leaves a broader software census open.
Uninspected Julia, Rust and JavaScript leads, kernel and multiscale Granger

complete dependency rights, executable boundaries and temporal calibration
have concrete prototype routes. Unknown confounding and observational
equivalence require additional justified information or narrower claims;
neither another package nor another search can guarantee their resolution.
These limits define a useful product proposal: explicit mathematical roles,
testable conversion contracts and a bounded experiment that can inform the
next investment.
\citep{exec17_temporal_contract}
\label{exec17:other-temporal-end}

\section[Discovery delegates and local model boundaries]{Discovery delegates and local model boundaries}
\label{sec:exec28-bp}
The language comparisons have shown why clocks, graph classes and mechanisms
cannot be inferred from a package interface. The remaining studies follow
these distinctions through particular delegate and evaluation paths. Some
apply to static as well as temporal discovery: they explain how a correctly
stated temporal question can be lost through variable relabeling, an
incomplete call, truth-assisted selection or a changed scoring population.

A banking proposal must preserve variable identity across discovery and execution boundaries.
Consider a collections team asking whether an early reminder changes later repayment.
Its proposed workflow first represents an information clock and candidate graph, then asks whether
the reminder effect is identified under that graph and the available observations. A Python
discovery wrapper and a local language-model endpoint can help implement this workflow, but each
introduces a separate conversion contract. The first can change the names attached to a matrix;
the second can change the place or completion state of a computation. Neither conversion may
silently redefine the causal question. The following comparison concerns selected original
source paths and exact authored examples, not an executed integration.

\subsection{What an R delegate actually contributes}
The selected CausalDiscoveryToolbox (CDT) commit delegates PC and GES through R templates.
The PC template loads pcalg, kpcalg, methods and RCIT, selects its conditional-test route, and
sets algorithm options including the stable.fast method and majority/conflict behavior.
Although the template's options list contains a core-count field, the inspected call does not
pass that field to PC. A proposal therefore cannot infer parallel scaling from the existence
of the field. The data and constraint matrices cross the boundary as headerless CSV, and a
matrix returns through another CSV. The representation has lost the protection that named
variables could otherwise provide.~\citep{exec28_bp_cdt}

The GES path provides a second semantic warning. Its wrapper describes an \texttt{int} option
with a categorical label while mapping that option to \texttt{GaussL0penIntScore}. The selected
template constructs the chosen score using the data alone, runs GES, extracts the essential
graph and writes a matrix. In the separately inspected pcalg source, that class is Gaussian;
its default target list is empty and its default row assignment places every row in the first
environment. This comparator explains why an adapter must inspect the actual likelihood and
intervention metadata. It does not prove which pcalg version a particular CDT installation
resolves. An intervention-labelled class name does not create an intervention design, and a
Gaussian score is not made appropriate for categorical banking outcomes by a wrapper's label.
The exact R and package versions, endpoint conventions and categorical alternative remain
explicit selection requirements.~\citep{exec28_bp_cdt}

Variable order is independently consequential. In the inspected direct-orientation paths,
skeleton or output labels are sorted while the input data retain their original column order.
This source observation motivates a conversion fixture; it is not a measured defect rate.
Let the declared data order be $v=(z,a)$ and suppose the interface convention interprets
$A_{ij}=1$ as a directed edge from row variable $i$ to column variable $j$. For the authored matrix
\[
 A=\begin{pmatrix}0&1\\0&0\end{pmatrix},
\]
the edge is $z\to a$. If the matrix stays fixed but labels become $(a,z)$, the named edge becomes
$a\to z$. A correct reordering uses the same permutation for the data, constraint matrices,
result matrix and label vector. Under a permutation matrix $P$, the corresponding matrix is
$PAP^{\mathsf T}$; changing labels alone does not perform that operation. The two-node example
reproduces exactly in the project reference. Its directed convention is stipulated for the
witness; PC/GES endpoint encodings must still be established on their selected native paths.
For reminder and repayment variables, exchanging names would change the scientific question
before an identification routine even starts.~\citep{exec28_bp_reference,exec28_bp_cdt}

The launcher introduces a different boundary. It creates a UUID-based template copy and
performs literal placeholder replacement. The inspected callback branch waits for the child
process and then retrieves output without conditioning that retrieval on a checked return code.
Package-availability probes do not record a resolved version or establish redistribution rights.
The source consequently motivates explicit trials for failed children, large stderr, partial
CSV, interrupted execution and stale output; it supplies no observed results for those trials.
A typed adapter should bind an ordered-variable manifest, data/constraint identities, score
family, interventions, selected package versions, exit state and output provenance before
returning an identified query to a banking user. A direct pcalg route is a substantive alternative
when explicit R dependency control is preferable. A wholesale port would add a numerical and
semantic equivalence obligation without resolving identification by itself. We therefore propose
conditional reuse of the selected delegate through a thin adapter, while deferring native
enablement until these finite conversion and failure contracts have been demonstrated.
\citep{exec28_bp_cdt}

\subsection{A local endpoint is only one part of a model profile}
The previously inspected Ollama Python client requires a separately selected server and model.
The current server review pins eleven originals to commit
\texttt{d3c846f8b0279e79b0e3\allowbreak{}a960a7575fde6920e9df}, dated 7 October 2026.
The source variable \texttt{Version} contains the placeholder \texttt{0.0.0}; this is not a
verified release identifier. The module file declares a Go toolchain requirement and dependency
versions, but does not by itself establish a reproducible binary or complete transitive rights.
The selected server's MIT notice and a Modelfile's license declaration also do not independently
establish the rights of separately obtained weights. A useful profile must bind the client,
server commit and build, runner, model manifest and weight hashes, tokenizer/template,
quantization, request configuration and execution destination. Unknown fields should remain
unknown until inspected, rather than inheriting a reassuring product-level label.
\citep{exec28_bp_ollama}

This distinction matters to a banking workflow that may contain customer information.
The inspected API documentation distinguishes local and cloud endpoints, while also describing
cloud inference through a local server. The selected Chat handler has an explicit remote-model
branch: it checks the remote configuration, forwards the request and records remote host and
model fields in responses. Thus a localhost address alone is insufficient evidence that inference
stays on the machine. The documentation describes local requests without authentication and
separate cloud credentials. These are source-supported boundary conditions, not a security
assessment of a deployed system. The proposal should require an explicit routing decision and
deployment controls for its chosen profile; a private local prototype can be designed using
public or generated data before bank data are involved.~\citep{exec28_bp_ollama}

\subsection{Completion, residency and scientific admission}
Selected endpoints stream newline-delimited JSON. The documented protocol includes nonterminal
chunks, a terminal \texttt{done} field and a stop reason. In the inspected stream handler an error
before output can set an HTTP error status; after output begins, an error is encoded in the
stream. The documentation correspondingly warns that an error arriving midstream cannot change
the status already sent. Receiving HTTP 200 and a plausible text prefix therefore does not
establish successful completion. Moreover, the inspected Chat handler can return
\texttt{done=true} with reason \texttt{unload}; successful unloading is not successful inference.
The full response state must survive the adapter boundary.~\citep{exec28_bp_ollama}

Define $T$ to mean a recognized inference terminal state, $E$ an error anywhere in the trace,
$V$ successful validation against the original response contract, and $I$ an identified causal
target under explicitly recorded assumptions. A proposed admission rule is
\[
 \mathrm{admit}=T\land\neg E\land V\land I.
\]
The precise terminal reasons allowed by $T$ belong to the chosen endpoint and profile.
In an authored six-trace example we stipulate an HTTP 200 status for every trace and allow
\texttt{stop} as the successful inference reason. Only the complete, valid, identified trace
passes. A midstream error, truncated trace, unload response, invalid representation and
nonidentified query each fail a different conjunct. Exactly one trace is admitted and five are
rejected. This is a transparent specification example, not evidence of a six-request model test
or an estimate of error frequency. A rejected inference may still yield a useful explanation,
identified set or request for more information; rejection must not be hidden as a numeric zero.
\citep{exec28_bp_reference}

Model residency must also be separated from workflow recovery. The request type describes
\texttt{keep\_alive} as how long a model stays loaded, and the inspected scheduler decrements
reference counts and schedules unloading after the residency duration. This does not persist
the banking decision, original assumptions, tool effects or a recoverable conversation.
Similarly, the generation path propagates a request context and cancels it on a selected parser
error, but source-level context propagation is not an observed guarantee that all downstream
work has stopped. The request's format is passed to a runner; this forwarding alone does not
establish conformance to every original schema constraint. Native cancellation and format
fixtures remain necessary for the chosen runner and model.~\citep{exec28_bp_ollama}

\subsection{Public prototype route and adoption decision}
These observations define a finite next prototype without requiring costly bank experiments.
The discovery fixture should use public or generated labelled columns, permutations and
constraint matrices, plus intentionally failing children, to test whether the selected CDT/R
path preserves the declared graph representation and refuses incomplete output. The model
fixture should bind one permitted build and weight profile, exercise complete and interrupted
streams, validate against the original schema, and retain routing and stop-state evidence.
The two exact authored witnesses provide independent expected behavior for narrow interface
contracts; they do not provide a truth oracle for an arbitrary discovered graph or language-model
answer. Native implementation, rights review and actual trial results remain separate work.

The proposed investment choice is therefore conditional reuse, with explicit alternatives.
CDT can supply selected discovery orchestration if its conversions and dependencies are controlled;
direct R usage can reduce wrapper ambiguity; a port is justified only when the maintenance and
equivalence burden is preferable. Ollama can supply a selected inference service boundary after
build, model, routing and termination contracts are pinned. A managed service is a different
choice with its own entitlement, cost and data-handling evidence. Neither choice earns causal
identification from a successful call. The resulting proposal keeps source-supported capabilities,
project specifications and future empirical qualifications distinct.
Variable identity and execution identity must survive every boundary before a causal result is admitted.

\section[Reinforcement search and discovery contracts]{Reinforcement search and discovery contracts}
\label{sec:exec28-rl}
Reinforcement learning can search for a causal graph without establishing that the graph is identified.
For a bank considering early reminders, the graph-search problem is to compare possible relations
among eligibility, reminder assignment, repayment and recorded customer characteristics. This is
different from learning a servicing policy that will act on customers. In the discovery methods
reviewed here, the reinforcement learner is an optimizer: its actions generate graphs or variable
orders, and a statistical score supplies a reward. A better search can improve a score while
leaving the information needed for a causal effect unchanged. Public or generated data can test
the search and interface contracts before costly bank experiments, provided the score's assumptions
and the target graph are declared separately.~\citep{exec28_rl_zhu,exec28_rl_wang}

\subsection{Graph search versus ordering search}
Zhu, Ng and Chen formulate discovery as a search over directed graphs with a score and acyclicity
penalties. Their model discussion assumes scalar structural equations with jointly independent
additive noises, causal minimality and independently sampled observations. The paper explicitly
recognizes that further restrictions are needed for unique graph identification; its selected
experiments use identifiable families. Its encoder-decoder proposes adjacency matrices, and the
best-scoring sampled graph is the output of the search. Those statements do not establish validity
under a latent common cause, a persistent panel or unmeasured selection into reminders. In a
banking application, such features must be represented or restricted before the graph score can
be interpreted scientifically.~\citep{exec28_rl_zhu}

Wang and coauthors instead search variable orderings. Each complete ordering defines a fully
connected acyclic candidate; variable selection subsequently removes edges. Their sequential
decoder masks previously selected nodes, and the paper distinguishes episodic and dense rewards.
The consistency discussion assumes an identifiable structural equation model and a suitable
distribution family. Its proposition explains why an ordering-compatible model reproducing the
same distribution must cover the true graph under those assumptions. It does not guarantee
global optimization by policy gradients; the paper explicitly discusses local convergence and
approximation. Ordering removes a combinatorial acyclicity burden from the candidate construction,
but does not remove misspecification, finite-sample selection error or causal nonidentification.
Attention in an encoder is a representation mechanism, not an edge-confidence or identification
certificate.~\citep{exec28_rl_wang}

\subsection{A precise qualification at the penalty boundary}
For a graph $G$ with binary adjacency matrix $A$, write $S(G)$ for the score to minimize and
$h(A)=\operatorname{tr}(e^A)-d$ for the nonnegative cycle measure on $d$ nodes. The graph-search
formulation adds $\lambda_1\mathbf{1}\{G\notin\mathcal D\}+\lambda_2h(A)$, where $\mathcal D$
is the set of DAGs. Proposition 1 in the inspected Zhu preprint gives the non-strict condition
\[
 \lambda_1+\lambda_2h_{\min}\geq S_U-S_L,
\]
with $S_L$ a lower bound on all graph scores, $S_U$ an upper bound on the optimum DAG score, and
$h_{\min}>0$ the smallest cycle measure over cyclic candidates. Its proof establishes that an
optimal DAG cannot be beaten by a cyclic candidate under this bound. At equality, however, that
argument need not exclude a cyclic candidate tied with the optimal DAG. The reverse proof uses
a strict improvement that does not follow from being a distinct tied minimizer. The distinction
matters if an implementation returns any maximizer of reward.~\citep{exec28_rl_zhu}

An exact project construction isolates the boundary without making a claim about the paper's
empirical BIC results. Enumerate the four loopless directed graphs on two nodes. Assign score 1
to each of the three DAGs and score 0 to the two-cycle. Set $S_L=0$, $S_U=1$,
$\lambda_1=1$ and $\lambda_2=0$. The displayed condition holds with equality, and every penalized
score is 1. The cyclic graph is therefore also a minimizer. The optimal value still equals the
DAG-constrained optimum, and an optimal DAG remains available; what fails is the stronger
conclusion that every unconstrained minimizer is acyclic.~\citep{exec28_rl_reference}

A sufficient repair for that stronger conclusion is strict domination,
$\lambda_1+\lambda_2h_{\min}>S_U-S_L$. Then every cyclic penalized score is strictly greater
than $S_U$, whereas some optimal DAG has score at most $S_U$. Alternatively, an exact optimizer
can explicitly prefer a DAG among tied optimal candidates, if such a candidate is available.
In the finite witness,$\lambda_1=3/2$ makes the cyclic score $3/2$ and leaves the DAG scores 1.
Neither repair proves that a practical policy-gradient search finds the global optimum or samples
a DAG. A returned candidate must still pass an independent acyclicity check, and approximate
cycle thresholds need a declared tolerance policy. The construction qualifies the stated general
score condition; it does not assert a failure rate for the original experiments.
\citep{exec28_rl_reference}

\subsection{What the selected implementation supports}
The selected gCastle source gives concrete contracts beyond the algorithm names. The RL reward
has BIC and unequal-variance variants, regression choices, and a cycle threshold of $10^{-5}$.
Its positive-$\ell_1$ branch refers to \texttt{l1\_grapha\_reg},whereas initialization stores
\texttt{l1\_graph\_reg}. Under the ordinary constructor path without an injected extra attribute,
that branch requires correction or a demonstrated supported alternative before enablement.
The selected normal-equation regression and median-scaled Gaussian-process paths also motivate
rank and scale fixtures. These are static source findings, not observed runtime error counts.
\citep{exec28_rl_gcastle}

The selected CORL entrypoint documents a \texttt{dag\_mask} keyword but retrieves it using
attribute lookup on the keyword dictionary. A plain Python dictionary does not expose a key
through that attribute lookup. The authored witness supplies an all-zero mask by key and obtains
the default through attribute lookup, while key lookup retrieves the mask. The next integration
must demonstrate that forbidden-edge constraints actually reach the graph constructor.
The inspected constructor builds order-consistent entries and multiplies by a mask; its pruning
routine treats row-selected columns as predictors of each variable,and the search returns a
transpose. This complete conversion needs a declared endpoint convention and a labelled
round-trip fixture. A high score cannot compensate for a reversed named edge.
\citep{exec28_rl_gcastle,exec28_rl_reference}

The reward comparison requires similar care. CORL's selected score branches omit the displayed
edge-count penalties, whereas the RL score includes them. That observation alone does not prove
incorrect ordering rankings: fully connected candidates of the same dimension have the same
number of edges before pruning. The correct comparison must trace which candidate is scored,
which regression family is fitted, and when pruning occurs. Its Transformer source normalizes
the attention scores along dimension 1 and calls functional dropout without an explicit training
argument. A pinned tensor-library profile and repeated evaluation fixture should establish the
intended normalization and evaluation behavior before this path is adopted. These source details
do not turn an attention matrix into a causal graph.~\citep{exec28_rl_gcastle}

\subsection{Dependency profiles and a finite public qualification}
The complementary CDT inspection shows why listing dependencies is insufficient. The selected
Python and R requirement files list package names without versions. Python setup and requirements
also differ: torch is listed in one route, while skrebate is included in setup. Container recipes use
mutable base-image tags and unpinned package installation. The default interpreter is
\texttt{Rscript}, resolved from the environment unless overridden; the availability template calls
\texttt{library} rather than querying versions. A repository MIT notice and Apache2 setup metadata
remain different declarations, so neither should be silently promoted to a complete distribution
rights decision. A proposed reproducible environment must be selected and recorded explicitly;
these manifests cannot reconstruct an exact historical installation by themselves.
\citep{exec28_rl_cdt}

A finite public prototype can address these known interfaces without requiring bank truth.
First, bind one package/build/dependency route and its component terms. Second, use labelled
generated variables to test permutation, mask and endpoint preservation, including forbidden edges
and ambiguous graph output. Third, separate equality and strict-penalty examples from finite search
tests, retaining every failed or nonacyclic candidate in the denominator. Fourth, exercise constant,
collinear and nonfinite data and repeated evaluation under the selected regression and tensor
profile. Finally, inject failed children, large diagnostics, partial files and interruption into the
R boundary. Each fixture needs an independently declared expected result; a numerical output is
not automatically success. These are proposed conformance tests, not trials performed by this review.

Conditional reuse remains the defensible product decision. A narrow discovery adapter can retain
upstream search mechanics while imposing explicit variable, score, constraint and failure contracts.
A direct R route or a separately implemented ordering search may be preferable when those
contracts are easier to verify than a broad wrapper. Porting requires an additional equivalence
argument and maintenance budget. The two primary papers and selected code paths strengthen the
proposal's mechanism-level comparison, but do not exhaust reinforcement or attention-based
discovery, establish graph confidence, or qualify dependent banking data.
A discovery optimizer is useful only when its search result preserves the declared causal target and assumptions.

\section[Attention discovery and evaluation contracts]{Attention discovery and evaluation contracts}
\label{sec:exec28-at}
Attention can rank predictive relationships without identifying the effect of a banking intervention.
Consider a bank asking whether an earlier reminder changes repayment, using histories of reminders,
balances, delinquency and recorded contacts. A prediction graph relates information available at
specified times to future repayments. An intervention question instead changes an assignment rule
and asks what would happen under that change. Shared financial stress, servicing selection and
measurement delays can make these different questions even when prediction is accurate. The
proposal therefore treats attention as a candidate-construction mechanism whose sampling law,
variable clock, graph meaning and evaluation procedure must be stated explicitly.

\subsection{Distinct meanings of attention and of a causal graph}
The inspected Liu preprint defines a DAG of Granger relationships, with Markov, faithfulness,
strict-order and minimum-signal assumptions. Its strict ordering is written as $i<j$ for a
relationship from variable $i$ to variable $j$, and the text excludes contemporaneous causation.
That is a substantive restriction on the admitted graph, rather than a consequence of computing
self-attention. A bank with feedback between arrears and subsequent reminders must decide whether
its nodes are time-indexed events, entire series, or a restricted ordering of series. A series-level
DAG cannot be silently substituted for an unfolded temporal graph with feedback across dates.
The inspected method aggregates attention contributions across tokens, selects potential edges
using an order-statistic threshold, and compares predictions after permuting a candidate series.
These operations support a particular predictive discovery procedure under the stated model;
they do not supply a general intervention-effect confidence region.~\citep{exec28_at_liu}

Attention also describes different computational objects. In the selected TCDF implementation,
a trainable vector supplies a softmax gate on input variables before depthwise convolution and a
pointwise convolution. Candidate selection uses attention scores, and a later permutation step
compares a fitted model's loss on the original training target. The delay extraction reads maxima
of convolutional kernel weights. These are concrete mechanisms, but neither a gate weight nor a
kernel maximum is automatically an intervention coefficient. The inspected source's
\texttt{significance} parameter enters a loss-improvement fraction; that expression alone does
not establish a calibrated $p$-value or a familywise graph error guarantee. The software is cited
for these selected source mechanics; its scholarly article remains a separate primary-source
obligation.~\citep{exec28_at_tcdf}

The selected CAMCNs model likewise contains a softmax feature gate followed by depthwise and
pointwise convolutions, while its discovery path adds correlation and lag selection. A README's
multihead description does not establish that every selected module implements query-key-value
multihead attention. The proposal should compare the actual selected computation, not collapse
all architectures into one label. Its entrypoint imports \texttt{train} and \texttt{VAL} from the
model module, whereas the inspected definitions are methods of \texttt{TCFMODEL} rather than
top-level functions. The namespace mismatch is a static integration finding at the pinned
source revision. It calls for a supported entrypoint or a documented repair and conformance
fixture before native evaluation; no runtime failure rate was measured here.
\citep{exec28_at_camcns}

\subsection{What permutation changes}
The inspected Liu text states that shuffling a candidate series while holding the other variables
fixed preserves the original data distribution. This requires qualification. A permutation
preserves that series' empirical marginal multiset, but generally changes its joint alignment
with other series and its temporal arrangement. The change can be the intended perturbation;
it cannot simultaneously be assumed to preserve every relevant observational law.
\citep{exec28_at_liu}

An exact author construction makes the distinction explicit. Let the four observations be
$x=z=(0,0,1,1)$, and keep $z$ fixed. Replacing $x$ with
$x^\pi=(1,1,0,0)$ leaves the marginal counts unchanged. With empirical covariance defined using
denominator four, however,
\[
 \widehat{\operatorname{Cov}}(x,z)=\tfrac14,
 \qquad \widehat{\operatorname{Cov}}(x^\pi,z)=-\tfrac14.
\]
The fitted predictor $f(x)=x$ has mean squared error zero before the permutation and one
after it. A different permutation, $(0,1,0,1)$, changes the proportion of adjacent equal values
from $2/3$ to zero. Thus even this small example separates preservation of the marginal,
the joint distribution and temporal structure.~\citep{exec28_at_reference}

The predictive-loss increase does not by itself identify an effect. Suppose the structural model
is $X=U$, $Z=U$, where $U$ is a fair binary common cause. The displayed observations are compatible
with that model. Intervening on $X$ leaves the equation for $Z$ unchanged, so
$E[Z\mid\operatorname{do}(X=1)]-E[Z\mid\operatorname{do}(X=0)]=0$, despite the loss increase of
the fixed predictor under the displayed permutation. This is a project witness against a
universal interpretation of permutation importance as intervention effect. It is not an
empirical reproduction of the paper, an estimate of its error rate, or a claim that a properly
specified permutation test can never be valid.~\citep{exec28_at_reference}

For repayment histories, the resampling design must answer a precise null question. An unrestricted
shuffle, a within-calendar shuffle, a block permutation and a conditional resampling scheme alter
different information. Restricting permutations can preserve some nuisance structure, but then
requires an exchangeability or conditional-law argument for the chosen null. Refitting after a
perturbation asks a different question from measuring reliance of a fixed predictor. Training,
candidate screening, threshold choice and held-out scoring also need separate information sets.
These are proposed design requirements; the exact witness establishes neither their calibration
under arbitrary banking dependence nor a universal repair for hidden common causes.

\subsection{Evaluation truth, empty denominators and temporal splits}
TACD addresses topological event sequences in telecommunications. Its selected source combines
attention with excitation, learned ordering and a regularized likelihood. This is a specialist
candidate for questions about event propagation, not an interchangeable estimator for IID tabular
reminder data. Any banking adaptation would first define devices or counterparties, event types,
network exposure and observation time. The resulting point-process or event target must remain
explicit through the adapter.~\citep{exec28_at_tacd}

Two selected evaluation branches are especially consequential. When \texttt{dag\_matrix} is supplied,
the training routine passes it to threshold optimization and computes graph F1 for checkpoint
selection. Such an experiment uses graph truth in model selection. It can be legitimate as a
declared oracle-assisted or training-graph study, but its score cannot be presented as blind
held-out discovery on that same truth. A public qualification should freeze thresholds and
selection rules on training graphs, then evaluate once on separate unseen graphs and independent
realizations under the intended deployment information. A prediction-loss selection branch is
also available in the selected source; it addresses a different objective and still requires
an explicit connection between prediction and graph quality.~\citep{exec28_at_tacd}

The evaluation routine omits NaN losses and divides the accumulated loss by
$\max(n_{\rm valid},1)$. If no batch has a valid loss, this returns zero. Zero is then a
sentinel produced by an empty effective denominator, not observed perfect prediction. The adapter
must preserve requested, valid and failed counts and return an unavailable score when the
predeclared valid-data rule fails. Likewise, the entrypoint randomly shuffles event pairs and
uses a default \texttt{split\_ratio} of one when that key is absent; at values at least one,
the training and validation pair lists are the same. This is a conditional source branch,
not a claim about every supplied dataset configuration. The following delegate study in
Section~\ref{sec:exec28-at2} establishes that four selected profiles explicitly take this
shared-pair branch. Event pairs may also share history, so a row split alone need not isolate
information. Those source findings resolve the selected configuration question; a native trial
still requires its actual configuration and event-construction rule before its split can be
described as temporal or independent.
\citep{exec28_at_tacd}

The appropriate public experiment therefore separates four denominators: candidate graphs
requested, graphs returned, graphs selected using available training information, and graphs
scored on untouched evaluation truth. Failed batches and unsupported graphs remain visible.
Evaluation on a known synthetic graph can verify mechanisms cheaply, while observational public
financial data can test data contracts and sensitivity without supplying nonexistent graph truth.
Neither exercise should be promoted to bank validation solely because the dataset is public.

\subsection{Reproduction scope and dependency identity}
The selected CausalTransformer repository illustrates a further boundary. Its README describes
figure regeneration from recorded benchmark results and explicitly says that model-training
benchmarks are not rerun. A reproduction command for those figures therefore does not by itself
reproduce learning, data generation, selection or reported performance. In the inspected revision,
the runner also conditionally requests two LaTeX source files that are absent from the complete
selected tree. That is a static packaging mismatch, not an observed execution result. The stated
journal target and current repository description cannot establish publication acceptance, and
an academic-review notice alone does not establish a broad reuse grant. The defensible proposal
disposition is to retain the artifact as a limited reproduction lead until the training source,
primary article and reuse terms are resolved.~\citep{exec28_at_ct}

Dependency identity is equally important for a method that delegates to R. The inspected CDT
installer is itself pinned, but installs unversioned operating-system and R packages, uses
several unauthenticated-package options, references HTTP CRAN endpoints, sources a mutable
Bioconductor script, and requests GitHub packages without commit pins. Freezing the wrapper's
bytes does not freeze those remote inputs. The installer was inspected as text and was not run;
the immediate remote script and package-installation bodies remain unresolved dependencies.
A proposed replacement should bind the operating system, interpreter, compiler, package archives,
digests and component terms, then qualify a selected isolated environment on public fixtures.
Verified HTTPS acquisition and an archive identity are necessary provenance steps, but do not
by themselves establish scientific correctness or transitive rights.~\citep{exec28_at_cdt}

\subsection{A conditional product decision}
The present evidence supports a differentiated reuse strategy. TCDF and CAMCNs can inform a
time-series candidate-generation comparison after their selected source and dependency contracts
are resolved. Their inspected GPL notices require component-level intake for the intended use;
this proposal does not declare a legal clearance. TACD is a specialist event-network candidate
whose truth-assisted selection and split routes need an explicit public protocol. CausalTransformer
currently contributes a figure-reproduction artifact rather than an established native learner
route. Porting any method would add an equivalence and maintenance obligation; an isolated adapter
may be preferable when it can retain upstream computation and expose the required semantics.
\citep{exec28_at_tcdf,exec28_at_camcns,exec28_at_tacd,exec28_at_ct}

Before enablement, a finite fixture set should check variable and timestamp identity, permitted
lags, target shifting and padding, missing and nonfinite values, candidate threshold ties,
empty score denominators, training/evaluation separation and failure propagation. A second layer
should compare generated confounded and unconfounded systems with independently specified truth,
including a fixed-predictor permutation witness. These are proposed public qualification steps,
not results of executing the acquired packages. The final report should retain predictive and
interventional targets separately, state which identification assumptions are substantive, and
refuse an effect claim when the required information is absent.
Attention discovery becomes a useful proposal component only when its predictive target, evaluation information and reuse conditions remain explicit.

\section[Delegate-level temporal and evaluation protocol]{Delegate-level temporal and evaluation protocol}
\label{sec:exec28-at2}
A precise temporal/evaluation contract keeps a predictive graph separate from banking intervention evidence.

\subsection{Temporal support is not a learned causal delay}
For a one-dimensional convolution with stride one and left padding $p=(K-1)d$, the source uses
cross-correlation, so output index $t$ can depend on input indices
$t-p+qd$, $q=0,\ldots,K-1$. The final point is $t$ and the first is $t-(K-1)d$.
The selected \texttt{Chomp1d} removes the rightmost $p$ padded outputs, preserving sequence
length and excluding future indices under this index convention. With layer dilations
$d_c^\ell$, the largest support lag across $L$ layers is
\[
  (K-1)\sum_{\ell=0}^{L-1}d_c^\ell.
\]
For $K=2$, $d_c=2$ and $L=3$, non-target channel support may include lags zero through seven.
The TCDF data path separately shifts only the target channel by one row, zero-fills the initial
shift, and predicts the unshifted target. Thus the target's raw-history support in this finite
index calculation is lags one through eight, while non-target variables may still contribute
at the contemporaneous index zero. A method called temporal or causal does not thereby exclude
same-row predictors; the variable clock and allowable information time must be explicit.
\citep{exec28_at_tcdf_temporal,exec28_at_protocol_reference}

The final temporal block also applies a learned linear map across channels at each time point.
The source extracts maxima from depthwise kernel weights and turns them into candidate delays.
That statistic does not describe every path through channel mixing and residual connections.
The support calculation bounds which indexed inputs could matter; it does not say which
parameters the trained model uses, establish a stable delay estimate, or identify an intervention.
The application should preserve an explicit representation for candidate lag support, learned
predictive attribution, and causal-effect timing rather than serializing each as one integer lag.
\citep{exec28_at_tcdf_temporal}

There are concrete boundary conditions for a native fixture. If $K=1$, then $p=0$ and the
selected source still applies the slice \texttt{:-0}; ordinary Python indexing yields an empty
sequence. A zero-layer Sequential stack is an identity on the input, so its support is lag zero; this is not the same as an empty output. The proposal does not
silently assign behavior to these parameter values. A version-pinned adapter must either reject
them with an informative contract error or establish valid supported semantics using a native
trial. The source-free reference records the empty-slice fact and proposed expectations without
importing the acquired model.~\citep{exec28_at_protocol_reference}

\subsection{A public protocol that preserves information boundaries}
A low-cost public experiment should have graph instances, rather than just rows, as part of its

a validation set used for thresholds and model selection, and a held-out evaluation set. If the

The selector must receive only its declared validation labels. After its threshold and checkpoint

not a numerical loss of zero. Tied scores require an explicit comparison convention and deterministic

valid count can also make the mean unavailable even when a finite score exists.

\section{When score helpers change the proposed banking comparison}
\label{sec:exec28-blip-helpers}

A score comparison is only meaningful when its rows and failure states have the same meaning.
For a bank comparing candidate structures for arrears, utilization and servicing contact,
the input adapter determines which borrowers enter the score and whether an unobserved
field is dropped, retained or silently interpreted. The preceding BLIP discussion left
the data and test helpers uninspected. Nine further originals at the same reliableAI
commit now resolve selected paths without running Java or treating a source review as
empirical qualification. The findings concern the named derivative and routes, not every
BLIP release or all of its searchers.~\citep{exec28_blip_helpers}

\paragraph{A test call is not a checked assertion.}
The selected BDeu test computes a score and calls
\texttt{RandomStuff.doubleEquals(-3627.0266, sk)}. The newly inspected helper returns a
boolean. Its default comparison is the strict absolute inequality
\( |s-v|<2^{-5}=1/32 \); it neither throws on inequality nor invokes a testing assertion.
The caller discards this return value. The inherited test base has a separate
\texttt{assertDoubleEquals} method that passes the boolean to \texttt{assertTrue}, but
the selected test does not call it. Consequently a score discrepancy alone does not
fail this particular comparison. File-read, score-computation or other exceptions can
still fail the test; no claim is made that the test cannot fail under any circumstance.
The proposed port must assert the result and state a justified absolute/relative error
policy, including nonfinite values. A test-suite name or a reported execution count
cannot establish numerical agreement.~\citep{exec28_blip_helpers}

\paragraph{The data extension changes the observation rule.}
The common loader uses \texttt{readMissing=false} unless a caller supplies another
value. The \texttt{.dat} reader skips a row containing a question mark under this
default and advances the input. With missingness enabled it retains the row count and
records missing indices separately from each variable's ordinary category indices.
The \texttt{.data} reader has a different branch: its question-mark skip is guarded
by \texttt{readMissing=true}. That branch continues without updating
\texttt{nextLine}. Its blank-line branch has the same nonadvancing structure. On the
shown state transition, the next iteration reads the same in-memory line again.
This identifies a concrete progress defect for those inputs, not an observed native
runtime or a claim that all files fail. With the default false flag, the DATA route
instead retains question-mark rows in its separate missing-index representation.
An adapter that changes only a filename extension can therefore change both row
selection and termination behavior.~\citep{exec28_blip_helpers}

For a servicing study this distinction is substantive. Dropping every borrower with
any missing recorded field changes the analyzed population; retaining a row with a
missing outcome does not by itself specify a valid observed-data likelihood. A
proposal must declare the missingness law and target population, record exclusion
counts, and distinguish source refusal from successful scoring. It must not call
either input branch an automatic treatment of informative missingness. A practical
first public fixture uses identical records in the two declared encodings, varies
the flag explicitly, and checks accepted rows, missing indices, progress and all
failure outcomes before comparing scores.~\citep{exec28_blip_helpers}

\paragraph{An exact denominator witness.}
Let \(\alpha>0\) denote the BDeu equivalent sample size, let a binary child have
observed state counts \(n_0,n_1\), and write
\((a)_m=\prod_{j=0}^{m-1}(a+j)\), with \((a)_0=1\). For a parent-free complete
case with \(N=n_0+n_1\), the marginal factor underlying the log score is
\[
 M(\alpha;n_0,n_1,N)
 =\frac{(\alpha/2)_{n_0}(\alpha/2)_{n_1}}{(\alpha)_N}.
\]
The inspected root-score implementation uses the dataset's total row count in
the denominator and the lengths of category-index arrays in the numerator.
If a retained row has a missing child, those two counts need not agree. For the
stipulated rows with child values \(0,1,?\) and \(\alpha=2\), complete-case
counts give \(M=1/6\), while retaining three total rows but only the two observed
category indices gives \(M=1/24\). The factor ratio is \(1/4\), so the log scores
differ by \(-\log 4\). These rational values are independently reproduced here.
They expose the consequence of the specified count mismatch; they are not a claim
that an observed-data likelihood must always delete rows or that the empirical
bias has a particular sign.~\citep{exec28_blip_helpers,exec28_blip_helper_reference}

For parented scores, the parent-configuration helper intersects ordinary category
indices. A missing parent can therefore remove a row from that configuration,
whereas a missing child can still leave the row in its parent count. The admission
contract should require a declared common row set or an explicitly derived
missing-data score. Compare each accepted configuration against an independent
count table. Otherwise a graph comparison may reward changes in its effective
sample as well as changes in the proposed conditional model. This source finding
does not identify the causal effect of a servicing intervention or remove hidden
confounding.~\citep{exec28_blip_helpers}

\paragraph{Ordered identities and bounded representations.}
Both selected intersection helpers traverse two arrays by advancing the smaller
current row index. Their set interpretation requires ordered indices. For example,
the sets represented by \([2,0]\) and \([0,2]\) are equal, but the inspected
two-pointer logic counts one match; sorted arrays give two. The file readers append
row indices in increasing order on their ordinary paths, so this is an adapter
precondition and a negative fixture, not evidence that their normal output is
unsorted. The proposed typed boundary validates strict ordering, uniqueness and
range before accepting externally constructed datasets.~\citep{exec28_blip_helpers,exec28_blip_helper_reference}

Parent cardinalities are multiplied in signed Java integers before allocating
configuration arrays and scaling the prior. The exact product \(65536^2=2^{32}\)
wraps to zero in that representation; \(46341^2\) exceeds the positive signed
range. These are representation witnesses, not estimates of typical banking table
sizes. Check multiplication before allocation and division, bound memory as well
as counts, and account for the helper's additional \texttt{short} state index.
The single-parent overload also returns the dataset's own indices instead of the
explicit alternative \texttt{rows} argument. Callers supplying a transformed row
view need a conformance check across one-parent and multi-parent routes.
The dataset copy constructor copies metadata references but leaves category and
missing-index fields unset; it is not a deep snapshot of the observations.
These contracts matter for reproducible resampling and recovery.~\citep{exec28_blip_helpers,exec28_blip_helper_reference}

\paragraph{Numerical and reuse decisions.}
The inspected log-gamma helper declares an adaptation from FDLIBM and retains a
separate Sun notice, in addition to the author's disclaimer. Preserve those
component notices when evaluating a port; the nested root declaration is not a
complete dependency inventory. Its bit-level special-value branch returns positive
infinity for NaN and either infinity, and NaN for zero or finite negative input.
The score boundary must validate positive finite prior and cardinality arguments
and reject nonfinite results explicitly. This inspection does not supply an error
bound for the approximation or establish binary equality with an installed engine.
The loader also catches exceptions and returns null, requiring a structured failure
translation rather than a successful empty dataset.~\citep{exec28_blip_helpers}

Retain BLIP as a conditional discrete score-search comparator. Reject direct
adoption of the selected DATA reader and nonasserting score test until repaired;
prefer an isolated, declared DAT route or a validated typed input adapter for the
first public comparison. A thin integration preserves the upstream search while
making row identity, finite-domain checks, progress, timeouts and failure accounting
explicit. A port needs the additional numerical and notice review. The next native
experiment should compare an independent table oracle across complete and missing
rows, category permutations, empty configurations, overflow refusal and interrupted
reads, with every requested case retained in the denominator. ARFF/generic readers,
remaining searchers, derivative origins, dependency rights and artifact equality
remain separate gaps. No acquired Java code was executed in this review.
\citep{exec28_blip_helpers,exec28_blip_helper_reference}

order does not establish an intervention, a fitted graph does not settle
its unresolved endpoints, and a valid score calculation does not supply a

can be preserved or lost. A useful implementation should return the
prediction, graph class, identified effect or refusal that the declared
information supports, together with the uncertainty appropriate to that
object. The next chapter develops the identification and counterfactual
