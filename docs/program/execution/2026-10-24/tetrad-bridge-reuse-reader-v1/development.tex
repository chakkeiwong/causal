\section{Tetrad across language boundaries: preserving the scientific object}
\label{sec:exec24-tetrad-bridge-reuse}

A bank may want an analyst in Python, a model reviewer in R and an approved
Java discovery engine to discuss the same borrower graph. Calling the same
algorithm name does not ensure that they have supplied the same variables,
categories, missingness policy, background knowledge or statistical test.
Nor does a returned graph identify an intervention merely because a bridge
makes it convenient to query. A useful proposal therefore treats the language
boundary as part of the scientific specification. The inherited restricted
Java PC/Fisher-Z candidate remains distinct from the Python and R surfaces
considered here.\citep{exec13_tetrad_reuse_decision,exec24_pytetrad_source}

\paragraph{The original design and the pinned implementation.}
Ramsey and Andrews describe a Python interface through JPype, an R interface
through Reticulate and Python, data conversion, endpoint graphs and examples
of background knowledge and resampling. Their 2023 primary paper explains why
access to the underlying Java classes is valuable, while its examples require
deliberate column typing. It is evidence for that architecture, not proof of
compatibility of every later distribution. The Python example declares ten
repetitions whereas the displayed edge-frequency table describes one hundred;
the paper alone does not establish a common request denominator for those
artifacts. We use neither the displayed frequencies as bank graph truth nor
this textual discrepancy as a measured software defect.\citep{exec24_pytetrad_paper}

The selected bridge revision is the 7 October 2026 commit recorded in the
source audit. Its setup declares version 0.1.2 and Python at least 3.7, whereas
its README asks for Python at least 3.12 and JDK 21 or later. Its packaged JAR
is described as a released version or a version with adjustments. The tree
records a 56,587,560-byte JAR, but the binary has not been acquired or executed
here. Consequently the Java revision previously inspected, the bridge commit,
the package version and the bundled binary are four identities to reconcile.
The bridge's permissive root license does not settle the inherited Java
distribution or embedded third-party terms. The selected R file separately
points to MIT (SEI)-style terms and third-party software; the referenced
\texttt{license.txt} is absent from the selected complete repository tree.
That is a bounded documentary gap, not a legal conclusion.
\citep{exec24_pytetrad_source,exec13_tetrad_reuse_primary}

\paragraph{Types and categories are substantive inputs.}
The selected Python converter treats floating columns as continuous and other
column types as discrete by default. Its optional integer-as-continuous switch
is not passed by the ordinary search constructor. An integer-valued account
balance can therefore enter a different statistical family from the same
values represented as floating point. A worker must require the scientific
type explicitly; storage dtype is an inadequate substitute for units and
measurement meaning.\citep{exec24_pytetrad_source}

For discrete variables, the converter assigns category numbers in first-seen
order. Consider two branch datasets containing the same categories but starting
respectively with approve then decline, and decline then approve. Independently
generated codes assign approve zero in the first and one in the second. This
does not show that Java necessarily pools them incorrectly: the eventual
delegate could reconcile labels. It shows why a wrapper cannot presume identical
codes merely from identical column names. The conversion also stringifies labels
and column names. The distinct Python objects integer one and string 1
both become the same string; a verified bijection must reject or reversibly
escape this collision before constructing Java variables.
\citep{exec24_pytetrad_source,exec24_pytetrad_choice}

Missingness needs a separate representation. Continuous output is reconstructed
as floating columns and discrete missing output as Python \texttt{None}. On
the forward path, the selected converter enumerates unique discrete values
without an explicit missing-sentinel branch, converts mapped codes to integer
and stringifies category names. This can turn a missing token into a named
category or encounter a mapping/cast failure, depending on the input and
installed pandas behavior. The audit does not claim one universal runtime
outcome. Preserve a typed category dictionary, a missing mask, ordered row and
column identifiers and the requested imputation or deletion policy. A successful
round trip must preserve each of these, including all-missing and mixed columns.
\citep{exec24_pytetrad_source}

The R directory contains more than one interface concept. Its README and the
2023 paper discuss the Reticulate route, while the selected temporary
\texttt{TetradSearch.R} class calls rJava directly. Its converter tests
\texttt{is.numeric} before \texttt{is.integer}, despite a comment recommending
integer columns for discrete data. An independent base-R witness verifies that
an ordinary integer vector satisfies both predicates and therefore takes the
first, continuous branch. This witness executes no Tetrad or rJava code.
Factor codes and Java helper behavior still need their own inspection; the
branch observation is not a finding about every R interface. The accompanying
utility refers to Tetrad 7.6.5 and a moving JDK download, which must not be
silently equated with the Python JAR.\citep{exec24_pytetrad_source,exec24_pytetrad_choice}

\paragraph{Endpoint matrices are not binary adjacencies.}
Let the ordered variables be $A,Y$, and suppose a graph contains $A\to Y$.
The selected endpoint converter places the endpoint at node $i$ in entry
$M_{ji}$, using three for a tail and two for an arrowhead. Hence
\[
 M=\begin{pmatrix}0&2\\3&0\end{pmatrix}.
\]
Both off-diagonal entries are nonzero because each describes one end of the
same edge. Treating them as independent binary arcs requests both directions.
The selected binary-adjacency converter's comment says entry $B_{ij}=1$
means $j\to i$, while its loop supplies nodes $i,j$ in that order to
\texttt{addDirectedEdge}. For
\[
 B=\begin{pmatrix}0&0\\1&0\end{pmatrix},
\]
the documented convention requests $A\to Y$ and the source loop requests
$Y\to A$. These are static argument-flow findings; no claim is made that a
particular Java graph accepts two opposing arcs. The converter also generates
new names rather than retaining caller labels.\citep{exec24_pytetrad_source,exec24_pytetrad_choice}

An adapter should expose distinct, validated types for binary adjacency,
endpoint graph, CPDAG, PAG and a deliberately selected DAG. Preserve both
endpoint symbols, row and column names, ordering and graph class. The selected
causal-learn converters map named enum members rather than relying solely on
the numeric comments; their target library must nevertheless be versioned.
A CPDAG-to-DAG convenience call selects an extension. It does not resolve
observational equivalence or authorize a point causal effect.
\citep{exec24_pytetrad_source}

The monetary importance can be demonstrated without fitting software. In one
authored Gaussian model, $A=U_A$ and $Y=\tfrac12 A+U_Y$, with independent
zero-mean noises of variances one and three quarters. In a second, $Y=V_Y$
and $A=\tfrac12 Y+V_A$, with independent noises having the same respective
variances. Both give the observed covariance
\[
 \Sigma_{A,Y}=\begin{pmatrix}1&1/2\\1/2&1\end{pmatrix}.
\]
The causal derivative of the mean of $Y$ with respect to an intervention on
$A$ is one half in the first model and zero in the second. An analyst cannot
choose between them from this observed distribution alone. If an action
increases $A$ by one unit for 200 accounts, each unit of $Y$ is stipulated to
be worth 100 USD, and implementation costs 4,000 USD, the net values are
6,000 USD and minus 4,000 USD respectively. These are exact illustrative
calculations, not an empirical return estimate. A reversed edge or arbitrary
DAG extension can therefore change an investment recommendation while leaving
observational fit unchanged.\citep{exec24_pytetrad_choice}

\paragraph{Failure, knowledge and process identity.}
The selected search object retains mutable parameters, graph results,
background knowledge and pooled datasets. The PC and FCI methods assign
\texttt{self.java} only after a search returns. A later failed search can
therefore leave the prior graph accessible through an ordinary getter;
\texttt{set\_data} itself does not invalidate that graph. This follows from
the assignment order and is illustrated by an independent state witness,
not an induced failure in downloaded software. New data also do not by
themselves empty the separately stored pooled datasets. A proposed worker
must bind every successful result to its own immutable request, input hashes,
parameter snapshot, knowledge and execution generation. It must never publish
a previous graph as the result of a failed new request.
\citep{exec24_pytetrad_source,exec24_pytetrad_choice}

Several smaller source observations reinforce the need for interface fixtures.
The mixed-variable polynomial setter calls the discretization parameter setter
without passing the requested value. Several explicit-graph getter branches
invoke converters without returning their result; the explicit graph-to-matrix
branch also drops custom endpoint codes. A bootstrap index check permits an
index equal to the number of stored graphs before indexing. These are selected
source-level mismatches, not a claim that every wrapper method fails. Test
default and explicit arguments separately, compare echoed effective parameters,
and make missing, stale, nonfinite, cancelled and unsupported results distinct.
The R knowledge-tier helper catches and prints errors; a worker needs a
machine-readable failure and a check of the effective constraints.
\citep{exec24_pytetrad_source}

JVM startup introduces a further shared-state boundary. The translation and
missing-data modules start a JVM at import when needed, and otherwise reuse
the already running process without a local equality check of the loaded JAR.
The G-regression module has its own startup path with different flags. A caught
startup exception followed by imports is not a structured job receipt. Use an
isolated worker whose Java version, binary hash, classpath and flags are fixed
before importing the bridge; fail closed if they cannot be attested. The setup
declares NumPy, pandas and JPype but the main search module also imports
NetworkX. Inspecting that fact and the G-regression delegate does not complete
the native dependency closure.\citep{exec24_pytetrad_source}

The missing-data helper delegates auditing, imputation and pooling by edge
frequency to Java. Checking for a class name does not establish the delegate's
scientific assumptions, calibration or identity. Likewise the G-regression
wrapper passes a supplied graph into an effect and bootstrap delegate; its
source comments about identification and prior parity tests are not new
verified results in this proposal. Preserve graph selection, missingness,
resampling units and all failures as separate uncertainty dimensions. A pooled
edge frequency is not automatically a posterior probability of a bank cause,
and fixed-graph effect uncertainty need not cover graph selection.
\citep{exec24_pytetrad_source}

\paragraph{A bounded reuse choice and qualification route.}
Retain the bridge and original paper as references. Consider an isolated
Python/Java integration only after its actual artifact, grants, dependency
closure and semantic fixtures are reconciled with a selected scientific
profile. Whole-package adoption is deferred; a port of the discovery engine
has no demonstrated advantage over maintaining a small explicit boundary.
Porting selected converters is a separate option requiring rights review and
independent graph/type tests. Reject loss of endpoint information, implicit
category meaning, stale-result publication and unsupported conversion of an
equivalence class into an identified effect; these rejected behaviors do not
justify discarding every Tetrad candidate.\citep{exec24_pytetrad_choice}

The scientific owner specifies target, observation law, measurement, temporal
knowledge and graph-class assumptions. The adapter owner maintains bijections,
missingness, request generations, result/refusal states and cancellation. The
platform and rights owner locks actual binaries and notices; the evaluation
owner predeclares public known-law and negative cases with complete task
denominators. Include setup, conversion, successful and failed computation,
review, correction and maintenance in costs. For an authored 6,000 USD trial
with 300 submitted, 240 completed and 200 qualified requests, the costs are
20, 25 and 30 USD per respective denominator. Completion must not replace
qualification in the investment case.\citep{exec24_pytetrad_choice}

The next evidence is concrete: authentic binary/source reconciliation;
category, missingness and endpoint round trips; explicit-argument and
failed-second-request fixtures; knowledge and pooling checks; and restricted
native comparisons using public or generated data. Full G-regression and
imputation delegates, separate R terms, support and actual costs remain open.
No public trial can recover an unknown bank assignment mechanism merely by
running this bridge. The reference decision grants no native capability;
independent, visual and final acceptance remain open.
