## Mission and reader contract

Make a credible investment and construction case for a common causal-analysis
library with useful standalone applications for a large universal bank.
The bank needs to learn what its actions change across repeated decisions,
products, entities and calendar regimes. A forecasting improvement alone does
not answer this question. The proposal must connect financial decisions to
identification, estimation, data organization, operating software and an
achievable delivery sequence.

Readers are quantitative economists, causal-inference researchers, bank product
owners, data engineers, model validators and investment sponsors. The common
story starts with a deposit-retention intervention and develops its repeated
decision counterpart. It extends to credit limits, collections, mortgages,
SME lending, branches, merchant partnerships and treasury transmission.
The sponsor can stop after the short proposal; researchers and engineers can
continue through the derivations and specifications without changing the claim.

Main proposition: a bank can reuse causal analysis safely and economically when
data timing, intervention definitions, identification assumptions and evidence
travel with each analysis. Supporting claims: (1) existing open-source methods
cover much of estimation but have materially different assumptions and
interfaces; (2) panel, sequential and discovery methods need a common temporal
data foundation and distinct identification routes; (3) three bounded initial workspaces can test shared construction while
POMDP estimation, temporal discovery and time-series analysis develop with
explicitly different scientific qualification states. The principal rival is an expert team composing
existing libraries around the bank's warehouse. The product must beat that
rival in useful throughput, reproducibility and decision quality, with measured
costs. Integration is not asserted to be a new identification theorem.

## Per-phase procedure and recovery

Before each phase, inspect its actual inputs and run a small dry run: query
one source, check one artifact, reconstruct one equation or compile one unit.
Record what that exposes. Refine paths, budgets and checks before scaling.
After the phase, compare intended and actual evidence, update affected plans
and record why unaffected requirements still stand. Preserve failed downloads,
failed checks and changed assumptions. Start the next eligible task in the
same session. A phase completion is not a reason to request permission.

On source failure try an authorized canonical author/preprint/local copy, then
classify the source as blocked and use an available primary alternative if
scientifically appropriate. Never relax an identification assumption to make a
method fit a use case. On numerical failure inspect the smallest exact case,
fix the implementation or revise the asserted result, preserve the failure,
and rerun the affected checks. On interruption consult state, outputs and
receipts; do not re-download identical artifacts. Reopening an accepted
upstream object reopens affected downstream claims and checks.

## Review contract and completion meaning

(2) source fidelity and omissions, (3) identification/mathematics,
