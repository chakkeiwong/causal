## Java missingness and population-transfer choices

Java integration requires a distinction between a completed input table, a justified causal estimate and an effect transferred to a new borrower population. The selected Tetrad, Smile and archived Weka sources offer complementary components, supported here by 36 authentic originals at retained commits. Tetrad offers missingness policies, conditional Gaussian and chained donor completions, graph ensembles and scalar pooling. Smile supplies numerical completion alternatives; Weka provides historical weighted and EM-filter comparators. None of these roles alone establishes the bank's population-transfer assumptions. The investment decision should fund a bounded public qualification stage. Exact authored examples show why this stage is necessary: per-pair majority of three acyclic graph members can create a cycle; pairwise covariance can fail to be positive semidefinite; fixed-parameter completion omits parameter uncertainty; diagonal fallback can change contrast variance. Weighted completion and conditional-mean completion also have different contracts. These examples are analytic requirements, not measurements of package failure rates. Conditionally reuse Tetrad audits and selected numerical contracts, qualify graph and uncertainty boundaries, and consider Smile as a numerical baseline. Defer current Weka adoption until the official edition is acquired.
