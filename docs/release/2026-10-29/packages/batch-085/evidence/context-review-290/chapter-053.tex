\chapter{Synthetic controls and the choice of a comparison}
When one region or institution changes policy, a weighted combination
of unaffected units may offer a comparison. Its usefulness depends on donor
information, pre-intervention fit and the assumptions linking that fit to the
untreated future. The methods differ in how they extrapolate and how they
represent uncertainty; those differences matter for the bank's decision.



% SOURCE docs/release/2026-10-29/source/docs/writing-repair/2026-10-29/src/22dcf08e8b74c135.tex CHAR 0
The chapter compares three ways to obtain the missing trajectory: constrained
donor matching, augmentation beyond the donor hull, and model-based
reconstruction. It first distinguishes the commercial host from the estimator
it runs and examines how panel wrappers define the target. Detailed R method
studies then precede the wider R, Python and cross-language comparisons.
The question throughout is whether the same donor information, intervention
clock and uncertainty reach the bank's decision after fitting and conversion.

\section{A commercial host does not settle synthetic-control semantics or rights}
\label{exec19:synth-scope}

A bank comparing a treated regional portfolio with other regions needs a
credible untreated path, not merely an optimizer that returns donor weights.
A commercial statistical host may run a community estimator, a vendor-native
command or a general optimization routine. These are different implementation,
support and rights arrangements. The proposed common service should compare
those arrangements explicitly while preserving donor eligibility, timing,
missingness, pre-fit and the uncertainty protocol.

The selected Synth-for-Stata repository is an author-maintained community
implementation inside the commercial Stata host. Its inspected command identifies
version 0.0.8 and declares Stata version 13.0. The selected commit,
\texttt{ae99fd1ed100e8f5ea38386f18f02e61a90956e6}, is dated 30 April 2026.
Twelve authenticated texts cover its command, help, loss helper, package
manifest, optimizer interface, component notices and selected test artifacts.
No Stata executable, plugin binary or compiled Mata library was run here.
A host compatibility declaration is not a verified installed edition,
entitlement or vendor-supported causal capability.~\citep{exec19_synth_stata_source}

\subsection{Freeze the donor universe and information used to select weights}
\label{exec19:synth-donors}

The selected help describes a convex weighted donor combination. Donors default
to all panel units other than the treated unit; an explicit donor list must
contain at least two units. That syntactic rule cannot establish that another
region is unaffected by the intervention, has comparable measurement or supplies
a credible untreated trajectory. Predictor averages ignore missing entries,
while a wholly missing predictor is rejected. Consequently, two units can
contribute averages over different observed dates. Predictor-specific windows
can also override the common predictor period.~\citep{exec19_synth_stata_source}

Consider an authored regional-portfolio example, with outcomes measured in
thousands of USD. Two donors and the treated region have trajectories
\begin{equation}
 D_1=(90,110,120),\quad D_2=(110,130,140),\quad T=(100,120,150).
 \label{exec19:synth-paths}
\end{equation}
The first two dates precede intervention. Equal donor weights reproduce both
preperiod treated values exactly and predict 130 at the third date. Stipulate
that this donor average is the treated region's true untreated path. The
corresponding treatment effect is then 20, or USD 20,000. This truth is an
assumption of the example, not something established by pre-fit alone.
\citep{exec19_synth_contract_reference}

Now suppose the second donor also receives a spillover of 20 at the final date.
Its observed final value becomes 160. The same weights predict 140 and the
apparent treated gap falls to 10. Alternatively, selecting weights using the
treated postintervention outcome can choose $1/4$ for the first donor and $3/4$
for the contaminated second donor. The selected synthetic path is then
\begin{equation}
 \widetilde T=(105,125,150),\qquad T_3-\widetilde T_3=0.
 \label{exec19:synth-leakage}
\end{equation}
The intervention has not disappeared from the stipulated world; contamination
and postoutcome selection have changed the comparison. A lower postperiod gap
cannot certify a better causal counterfactual.~\citep{exec19_synth_contract_reference}

The source makes this timing check operationally relevant. Default predictor
and MSPE periods precede treatment. For an explicitly supplied MSPE period,
however, the inspected command checks that the requested dates occur in the
panel, without imposing a separate before-treatment inequality in that branch.
The help allows later predictor dates only under a substantive unaffectedness
condition. The proposed adapter must therefore declare and check the scientific
window; passing a command's membership validation is a narrower result.
\citep{exec19_synth_stata_source}

\subsection{Keep optimizer settings and failure states attached to the result}
\label{exec19:synth-numerics}

The selected help and code disagree on two defaults. The help gives constraint
margin 0.05 and precision parameter 7, whereas the command syntax uses 0.005 and
12. A reproducible comparison must record explicit supplied values and the
actual source or binary rather than rely on an unqualified default. The source
also computes RMSPE before calling a compiled Mata rounding routine on the
weight vector. The routine's body has not been inspected, so its precise
rounding rule and the resulting relation between displayed weights and the
reported pre-fit score remain open.~\citep{exec19_synth_stata_source}

More directly, the inspected C wrapper assigns the return status from
\texttt{pr\_loqo}, stores the primal vector and returns zero without branching
on that optimizer status. The associated header distinguishes optimal,
suboptimal, iteration-limit and infeasible outcomes. A successful wrapper return
therefore cannot, on this source evidence alone, be interpreted as an optimal
feasible synthetic control. Future native conformance should inspect the actual
binary, status propagation, constraint residuals and support of the returned
weights before reporting scientific results. These are static observations,
not measured failure frequencies or proof that every invocation fails.
\citep{exec19_synth_stata_source}

Source criticism also requires avoiding false defects. The nested loss helper
returns negative squared error to a maximizer. Selecting the larger log
objective among alternative starts is consistent with minimizing the underlying
squared error. A nearby comment about the \emph{lowest loss} does not justify
reversing the comparison signs. The relevant object is the implemented objective
and its sign, not the variable name alone.~\citep{exec19_synth_stata_source}

\subsection{A placebo count needs its own sampling and selection argument}
\label{exec19:synth-inference}

The selected help says the estimator can support placebo and permutation
analyses, but that does not supply a universally calibrated test for a bank's
regional intervention. The protocol must identify which units could have been
treated under the null, how pre-fit filters and donor eligibility were chosen,
whether the treated region enters the reference set, the tail direction and
which tuning steps are repeated for every placebo. Donor and time dependence
also remain substantive assumptions.

A purely arithmetic illustration makes the denominator visible. One equally or
more extreme statistic among five eligible statistics, including the treated
unit, yields $1/5$. Retaining only two statistics yields $1/2$. Neither fraction
is automatically a valid $p$-value: the assignment or exchangeability argument
and the rule selecting retained cases still need justification. The finite count
is an authored reference, not a theorem attributed to an uninspected original
or an inference result from the vendor engine.~\citep{exec19_synth_contract_reference}

The proposed common output should keep donor weights, balance, outcome paths,
pre-fit diagnostics, optimizer status and any separately justified inference
object distinct. A trajectory difference must not become a confidence interval
or policy value merely because downstream software expects a scalar.

\subsection{Preserve unresolved component notices and comparison breadth}
\label{exec19:synth-rights}

The pinned README states GPL version 2 or later, while the bundled optimizer
source and header retain proprietary notices, including a restriction on
unauthorized commercial use. This discrepancy is an unresolved rights record.
It is not a finding of lawful distribution, an accusation of infringement or
permission to embed the component. Authoritative clarification for the exact
distribution is required before an adoption decision. The commercial host,
community code, compiled plugin, Mata library and any hosted service must each
retain their own scope.~\citep{exec19_synth_stata_source}

The broader comparison remains inconclusive. Stata, EViews, SAS, IBM,
MathWorks and commercial hosted open-source frontends remain separate candidate
families; only the selected community implementation has matching technical
originals in this tranche. Generic regression, optimization, synthetic-data or
control-arm descriptions cannot establish a donor-weighted comparative panel
estimator. Uninspected sources and failed acquisition routes likewise cannot
establish product absence. Prices, entitlements, full native alternatives and
applicable automation or redistribution rights remain unresolved.

For the prototype proposal, retain the community estimator as a documentary
comparator and defer executable admission until the rights conflict, binary
correspondence and numerical contract are resolved. Compare transparent exact
examples and separately reviewed open-source estimators under the same donor,
clock and inference specification. Public evidence can establish that design
before a paid vendor trial; it cannot substitute for institutional assignment
truth or realized banking value.

\section{Generalized synthetic control: preserve the panel target across a wrapper}
\label{exec21:gsynth-scope}

A branch manager evaluates a staggered rollout of a servicing policy. Some
branches adopt early, some late, and some remain untreated. A useful analysis
must say whether its answer concerns a typical branch, a typical treated
branch-month, or a portfolio weighted by an explicitly chosen exposure.
These targets differ before any model is fitted. A package wrapper can change
the answer by losing a weight or substituting an estimator even when the
underlying numerical engine is otherwise appropriate.

The selected pre-cutoff \texttt{gsynth}~1.4.0 source is a compatibility
wrapper around \texttt{fect}. Its maintainers describe the wrapper as retained
solely for backward compatibility. The reviewed dependency candidate is
\texttt{fect}~2.4.5, declared on 29~May~2026 and published through the selected
CRAN revision on 30~May. Matching pinned upstream and CRAN wrapper, manual,
license and change-log files agree byte for byte. This establishes a concrete
source comparison; it does not establish an installed combination. The
wrapper's declared lower bound, \texttt{fect >= 2.0.0}, permits multiple engine
versions with potentially different behavior. \citep{exec21_gsynth_wrapper,exec21_gsynth_engine}

\subsection{Weights and exposure duration define the business quantity}
\label{exec21:gsynth-target}

Let $i$ index branches and $t$ calendar periods. Let $D_{it}$ indicate an
active intervention, $\mathcal S$ denote the retained treated cells, and
$\delta_{it}=Y_{it}(1)-Y_{it}(0)$ the corresponding effect in stated monetary
units. With positive prespecified weights $w_{it}$, two possible targets are
\begin{equation}
\label{exec21:gsynth-weights}
 \tau_{\rm cell}=\frac{1}{|\mathcal S|}\sum_{(i,t)\in\mathcal S}\delta_{it},
 \qquad
 \tau_w=\frac{\sum_{(i,t)\in\mathcal S}w_{it}\delta_{it}}
                  {\sum_{(i,t)\in\mathcal S}w_{it}}.
\end{equation}
If $\mathcal I$ is the retained treated-unit set and $T_i^+$ its observed
treated periods, a third target gives each unit equal weight:
\begin{equation}
\label{exec21:gsynth-units}
 \tau_{\rm unit}=\frac{1}{|\mathcal I|}\sum_{i\in\mathcal I}
       \frac{1}{T_i^+}\sum_{t:(i,t)\in\mathcal S}\delta_{it}.
\end{equation}
Identification of the missing $Y_{it}(0)$ is a separate question from these
definitions. A sample's retained cells need not represent the original
portfolio when observation or unit-removal rules depend on risk or outcome.

The selected \texttt{gsynth} manual promises that \texttt{weight} specifies
the weighting variable for the weighted average effect. The complete
95-line wrapper declares that argument but never reads it again and never
passes it to \texttt{fect}. Its documented weighted interface therefore has
a concrete source-level defect. A successful call or the stored call string
would not demonstrate that the requested weights reached estimation.
This is a source finding; the current review has not executed the native
wrapper. \citep{exec21_gsynth_wrapper}

For an exact illustration, two equally represented treated cells have effects
$-6$ and $10$ dollars. Their unweighted mean is $2$, whereas weights $9$ and
$1$ give $(-54+10)/10=-22/5=-4.4$. If the decision assumes a cost of USD~1
on the corresponding average-exposure basis, the two calculated margins are
USD~1 and USD~$-5.4$. A weighting omission can reverse the indicated decision;
these are authored arithmetic examples, not measured branch results or
observed outputs of either package. \citep{exec21_gsynth_reference}

Exposure duration creates another distinction. Suppose one unit experiences
effect $10$ in each of three treated periods, while another experiences
effect $-6$ in one treated period. Equation~\eqref{exec21:gsynth-weights}
gives $\tau_{\rm cell}=6$ and equation~\eqref{exec21:gsynth-units} gives
$\tau_{\rm unit}=2$. At an assumed per-period cost of $4$, averaging the
net effects using the same respective measures gives margins $2$ and $-2$.
A longer observed treatment history should not silently make one branch
three times as influential in an analysis intended to describe a typical
branch. \citep{exec21_gsynth_reference}

The selected engine exposes both treated-cell and unit-average calculations.
It also distinguishes weights for outcome-model fitting from weights for
aggregation. Supplying \texttt{W} fills both roles; supplying only
\texttt{W.agg} is intended to change aggregation, while \texttt{W.est}
alone leaves canonical aggregation unweighted. The inspected source rejects
distinct columns for the two roles, despite an error message referring to
earlier versions and a future release. Its executed conditional, rather than
that stale version message, determines the limitation. Zero-weight rows are
dropped, and weighted aggregates are routed into the ordinary output slots.
A proposed adapter must therefore record both the requested role and the
actual retained population; blindly multiplying supplied weights is not a
general substitute for missing role support. \citep{exec21_gsynth_engine}

\subsection{A factor model needs information in the relevant directions}
\label{exec21:gsynth-rank}

A useful working model for an untreated outcome is
\begin{equation}
\label{exec21:gsynth-factor}
 Y_{it}(0)=\alpha_i+\xi_t+x_{it}^{\mathsf T}\beta
                     +\lambda_i^{\mathsf T}f_t+\varepsilon_{it},
\end{equation}
where $x_{it}$ contains covariates with a justified intervention-time meaning,
$f_t$ represents common latent factors and $\lambda_i$ is the unit's loading.
Even if donor observations reveal $f_t$ exactly, a treated unit's pre-period
outcomes must determine the component of $\lambda_i$ that matters after
treatment. Covariates caused by the intervention, anticipation, spillovers
to donors, or changing loadings require additional arguments. A low prediction
error on past observations cannot establish those substantive conditions.

For a precise obstruction, suppress the intercepts, observed covariates and
errors. Let the factors in two pre-periods and one post-period be
\begin{equation}
\label{exec21:gsynth-witness}
 f_1=(1,0)^{\mathsf T},\quad f_2=(2,0)^{\mathsf T},\quad
 f_3=(1,1)^{\mathsf T}.
\end{equation}
Donor loadings $(0,1)$ and $(1,1)$ generate observed paths $(0,0,1)$ and
$(1,2,2)$. A treated loading of either $(2,0)$ or $(2,4)$ gives the same
pre-treatment path $(2,4)$. Hold its observed post-treatment outcome at $8$.
The two compatible untreated post outcomes are $2$ and $6$, giving effects
$6$ and $2$. With an assumed intervention cost of $4$, the net values are $2$
and $-2$. The complete observed panels agree between these two worlds.
\citep{exec21_gsynth_reference}

Writing $F_{\rm pre}$ for the pre-period factor matrix, the direction
$v=(0,1)^{\mathsf T}$ satisfies
\begin{equation}
\label{exec21:gsynth-null}
 F_{\rm pre}v=0,\qquad f_3^{\mathsf T}v=1.
\end{equation}
The pre-period factor rank is one while the full factor rank is two.
Repeating the two pre-factor rows over six distinct calendar periods does
not change that rank. A third donor with loading $(2,1)$ can raise the donor
count without resolving this missing treated-unit information. Thus minimum
period and donor counts are useful guards, but are not proofs of the relevant
rank condition. This example lies outside full pre-factor-rank qualification;
it is not evidence that an estimator valid under that qualification fails.
\citep{exec21_gsynth_reference}

The inspected engine includes count/rank restrictions and, in one unbounded
treated-loading branch, solves using the inverse of
$F_{\rm pre}^{\mathsf T}F_{\rm pre}$. A failed solve returns unavailable
effect fields. Near singularity can remain problematic even when the solve
returns. Its inspected rank-selection paths aggregate cross-validation
scores and can apply a minimum-error, one-standard-error or legacy
one-percent selection rule. The final rule may override an intermediate
rank update. These are predictive selection procedures, not tests proving
counterfactual identification. A restricted loading model, an informative
additional pre-period, an external loading restriction or a prospective
experiment could address a particular ambiguity, but each changes the
information or assumptions of the problem. \citep{exec21_gsynth_engine}

\subsection{Defaults, missingness and uncertainty must travel together}
\label{exec21:gsynth-inference}

In the selected wrapper, the default estimator is \texttt{gsynth}. Legacy
\texttt{EM=TRUE} selects \texttt{ife} only if the estimator argument was
omitted. The default requested inference is parametric for the gsynth route
and bootstrap for the IFE or matrix-completion routes. A parametric request
for the latter routes is changed to bootstrap with a warning; the legacy
name \texttt{nonparametric} maps to bootstrap. The wrapper also sets unit
fixed effects, five CV folds and tolerance $10^{-3}$, whereas the direct
engine's inspected defaults include two-way effects, twenty folds and
tolerance $10^{-5}$. Direct-engine adoption therefore requires explicit
configuration rather than assuming identical defaults.
\citep{exec21_gsynth_wrapper,exec21_gsynth_engine}

The engine's gsynth route forces a never-treated donor pool and rejects
treatment reversals. Too few pre-treatment observations or excessive
missingness can remove units; the returned result must disclose this change
in population. A package family's support for switching treatments does not
override the restrictions of this selected method. Missing-cell masks also
enter fitting and effect aggregation, so reporting only the number of
input rows conceals the denominator actually used. \citep{exec21_gsynth_engine}

For parametric uncertainty, the selected engine requires the isolated
never-treated pool. Its automatic error mode uses an autoregressive strategy
when cells are missing and an empirical strategy otherwise; explicitly
requested empirical or wild modes require a complete panel. In inspected
case-bootstrap code, units or cluster identifiers are resampled, with
support-conditioned retries in unit-resampling branches. Ordinary jackknife
with a cluster argument emits a warning that clustering is ignored. These
are different sampling mechanisms; a generic confidence-interval label
cannot make them interchangeable. \citep{exec21_gsynth_engine}

The inspected average-effect uncertainty uses the standard deviation of
bootstrap draws with missing values removed and, by default, a normal
interval. The basic-pivot option has a different construction. Any future
qualification must preserve attempted, valid and failed draws, resampling
units, selection/refitting behavior and reasons for unavailable output.
Dropping failed draws from a standard-deviation calculation is not evidence
that inference remains valid. Dependence across branches, common calendar
shocks, model misspecification and post-selection uncertainty each require a
declared law and a specific argument. This source comparison has executed
neither native package and makes no empirical coverage claim.
\citep{exec21_gsynth_engine}

\subsection{Reuse through an explicit panel contract}
\label{exec21:gsynth-integration}

The proposal retains the pinned wrapper as a compatibility reference and
favors evaluating a direct \texttt{fect} worker if a prototype is funded.
The ignored weight and implicit remapping make an unrestricted wrapper
pass-through unsuitable for a new interface. Porting the engine immediately
would duplicate panel conversion, rank selection, native numerical routines
and inference before a behavioral comparison exists. Classic synthetic
control, difference-in-differences, matrix-completion and state-space
approaches remain substantive comparators whose targets and identifying
assumptions must be matched to the banking question.

Both packages declare \texttt{MIT + file LICENSE}; the saved license files
contain the holder and year. That declaration supports identifying the
stated license, but this review has not inspected the complete standard
template or every dependency's terms. The wrapper says it needs no
compilation, while the selected engine requires compiled components,
R~4.1 or later, Rcpp and RcppArmadillo. A deployment estimate must include
that environment. Process isolation does not itself establish rights,
reproducibility or numerical validity. \citep{exec21_gsynth_wrapper,exec21_gsynth_engine}

A common library, CLI and MCP request should carry unique unit/time keys,
the complete calendar, action timing, outcome units, the donor population,
observation masks, target weights and their fitting/aggregation roles. It
should also freeze the method, fixed effects, rank candidates, selection
rule, tolerance, resampling law and dependency identities. The response
should return the actual configuration, retained sample and denominators,
conditioning and convergence diagnostics, original warnings, named effect
aggregates and a separately typed uncertainty result. An agent translating
the business question may propose these fields; it cannot infer a missing
weighting basis or certify donor validity from a fluent explanation.

Before admission, a public reference comparison should reproduce the
wrapper's weight omission and compare an explicitly configured engine on
known target calculations. It should then exercise unequal exposure
durations, missingness, reversals, donor shortages, weak factor support,
rank resets, failed solves, cluster warnings and bounded runtime failures.
Known-law factor panels can test selected calibration claims before any
costly bank experiment, provided selection and failure-denominator rules
are frozen in advance. Total cost includes validation, conversion, rank
search, repeated fits, uncertainty, serialization, review and maintenance.
These public comparisons can establish whether a panel prototype merits
investment while preserving the assumptions a later banking study must test.
\citep{exec21_gsynth_reference}

\section{Julia and MATLAB panel estimators: matching the decision before the interface}
\label{sec:exec25-panels-other}
Other-language coverage cannot be inferred from the presence of a regression
routine or a familiar estimator name. A branch-policy rollout requires a
specified adoption history, eligible comparison groups, baseline periods,
aggregation weights and uncertainty calculation. The inspected set includes
the Julia DiffinDiffs suite and its interaction-weighted implementation,
DiDInt, and two independent MATLAB repositories. Forty original files are
authenticated to selected pre-cutoff Git trees. Repository searches identify
additional candidates, but do not provide exhaustive coverage of all archives,
commercial offerings or languages. No downloaded package was executed.
\citep{exec25_panelother_choice}

\subsection{Resolve suite names, archived aliases and dependencies}
The selected DiffinDiffs repository is a suite: its short entry module
reexports DiffinDiffsBase and InteractionWeightedDIDs. The older standalone
InteractionWeightedDIDs repository explicitly points to the suite's monorepo
and says that development moved there. It should not count as a second
independent estimator. At the selected 10 April 2024 monorepo commit, the
suite declares version 0.2.0 and its interaction-weighted component declares
0.3.2. The latter names FixedEffectModels, FixedEffects and Vcov dependencies
with version ranges. The previously inspected FixedEffectModels 2.1.0 IV/FE
source is a useful separate comparator, but cannot silently replace this
component's declared 1.10 compatibility line. A resolved environment must
identify the actual delegates before native comparisons. The inspected
Julia notices are MIT-style grants; downstream data and dependency rights
remain separate.~\citep{exec25_panelother_julia,exec23_otheriv_source_0}

The treatment type declares absorbing binary treatment, allowing effects to
evolve over time. Its excluded relative periods define an omitted baseline
or other sample restriction. Separate parallel-trend types specify
never-treated or not-yet-treated comparison relations; an unspecified type
suppresses trend-specific sample alterations. These declarations organize
an analysis under assumptions. They do not prove parallel untreated trends,
absence of anticipation or absence of spillovers between branches. A service
must preserve which relation was requested and distinguish an asserted
restriction from one contradicted by the recorded treatment history.
\citep{exec25_panelother_julia,exec25_panelother_choice}

For example, a servicing regime with history $(0,1,0)$ has first adoption in
period two, but reconstructing treatment from that date as an absorbing policy
produces $(0,1,1)$. The last observation changes meaning. The adapter must
refuse that conversion or select a method that explicitly models reversals;
it cannot quietly reinterpret the policy. Similarly, dropping the period
immediately before adoption is not by itself a justification for an
anticipation restriction. The interval during which staff or customers
can respond must be part of the banking question.~\citep{exec25_panelother_choice}

\subsection{Aggregation and fixed effects are substantive choices}
The Julia interaction-weighted source constructs cohort/relative-time cells,
records their counts and sample-weight totals, estimates coefficients and
retains their covariance. Its aggregation routine constructs a weight matrix
$W$ and returns $W'\widehat\beta$ with covariance $W'\widehat V W$.
The inspected code normalizes cohort weights within each relative-time group.
Consequently the grouping variables, retained coefficient subset and returned
weight matrix are part of the estimand, not formatting details. The source
offers optional cell-level least-squares weights, which can help reconcile
why specifications disagree.~\citep{exec25_panelother_julia}

If two cohort effects are one and four units of prevented loss, equal cohort
weights give $5/2$, while weights $(3/4,1/4)$ give $7/4$. A bank allocating
equal attention to regions and a bank weighting every treated account equally
may reasonably choose different targets. Their results should not be labeled
inconsistent until the targets agree. The proposed output therefore carries
the cohort-time cells, weight basis, missing-cell exclusions, aggregation
matrix and monetary conversion alongside the estimate.~\citep{exec25_panelother_choice}

An exact six-cell example also prevents a generic two-way fixed-effects
regression from being treated as a universal staggered-adoption estimator.
Two cohorts have treatment histories $(0,1,1)$ and $(0,0,1)$, untreated
outcomes zero, and observed outcomes $(0,1,4)$ and $(0,0,1)$. Every realized
treated effect is positive, with average two. Residualizing treatment against
cohort and period effects gives a regression coefficient of $-1/2$.
The independent fraction calculation establishes the algebraic example,
not package performance. There is also no untreated comparison group left
in the final period, so a modern cohort estimator must not invent support
for that cell. Scientific identification and numerical regression output
are separate acceptance questions.~\citep{exec25_panelother_choice}

The inspected Julia default covariance is heteroskedasticity-robust; cluster
covariance is a separately selected option. Fixed-effect singleton removal
and missing cluster identifiers can change the estimation sample. The
residualization helper warns on nonconvergence and records convergence
information. The proposed wrapper should expose that state and enforce its
declared acceptance rule, rather than interpreting every returned coefficient
as a qualified solution. Cluster unit, small-cluster treatment, dependence
assumptions and the full sample mask must be retained.~\citep{exec25_panelother_julia}

\subsection{DiDInt separates covariate adjustment and inference choices}
The selected DiDInt revision of 7 June 2026 declares version 0.9.6 and Julia
1.10 compatibility. Its interface accepts treatment dates or a cohort
variable, covariates, aggregation and weighting choices, a not-yet-treated
control option, heteroskedasticity corrections, jackknife settings and
randomization repetitions. The inspected implementation constructs
state-time differences after covariate adjustment. Missing outcomes, group
identifiers, times or selected covariates are dropped with warnings. Such
filtering needs an exported sample ledger because eligibility can differ
across effects and inference procedures.~\citep{exec25_panelother_didint}

The selected least-squares helper catches solve failures and returns missing,
while the covariance helper explicitly inverts the cross-product matrix and
implements HC0--HC4 corrections. Those are distinct paths with distinct
rank and leverage conditions; a successful mean estimate does not establish
valid covariance. Randomization inference checks the availability of
required state/difference pairs, limits requested permutations to the number
of unique assignments, and permutes state and treatment-time assignments.
Exchangeability of those assignments must be justified by the design;
permutation machinery alone does not randomize a historical banking rollout.
\citep{exec25_panelother_didint,exec25_panelother_choice}

One conditional source detail warrants a focused test. In the branch for
an edge-case calculation combined with the additive covariate setting, the
code warns that the option is unavailable and evaluates
\texttt{edgecase == false}, an equality expression, rather than assigning
false. Other branches can change the flag separately. This is a static
branch-level finding, not an observed native failure. Qualification must
test the actual option combination and resulting status before deciding
whether the surrounding conditions make it reachable or consequential.
\citep{exec25_panelother_didint}

\subsection{MATLAB implementations need their own algorithm and rights audit}
The selected DiDToolbox source declares MATLAB 2021+ and the Statistics and
Machine Learning Toolbox. Its complete 103-entry tree contains no standalone
license file; no package-wide reuse permission is established by the inspected
README or source subset. A downloadable toolbox or public Git repository
does not establish rights to adopt or redistribute it. It is also an
independent repository, not evidence that its estimators are native
MathWorks capabilities or available in GNU Octave.~\citep{exec25_panelother_matlab}

The method named IW delegates to the CS engine, selects its unconditional
path and packages the returned cohort-time/event-time aggregates. The source
labels a cohort-share option as its intended IW weighting. This is a concrete
implementation route that must be compared with the target specification;
the name alone does not establish finite-sample equivalence to the Julia
regression estimator. The selected CS path defines a baseline
$g-\Delta-1$, uses not-yet-treated controls satisfying $G>t+\Delta$
while excluding the target cohort, and skips cells without the necessary
baseline, treated observations, comparison observations or positive weight.
For $g=3$, $\Delta=1$ and $t=3$, the baseline is one and a comparison cohort
adopting at four is ineligible. Output denominators must disclose such
support losses.~\citep{exec25_panelother_matlab,exec25_panelother_choice}

The selected first-treatment helper takes the earliest observed treatment
indicator. That date alone cannot establish irreversibility, and its mapping

\subsection{The dispatcher determines the scientific comparison}

\citep{exec24_augsynth_source}

\subsection{Negative weights represent extrapolation}
For the selected single-treatment ridge route without auxiliary covariates,
let $X$ be the $n_0\times p$ donor matrix after centering each feature on its

\[
 w^{\rm aug}=w^{\rm sc}

\]
Since $\mathbf{1}'X=0$, the adjustment sums to zero. Individual weights
need not be nonnegative. This argument concerns the specified centered

In an authored example, centered donors are $(-1,1)$, the treated value is

relevant interference need justification. Truncating the negative weight

\citep{exec24_augsynth_choice}

\section{scpi: prediction uncertainty, failed optimization and the proposed inference contract}
\label{sec:exec24-scpi-reuse}

A synthetic banking portfolio needs more than a fitted counterfactual curve.
The uncertainty in fitted weights differs from uncertainty about a future
untreated outcome. The inspected R \texttt{scpi} source provides a concrete
reference for separating these components, choosing weight constraints and
comparing prediction intervals. Its proposed role is a reference for public
experiments, conditional on numerical and law-specific qualification. A
prediction interval alone does not establish the bank's counterfactual
identification assumptions.~\citep{exec24_scpi_choice}

Eight selected originals authenticate to the CRAN-mirror revision of 10 June
2026. Its description declares version 4.0.1, GPL-3, R at least 4.1.0 and
dependencies including CVXR greater than 1.9 and ECOSolveR. The observed
packager field is \texttt{CodexSandboxOffline}. That field is retained as
source metadata, not equated with an independently verified author release
or installed distribution. A bibliography entry dated 2027 does not establish
availability before the 7 October 2026 literature cutoff. No theorem from
that entry is used here. The inherited official manual remains preserved;
complete release equivalence, transitive rights and native behavior are open.
\citep{exec24_scpi_source,v12_sw_scpi}

\subsection{Targets and donor clocks precede optimization}
Single-unit preparation validates a distinct treated unit, at least two
donors, observed requested periods and disjoint pre/post period sets. It sorts
periods and can move final pretreatment periods into the post period under
an anticipation setting. It expands the panel with missing entries before
forming feature, donor and prediction matrices. Completing a rectangular
index is not imputation or evidence of donor eligibility. The proposed
contract retains original missingness, retained rows, requested and resolved
periods, unit identities and the measurement clock.
\citep{exec24_scpi_source}

Multiple-unit preparation distinguishes unit-time outcomes, averages within
treated units and time aggregates. The inspected time-aggregate prediction
matrix is divided by the number of treated units, then incomplete rows are
omitted. This is not automatically an exposure-weighted portfolio target.
Donors default to units not treated in the relevant supplied population;
a bounded post horizon can admit not-yet-treated donors for unit-time and
unit routes. Horizon, anticipation and aggregation can therefore alter the
comparison. Full staggered identification and simultaneous coverage require
separate scientific justification.~\citep{exec24_scpi_source,exec24_scpi_choice}

Let $A$ stack treated pretreatment features, $B$ donor features and $C$
adjustment covariates. With $Z=[B,C]$ and $b=(w',r')'$, fitting minimizes
$(A-Zb)'V(A-Zb)$ under the chosen weight constraints. The default uses
nonnegative weights summing to one. Alternatives include unconstrained
least squares, an $L_1$ ball, an $L_2$ ball and a combined sum-to-one,
nonnegative and $L_2$ restriction. Adjustment coefficients are not
automatically constrained as donor weights. Separate and pooled metrics
also define different objectives.~\citep{exec24_scpi_source}

The constrained path defaults to CLARABEL through CVXR, checks availability
and accepts \texttt{optimal} and \texttt{optimal\_inaccurate} statuses. The
latter must remain visible in any adapter. A diagonal-metric unconstrained
path first tries weighted least squares before the general optimizer.
Status, rank, metric, active constraints and residuals belong in the output;
successful optimization cannot establish an untreated counterfactual law.
\citep{exec24_scpi_source,exec24_scpi_choice}

\subsection{Two uncertainty components need two declared guarantees}
Write counterfactual prediction error as $U_t+E_t$, with $U_t$ the fitted
coefficient component and $E_t$ the future residual component. If valid
events separately place these in $[l_U,u_U]$ and $[l_E,u_E]$ with error
probabilities at most $\alpha_U$ and $\alpha_E$, their sum lies in
$[l_U+l_E,u_U+u_E]$ with probability at least $1-\alpha_U-\alpha_E$ by
the union bound. This elementary conditional statement does not prove that
estimated component intervals have those probabilities. Two 95 percent
component statements do not automatically give a 95 percent joint claim.
\citep{exec24_scpi_choice}

In an authored example, fitted untreated revenue is 100 thousand USD,
coefficient error lies in $[-5,5]$ and future error in $[-10,10]$. The
combined counterfactual interval is $[85,115]$. Observed treated revenue
120 gives effect interval $[5,35]$, reversing endpoints on subtraction.
If justified component error rates were each 0.05, the union-bound
guarantee would be 0.90. These values illustrate arithmetic, not package
output, bank data or verified coverage.~\citep{exec24_scpi_choice}

The source estimates in-sample residual moments with optional
misspecification adjustment and HC0--HC4 scaling. It can simplify moment
designs when observations are too few relative to parameters, and caps a
degrees-of-freedom quantity when it reaches the sample size. Requested and
resolved designs must both be retained. Adding lags as regression features
does not itself establish arbitrary serial-correlation robustness.
Out-of-sample alternatives use conditional sub-Gaussian bounds, a
location-scale construction or conditional quantile regression; each needs
its own assumptions and calibration study.~\citep{exec24_scpi_source}

The joint-interval dispatcher changes scope with the target: within a unit
trajectory, across unit averages, or within an aggregate trajectory. The
label \emph{joint} must name the indexed set covered. It cannot imply
coverage over every branch, calendar, tuning choice and scientific
hypothesis without another argument.~\citep{exec24_scpi_source,exec24_scpi_choice}

\subsection{Failed simulated optimization can change the tails}
The coefficient-error helper simulates Gaussian perturbations and solves
lower and upper conic problems. It accepts optimal or close-to-optimal
ECOS messages; other statuses produce missing simulated bounds. The caller
drops rows that failed at all horizons and computes marginal quantiles
with missing entries removed. Failure percentages use the original
requested simulation count. A warning above 20 percent depends on verbose
output; an adapter must inspect those fractions regardless of logging.
\citep{exec24_scpi_source}

An authored finite example isolates the selection issue. Nine zero upper
bounds and one upper bound 100 have a type-seven 97.5 percent quantile of
77.5. If the final value is unavailable after failure, the successful
values alone have quantile zero, although the failure fraction is only
10 percent. The omitted 100 is hypothetical, not recoverable from an
actual failed solve. A small failure percentage alone cannot certify
harmless omission. Qualification should retain every draw, status, horizon
and both bounds, predeclare thresholds, and compare numerical repairs on
matched perturbations. Discarding difficult draws is not a coverage proof.
\citep{exec24_scpi_choice}

Parallel and serial branches also need bound RNG streams, worker counts,
perturbations, retries and failures. More simulations can improve Monte
Carlo resolution under a valid law; they cannot repair unidentified
counterfactuals, misspecified residuals or failure-driven selection.
\citep{exec24_scpi_source,exec24_scpi_choice}

\subsection{Asymmetric bounds and degenerate matrices need explicit states}
The interface permits supplying one out-of-sample bound while estimating
the other. In the Gaussian and location-scale calls, however, the
lower-side estimation flag is forwarded to both helper parameters.
With a supplied lower bound and unsupplied upper bound, intended flags
$(\mathrm{false},\mathrm{true})$ become
$(\mathrm{false},\mathrm{false})$, so the helper skips fitting. In the
branch with the outcome among the features, the upper bound remains
missing while the supplied lower bound is restored. Other branches can
encounter additional missing-value checks. The quantile-regression call
forwards the flags separately. This conditional static discrepancy has
an exact Boolean witness; it is not an observed native failure. The
proposed adapter refuses the affected request until a tested repair
preserves the requested sides.~\citep{exec24_scpi_source,exec24_scpi_choice}

The square-root helper uses singular values and left singular vectors,
which has the intended interpretation for a symmetric positive-semidefinite
matrix. Applied algebraically to $\operatorname{diag}(-1,4)$, the
construction gives $\operatorname{diag}(1,2)$, whose square is
$\operatorname{diag}(1,4)$, not the input. This does not establish that the
estimator normally supplies indefinite covariances. It motivates a domain
check instead of interpreting SVD as an automatic repair. A near-zero
regularizer also returns field names different from its ordinary branch;
callers need explicit tests for degenerate covariance states.
\citep{exec24_scpi_source,exec24_scpi_choice}

\subsection{A reference decision with a measurable adoption route}
The proposal retains the selected R source as a comparison reference.
Direct adoption awaits release/dependency identity, rights, transformations,
constraint parity, diagnostics, asymmetric bounds and preregistered public
uncertainty tests. A full port is deferred because it must reproduce local
geometry, moment-design fallbacks, constrained simulation, parallel
randomness and failure accounting as well as the point estimator.
Independent oracles test specific contracts but do not replace package

Scientific owners justify donors and probability claims; adapter owners

\section{fect: switching interventions, validation clocks and numerical accountability}
\label{sec:exec24-fect-reuse}

A banking servicing policy may start, stop and restart across regional
portfolios. A useful counterfactual analysis must then distinguish the effect
during treatment, persistence after withdrawal, changes in the comparison
population and the uncertainty of the fitted untreated path. The earlier
\texttt{gsynth} comparison established a compatibility wrapper and selected
engine behavior. A separate review of \texttt{fect} is needed because its
direct interface exposes additional estimators, treatment reversals,
validation choices and sensitivity delegation. The proposed disposition is
reference use with a conditional future R worker; native adoption and a full
port remain deferred.~\citep{exec21_gsynth_wrapper,exec21_gsynth_engine,exec24_fect_choice}

The inspected originals come from the preserved CRAN-mirror commit of
30 May 2026, declaring version 2.4.5. The description declares R at least
4.1.0, native compilation through Rcpp and RcppArmadillo, and dependencies
including \texttt{fixest}, parallel backends and numerical libraries.
Its MIT-plus-file declaration and holder/year file identify a licensing
lead; this review does not supply complete installed-distribution rights.
Archive identity establishes the selected bytes, not equivalence to every
author release, binary or operating environment. Original paper theorems
are not inferred from the package bibliography.~\citep{exec24_fect_source,v12_sw_fect}

\subsection{The estimand is an explicit product choice}
Let $\mathcal S$ be retained observed treated unit-period cells, and let
$\widehat\tau_{it}=Y_{it}-\widehat Y_{it}(0)$ denote the imputed contrast.
Three possible summaries are
\begin{align}
 \widehat\tau_{\rm cell}&=|\mathcal S|^{-1}
      \sum_{(i,t)\in\mathcal S}\widehat\tau_{it},\\
 \widehat\tau_{\rm unit}&=|\mathcal U|^{-1}\sum_{i\in\mathcal U}
      |\mathcal S_i|^{-1}\sum_{t\in\mathcal S_i}\widehat\tau_{it},\\
 \widehat\tau_w&=\frac{\sum_{(i,t)\in\mathcal S}w_{it}\widehat\tau_{it}}
                       {\sum_{(i,t)\in\mathcal S}w_{it}}.
\end{align}
Here $\mathcal U$ contains retained treated units and $\mathcal S_i$ their
treated periods. These definitions already differ before any choice of
factor model. In an authored complete-data example, region A has effects
2 and 4 thousand USD in two treated months and region B has effect 10 in
one month. The cell average is $16/3$, the equal-region average $13/2$,
and cell weights $(1,1,4)$ produce $23/3$ thousand USD. A ranking or budget
decision can change solely through this target choice. None of these
numbers is an observed bank return.~\citep{exec24_fect_choice}

The inspected matrix-completion path constructs cell and unit summaries
separately. Its cell summary uses complete effects; the unit path has its
own missing-value operations. Equality to a proposed missing-data target
therefore requires a matched fixture, not merely a matching output name.
Weight roles also matter: \texttt{W.est} governs fitting and \texttt{W.agg}
governs aggregation, with a common \texttt{W} supplying both defaults.
The selected source rejects two distinct weight-column names, removes
zero-weight rows, and routes weighted aggregation into canonical output
slots. Reusing an exposure weight as a precision weight is a scientific
choice, not a convenient adapter conversion. The proposed interface
preserves both roles, row removals and resolved target denominators.
\citep{exec24_fect_source,exec21_gsynth_engine}

The counterfactual model still requires substantive restrictions. An
additive specification, a low-rank interactive structure and a regularized
matrix completion assumption offer different explanations of untreated
outcomes. Covariates affected by treatment, unsupported extrapolation,
interference and informative missingness can defeat these explanations.
An estimated untreated path or a small pretreatment error does not itself
identify the policy effect. Public synthetic experiments can test a chosen
law with known truth; they cannot certify the bank's assignment mechanism.
\citep{exec24_fect_choice}

\subsection{Treatment switches and carryover require separate clocks}
The direct source distinguishes never-treated and not-yet-treated factor
samples, with method-specific gates. Matrix completion and the combined
method reject the never-treated option in the inspected dispatcher.
The gsynth method resolves its default factor sample to never-treated
controls and rejects treatment reversals. Parametric inference requires
never-treated controls and rejects reversal paths. Those checks bound a
supported route; they do not prove that an accepted declaration is true.
\citep{exec24_fect_source}

For a positive \texttt{carryover.rm}, the source marks specified subsequent
untreated positions with status two, retains treatment status one where
the two would overlap, and constructs separate event-time coordinates.
On an authored regular six-period clock, treatment $(0,1,0,0,1,0)$ with
one subsequent carryover position becomes $(0,1,2,0,1,2)$. This coding
clarifies which effect is being discussed. It is not an estimate of how
long a servicing intervention actually persists. The adapter must retain
original calendar labels, internal indices, treatment, carryover, observed
outcome and estimation masks as distinct objects. A carryover test and a
requested exclusion interval are separate controls; the full mask behavior
needs native fixtures before admission.~\citep{exec24_fect_source,exec24_fect_choice}

Similarly, group effects and resampling groups are distinct. The inspected
modern \texttt{group.fe} route checks nesting within units and can select
the complex-fixed-effects method. A single group column can supply the
default bootstrap cluster, while multiple group columns require an
explicit cluster choice. The code rejects \texttt{cl=FALSE}: even the
ordinary case bootstrap resamples units. Cross-region common shocks need
a justified sampling law; a group-name argument alone cannot provide it.
\citep{exec24_fect_source}

\subsection{Cross-validation answers a declared prediction question}
The formula interface defaults to rolling validation, but the selected
default method declares \texttt{all\_units}. A small authored base-R
dispatch experiment confirms that an omitted generic default need not
override the selected method's own default. It establishes R dispatch
semantics, not a native fect execution. The proposed worker therefore
passes the validation method explicitly and records both the requested
call form and resolved arguments.~\citep{exec24_fect_source,exec24_fect_choice}

The rolling mask chooses eligible units and anchors, scores a held-out
block, drops a preceding buffer and removes subsequent eligible outcomes
for each sampled unit. Unsampled units remain available across periods.
For example, with six eligible periods, anchor four, block length two and
buffer one, a sampled unit trains on periods one and two, excludes three,
scores four and five, and drops six. An unsampled donor can still provide
periods one through six. This may suit retrospective counterfactual
imputation using contemporaneous donors. It is not automatically a
prospective forecasting experiment in which every future donor outcome
is unavailable. The banking decision clock determines the appropriate
holdout construction.~\citep{exec24_fect_source,exec24_fect_choice}

Validation averaging and failed fits are equally material. The standalone
rolling wrapper removes nonfinite squared errors, computes per-fold mean
errors and then averages the retained fold scores. It exposes used-fold
and held-out-cell counts. A candidate with fold mean errors $(1,9)$ on
$(100,1)$ scored cells has equal-fold score 5 but pooled-cell score
$109/101$. A comparator with errors $(3,3)$ scores 3 under both rules.
The preferred candidate reverses with the aggregation rule. This is an
authored denominator example, not evidence that either rule is always
correct. Candidate-specific missing folds need explicit refusal or a
predeclared comparison policy.~\citep{exec24_fect_source,exec24_fect_choice}

The selection helper offers minimum, one-percent and one-standard-error
rules. For ordered ranks $(0,1,2)$ with mean scores $(1.2,1,1.1)$ and
best-rank fold standard error 0.3, the one-standard-error threshold is 1.3
and chooses rank zero; minimum and one-percent rules choose rank one.
The standard error is computed from available fold values, so dependence
between folds and missing scores remain qualifications. This is a tuning
heuristic, not a confidence interval for a causal effect or a theorem that
the smallest retained rank is scientifically correct.
\citep{exec24_fect_source,exec24_fect_choice}

\subsection{A numerical result must retain its termination evidence}
The matrix-completion helper takes singular values of $E/(TN)$ and
subtracts the regularization parameter before multiplying the reconstructed
matrix by $TN$. Thus, for an authored two-by-two diagonal matrix
$E=\operatorname{diag}(12,4)$ and $\lambda=1.5$, its soft-thresholding
convention yields $\operatorname{diag}(6,0)$. Porting a library that
thresholds the unnormalized singular values with the same numeric
parameter would produce a different problem. Missing entries, fixed
effects, weights and iterative reconstruction add further semantics that
this diagonal example does not qualify.~\citep{exec24_fect_source,exec24_fect_choice}

The inspected interactive helper uses a relative-change criterion,
iteration cap and a possible weighted burn-in restart. It returns an
iteration count and fitted quantities but not the final relative change
or an explicit termination category in that selected return path. A
distinct additive helper accepts a maximum-iteration argument but tests
against a literal 500 in its loop. Starting at zero, that guard can allow
501 iterations if convergence never occurs. The outer diagnostic compares
the returned count against the requested maximum. If the request was
5,000, the conditional 501-iteration path would not trigger that cap
warning. This is a source control-flow witness, not an observed failed
fit. A wrapper should require matched residual, rank, perturbation and
termination evidence rather than interpret the absence of a warning as
convergence.~\citep{exec24_fect_source,exec24_fect_choice}

The additive helper also divides a fit-change norm by the old-fit norm
without the small denominator adjustment used in the inspected
interactive branch. Zero and nearly zero starts belong in the public
numerical test matrix. A repair must preserve the optimization target and
document numerical policy; blindly adding constants or increasing an
iteration limit is not proof of accuracy.~\citep{exec24_fect_source,exec24_fect_choice}

\subsection{Bootstrap and sensitivity are complete request contracts}
The nonparametric parallel branch contains backend retries and local
fallbacks. Residual worker errors can become all-missing replicate objects;
later standard deviations and quantiles omit missing entries. Covariance
uses pairwise-complete observations in the inspected path. Successful
replicates can therefore define different effective samples across
coordinates, and a finite covariance is not automatically suitable for a
joint sensitivity calculation. An adapter must retain initial failures,
retries, random streams, retained replicate identities, coordinate counts
and total requested simulations. Repeating a selected successful subset
does not establish the intended bootstrap law.~\citep{exec24_fect_source}

The built-in interval choices distinguish a normal interval and a reflected
basic interval; a jackknife fit rejects the basic choice. In the inspected
parametric route the basic-interval helper recenters a null-centered
replicate distribution around the point estimate. To isolate the arithmetic,
take estimate 10 and null-centered draws $(-2,-1,0,1,2)$. Their type-seven
quartiles are $(-1,1)$. At the deliberately illustrative error level
$\alpha=1/2$, reflecting the unrecentered quartiles about 10 gives
$[19,21]$; recentering first gives $[9,11]$. This example explains the
location contract. It makes no sampling-coverage claim and does not
recommend that error level for banking decisions.
\citep{exec24_fect_source,exec24_fect_choice}

Sensitivity is delegated to the optional \texttt{HonestDiDFEct} package.
The inspected wrapper matches requested event-time labels, drops unmatched
indices, obtains a covariance matrix or bootstrap fallback, and constructs
default post-period weights from counts. Requested pre/post counts are
formed separately, so incomplete label matching requires an explicit
shape and identity check before delegation. Scalar subsetting and
pairwise covariance need their own tests. Optional average and period
branches are separate; disabling an average branch while retaining a
period branch can leave the average result name undefined at assembly.
The parallel cleanup path also needs testing when a core count is supplied.
These conditional findings are not executions of the dependency or
counterexamples to its underlying statistical theorems. The dependency's
original implementation, rights and scientific premises remain separate
qualification work.~\citep{exec24_fect_source,exec24_fect_choice}

\subsection{A conditional R worker is more defensible than a premature port}
A direct worker could preserve fect's estimator dispatch and provide a
bounded JSON result through the proposed CLI and MCP interfaces. The
request would name the target, original and internal calendars, missingness
and treatment masks, comparison population, estimator, tuning rule,
resampling unit and numerical tolerances. The response would preserve
requested and resolved options, all denominators, fit diagnostics,
replicate and retry records, interval orientation and refusal reasons.
Large arrays would be immutable hashed artifacts with explicit schemas.
No such native worker is admitted by this source review.
\citep{exec24_fect_choice}

Direct adoption is deferred until the exact environment, complete rights,
target and diagnostics pass public trials. A full Python or C++ port is
also deferred: reproducing missingness, role-dependent weights, tuning,
factor normalization, bootstrap and optional sensitivity is substantial
work with no measured benefit here. A small independent exact oracle is
useful for conversion checks. Simpler additive models, the separately
reviewed synthetic-control families and method-specific difference-in-
differences alternatives remain comparators at matched targets, clocks
and uncertainty standards. Their source reviews do not grant blanket
permission to substitute estimates with different scientific meanings.
\citep{exec24_fect_choice}

Scientific ownership must cover counterfactual restrictions and the
decision clock; an adapter owner must preserve semantics and failure
states; a platform and rights owner must qualify the distribution; an
evaluation owner must freeze public tasks, splits, oracles and costs.
An illustrative 4,800 USD workflow serving 240 requests, 200 finite
outputs and 160 scientifically accepted outputs costs 20, 24 and 30 USD
per corresponding denominator. These are authored cost examples, not
measured prices or ROI. Qualification must count tuning, compilation,
retries, storage, review and maintenance, not only a successful fit.
\citep{exec24_fect_choice}

The revisit trigger is a justified panel prototype with resolved rights
and a frozen native test matrix covering call-form defaults, target
weights, irregular calendars, reversals, carryover masks, failed folds,
normalization, iteration exits, bootstrap failures and sensitivity
delegation. Known engineering routes exist for these bounded checks.
Unknown assignment truth, arbitrary common shocks and unrestricted
counterfactual stability have no universal repair from this interface.
Execution and independent validation remain outstanding.
\citep{exec24_fect_choice}

\section{Comparing R synthetic controls: donor information, uncertainty and failure denominators}
\label{sec:exec25-synthetic-r-coverage}

A regional banking policy leaves a fundamental comparison problem: what would
the treated portfolio have earned without the intervention? Choosing an R
package does not answer that question. The proposal needs to distinguish the
counterfactual restriction, the numerical construction, the source of
uncertainty and the unit over which success is counted. The preceding reviews
of Synth, augsynth, scpi, fect, gsynth and synthdid supply complementary
reference implementations. This comparison adds inspected inference paths,
the selected Synth solver delegate, and three additional R candidates. It
does not transfer a reference decision into permission to integrate a package.
\citep{exec24_synth_source,exec24_augsynth_source,exec24_scpi_source,
exec24_fect_source,exec21_gsynth_wrapper,exec23_synthdid_reuse_source,
exec25_synthr_choice}

The detailed findings constrain this wider comparison. Synth's ordinary
predictor route needs a matched aggregation operator and admissible custom
weights. Augmentation must preserve the tuning calendar, accepted null set
and numerical status. The selected scpi path requires explicit handling of
failed perturbation bounds and asymmetric requests. The direct fect route
must retain actual iteration exits, retained resamples and covariance
provenance. These are different conditions for admitting a request, even
where the packages can produce similar fitted trajectories.

\subsection{One banking target, several distinct constructions}
Let $Y_{1t}(0)$ denote untreated revenue for the intervention region, $Y_{jt}$
the observed donor outcomes and $w_j$ weights chosen from the declared
information available before treatment. A fitted comparison is
$\widehat Y_{1t}(0)=\sum_jw_jY_{jt}$, possibly augmented by a prediction
model. The reported gap $Y_{1t}-\widehat Y_{1t}(0)$ is a causal effect only
under restrictions that connect the fitted comparison to the untreated
potential outcome. Donor eligibility, measurement revisions, anticipation
and interference therefore belong in the request, rather than being inferred
from a successful optimization.~\citep{exec25_synthr_choice}

The constrained Synth fit and ridge augmentation solve different problems:
nonnegative weights summing to one restrict extrapolation, whereas an
augmentation can alter weights beyond that set. The selected gsynth version
delegates estimation to fect, so their appearance in a catalog does not create
two independent numerical engines. Factor or matrix-completion restrictions
and target aggregation differ from a single constrained donor portfolio.
The original synthdid implementation assumes its declared block-adoption
layout; it cannot be renamed as a general staggered estimator. scpi separates
uncertainty in fitted coefficients from uncertainty in a future untreated
outcome. None of these distinctions can be resolved by choosing the smallest
pretreatment residual.~\citep{exec24_synth_source,exec24_augsynth_source,
exec21_gsynth_wrapper,exec24_fect_source,exec23_synthdid_reuse_source,
exec24_scpi_source}

An exact authored example makes donor contamination visible. Equal weights
on donor revenues 80 and 120 thousand USD give an untreated prediction of
100. Observed treated revenue of 120 gives a gap of 20. If the intervention
also increases the second donor's observed revenue to 140, the same weights
give 110 and a gap of 10. Weight fitting has not discovered or corrected the
spillover. The scientific role must justify the donor exclusions or introduce
a model of the exposure mechanism. These numbers are a stipulated example,
not an observed banking experiment.~\citep{exec25_synthr_choice}

\subsection{Numerical termination is information that the adapter must retain}
The newly inspected kernlab 0.9-33 source is pinned to its August 2024 CRAN
mirror revision. Its description declares GPL-2 and compilation requirements;
the retained copyright file distinguishes R and native-code authorship. This
is a selected possible delegate, not proof of the runtime resolved by every
Synth installation. The \texttt{ipop} loop computes primal and dual
infeasibility, objective values and a significant-figure measure. It breaks
when the latter is at least the requested value, while its final
\texttt{converged} label requires a strict inequality and an iteration count
below the limit. Thus an exact equality is a conditional distinction between
two source predicates. No native equality event or package failure was
observed.~\citep{exec25_synthr_kernlab}

The delegate returns primal and dual variables and a status field. Earlier
Synth wrapper observations about extracting the primal solution therefore
must not be generalized into a claim that the underlying solver has no
diagnostics. The proposed adapter retains requested and resolved tolerances,
termination status, feasibility residuals and the objective before admitting
an output. It also verifies the original donor and feature order. Neither a
status label nor a small objective proves counterfactual identification.
Complete optimx, rgenoud, linear-algebra and installed-artifact qualification
remain separate work.~\citep{exec25_synthr_kernlab,exec24_synth_source,
exec25_synthr_choice}

\subsection{Tidy preparation does not make placebo ranks exchangeable}
The selected tidysynth 0.2.0 revision is from May 2023. Its MIT notice is
retained, together with the declared kernlab, optimx and rgenoud dependencies.
The source constructs treated and placebo data configurations, classifies
dates at or before the supplied intervention time as pretreatment, and uses
the first fitted predictor weights for later placebo configurations when no
custom weights were supplied. Predictor weights and donor weights are
different objects: sharing the former is an algorithmic choice that must
be retained in a comparison.~\citep{exec25_synthr_tidysynth}

The internal fitting file explicitly credits a Synth implementation as its
origin. The package-level MIT notice must therefore be reviewed alongside
the provenance and applicable terms of reused code; it cannot by itself
settle distribution rights for that file or its dependencies. This source
observation is a rights-review task, not a finding of infringement.
\citep{exec25_synthr_tidysynth,exec24_synth_source}

The inspected significance routine computes post/pre mean-squared-error
ratios, sorts them in descending order, assigns sequential row numbers and
reports rank divided by the number of rows. Its returned column name does
not establish a valid assignment distribution. For ratios $(4,4,1)$, sequential
ranks give $(1/3,2/3,1)$; the inclusive upper-tail frequencies are
$(2/3,2/3,1)$. A tied treated observation can therefore receive different
sequential ranks depending on its ordering. This is an authored arithmetic
witness for a qualification test, not a native benchmark or a universal
prescription for inference. Zero pretreatment error, failed fits and
post-outcome donor selection also require explicit policies.
\citep{exec25_synthr_tidysynth,exec25_synthr_choice}

The proposal retains tidysynth as a preparation and comparison candidate.
Adoption or a port would first need matched intervention-date conventions,
predictor sharing, nested-data identities, failure handling and a justified
placebo law. The current source comparison does not grant that admission.
\citep{exec25_synthr_choice}

\subsection{Time resampling and unit resampling answer different questions}
The selected scinference development version 0.0.0.9000 is pinned to May
2021. Its description contains the literal license declaration
\texttt{use\_gpl3\_license()}, while the repository contains genuine GPL-v3
text. Both are retained rather than silently normalizing the metadata.
Its estimator delegates constrained fitting to limSolve or CVXR and also
offers a difference-in-differences residual construction. Numerical status
and rights for those delegates are not settled by the wrapper inspection.
\citep{exec25_synthr_scinference}

The conformal branch adjusts the post-treatment observations by a proposed
null effect, refits the selected model and compares residual statistics.
One route cycles contiguous windows through a doubled residual vector; another
uses random permutations and the correction $(1+E)/(B+1)$ for $E$
exceedances among $B$ draws. With $B=19$ and no exceedances, that expression
is $1/20$, whereas a raw frequency is zero. In a five-shift example whose
observed statistic is the unique maximum, including its own shift gives
$1/5$. These support calculations do not prove exchangeability under common
regional shocks or serial dependence.~\citep{exec25_synthr_scinference,
exec25_synthr_choice}

The pointwise interval routine inverts a supplied finite grid and returns
its accepted minimum and maximum. If only 0 and 2 are accepted, the interval
hull also contains the rejected value 1. If no grid value is accepted, no
finite interval is certified. The contract should retain the accepted set,
grid range, empty-set condition and truncation warning. A pointwise hull is
not automatically a joint statement about an entire revenue trajectory.
The alternative cross-fit t procedure partitions pretreatment dates and
uses a stated degrees-of-freedom calculation; its source comment is not a
theorem validating every banking dependence law.~\citep{exec25_synthr_scinference,
exec25_synthr_choice}

Further inspection of the retained augsynth source shows why resampling
labels alone are insufficient. Its time jackknife removes pretreatment
dates, refits and forms prediction-error bounds before shifting back to
the treatment-effect scale. Its single-estimate unit jackknife selects
controls using weights rounded to three decimals and, with multiple treated
units, includes those treated units. The variance multiplier uses the full
row count, which differs from the number of selected leave-one-out fits.
For two replicate effects 0 and 2, the sum of squared centered values is 2;
a full count of four gives $3/2$ under the displayed multiplier, whereas
the two-replicate multiplier gives 1. Neither calculation proves which
sampling experiment is appropriate.~\citep{exec25_synthr_auginference,
exec25_synthr_choice}

\subsection{Microdata matching and missing permutations need separate records}
The selected microsynth 2.0.50 source is pinned to April 2025. Its description
declares GPL-3 and imports survey, kernlab and LowRankQP among other packages.
Unlike treating every region as a single donor column, it supports matching
aggregates from more granular data. The inspected weighting routine selects
LowRankQP when available and otherwise ipop, can change among backup matching
models, and returns model choices, mean-squared errors and retained-group
indicators. An adapter must preserve those changes rather than reporting
only a final weight vector. Full delegated calibration and solver rights
remain unqualified.~\citep{exec25_synthr_microsynth}

The selected routine filters permutation groups by a matching-error rule.
Its permutation helper replaces infinite statistics with missing values,
counts missing entries, and averages a comparison over finite entries;
callers then apply lower-, upper- or two-sided transformations. A result
must therefore retain both the requested draws and the finite denominator,
the filter and the tail convention. Consider 19 requested draws, ten finite
statistics, nine unknown results and two finite exceedances. The retained
frequency is $2/10$, but the all-request exceedance fraction could lie
between $2/19$ and $11/19$ depending on the unknown results. These are bounds
on an incomplete frequency, not calibrated p-values. Silent deletion cannot
establish the missing classifications.~\citep{exec25_synthr_microsynth,
exec25_synthr_choice}

\subsection{A public qualification program with explicit unresolved coverage}
The source evidence supports distinct reference roles: constrained donor
fitting, augmentation, factor reconstruction, block-adoption estimation,
prediction uncertainty, preparation, null-based time inference and granular
matching. None deserves blanket rejection solely because it uses another
target. A proposed adapter should select only a declared regime and report
the reason for refusing incompatible requests. Direct adoption remains
conditional on rights, complete delegates, source-to-artifact identity and
native conformance. A broad port lacks a demonstrated benefit until those
comparisons are measured.~\citep{exec25_synthr_choice}

Public or generated experiments can first test stable donor identities,
spillovers, pretreatment missingness, tied ranks, empty grids, failed draws,
solver boundaries, backup-model changes and dependence-sensitive uncertainty.
The scientific role owns the target and observation law; the adapter role
owns conversion and refusal; the environment and rights role owns the actual
distribution; the evaluation role freezes the tests and all denominators.
An illustrative 9,000 USD cost for 300 attempted, 240 conformant and 150 useful
requests yields 30, 37.5 and 60 USD respectively. These are planning inputs,
not software quotations, measured performance or bank returns.
\citep{exec25_synthr_choice}

The bounded complementary search returned 40 unique repository leads across
three queries, with additional pages uninspected for two searches. Candidates
such as GeoLift, penalized and distributional approaches remain discovery
leads until their primary texts and dependencies are reviewed. The selected
coverage is therefore inconclusive. Unknown counterfactual stability, valid
assignment laws and arbitrary serial dependence have no universal repair
through a package choice. The remaining source, native, visual and independent
acceptance obligations remain explicit.~\citep{exec25_synthr_choice}

\section{Python synthetic controls: aligning time, targets and uncertainty before integration}
\label{sec:exec25-synthetic-python-coverage}

A bank comparing a regional intervention across Python implementations must
first agree on which observation is treated, which donors remain eligible,
and what uncertainty the reported interval describes. Similar package names
and similar fitted curves can conceal different answers. This comparison
extends the inherited CausalPy review to its synthetic-control path and
inspects selected pysyncon, SparseSC and SyntheticControlMethods originals.
The evidence establishes bounded source contracts and proposed public tests;
it does not establish native parity, calibrated inference or adoption rights.
\citep{exec25_synthpy_choice}

\subsection{One intervention date needs one explicit observation clock}
The pinned CausalPy 1.0.0rc1 source divides observations into dates strictly
before treatment and dates on or after treatment. It builds labeled control
and treated matrices, checks observation-index equality when subtracting
predictions, and forms cumulative impact by summing rows. The treatment-date
validator checks missingness, broad index type and timezone-awareness
compatibility. These guards do not by themselves define a business exposure,
prove that the donors are untreated or convert irregular observations into
equal-duration economic quantities.~\citep{exec25_synthpy_causalpy}

The selected pysyncon 1.7.0 placebo helper uses label slices ending and
beginning at the supplied treatment time. On a monotonically indexed series
whose cutoff label exists, the displayed formulas include that label in both
sums, while the post denominator is total rows minus the inclusive
pretreatment count. This is a conditional source-level boundary issue for
qualification, not an observed run. With gaps $(1,1,4,2)$ at dates one to
four and cutoff three, the literal overlapping formula gives $10/3$.
An inclusive-pre/exclusive-post split gives $2/3$; a strict-pre/inclusive-post
split gives 10. An adapter must map the bank's event clock into an explicit
partition rather than forwarding an ambiguous date unchanged.
\citep{exec25_synthpy_pysyncon,exec25_synthpy_choice}

Calendar aggregation is equally substantive. Two observed effects of two
units sum to four. If they are rates covering durations one and three,
the duration-weighted total is eight. Neither quantity follows from a date
index alone. For a cumulative uncertainty statement, covariance also matters:
two effects with variances one and covariance one have sum variance four,
whereas an independence shortcut gives two. These exact authored examples
specify target and dependence questions; they do not diagnose a bank dataset.
\citep{exec25_synthpy_choice}

\subsection{CausalPy distinguishes conditional expectations from future observations}
The selected experiment supports a Bayesian weighted-sum model and a
scikit-learn route. Its constructor prepares and checks data; fitting is
an explicit later lifecycle operation. The Bayesian model declares
Dirichlet simplex weights and can scale a stock noise prior from
pretreatment data unless the user supplies a prior. The inspected adapter
extracts draws of the conditional expectation \texttt{mu}; impact subtracts
those expected outcomes from observed treated outcomes. The scikit-learn
weighted-proportion delegate instead uses a constrained numerical point
fit. These are different uncertainty objects even if their point estimates
are close.~\citep{exec25_synthpy_causalpy}

Suppose observed revenue is 120, conditional-mean draws are 90 and 110, and
separately stipulated predictive draws are 70 and 130. The corresponding
effect draws are $(30,10)$ and $(50,-10)$. The second includes a different
source of variation. Neither is automatically an identified causal effect
distribution or a frequentist confidence interval. A result must identify
the backend, likelihood, priors, conditioning set, draw diagnostics,
observation clock and whether the target is a mean or a future realized
outcome. A donor-correlation or convex-hull warning is diagnostic evidence,
not proof of the counterfactual restrictions.~\citep{exec25_synthpy_causalpy,
exec25_synthpy_choice}

The proposed CausalPy use is a labeled Bayesian/point-estimation reference
with explicit lifecycle and target contracts. Integration remains conditional
on complete installed dependencies, model diagnostics, public conformance
and refusal behavior. Retaining coordinate assertions is useful, but those
assertions cannot supply the bank's intervention and spillover truth.
\citep{exec25_synthpy_choice}

\subsection{pysyncon provides several estimators, with distinct validation obligations}
The September 2026 pysyncon revision retains an MIT notice and declares
version 1.7.0. Its constrained Synth path scales predictors across treated
and donor columns, chooses predictor weights through an outer optimization,
and solves a bounded sum-to-one donor problem. The selected inner and outer
paths extract optimized values without a local success-status gate. This
does not imply that SciPy has no diagnostics; the proposed adapter must
retain termination and feasibility evidence from the exact resolved solver.
Custom predictor metrics, degenerate scales and row/column identities need
separate tests.~\citep{exec25_synthpy_pysyncon}

Its augmented path requires the selected pretreatment periods to be exactly
the dates before the first post period. The robust path applies a singular
value decomposition to donor outcomes over the supplied full date range
before fitting weights using the pretreatment segment. Post-intervention
donor information can be appropriate for retrospective reconstruction under
declared assumptions; it is not available for a prospectively frozen
decision. Its penalized donor problem adds a pairwise discrepancy term.
These alternatives deserve comparison at matched targets and clocks, not
interchangeable labels or a generic robustness claim.
\citep{exec25_synthpy_pysyncon,exec25_synthpy_choice}

The conformal interval route adjusts an outcome under a candidate effect,
refits and compares absolute residuals. A numerical search returns lower
and upper endpoints when its step shrinks sufficiently, and raises after
the maximum iteration count. This is a numerical search around a discrete
test, not proof that every possible accepted effect forms a connected set.
The interval routine refits the supplied estimator during its calculations;
the visible wrapper does not restore the original fitted state. A public
test should therefore check both reported intervals and subsequent calls
to the same estimator, along with failed searches, insufficient pre-periods
and exact solver status.~\citep{exec25_synthpy_pysyncon}

The placebo helper excludes the treated unit from its exceedance numerator
but retains it in the denominator. With two donor ratios and a treated
ratio strictly above both, that formula is zero, while including the
observed assignment gives $1/3$. This arithmetic identifies the convention
that must be declared; it does not establish the appropriate assignment
law. The source's method label cannot replace a justification of which
assignments are exchangeable.~\citep{exec25_synthpy_pysyncon,
exec25_synthpy_choice}

The plotting helper can filter poor-fit placebo curves, whereas the inspected
p-value helper uses the stored gaps without that display filter. A plot and
a test can therefore use different populations unless an adapter makes the
distinction explicit. This requires denominator reconciliation, not an
assumption that a visually excluded donor was removed from inference.
\citep{exec25_synthpy_pysyncon}

\subsection{SparseSC separates matching, retrospective fitting and placebo aggregation}
The selected SparseSC revision is from March 2024 and its retained version
file declares 0.2.0. The repository contains an MIT license; packaging also
contains a BSD classifier. Both declarations remain in the record and require
reconciliation with the actual distribution. The selected effect routine
distinguishes retrospective and prospective designs, converts treatment
times, and forms local samples. Its finite donor-time rule requires a donor
to be treated strictly after treatment time plus the supplied horizon;
never-treated encodings follow a separate branch. Thus at time five and
horizon three, a cohort treated at eight is excluded while one treated at
nine is eligible under that source rule.~\citep{exec25_synthpy_sparse,
exec25_synthpy_choice}

The date-conversion helper returns a missing index when a supplied treatment
date is absent from the outcome calendar. The sample-mask helper classifies
nonfinite treatment indices as controls. A conditional conversion path can
therefore collapse an unmatched date into the same encoding as never-treated
status. The proposed adapter refuses unmatched intervention dates before
constructing donors; native reproduction and complete caller validation
remain open.~\citep{exec25_synthpy_sparse}

The routine can use held-out control folds to form placebo predictions.
That algorithmic separation does not establish exchangeable assignments,
donor stability or absence of common shocks. The source also scales some
effects by pretreatment root-mean-square error and optionally treatment
size. Zero scaling denominators, changing target weights and nonfinite
requests require declared refusal and counting rules. The reference
contract retains requested and realized samples, treatment horizons,
folds, random state and every scaling factor.~\citep{exec25_synthpy_sparse}

The placebo helper averages treated effect vectors, separately averages
unit-level root-mean-square effects, and compares analogous control
combinations. These are different targets: two unit trajectories $(1,-1)$
and $(-1,1)$ have average unit RMS one but RMS of their average trajectory
zero. If combinations exceed a cap, the helper samples subsets; distinct
draws can repeat a subset. Its default p-value helper adds one to both
the exceedance count and the denominator. Confidence interval order
statistics depend on the available combination count. A result should
preserve Monte Carlo versus exhaustive enumeration, duplicate subsets,
finite counts and target identity rather than reporting a bare p-value.
\citep{exec25_synthpy_sparse,exec25_synthpy_choice}

\subsection{SyntheticControlMethods exposes another optimization and provenance contract}
The pinned October 2021 source declares version 1.1.17. Its license file
and source headers specify Apache 2.0 while packaging has an MIT field
and an Apache classifier. The inconsistency is retained as an artifact
rights-review issue, without a legal conclusion. Its nested objective
uses nonnegative donor weights summing to one and permits a pairwise
discrepancy penalty; outer optimization can start from multiple predictor
weights.~\citep{exec25_synthpy_methods}

The selected optimizer prints a success flag only when verbose and separately
checks for a result attribute. Existence of that attribute is not a successful
termination certificate. The inner solve maps caught exceptions to infinite
loss, and the original fit updates a stored best loss. The in-space placebo
path stores the donor weights from its objective calls and requests an
automatic penalty. Qualification must inspect whether the final placebo
represents the intended optimum under the same penalty and initialization
policy as the original fit. These are conditional static concerns and
proposed tests, not measured failures.~\citep{exec25_synthpy_methods}

Direct adoption of this version is deferred until result identity, status,
placebo equivalence, artifact terms and maintenance choices are resolved.
Its constrained and penalized objectives remain useful references. Porting
the entire implementation is not justified merely to avoid a packaging
question; a limited independent oracle can instead verify a declared
quadratic subproblem while leaving identification and inference explicit.
\citep{exec25_synthpy_choice}

\subsection{Public qualification and the remaining Python search}
The shared request should identify the monetary target, measurement units,
intervention and observation clock, donor restrictions, estimation window,
prospective or retrospective information set, target weights and uncertainty
claim. The response should retain converted data identities, resolved
parameters, model state, numerical diagnostics, failed requests and refusal
reasons. Public or generated trials can check boundaries, ties, zero
prefit error, repeated calls after interval construction, donor spillovers,

\citep{exec25_synthpy_choice}

An illustrative total cost of 12,000 USD over 400 attempts, 300 conformant

These are hypothetical planning denominators. The two bounded discovery

\citep{exec25_synthpy_choice}

\section{Synthetic controls across language boundaries: solver, interface and inference contracts}
\label{sec:exec25-synthetic-crosslanguage}

A regional lending policy can be evaluated through an R worker, a Julia
estimator, a C++ numerical component or a Java service, but these choices
do not represent the same scientific or operational commitment. A repository's
dominant language may describe its generated code or service layer rather
than an exposed synthetic-control estimator. The bank must preserve the
donor population, intervention clock, fitted target, uncertainty population
and failed requests across every boundary. This comparison supplements the
R and Python analyses with selected original implementations and an explicit
decision about what each source supports.~\citep{exec25_synthcross_choice}

\subsection{Choose an interface after specifying the banking contrast}
Let $y_{1t}$ be revenue in the treated region and let $y_{jt}$ denote revenue
in eligible donor regions. A simple synthetic trajectory is
$\widehat y_{1t}(0)=\sum_j w_jy_{jt}$, with nonnegative weights summing to one.
The observed gap $y_{1t}-\widehat y_{1t}(0)$ becomes a causal contrast only
under additional counterfactual and interference restrictions. Numerical
optimality of a pretreatment loss does not supply those restrictions.
Even numerical agreement needs a target beyond the objective value.
\citep{exec25_synthcross_choice}

Consider two donors both equal to 100 before intervention, with later values
100 and 200, while the treated region has later revenue 150. Every convex
weight has zero pretreatment loss. Weights $(1,0)$, $(1/2,1/2)$ and $(0,1)$
give later counterfactuals 100, 150 and 200 and gaps 50, zero and $-50$.
These are exact stipulated values, not package outputs. An adapter comparison
must therefore specify whether it requires weight equality, fitted-value
equality, objective agreement or an admissible set of solutions. A sparse
solution and a dense solution can satisfy the same numerical optimization
while leading to different extrapolations.~\citep{exec25_synthcross_choice}

For the proposal, direct adoption means retaining a supported public
interface and its declared runtime. A worker bridge preserves that interface
behind a typed request and a versioned result. A port entails responsibility
for the algorithm, dependency substitutions, numerical criteria and inference
semantics. Reimplementing a quadratic subproblem does not reproduce the
entire estimator. These distinctions govern the choices below.
\citep{exec25_synthcross_choice}

\subsection{Julia: explicit quadratic status and less explicit inference population}
The pinned SynthControl.jl revision declares version 0.4.4 and an MIT notice.
Its module exports \texttt{SimpleSCM} and \texttt{SyntheticDiD}, reexports
TreatmentPanels, and includes the simple estimator, synthetic differences
in differences and a matrix-completion file. The retained ADH development
file is not included by this module; its existence is not evidence of an
available exported estimator. The resolved TreatmentPanels, JuMP and HiGHS
artifacts remain separate dependencies requiring inspection and qualification.
\citep{exec25_synthcross_julia}

The SimpleSCM path accepts a balanced panel with one continuously treated
unit. It fits nonnegative simplex weights to pretreatment outcomes using
a quadratic objective, requires a JuMP termination status of
\texttt{OPTIMAL}, and then extracts weights and the post-treatment gap.
Its optional donor-placebo loop also requires that status. This explicit
gate contrasts with wrappers that extract a numerical vector without
carrying its termination evidence. However, an optimum status still needs
feasibility and tolerance interpretation for the resolved optimizer;
it proves neither donor eligibility nor exchangeability.
\citep{exec25_synthcross_julia,exec25_synthcross_choice}

The synthetic differences-in-differences path permits placebo standard
errors and rejects other requested standard-error modes in the inspected
method. It may reorder the panel's outcome and treatment matrices in place
to put the treated unit last. A bridge must preserve or deliberately copy
unit identities and reconcile later consumers of the same panel object.
The fitted-state predicate tests for nonzero effect or standard-error
entries. A zero-effect result with no requested standard error can therefore
fail that predicate under its literal values, although zero is a valid
effect value. This is a conditional source concern and a proposed lifecycle
test, not a native failure observed here.~\citep{exec25_synthcross_julia}

The placebo helper also merits an explicit population oracle. With $J$
untreated rows, the inspected code sets its fitting-control count to $J-1$,
allocates that many effect entries, swaps rows for the first $J-2$ iterations,
and performs one final swap. In an independent label-only replay with four
donors initially ordered A, B, C, D, the held-out labels are A, B and D;
C is not selected. If stipulated effects for A, B, C, D are 2, 4, 6, 10,
the sample variance of the selected three is $52/3$, while that of all four
is $35/3$. Neither number is a certified causal variance. The example shows
why the realized placebo identities must be checked rather than inferred
from a method name.~\citep{exec25_synthcross_julia,exec25_synthcross_choice}

Its weight routine returns weights and an objective-history array after
either limited objective improvement or the maximum iteration count.
The selected estimator extracts weights from that result. A qualification
fixture should distinguish the stopping reason, finite history, a valid
zero effect, panel mutation, and complete placebo population. The proposed
role is a version-pinned Julia reference and conditional worker bridge;
direct adoption awaits those tests and resolved dependencies. Other Julia
leads remain uninspected, so this is not closure of the entire language cell.
\citep{exec25_synthcross_julia,exec25_synthcross_choice}

\subsection{C++ inside an R package is a component contract}
The selected coresynth 1.0.0 source exposes an R formula workflow with
RcppArmadillo numerical components and an MIT notice. Its inner synthetic
control routine forms a factored quadratic problem and returns a donor-weight
vector. The implementation tries active-set and related numerical routes,
then an accelerated projected-gradient fallback with a weight-change
tolerance and iteration cap. A later exact-solve attempt may succeed;
otherwise the path can return the current iterate. The returned vector alone
does not identify which route succeeded or provide a universal optimality
certificate. The source's conditional KKT statements must remain conditional
on the route that actually established them.~\citep{exec25_synthcross_core}

This matters in a bank comparison with nearly collinear donors. A worker
should report solver route, convergence reason, feasibility, objective and
donor identity. A direct C++ port would need to expose those quantities and
qualify the Armadillo and linear-algebra environment, as well as preserve
the R-side construction of predictors, windows, filters and estimands.
The proposal therefore retains coresynth as an R-facing reference with
inspectable C++ kernels, while deferring a standalone C++ service claim.
\citep{exec25_synthcross_core,exec25_synthcross_choice}

Its placebo inference contains useful safeguards and further denominator
obligations. The R wrapper rejects the single-donor MSPE-ratio comparison
for unsupported pooled or staggered settings, carries the original
optimizer/window choices into selected refits, and can exclude poorly
fitting placebo runs. The C++ covariate-placebo route marks failed refits
with nonfinite results; the R wrapper forms a surviving population and
reports the number used. Its rank calculation includes the treated statistic
when it is valid. These source-level features are preferable to silently
asserting that every requested donor yielded a comparable statistic, but
they do not justify ignoring the probability of failure or selection.
\citep{exec25_synthcross_core}

For an authored counting example, suppose four donor requests yield two
usable statistics below the treated statistic and two unresolved failures.
Including the treated assignment among the three observed statistics gives
$1/3$. If all five requested assignments were the intended population,
the unresolved rankings allow counts from $1/5$ to $3/5$. These are arithmetic
bounds on possible rankings, not calibrated p-values. The adapter must
report attempts, successful refits, pruning, invalid ratios and usable
statistics separately, and justify any inference conditional on retention.
\citep{exec25_synthcross_choice}

SynthHelpers provides a smaller but instructive boundary. Its dated
development version declares GPL-2 and links Rcpp and RcppArmadillo.
The retained C++ routine constructs nonnegative simplex weights through
an interior-point call. That call returns primal, dual and convergence
fields, but the exported weight wrapper extracts the primal vector while
its convergence extraction is commented out. This is not evidence that
the solver fails; it is evidence that the public wrapper does not return
all inspected diagnostics. Reusing the kernel requires preserving its
provenance and terms, specifying a diagnostic response, and qualifying
the resolved runtime. A whole-package port is deferred until that work is
justified against an existing worker bridge.~\citep{exec25_synthcross_helpers}

\subsection{Bayesian and network-aware candidates need different evidence}
The selected nasc metadata describes an R package with Stan/Rcpp components,
not a general standalone C++ estimator. Its inspected constructor requires
a spatial matrix for selected corrections and penalties and checks that
row sums are approximately one or zero. That local calculation removes
missing values before summing. A row containing a missing entry and one
can therefore satisfy this particular sum check. A complete validator must
separately establish finite entries, dimensions, unit alignment and the
scientific meaning of the network. Further caller and model inspection
is needed before claiming that such input reaches a sampler.
\citep{exec25_synthcross_nasc,exec25_synthcross_choice}

A supplied normalized matrix is not evidence of the bank's true spillover
structure. The proposal treats this candidate as a network-aware reference
requiring explicit exposure semantics, sensitivity to missing ties and
public validation of its model and MCMC behavior. The remaining Stan models,
network assumptions and estimation delegates are unqualified. Numerical
sampling success cannot settle whether a regional policy contaminates
the proposed donor portfolios.~\citep{exec25_synthcross_choice}

The bsynth source likewise describes an R/Stan workflow. Its selected draw
helper extracts separate fitted and post-treatment arrays, joins them to
row-index-derived dates and then joins observed outcomes by date. That is
an important conversion contract: unique date keys, draw identity and
the model's meaning of each array require checks before reporting an
effect distribution. The selected source does not establish calibration
or authorize a general C++ API.~\citep{exec25_synthcross_bsynth}

Artifact rights are unresolved for this pin. The package DESCRIPTION and
the inspected R helper declare Apache 2.0, while a retained Stan include
contains GPL version 3-or-later terms. Both original declarations remain
visible; no legal conclusion follows from choosing one metadata field.
The proposed decision defers distribution or porting pending a file-level
rights review and complete model/source inspection, while retaining the
workflow as a comparison candidate.~\citep{exec25_synthcross_bsynth}

\subsection{Java discovery supports a service lead, not an estimator claim}
The bounded Java title/description search returned no matching repository;
a Java README search returned additional leads, including Tencent's
fast-causal-inference. The pinned December 2025 README describes a SQL/OLAP
architecture and lists synthetic control among incubating capabilities.
Its Java SQL gateway has a Spring-based Maven descriptor and a separate
gateway description. These authentic sources support a service-layer lead;
they do not establish an available, qualified Java synthetic-control
estimator or reproduce vendor performance claims.~\citep{exec25_synthcross_tencent}

The present choice is to defer direct estimator adoption and inspect a
concrete supported method and its engine implementation before proposing
integration. A Java-facing product could instead call a qualified R,
Python or Julia worker, but that is a design option requiring a frozen
schema, row/column identities, monetary units, clock, donor population,
failure semantics and whole-request accounting. Transporting a weight
vector or a p-value alone is insufficient. Empty Scala or Kotlin search
results and unrelated control-chart hits do not prove that relevant JVM
software is absent.~\citep{exec25_synthcross_choice}

\subsection{A common public qualification package and an honest search boundary}
The proposed public tests cover zero effects, tied and nonunique optima,
treated-unit ordering, reused mutable panels, incomplete placebo loops,
solver fallback, failed and pruned donors, missing network entries,
duplicate dates and posterior-array identities. A test records requested
and realized populations and all costs; a scientific evaluation adds a
declared assignment or sampling law and counterfactual assumptions.
These are related but distinct obligations.~\citep{exec25_synthcross_choice}

For illustration, 15,000 USD across 500 attempts, 300 conformant outputs
and 250 useful outputs gives 30, 50 and 60 USD per respective denominator.
The figures are hypothetical. Neither local compilation nor a repository's
speed claim provides actual operating cost or banking value.
\citep{exec25_synthcross_choice}

The retained queries and screened leads define a bounded search. Additional
Julia candidates, native interfaces, dependent artifacts, full network and
Bayesian models, commercial alternatives and other languages remain
uninspected. The comparisons in all three languages remain incomplete. Source comparison
can specify a credible next experiment, but cannot promise a universal
repair for unidentified counterfactual trajectories, arbitrary dependence
or unknown spillover truth. The packages have not been validated by execution in this comparison.
\citep{exec25_synthcross_choice}

For the banking decision, the preferred comparator follows from the missing
information and the defended restriction. Constrained donors limit
extrapolation; augmentation trades imbalance against model dependence;
factor reconstruction needs informative pre-treatment directions; prediction
intervals must include the uncertainty appropriate to the requested outcome.
The source studies show where those meanings can be lost through weights,
clocks, solver status or selected placebo populations. A good pre-fit curve
alone settles none of these choices. The following synthesis returns them
to population targets, rollout timing and the alternatives available to the
bank, before the later time-series treatment examines changing mechanisms.
