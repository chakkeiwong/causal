39.5.6     BayesNetty: constraints and failure values need precise translation

BayesNetty’s selected June 2025 source documents genetic-network modeling, greedy search
and random or jittered restarts. Its score documentation assumes multinomial discrete nodes
and normal continuous nodes. These sources make it a useful constrained-network reference,
but do not qualify a temporal or interventional banking estimator. The input documentation
gives ordered blacklist edges. If both directions appear in a whitelist, an adjacency is required
while either orientation is allowed. A whitelist/blacklist conflict is documented as an error.
(NewcastleRSE/BayesNetty, 2025)
   These conventions differ from pcalg’s symmetric gaps. In a two-node DAG universe, a
forbidden adjacency permits only the empty graph; banning only A → B also permits B → A;
requiring adjacency permits either one-edge orientation. Two whitelist lines do not represent an
unmeasured common cause with a bidirected edge. The proposed conversion must preserve the
predicate being asserted, with endpoint semantics carried separately from input-file conventions.
(NewcastleRSE/BayesNetty, 2025; cran/pcalg, 2024; Causal banking proposal, 2026bd)
  Failure values must also retain their meaning. The inspected serial search method returns
numeric zero when its initial network has a loop. Its caller has not been traced in this
comparison, so this does not establish the final CLI behavior. It does establish why a wrapper
cannot assume that every numeric return is a successful score. The prospective contract
needs an independent acyclicity check and an explicit failure status. The GPL3 source and
documented compiler route support a conditional reference decision, with dependency, licensing
and target semantics checked before a wider integration is enabled. (NewcastleRSE/BayesNetty,
2025; Causal banking proposal, 2026bc)


39.5.7     DBN++: filtering depends on model identity and the evidence clock

DBN++ makes the supplied-model distinction especially clear. Its February 2016 revision
describes filtering in discrete-time finite-state dynamic Bayesian networks. The three advertised
routes are variable elimination in an unrolled network, the interface forward algorithm, and

a forward algorithm using algebraic decision diagrams. The model file supplies factors and

paths do not estimate a causal structure or identify the effect of a servicing action. They can
nevertheless be useful reference calculations when a bank has justified a particular latent-state
model. The experimental file format must then carry the ordered state dictionary and the
physical meaning of a transition. (Bueno, 2016)

forward distribution, project it through the transition factors, and then update it with the
first observation. Let Dt denote a binary borrower distress state, let K(d′ | d) be its supplied
transition law, and let ℓt+1 (d′ ) be the likelihood of the next observed flag. If pt is the current

Thus a wrapper must say whether its initial distribution precedes the first evidence interval.

a service evaluating several portfolios or actions in one process. Replacing its factor objects

raises lifetime and identity questions. This is a static source finding, not an executed failure

and 9/10. The next distress probabilities before the flag are 11/40 and 21/40. Equation (39.4)
then gives posterior probabilities 44/73 and 84/103. Suppose, as an additional stipulated

39.5.8     EISALab/DBN: anomaly processing changes the observation experi-
           ment

The July 2013 EISALab/DBN revision contains a flat-file anomaly-detection application.
Its Bayesian driver selects ordinary, robust, mixture and online Kalman variants, Rao–
Blackwellized particle filters and scale-recursive methods from supplied model specifications.
The inspected path is therefore relevant to observation construction and state estimation. It
does not establish a causal structure learner merely because the repository is named DBN.
The wrapper calls an external batch-EM routine for ordinary Kalman learning; the robust
Kalman class’s two Learn overloads explicitly perform no learning. The common command-line
learning option cannot be treated as evidence that every selected filter fits new parameters.
The external numerical implementations remain outside this inspection. (EISALab, 2013)
   Its clock and output policies are consequential. The driver advances an expected timestamp
by a configured number of seconds and creates all-missing records while awaiting the next
observation. An optional sufficiently long gap resets the filter and starts another training
sequence; the shown reset branch supports only the ordinary Kalman and first particle-filter
choices. The chronology check rejects any record earlier than the expected timestamp before
applying the nominal symmetric timing tolerance. A banking adapter must therefore define
positive time resolution, arrival ordering, gaps and restart meaning explicitly. A missing
interval, a delayed report and a new customer history must not acquire the same interpretation
by accident. (EISALab, 2013)
  The ordinary filter wrapper returns an observation, lower and upper predictive limits,
a predictive mean and an anomaly indicator. In the optional cleaned file, a nonmissing
observation flagged as anomalous is written as NA. That policy may help isolate sensor failures,
but a large genuine response to a bank action is not a sensor failure. Consider an exact
randomized example: customer type U and action A are independent Bernoulli variables with
probability one half, and monetary outcomes obey

                  Y (0) = 100,       Y (1) = 100 + 100U,        R = 1{Y ≤ 150}.          (39.5)

Here R records retention after a stipulated anomaly rule, and all outcomes are accurate
measurements. The population treatment effect is USD 50. Among retained treated customers
only type zero remains; both retained group means are USD 100, so their contrast is zero. At a
stipulated action cost of USD 20, the population net benefit is USD 30 while the retained-row
comparison suggests USD −20. Randomization before cleaning does not justify the latter
comparison after outcome-dependent selection. This is a constructed law, not an assertion that
the external filter necessarily implements this threshold or produced these results. (Causal
banking proposal project, 2026hg)
   The defensible alternative retains the original outcome, flag, missingness reason and trans-
formation history as separate fields. A causal analysis must justify any exclusion, model
the measurement or selection mechanism when appropriate, and examine sensitivity when

scientific and interface reference until dependency, rights and numerical behavior are resolved.

39.5.9     pdbntk: a parallel skeleton is not a fitted dynamic model

The July 2013 pdbntk revision describes a parallel dynamic-network toolkit, but the actual
demonstration path is unfinished. Its executable declares hidden-state models and allocates
40,000 sequences of length 100, then passes a DummyInfEngine to the parallel driver. That
engine performs an arithmetic workload and returns one for each sequence, with an empty
vector of sufficient-statistic objects. The iteration loop repeatedly calls its expectation routine;
the maximization routine is empty and is never called, and the convergence flag is never
updated. If those loops complete as written, the last accumulated value is 40,000, irrespective
of the observations. Its printed label loglik does not make it a fitted likelihood. No timing,
successful build or native execution is inferred here. (ushadow, 2013; Causal banking proposal
project, 2026hg)
   The alternative junction-tree interface does not close the gap: its sequence evidence entry
returns zero and its sufficient-statistic method returns an empty vector. A separate tabular
parser checks header identities and numeric characters but appends an empty observation map
without inserting the parsed values. These are concrete reasons to reject the inspected path as
an admitted learning backend. They do not show that the borrowed Mocapy++ and libDAI
libraries lack their own inference capabilities. The driver also shares one inference-engine
pointer across its OpenMP region; replacing the dummy with a mutable engine would require
an explicit state-ownership design before parallel correctness could be claimed. (ushadow,
2013)
   For banking, an acceptable future EM implementation would need an observation contract,
actual posterior sufficient statistics, a defined parameter update, an evaluated objective and
convergence diagnostics. Those requirements concern parameter estimation in a supplied
model; successful EM would still not turn an observational hidden-state model into an identified
intervention model. The selected build depends on Boost, OpenMP, GMP, LAPACK and
borrowed native libraries. Inspected libDAI and Mocapy headers carry distinct notices,
while the tree has no project-root license. Resolve their respective scope before reuse. The
appropriate current role is an unfinished design reference, with no claimed bank benefit from
parallelism. (ushadow, 2013)

39.6     Temporal discovery in Julia, Rust and MATLAB
A treasury analyst can ask whether yesterday’s pricing action predicts tomorrow’s retained
funding, whether a common liquidity shock explains both, or what funding would change if
a particular action were imposed. These questions require different mathematical objects.
A predictive lag, a structural lag coefficient, a supplied dynamic Bayesian network and
a distribution-change orientation rule cannot share an unqualified causal edge field. The
languages considered here provide useful alternatives, but the proposed product must preserve
the question that each alternative actually answers.

39.6.1    The observation clock precedes the choice of engine

Let Xit denote quantities recorded for account i on business date t. The index must carry
a sampling interval, calendar and availability rule: a one-step lag in daily closing balances
is different from a one-step lag in monthly averages. The closing balance can also become
available after the pricing decision. An engine that accepts an array cannot recover these
facts from its dimensions. Joining accounts into a single series can create lags across account
boundaries; treating account copies of the same market shock as independent observations
can create spurious precision. These are input and sampling-law questions even when the
numerical estimator is correct.
   The proposed temporal request should consequently declare entity and trial boundaries,
timestamp alignment, units, missing dates, event and availability times, lagged and contem-
poraneous variables, and regime labels. Its causal part should separately declare the action,
intervention type, outcome horizon, population and identification assumptions. A one-time
structural innovation, a persistent policy replacing a conditional distribution, and a surgical
setting of one state coordinate have different propagation laws. This is a proposed contract; it
has not been enabled by inspecting software. (Causal banking proposal, 2026dd)
