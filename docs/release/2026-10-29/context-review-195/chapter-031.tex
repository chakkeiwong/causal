\chapter{What the local study interfaces preserve}
\label{scisyn:investment}

\section{One question through three ways of using the library}
An illustrative economist asks about the twelve-month value of an offer among
eligible accounts. The supplied diagram contains an arrow from offer to value,
and the sampling assumption is independent accounts. That diagram is explicitly
unverified. The local walkthrough sends the same question through the Python
library, a command-line process and a local MCP client. It exercises the
repository's existing implementation; it does not connect another repository,
invoke a language model or fit an external statistical package.

Four cases have distinct economic interpretations. The diagram check preserves
the supplied graph and establishes only its accepted syntax. The adjustment
calculation returns a result conditional on the supplied graph and independent
sampling. The information-date check examines three constructed records:
one was available before the decision, one became available afterwards, and
one lacks an availability date. The latter two are flagged. Finally, changing
the sampling law to dependent months causes the identification request to be
reported as unsupported by that route.

An initial client attempt timed out during initialization after 20 seconds.
The retry used the established bounded environment with one numerical thread;
the cause of the first timeout was not conclusively isolated.
The saved retry responses agree exactly across all three interfaces for the four
cases. The local MCP negotiation uses protocol 2025-11-25 and the installed
1.27.0 SDK. This is a bounded observed result. It establishes neither general
protocol compatibility nor the scientific truth of the supplied assumptions.
An unsupported scientific request can be delivered successfully by the command
line and protocol: the economist must read the substantive disposition rather
than infer validity from a successful process exit.

The executable walkthrough is reproduced from the repository root by
\begin{quote}\small\ttfamily
python3 tools/run\_banking\_walkthrough\_20261029.py
\end{quote}
It requires the locally installed research dependencies recorded with its
results. The numerical offer comparison is reproduced by
\begin{quote}\small\ttfamily
python3 tools/run\_scientific\_synthesis\_20261029.py
\end{quote}
Both calculations use constructed inputs. Neither is a completed customer
policy analysis. A full study still needs observed assignment and outcome
information, a justified design, estimation and interpretation.

The separate sparse-support comparison can be reproduced with
\begin{quote}\small\ttfamily
python3 tools/run\_sparse\_support\_20261029.py
\end{quote}
Its narrower and broader normal-model intervals make their additional
assumptions and loss of precision explicit.

The actual public-data timing comparison uses the retained UCI archive:
\begin{quote}\small\ttfamily
python3 tools/run\_public\_timing\_20261029.py
\end{quote}
It fits the specified prediction models; it does not estimate a contact effect.

\section{How public evidence can support the proposal}
Public records and generated data serve different purposes. The executed UCI
comparison shows why a variable's availability can outweigh its apparent
predictive benefit. The retained UCI
Bank Marketing description supports a useful information-date example and
data-preparation exercise, but not an experimental effect of calling. FDIC
branch deposits and institutional histories are promising for observation and
panel construction; the documented branch outcomes do not make a merger or
closure exogenous. ACIC provides a route to comparing methods with generated
causal truth while retaining the distinction between real covariates and
simulated outcomes.
\citep{pd15_uci_bank,pd15_fdic_sod,pd15_fdic_api_spec,pd15_acic_pinned}

Use generated studies to test questions with known answers, then public data
to expose realistic observations, missingness and timing. The offer experiment
already changes a design requirement: outputs must distinguish projections
from population benefits and report sparse-support failures. The walkthrough
changes another: a study must preserve scientific meaning when passed between
interfaces. Neither result warrants spending on a broad bank trial yet. The
next public comparison should ask whether these protections materially improve
an analyst's completed study relative to ordinary practice.

The economic comparison of these workflows is developed in
Chapter~\ref{rewrite:investment-decision}. Its account includes unsuccessful
studies, correction, interpretation and maintenance, and distinguishes a
prototype comparison from a later bank-data pilot.
