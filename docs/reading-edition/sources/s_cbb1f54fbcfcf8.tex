\section{Why reported uncertainty must survive a change of software}
\label{sec:exec29-panel-runtime-semantics}

A panel adapter needs a runtime contract as well as an estimator contract. The bank's question might be unchanged when software moves between machines, yet the covariance dispatch, random-number implementation or result attributes can differ. This distinction matters for a servicing-policy comparison whose analyst combines branch estimates through a CLI and whose downstream agent reads the same objects through MCP. A dependency name does not identify the executed method, and a repository snapshot does not establish the installed dependency graph. The selected cutoff sources make three concrete requirements visible: align covariance by coefficient identity, state the multiplier law, and preserve uncertainty metadata at the row or result level.\citep{exec29_panel_runtime_sources}

\subsection{Software versions and the scope of the evidence}

The selected R development commit reports version 4.7.0 under development. A separately pinned commit on the 4.6 branch reports 4.6.1 Patched. The locally available runtime reports R 4.1.2; none of the selected panel and data-frame packages was installed in that inspection. These facts describe three different objects. The development and patched branch sources can support a bounded comparison of selected methods, but neither is evidence of a released binary or the local execution environment. The constructed numerical check below uses the installed runtime and records its method bodies. It does not execute the acquired parglm, fastdid, BMisc or data-frame package code.\citep{exec29_panel_runtime_sources,exec29_panel_runtime_reference}

The selected dependency candidates declare Rcpp 1.1.2, RcppArmadillo 15.6.0-1, dplyr 1.2.1 and tibble 3.3.1. Version and licence declarations identify the candidate and its stated dependency constraints; they do not prove that those versions form a complete, buildable or rights-cleared product profile. A supported service must bind the interpreter, package versions, compiler and numerical libraries to the result. Public qualification must record successful and failed build attempts under that profile, rather than equating an acquired source tree with a reproducible installation.\citep{exec29_panel_runtime_sources}

\subsection{Covariance has an ordering, even when it has names}

The selected R summary.glm method obtains the stored QR object, uses its pivot to order the coefficient names, and computes covariance from the leading triangular factor. The selected vcov.glm calls summary.glm explicitly. In the full-rank case its aliased-coefficient helper returns that covariance without restoring the original coefficient order. This matches the earlier reason for inspecting parglm's own pivot-aware summary and covariance methods: a caller that changes the class to glm must not assume that a matrix multiplication later aligns its columns by their displayed names. The selected fastdid nuisance path multiplies a score matrix built in covariate-column order by the returned covariance numerically.\citep{exec28_panel_estimator_sources,exec29_panel_inference_sources,exec29_panel_runtime_sources}

Consider original coefficient order $(a,b)$ and a coherent triangular factor $R=\operatorname{diag}(2,1)$ in pivot order $(b,a)$. With dispersion one, the covariance in pivot order is $\operatorname{diag}(1/4,1)$, whereas the covariance in original order is $\operatorname{diag}(1,1/4)$. For an original-order score vector $s=(1,0)$, the quadratic form $sVs^{\mathsf T}$ is $1/4$ if the pivot-order matrix is consumed positionally and one after correct alignment. An authored constructed-object fixture using the installed R runtime reproduces both values and the returned covariance names. The independent rational calculation gives the same result.\citep{exec29_panel_runtime_reference}

The condition on the pivot is essential. This fixture deliberately supplies a nontrivial full-rank pivot and does not demonstrate that fastdid's default LINPACK path reaches it. The inspected parglm source also exposes LAPACK and FAST paths with different rank and pivot behavior. Native reachability, rank-deficient covariance placement and a complete nuisance-influence comparison remain tests for an exact installed profile. The supported adapter should align covariance against an explicit coefficient identifier vector, reject missing or duplicate identifiers, retain aliases and rank, and propagate nonconvergence before calculating influence terms. The same requirement applies to a port in Python, Java or C++: names attached to a matrix are not an automatic proof that subsequent positional operations respect them.\citep{exec29_panel_inference_sources,exec29_panel_runtime_sources,exec29_panel_runtime_reference}

\subsection{Packed multiplier bits need a stated law}

The selected BMisc generator samples a positive integer up to $2^{31}-1$ and extracts its bits to produce up to 31 signs. In the selected Rcpp integer-sampling overload, one-based output is the default and a size-one request reaches the expression that converts $nU+1$ to an integer, where $U$ is supplied by the runtime's uniform generator. The inspected RcppArmadillo header includes Rcpp, while the separately inspected sampling extension has its own namespace and include guard. These selected paths support a conditional analysis of positive-integer bit extraction; complete header inclusion, build options and the actual finite-state RNG law still require a pinned native build.\citep{exec29_panel_inference_sources,exec29_panel_runtime_sources}

Under the deliberately idealized law in which the integer is uniform on $1,\ldots,2^b-1$, every $b$-bit pattern except the all-zero pattern has equal probability. Let $S_j=2B_j-1$ be the sign for bit $j$. Counting patterns gives
\[
 \mathbb E[S_j]=\frac{1}{2^b-1},\qquad
 \mathbb E[S_jS_k]=-\frac{1}{2^b-1}\quad(j\ne k),
\]
and hence
\[
 \operatorname{Cov}(S_j,S_k)=-\frac{2^b}{(2^b-1)^2}.
\]
The all-negative block has probability zero under this conditional law, rather than $2^{-b}$ under independent symmetric signs. Exhaustive enumerations for $b=2,\ldots,8$ verify the counting formula, and the authored reference evaluates the exact fractions for $b=31$. The discrepancy is small at that block size. It is a distinction between laws, not an established material confidence-coverage defect. Nor does the ideal-uniform calculation establish the probabilities produced by the actual finite-precision generator.\citep{exec29_panel_runtime_reference}

For a public qualification trial, the relevant question is whether the intended bootstrap theorem and finite algorithm refer to the same multiplier distribution. The test contract should record block size, seed, RNG kind, exact sampling implementation, dependence between signs, number of attempted draws and any filtered outcomes. A separately implemented independent-sign reference can test sensitivity under a stated alternative law. It cannot silently replace the package generator while preserving a claim of bitwise native reproduction. A scientific conclusion about coverage requires the full influence construction and sampling experiment, not just a label such as Rademacher attached to a helper.\citep{exec29_panel_runtime_sources,exec29_panel_runtime_reference}

\subsection{Row binding can inherit the first result's confidence attribute}

The selected dplyr \texttt{bind\_rows} implementation retains its first input as a template, combines rows through vctrs, and then reconstructs the result using that template. Its default data-frame reconstruction clears other result attributes and installs the template's attributes except for names and row names. The inspected dplyr and tibble namespace files show no dedicated reconstruction method for the nonabsdid result class. Under that selected default route, a confidence-level attribute belongs to the first template; it is not a reconciliation of the levels used to construct every incoming interval. External method registration, other subclasses and the complete vctrs route remain separate qualifications.\citep{exec29_panel_runtime_sources}

This narrows the earlier uncertainty without overstating it. Two already tidied result objects can carry different native interval levels, and the inspected nonabsdid idempotent conversion does not recalculate them merely because a caller supplies a new level. An interface that then relies on one inherited table attribute can describe a mixed collection misleadingly. The proposed contract preserves a result identifier, native method, outcome, interval level and derivation provenance for every row group. A list-level request either verifies uniformity or returns the heterogeneity explicitly. An agent may explain or compare those results, but should not infer a common inferential guarantee from the appearance of a common table.\citep{exec29_panel_inference_sources,exec29_panel_runtime_sources}

The adoption route is therefore conditional and testable. Pin the full runtime; align parameter identities; expose solver and rank failures; separate ideal multiplier references from native RNG behavior; and carry uncertainty provenance through reconstruction. The constructed covariance fixture and exact bit-counting formulas close bounded questions about possible semantic failures. They do not close native package calibration, transitive rights, complete coverage or institutional acceptance. The product proposal can specify these tests now and use public profiles to justify their cost, while retaining the limits of what the current evidence establishes.\citep{exec29_panel_runtime_sources,exec29_panel_runtime_reference}
