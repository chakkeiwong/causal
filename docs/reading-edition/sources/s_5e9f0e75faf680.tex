\section{MCP across languages: preserving a causal decision through an executable interface}
\label{sec:exec24-mcp-reuse}

A causal tool becomes useful to a bank when another application can ask the
right question and interpret its answer without silently changing its meaning.
Consider a servicing analyst asking whether a payment holiday reduces default
among eligible accounts. The proposed library must distinguish the assignment
of the holiday from its receipt, define the decision date and eligible
population, identify subsequent default, and retain the assumptions supporting
an intervention contrast. A protocol can carry this information, but successful
message exchange cannot supply missing assignment information or establish that
the proposed comparison identifies a causal effect. This distinction governs
the choice among the official Python and TypeScript SDKs, Java, the separate
FastMCP project, R interfaces and concrete C++ implementations.
\citep{exec24_mcp_contracts}

The inherited protocol comparison distinguishes the 2025-11-25 initialization
handshake from the 2026-07-28 discovery and per-request model. Those identities
remain intact. The selected new source revisions are bounded by the 7 October
2026 research cutoff. They are evidence about those source trees, not a claim
that a particular distribution has been installed or that every client can
negotiate every server. A software version, a protocol revision, a transport
and an application schema are separate coordinates. Compatibility must name
all four, together with the configuration that determines validation and
failure handling.\citep{v12_mcp_legacy_lifecycle,v12_mcp_basic,
v12_mcp_versioning,exec24_mcp_contracts}

\subsection{What the boundary must preserve}

Let a scientific request be
\[
 q=(\mathcal P,t_0,A,Y,\mathcal G,\mathcal A,\psi,\mathcal D),
\]
where $\mathcal P$ is the target population, $t_0$ the information cutoff,
$A$ the action, $Y$ the outcome, $\mathcal G$ the graph with endpoint marks,
$\mathcal A$ the identifying assumptions, $\psi$ the estimand and $\mathcal D$
the immutable data identity. A result requires a scientific status, an
estimate or identified set when justified, uncertainty, diagnostics, units,
and the request and artifact identities. Protocol status and tool execution
status are additional fields. A refusal can be a correctly executed and
scientifically appropriate result; a well-formed number can still be an
inappropriate answer.\citep{exec24_mcp_contracts}

This requirement can be expressed without assuming a particular language.
If $E$ encodes a scientific object for transport and $D$ decodes it, an accepted
profile should satisfy $D(E(q))\equiv q$ on the declared domain. Here
equivalence concerns scientific meaning, not byte identity: reordered JSON
keys can be harmless, whereas replacing a circle endpoint by a tail is not.
A graph with $X\to Y$ and one with $X\mathbin{\circ\!\!\to}Y$ collapse to
the same ordered pair if the serializer retains only node names. No decoder
of that pair can uniquely recover both originals. The proposed interface must
preserve endpoint marks or refuse the unsupported graph type.
\citep{exec24_mcp_contracts}

An equally simple monetary example exposes the limits of type checking.
Two objects can both contain an integer estimate equal to one and a string
unit, while one denotes USD and the other thousands of USD. Both satisfy that
elementary shape predicate; their normalized values are 1 and 1,000 USD.
Similarly, a nonidentified result with a missing estimate and an identified
zero effect both become zero under a missing-to-zero fallback. The proposed
scientific schema therefore uses explicit status, units and uncertainty
objects, and validates relationships between fields. These are authored
counterexamples to insufficient contracts, not observed failures in any
selected SDK.\citep{exec24_mcp_contracts}

Even a complete shape contract cannot establish identification. Let an
unobserved fair binary variable $U$ determine holiday assignment $A=U$ and
potential default $Y(a)=U$ for both actions. The observed difference between
$A=1$ and $A=0$ is one, while
\[
 E\{Y(1)-Y(0)\}=0.
\]
A typed result containing the observed difference remains noncausal for this
construction. The interface must retain the evidence and assumptions by which
the engine distinguishes association, an identified effect, an identified
set and refusal.\citep{exec24_mcp_contracts}

\subsection{Official Python and TypeScript: version and validation are explicit choices}

The selected Python source is an MCP 2.x development tree with dynamic package
versioning. Its old \texttt{mcp.server.fastmcp} module deliberately raises an
import error and directs users to \texttt{MCPServer} or a version-one pin. This
is a concrete migration boundary; it does not make the separate FastMCP
project an alias for the SDK. The protocol registry is delegated to
\texttt{mcp-types}, whose inspected source enumerates four handshake revisions
through 2025-11-25 and the modern 2026-07-28 revision. Unknown version strings
are not accepted by its ordered comparison helper merely because their
lexical order is high. The proposal should pin the SDK and its delegated type
package together and retain the existing legacy profile as a separate
compatibility case.\citep{exec24_mcp_python}

The inspected Python client validates a successful tool result against a
declared output schema. It refreshes the tool listing when the name is absent
from its schema cache, warns if the tool still cannot be found, and raises
for missing or nonconforming structured content when a schema is available.
The high-level server's result conversion has a separate condition: an output
schema supplied without an output model is advertised but is not validated
by that conversion routine. Direct tool-result objects are checked through
the output model only on the successful-result branch. These observations
identify where an adapter must supply and verify its application contract;
they do not establish that every low-level path has the same behavior.
\citep{exec24_mcp_python}

The selected TypeScript core and server packages declare version 2.3.1 and
Node 20 or later. Its client can compile an output validator before sending a
tool request, exposing invalid schemas before the tool body is invoked.
Successful results with an available validator must carry structured content
and conform to it. However, the inspected cache path reports a cache-store
error and can continue without that validator. A caller-supplied tool
definition provides an explicit alternative. A bank adapter should record
which definition was used and should refuse to upgrade an unvalidated
transport result to a qualified scientific result.\citep{exec24_mcp_typescript}

The same TypeScript path can refresh a tool listing and retry once after a
specific modern parameter-header mismatch. This is a narrowly implemented
recovery path, not a general exactly-once guarantee. It relies on the error
meaning and the server's corresponding behavior. The product's logical
operation identifier must remain stable across transport attempts, while
attempt identifiers and actual costs remain distinct. A source inspection
does not establish how an arbitrary remote server behaved before reporting
an error.\citep{exec24_mcp_typescript,exec24_mcp_contracts}

The selected Python root notice is MIT. The TypeScript root notice describes
an ongoing MIT-to-Apache transition, retaining original MIT terms for
contributions without relicensing consent; the package declaration alone is
not a complete provenance inventory. The comparison records those notices
and leaves distribution-level dependency and rights review to the exact
artifact selected for a prototype. Reference use is justified now;
conditional integration follows a resolved environment and shared public
contract fixtures. Reimplementing an entire evolving protocol is unlikely
to be justified by a banking-specific output requirement that can instead
be enforced at a narrow adapter boundary.\citep{exec24_mcp_python,
exec24_mcp_typescript,exec24_mcp_contracts}

\subsection{FastMCP is a separate, layered candidate}

The selected former \texttt{jlowin/fastmcp} repository resolves to
\texttt{PrefectHQ/fastmcp}. Its root and slim package declare dynamic versions;
the source pin is the reproducible identity here. The slim package separates
core dependencies from client, server and MCP extras, with a selected
\texttt{mcp>=2,<3} dependency range. The original Apache notice is retained.
Neither the historical SDK class name nor an install command establishes
parity with this separately maintained composition.
\citep{exec24_mcp_fastmcp}

The inspected server applies middleware by default and resolves an unspecified
tool version to the highest available version. Its error policy preserves
explicit tool errors and can mask other exception details; rate limits and
timeouts receive actionable error messages. Consequently, the scientific
adapter should bind a specific tool revision, middleware configuration and
result schema. A middleware transformation that compresses an identified
set into prose requires the same semantic review as any other lossy
conversion.\citep{exec24_mcp_fastmcp,exec24_mcp_contracts}

The client offers two useful but different interfaces: the raw MCP call
returns the protocol result and error flag, whereas the convenience call
raises a tool error by default. Neither should cause failed requests to
disappear from a reliability or cost denominator. The inspected function-tool
timeout path also explains that worker threads can shield cancellation until
they finish; it rejects a result that arrives after the deadline. Rejecting
a late result is distinct from proving that external work stopped at the
deadline. The proposed wrapper therefore reconciles remote job state and
side effects explicitly.\citep{exec24_mcp_fastmcp}

The adoption decision is conditional integration for a prototype requiring
its composition and middleware facilities, with reference-only standing
until the native profile is tested. A direct SDK adapter remains a substantive
alternative when the needed surface is smaller. Selective porting may be
reasonable for a stable, independently specified conversion, but importing
large orchestration internals creates maintenance obligations that must be
compared with the cost of retaining the upstream package.
\citep{exec24_mcp_contracts}

\subsection{R and Java: language access does not imply identical result semantics}

The selected Posit \texttt{mcptools} source declares version 1.0.3.9000,
R 4.1 or later, and dependencies including \texttt{ellmer}, \texttt{httpuv},
\texttt{nanonext} and \texttt{jsonlite}. Its MIT notice and development-version
identity are preserved. The inspected protocol registry ends at 2025-11-25;
that is not evidence of the newer discovery profile. A shared protocol
revision is only one prerequisite for interoperability.
\citep{exec24_mcp_r}

Its result conversion is particularly relevant to causal estimators written
in R. Structured content is not produced for protocol revisions earlier than
2025-06-18. Even on a later revision, the inspected predicate excludes data
frames, matrices and arrays from automatic structured content and requires
fully named entries for the accepted list-like case. This does not establish
that those excluded values cannot be represented at all: another content
representation may be returned. It means a scientifically typed estimate,
covariance matrix or identified set needs an explicit envelope rather than
an assumption that the original R object survives transport unchanged.
\citep{exec24_mcp_r}

The R client distinguishes JSON-RPC errors, tool errors and successful
structured results when converting to \texttt{ellmer}. On a local interrupt
it attempts a cancellation notification and then rethrows the interrupt;
the helper declines to cancel initialization and returns false when sending
the notification fails. The presence of that attempt does not prove remote
termination. An R adapter should preserve the remote request identity and
report an unresolved outcome until its reconciliation rule is satisfied.
\citep{exec24_mcp_r,exec24_mcp_contracts}

The selected Java source declares 2.1.0-SNAPSHOT and Java 17. Its inspected
protocol constants also stop at 2025-11-25. The async server delegates input
validation to a helper that returns without validation when validation is
disabled, the schema is absent or empty, or no validator is supplied. When
enabled validation fails, it returns a tool-error result. The client skips
output validation when schema caching is disabled or the result is a tool
error; an unavailable cached output schema produces a warning and leaves
the result unchanged. Its no-argument tool-listing method follows cursors
and aggregates pages. These are concrete configuration and conversion
contracts, not a claim of default equivalence across transports.
\citep{exec24_mcp_java}

For a bank's Java service estate, a bounded adapter can be attractive because
it avoids rewriting numerical estimators merely to expose them as tools.
The scientific engine can remain in its justified implementation language.
The public prototype must compare exact inputs, refusal and uncertainty
objects through both the native library and the Java boundary, including a
tool on a later listing page, disabled-validation configuration and malformed
structured results. Porting an estimator is a separate numerical decision
requiring its own reproducibility and uncertainty evidence.
\citep{exec24_mcp_java,exec24_mcp_contracts}

\subsection{Three C++ candidates require three distinct decisions within the comparison}

The C++ search resolves a language umbrella into concrete source trees.
The selected \texttt{hkr04/cpp-mcp} declares a 2025-03-26 protocol constant
and an MIT root notice. Its inspected tool serializer publishes a name,
description, input schema and optional annotations. The default tool-call
handler invokes the registered callback, wraps returned content and
converts ordinary exceptions to tool errors. That selected path does not
perform an input-schema check before invocation or return a separate
structured-content field. An application callback may implement additional
checks, and these observations do not assert product-wide absence of every
extension. They do establish that this path needs an explicit application
adapter before carrying the proposed scientific contract.
\citep{exec24_mcp_cpp_hkr}

The \texttt{jesspig/modelcontextprotocol-cpp-sdk} source identifies SDK 0.3.5
and includes protocol revisions through 2026-07-28. Its synchronous callable
wrapper converts caught exceptions to tool-error results. The inspected
asynchronous server path validates an output only when both an output schema
and structured content are present. This condition alone does not reject
missing structured content when a schema exists. Task execution also has
an explicit era boundary: the selected branch rejects task-mode tool calls
under the modern protocol and permits the older path under its declared
conditions. The cancellation flag is exposed in request context, allowing
cooperative checks; it is not proof that a callback or external transaction
has already stopped.\citep{exec24_mcp_cpp_jesspig}

The \texttt{vogler75/mcp-cpp-sdk} source declares version 0.1.0. Its model
supports structured tool results, an error flag and serialization of the
structured field. The selected router dispatches a known tool to its handler
and returns a tool-error result for an unknown name; no schema validation is
shown in that router. Its cancellation token propagates a cancellation state
to children and exposes cooperative polling. The root notice, like the
selected TypeScript notice, explicitly retains a licensing-transition
qualification. These details justify separate profiling rather than treating
all C++ implementations as interchangeable.
\citep{exec24_mcp_cpp_vogler}

For all three, a reference disposition is appropriate at this stage, with
conditional integration against the exact scientific adapter. A small C++
wrapper around an existing engine may avoid serializing large native objects,
but it still needs stable artifact custody, bounded resource use and exact
error semantics. Porting the protocol or estimator is not required merely
because the surrounding application is C++. The relevant comparison includes
maintenance, dependency resolution, compiler and platform support, conversion
cost and the effort needed to prove the declared profile.
\citep{exec24_mcp_contracts}

\subsection{Public qualification before expensive bank experiments}

Declared version sets illustrate the difference between a necessary condition
and a qualified integration. In the finite authored example, the Python
registry, the R registry and the hkr C++ constant share only 2025-03-26.
That intersection does not prove a successful native exchange, and selecting
it removes the newer R automatic structured-content route described above.
An adapter must either use an explicitly specified compatible representation,
select a different profile, or refuse the requested result type. Silently
downgrading a protocol while retaining claims about a newer output contract
is not an acceptable conversion rule.\citep{exec24_mcp_python,
exec24_mcp_r,exec24_mcp_cpp_hkr,exec24_mcp_contracts}

Cancellation and retry deserve a public fixture with a durable external
action. In the authored event history, a 500 USD charge commits at time two,
cancellation is requested at time three and local cancellation is observed
at time four. The charge remains 500 USD; a naive retry can make it 1,000 USD.
This example does not accuse any SDK of making a duplicate charge. It shows
why the bank adapter needs an idempotency key for the economic intent, an
attempt ledger, an outcome that can remain unresolved, and reconciliation
with the external owner. A protocol request identifier alone is not that
economic key.\citep{exec24_mcp_contracts}

A proposed qualification suite should first use generated requests whose
graph, units, information cutoff, identification status and intended output
are known. It should then pass the same requests through the library, CLI
and each declared MCP adapter. The oracle checks scientific equivalence,
not merely that some text was returned. Adverse cases include unsupported
endpoint marks, nonidentification, missing versus zero, wrong currency scale,
absent output schemas, disabled validators, malformed structured results,
late replies, interrupted work, repeated delivery and list pagination.
Public fixtures can establish the merit of conducting later bank trials
without pretending to supply genuine bank assignment truth.
\citep{exec24_mcp_contracts}

The denominator must remain the original request population. Suppose 100
requests are submitted, 90 return a protocol result, 80 report tool success
and 60 satisfy the scientific contract. Qualified yield is $60/100=3/5$;
the conditional fractions $60/90=2/3$ and $60/80=3/4$ answer different
questions. With hypothetical expenditure of 18,000 USD, cost per submitted,
returned and qualified request is 180, 200 and 300 USD respectively. The
expense includes failed and interrupted work, retries, remote charges,
operator review and maintenance. These exact examples define the comparison;
they are not measured prices, latency or realized bank value.
\citep{exec24_mcp_contracts}

The scientific owner remains responsible for the intervention question and
assumptions; the statistical owner for uncertainty, dependence and refusal;
the adapter owner for conversion and durable identities; and the platform
owner for versions, dependencies, rights, resource limits and recovery.
The source-based choices now identify concrete integration routes and
reasons to defer unconditional adoption. They do not close the hosted/local
model-backend survey, broader framework and language search tails, native
public qualification or the frontier literature census. The proposed integration still requires independent review.
\citep{exec24_mcp_contracts}
