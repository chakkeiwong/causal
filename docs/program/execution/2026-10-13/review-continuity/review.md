# Preserve acceptance reviews as the monograph changes

The current proposal controller correctly required Q1–Q5 to review the exact delivered reader. However, it also rejected every second result for the same operation and required the same fixed output filename. After a reader changed, an earlier passing review no longer counted, but it could not be replaced through the current controller without either overwriting evidence or changing the program contracts. A temporary-workspace regression reproduced the rejection: `Task already recorded; create a reviewed successor, do not rerun it`.

The repair adds an explicit `reopen` transition for proposal acceptance reviews. It requires a reason, the exact prior result, the actual current reader, evidence and a next action. It archives the previous binding and preserves its receipt and output files. Later reviews use a versioned output path beneath the original logical output directory, keyed by the reader hash and review attempt. The original operation contract, criteria and capability restrictions stay in force. The adapter to the inherited validator changes only the expected physical output paths during validation and checks the original contract hash first.

Recorded prerequisite identities let an old Q5 review remain replayable when a prerequisite review is reopened. They must correspond to actual preserved ledger receipts, with matching operation, outcome and capabilities. This historical replay does not grant acceptance to the new reader: all five current reviews must still pass, and Q5 still requires Q1–Q4 to concern exactly the current path and hash. Nonexecuted negative dispositions retain their missing prerequisites and cannot become acceptance.

The transition cannot reopen ordinary completed operations or a passing review of the same reader. Reopening starts an active continuation without granting acceptance. Invalid or changed evidence, stale reader bindings, incorrect attempt numbers and reuse of an earlier output path are rejected. The existing lock and stale-state checks protect canonical commits. A template request for already recorded work is rejected before it can suggest rewriting an immutable output.

Author review checked the initial failing regression, a changed-reader second review with byte-identical earlier receipts/outputs, preserved negative outcomes, missing-prerequisite dispositions, replay of a previous Q5 review while Q2 is open, changed historical evidence, old-output reuse and ordinary-task protection. The final focused suite includes the existing execution and proposal-scope tests: 36 tests pass. These are temporary-workspace controller checks; no real proposal acceptance receipt was created.

The controller does not independently verify scholarship or run an unattended agent. The actual Q2 review remains active on the 469-page reader, with complete structural source checks and a bounded initial primary-text review. Its remaining semantic review is recorded separately. The broader manuscript coverage and rendered-release requirements remain open.
