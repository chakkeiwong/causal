\section{Identification software must preserve what is and is not identified}
\label{exec18:r-identification}

Suppose a bank is considering an encouragement to make an additional repayment. Let $A$ denote randomized access to a reminder and $Y$ denote repayment by twelve months. The business question may ask for the effect of offering the reminder, whether a particular customer would repay only if reminded, or the range of possible repayment effects when an assumption is unavailable. Those are three different targets. A fitted conditional association, an interventional functional, a cross-world probability and a sharp identified set do not have interchangeable meanings. The proposed interface must name the target and information regime before it calls an R package.

For a supplied directed acyclic graph, \texttt{dagitty} can enumerate covariate sets that block specified back-door paths. That is a useful graph diagnostic; it is not a general algorithm for deriving every interventional functional under latent confounding. The existing \texttt{pcalg} and \texttt{bnlearn} comparison adds equivalence-class and causal-network procedures, but their returned graph or effect list has its own model class and assumptions. In particular, \texttt{pcalg}'s IDA manual specifies a linear Gaussian total-effect target over admissible DAG extensions. It is neither an arbitrary nonlinear effect region nor a confidence set for a bank decision. The \texttt{ivmodel} confidence-set interface answers another question again: it preserves weak-instrument and unbounded-set behavior under its declared IV design. A single label such as “causal effect” would erase these distinctions~\citep{exec13_other_dagitty,exec13_pcalg,exec13_bnlearn,v12_sw_ivmodel}.

The R package \texttt{causaleffect} supplies symbolic ID/IDC functionality and selected transportability and selection-recovery procedures. Its pinned R function accepts outcome, treatment, optional conditioning variables and a graph; it can return an expression or a derivation object. The selected implementation has an important adapter consequence: with its default \texttt{stop\_on\_nonid=TRUE}, nonidentification raises an error; with the option false, a failed identification can be represented by \texttt{id=FALSE} in the step result, an empty string, or \texttt{NULL}, depending on the other output options. A production wrapper must distinguish that documented algorithmic result from parse errors, unsupported graphs and runtime exceptions. It should also retain the graph class and functional, not just a Boolean or formatted string~\citep{exec18_rid\_causaleffect}.

The pinned \texttt{dosearch} package asks whether an interventional target follows from multiple observational or experimental distributions and a graph, including selected transport, selection and missingness mechanisms. Its 2021 paper describes a sound search over do-calculus rules and completeness for the problem classes characterized by those rules. The package documentation expressly says its missing-data search is not complete. More subtly, the pinned C++ source applies a positive time limit by returning early from the search; its initializer then decides identifiability from whether a target distribution was found and does not expose a separate timeout state in that result. Therefore, under that code path, a limit-truncated search can be represented like “not identifiable by this search.” An adapter must not promote that output to a proof of nonidentifiability. It must either disable the limit for the bounded admitted problem, instrument a distinct timeout/unknown state, or report the uncompleted search as unknown. This is a source-level review of a pinned revision, not an executed package trial~\citep{exec18_rid\_dosearch,exec18_rid\_dosearch\_paper}.

Counterfactual identification is a further level. \texttt{cfid} implements ID*/IDC* for counterfactual conjunctions by constructing a parallel-worlds graph with shared latent variables and then applying recursive identification. Its function defaults to identifying from interventions, not from observations; the observational level must be requested or obtained through the documented alternatives. A true \texttt{id} field is not sufficient on its own: an inconsistent conjunction may be identifiable with probability zero, and a conditional query may be undefined when its conditioning event has zero probability. An adapter therefore retains the requested data level, identifying formula, inconsistency/undefined flags and query itself. The author manuscript for the 2023 package paper is preserved locally as the arXiv version; the published R Journal identity and date are separately recorded. No claim depends on substituting metadata for that original technical text~\citep{exec18_rid\_cfid,exec18_rid\_cfid\_paper}.

When point identification fails, bounds may still be useful, but their scope is not universal. \texttt{causaloptim} encodes certain graph-defined response-function problems as linear programs and permits added constraints; its documented graph attributes and admissible left/right structure delimit the class. \texttt{bpbounds} implements binary treatment and outcome bounds for an instrument with two or three categories, in a single trivariate table or a specified two-source bivariate design, with separate monotonicity outputs. Neither manual claims to deliver a sampling confidence region for every reported plug-in endpoint. The distinction matters: an identified set describes values compatible with a population law and assumptions; sampling uncertainty concerns how an estimator or set varies across repeated samples. A posterior interval from a separate Bayesian model is different again. The software contract should return these objects with different types and labels, including empty, unbounded, undefined and unknown states where relevant~\citep{exec18_rid\_causaloptim,exec18_rid\_bpbounds}.

\texttt{CausalQueries} is a useful adjacent tool rather than a substitute for a graphical identification test. Its documentation defines binary causal models, updates model parameters and supports queries over priors, parameters or posterior draws; it reports means and credible summaries. Such a posterior answers a question conditional on the declared graph, response-type parameterization, restrictions, prior and update model. It need not equal a likelihood-identified set, and a narrow credible interval cannot certify that omitted graphs or cross-world dependence have been resolved. For the proposed library, the package is a reference for probabilistic model-query syntax and an optional R adapter candidate. The described package and its compiled Stan dependencies have not been installed, executed or cleared for redistribution in this review~\citep{exec18_rid\_causalqueries}.

\subsection{An exact repayment example separates four outputs}

Let $Y_0,Y_1\in\{0,1\}$ be repayment under no reminder and reminder. Randomization identifies $\Pr(Y_0=1)=1/4$ and $\Pr(Y_1=1)=3/4$ in this deliberately stipulated population example. Write $q_{ij}=\Pr(Y_0=i,Y_1=j)$ and let $t=q_{11}$. The observed arm risks imply
\begin{align}
 q_{11}&=t,&q_{10}&=\frac14-t,&q_{01}&=\frac34-t,&q_{00}&=t,
 \qquad 0\leq t\leq\frac14. \label{exec18:r-fiber}
\end{align}
The intervention effect is point identified throughout this fiber:
\begin{equation}
 \operatorname{ATE}=\mathbb E(Y_1-Y_0)=\frac34-\frac14=\frac12.
 \label{exec18:r-ate}
\end{equation}
But the retrospective “necessity” fraction among would-be responders under the reminder is
\begin{equation}
 \operatorname{PN}=\Pr(Y_0=0\mid Y_1=1)
 =\frac{q_{01}}{q_{01}+q_{11}}=1-\frac{4t}{3}\in\left[\frac23,1\right].
 \label{exec18:r-pn}
\end{equation}
The average effect is a point, while the counterfactual fraction is only set identified. Assuming monotonicity $Y_1\geq Y_0$ removes the response type $q_{10}$, forces $t=1/4$ and narrows PN to $2/3$. That is an added scientific restriction, not information generated by a software call.

The same distinction survives Bayesian updating. Consider the three compatible worlds $t\in\{0,1/8,1/4\}$. With four randomized units in each arm and the stated one-of-four versus three-of-four successes, the likelihood of the ordered outcomes is $(1/4)^2(3/4)^6=729/65536$ in every world. Thus the data do not change their relative weights. A uniform prior on these three worlds gives posterior mean PN $5/6$; prior weights $(1/6,1/3,1/2)$ give $7/9$. These are exact project calculations, not output from \texttt{CausalQueries} and not a defect in Bayesian computation: the difference records prior sensitivity along a likelihood-flat fiber. The aggregate binomial likelihood is $729/4096$ in every world, including the common combinatorial factor.

For an illustrative retrospective accounting rule, assign USD 1,000 to a responder whose repayment is attributed to the reminder and subtract USD 800 per responder. The compatible net amount per responder ranges from $1000(2/3)-800=-\$400/3$ to $1000(1)-800=\$200$. The two posterior means are USD $1000(5/6)-800=100/3$ and USD $1000(7/9)-800=-200/9$, respectively. These stipulated amounts are not observed economics or ROI, and attribution after the outcome must not be misread as prospective treatment selection on future repayment. The executable Fraction reference enumerates all three response-type distributions and checks every displayed likelihood and monetary value~\citep{exec18_rid\_exact}.

For this use, the proposed adapter result has three epistemic states: identified with a functional or point; not identified by a complete algorithm for its declared graph/data class; and unknown because the class is unsupported, the input is invalid, or computation ended before a certificate. A fourth output family carries a sharp identified set or a sampling confidence set with its own assumptions. Bayesian posterior summaries stay separately typed. The software comparison supports conditional reuse of symbolic ID/IDC, counterfactual and restricted-bound routines as references; it supports no integration permission, no R runtime claim, and no bank validation. The small source search is bounded rather than exhaustive: a GitHub repository search returned HTTP 403, the current CRAN task view is a post-cutoff discovery snapshot, and aliases or releases outside the selected queries remain omissions. Candidate and source limits are retained in the audit register.
