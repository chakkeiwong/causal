\section{Reusing R bnlearn without losing graph, intervention or sampling meaning}
\label{sec:exec24-bnlearn-reuse}
A banking team may want one workflow that learns a dependency graph, fits local distributions, simulates an intervention and reports a customer-level counterfactual. These are different inferential tasks even when a package exposes them through neighboring functions. R bnlearn provides a useful concrete case for the proposed library: preserve the package's graph and fitted-model semantics, state the extra causal assumptions, and refuse a stronger interpretation than the supplied information supports. The present decision is to retain the selected release as a reference and a conditional original-worker candidate. It does not enable a native adapter.~\citep{exec24_bnlearn_sources,exec24_bnlearn_contract}

\subsection{Identity, maintenance and a bounded reuse choice}
The selected CRAN mirror revision is 7d44622a52c29c2d666a8661d048e2b5709a7944, dated 17 July 2026, and declares package version 5.2.1. Its DESCRIPTION names Marco Scutari as maintainer, requires R at least 4.4.0 and compiled C17 support, declares GPL version 2 or later, and lists optional packages for graph conversion, inference, precision and regularization. The mirror is a distribution snapshot; its activity is not the author's complete development history or a promise of future support. Installed-library equivalence, transitive terms, build provenance and an operator remain to be qualified.~\citep{exec24_bnlearn_sources}

The Python project with the same name is a distinct repository and distribution. Its pinned README describes Python workflows and links to another inference ecosystem. It is not an alias for the R package or evidence that the same functions, licenses, numerical conventions or objects are interchangeable. A source-identity record must therefore include language, repository, distribution and revision, rather than just the string bnlearn. The current review makes no technical or rights admission for that namesake.~\citep{exec24_bnlearn_identity,exec24_bnlearn_contract}

Scutari's original article explains the historical separation between structure learning, local parameter estimation, conditional-independence tests and score-based search. Its discrete and Gaussian examples help motivate an interface that preserves data types and model assumptions. The locally retained author version is arXiv revision 2, dated 10 July 2010, with placeholder journal issue fields; it is not silently relabeled as the publisher's final typesetting. Its 2010 algorithm and computing environment cannot establish the capabilities or behavior of the selected 2026 source.~\citep{exec24_bnlearn_original}

\subsection{An equivalent graph is not an equivalent intervention}
The inspected CPDAG documentation distinguishes an equivalence class from one consistent DAG extension. It also explains that parametric restrictions, such as the permitted direction between discrete and continuous variables in a conditional Gaussian model, can preserve directions independently of observational evidence. A returned orientation must therefore carry its provenance: compelled by the observational class, imposed by background knowledge, forced by the model family, or selected as an extension.~\citep{exec24_bnlearn_sources}

An exact authored example shows why this distinction changes a banking decision. Let $A$ be a standardized action intensity and $Y$ a standardized response. Both variables have mean zero, variance one and covariance $1/2$. One Gaussian structural model is
\[
 A=U_A,\qquad Y=\tfrac12 A+U_Y,
 \qquad \operatorname{Var}(U_A)=1,\quad \operatorname{Var}(U_Y)=\tfrac34,
\]
with independent disturbances. Another is
\[
 Y=V_Y,\qquad A=\tfrac12 Y+V_A,
 \qquad \operatorname{Var}(V_Y)=1,\quad \operatorname{Var}(V_A)=\tfrac34,
\]
again with independent disturbances. Both generate exactly the same bivariate Gaussian observation law. Increasing $A$ by one unit changes expected $Y$ by $1/2$ in the first model and by zero in the second. At a stipulated 100 USD per unit response and a 20 USD action cost, the corresponding net values are 30 USD and minus 20 USD. More samples from that unchanged observation law cannot select the correct action. External direction information, a justified restriction or an intervention is needed.~\citep{exec24_bnlearn_contract}

The package's causal frontend rejects a partially directed or cyclic graph for the inspected graph-to-SCM, intervention and counterfactual branches. This is a useful syntactic boundary. It does not establish that an accepted DAG is the correct causal graph. The proposed interface retains the CPDAG and the reason for each additional orientation; it never silently turns one consistent extension into an identified effect.~\citep{exec24_bnlearn_sources,exec24_bnlearn_contract}

\subsection{A twin graph needs a specified cross-world model}
The inspected graph conversion creates one exogenous parent per factual node and checks generated labels for collisions. Twin construction shares exogenous nodes between factual and counterfactual copies. For a fitted Gaussian network, the implementation constructs fitted twin components. For other fitted-network classes, the inspected frontend falls back to a graph construction, which does not retain a full fitted counterfactual distribution. A caller must inspect the returned class and content before claiming a numerical counterfactual.~\citep{exec24_bnlearn_sources}

Even an interventional response distribution need not identify an individual's cross-world outcome. Let $A$ and $U$ be independent fair binary variables. In world one set $Y=U$ for either action; in world two set $Y=U\mathbin{\mathrm{xor}}A$. Both worlds give the same observed joint distribution, with probability $1/4$ for each $(A,Y)$ pair, and both give $P(Y=1\mid\operatorname{do}(A=a))=1/2$ for either $a$. For a customer observed with $A=0,Y=0$, however, the counterfactual $Y(1)$ is zero in world one and one in world two. These are explicitly stipulated structural models; the second need not satisfy a faithfulness restriction. Their purpose is to show the information a cross-world claim requires. A convenient twin representation does not supply that information by itself.~\citep{exec24_bnlearn_contract}

Intervention values also have a distributional meaning. The selected discrete fitted-node branch gives equal mass to the supplied set of levels. Supplying two levels is therefore not a declaration of an arbitrary 90/10 stochastic intervention. With losses zero and 100 USD, an equal mixture has expected loss 50 USD whereas a 90/10 mixture has expected loss ten. A request for a stochastic policy must carry its probability law and use a qualified path that preserves it.~\citep{exec24_bnlearn_sources,exec24_bnlearn_contract}

A separate static metadata question concerns Gaussian interventions. The inspected branch changes the intercept and sets the standard deviation to zero, but assigns the requested fixed values to the residual field before zeroing that field; it does not assign them to the stored fitted-values field in those lines. With stored fitted values $(1,2)$ and a requested fixed value five, the literal field assignments retain $(1,2)$ while residuals become zero. This is a targeted cache-consistency test for a future native worker, not an observed error in its returned intervention distribution.~\citep{exec24_bnlearn_sources,exec24_bnlearn_contract}

\subsection{Bootstrap strength is a statistic with a sampling law}
The selected bootstrap frontend defaults to 200 replicates, a sample size equal to the number of input rows and conversion to a CPDAG for arc strength. The generic backend samples rows with replacement. A customer's repeated visits or a common calendar shock are therefore not automatically respected as independent sampling units. In an authored mean example with 20 independent customer clusters, 25 visits per customer, unit marginal variance and within-customer correlation 0.6, the mean variance is 0.0308. Treating all 500 visits as independent gives 0.002. That arithmetic is not a coverage theorem for graph search; it explains why a row-resampling option cannot certify the graph's sampling law.~\citep{exec24_bnlearn_sources,exec24_bnlearn_contract}

The inspected C counter gives half weight in each direction to an undirected arc. It computes adjacency strength by adding the two directional counts and direction by dividing one directional count by that adjacency strength. Suppose 100 equally weighted graph replicates contain 20 $A\to Y$ arcs, 40 undirected $A-Y$ arcs and 40 absences. The forward counter is 0.4, the reverse counter 0.2, adjacency strength 0.6 and reported forward direction $2/3$. Only 0.2 of the replicates actually contain the directed arc. None of these quantities is automatically a posterior probability that a causal orientation is true, or a confidence interval for its effect.~\citep{exec24_bnlearn_sources,exec24_bnlearn_contract}

Model averaging adds another transformation: the inspected backend retains strengths strictly above the selected threshold, always retains strength one, filters directions at least 0.5 and invokes a cycle-aware delegate where required. The returned graph and the complete strength table should both survive conversion. Thresholding must not erase unresolved orientations, missing edges or the distinction between stability and causal truth.~\citep{exec24_bnlearn_sources,exec24_bnlearn_contract}

The generic bootstrap's remapping of manipulated observations deserves an independent test. Its inspected branch applies a first-match operation to each original manipulated row index. For an original manipulated row two and a bootstrap index vector $(2,2,3,1)$, that operation returns only position one, whereas the replicate contains manipulated copies at positions one and two. This exact indexing witness motivates a targeted test of the selected score and experiment-label path. It does not claim that every bootstrap algorithm takes that branch or establish an observed end-to-end package failure.~\citep{exec24_bnlearn_sources,exec24_bnlearn_contract}

\subsection{Conditional queries need denominators and retained weights}
The query documentation distinguishes logic sampling from likelihood weighting. Logic sampling retains observations matching the evidence; the number accepted can be much smaller than the number generated. The inspected probability routine returns zero when no simulated observations match. That zero conflates a numerical convention with an unresolved conditional query if an adapter reports it without the accepted-sample denominator. A future worker should return a distinct insufficient-evidence status, its generated and accepted counts and a justified Monte Carlo diagnostic.~\citep{exec24_bnlearn_sources,exec24_bnlearn_contract}

Parallel query aggregation also requires an explicit estimator. The inspected dispatcher takes the mean of worker probability estimates. If one worker has one accepted sample and one event success while another has nine accepted samples and no success, the mean of ratios is $1/2$ but the pooled ratio is $1/10$. These are different finite simulation statistics. This witness does not establish a general bias claim; it requires the product to name the aggregation law rather than suggesting a pooled denominator it did not use.~\citep{exec24_bnlearn_sources,exec24_bnlearn_contract}

Likelihood-weighted samples carry a weights attribute. Dropping that attribute while exporting a table changes the estimate: with outcomes $(0,1)$ and weights $(0.1,0.9)$, the weighted mean is 0.9 and the unweighted mean 0.5. The inspected C distribution sampler explicitly errors on all-zero or all-missing weights, while the R probability path ends with a weighted numerator divided by a weighted denominator. These are distinct failure interfaces to test. The adapter should bind weights, effective information, missingness, random streams and error status, rather than converting every numerical object into a successful causal answer.~\citep{exec24_bnlearn_sources,exec24_bnlearn_contract}

\subsection{A concrete proposal decision and public prototype route}
Retain bnlearn as a reference for graph-class, fitted-model and query contracts. A future pinned R worker is a conditional candidate because it preserves native object semantics more directly than a whole-library port. Defer native admission until exact distribution and dependency rights, graph/class conversions, sampling units, numerical diagnostics and failure behavior are qualified. Reject an automatic DAG-extension-to-causal-effect path, silent weight removal, default zero for an unresolved query and a port justified only by language preference. Alternatives include an independent small exact enumerator, another separately qualified graph learner and a distinct symbolic identification stage.~\citep{exec24_bnlearn_contract}

The proposed CLI/MCP request includes graph type and orientation provenance; variable states and units; population and information clock; model family and noise assumptions; fitted parameter identity; observational, interventional or counterfactual target; intervention law; sampling unit; seed, budget and computational limits. The response preserves the source object class, ambiguity, weights, denominators, convergence and refusal status. A typed query language should be translated through an allowlisted expression grammar; source examples that evaluate R expressions do not justify exposing unrestricted expression execution to a general caller.~\citep{exec24_bnlearn_sources,exec24_bnlearn_contract}

The next experiments can use generated finite networks and public data with documented permissions. Predeclare graph equivalence, counterfactual-coupling, intervention-mixture, manipulated-row, rare-evidence, parallel aggregation and weighted-export tests. Compare independent exact answers and complete workflows before using authentic bank data. The scientific owner supplies causal and sampling assumptions; the adapter owner supplies conversion and refusal behavior; rights and platform owners bind distributions and dependencies; the evaluation owner records all attempts and complete costs. At a stipulated 1,200 USD total, 100 requests, 80 conformant outputs and 50 useful outputs imply 12, 15 and 24 USD per respective unit. These costs explain denominators; they are not measured prices or adoption evidence.~\citep{exec24_bnlearn_contract}
