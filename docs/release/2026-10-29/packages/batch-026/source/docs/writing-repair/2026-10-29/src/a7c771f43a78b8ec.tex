\section[Remaining-language transport and missingness contracts]{Julia, Scala and Rust: missingness contracts before population transport}
\label{sec:exec25-otm}

A bank selecting Julia, Scala or Rust components for incomplete customer data must specify what a completed value means before using it in a transported causal effect. Let $S$ denote the population, $A$ the intervention, $Y$ the outcome, $X$ the pre-intervention covariates, and $R$ the observation mask. The target is a contrast such as $E[Y(1)-Y(0)\mid S=t]$. A numerical operator that maps $(X,R)$ to a completed table has no general authority to supply the assumptions relating the observation process, treatment assignment and target population. Its useful role is narrower: preserve the declared observation law and expose exactly what information its completion algorithm uses. The selected Impute.jl, Apache Spark and Polars originals support three complementary component roles: local numerical imputation, fitted distributed surrogates, and typed column operations. Their comparison therefore begins with masks, types, identities and time, then asks what public qualification would justify their use in a causal workflow.~\citep{exec25_otm_imputejl,exec25_otm_spark,exec25_otm_polars,exec25_otm_choice}

The inspected revisions precede the client cutoff of 7 October 2026. Impute.jl is pinned to 4 October; the selected Spark and Polars revisions are dated 7 October before the cutoff. Thirty-five retained original files support the bounded comparison. Four discovery queries leave returned and unreturned candidates, additional languages and numerical delegates uninspected. These are selected implementation contracts, not a claim that the ecosystems have been exhaustively surveyed. No downloaded implementation was executed. The exact examples below are project derivations; they establish consequences of stated laws and branches, not measured native failure rates. References mentioned inside package comments remain discovery leads unless a genuine original has separately been admitted.~\citep{exec25_otm_choice}

\subsection{Julia: initialization, neighbor identity and a completed table}

Impute.jl's selected nearest-neighbor routine first retains the missingness mask, fills missing entries through \texttt{Substitute()}, builds a tree on the initialized matrix, and queries observations that originally contained missing values. A comment describes initialization as a mean fill. The actual delegated defaults are different: real-valued data use a median; Boolean data use a mode; integer data use a mode when the number of unique observed values is less than one quarter of the sample size and otherwise a rounded median. The adapter must follow the selected implementation and data type rather than reproducing the comment as a universal mean contract. Initialization affects both the coordinates used for neighbor search and the fallback values left when a later branch does not update an entry.~\citep{exec25_otm_imputejl}

The constructor increases requested $k$ to $k+1$ to include the presumed query point. The routine asserts that the first returned distance is zero, then uses the first returned index as the observation to update. Zero distance establishes coincidence in the completed coordinates; it does not by itself establish row identity when distinct customers have equal coordinates. A qualification fixture should therefore retain a stable customer identifier, place duplicate completed rows in different orders, and compare the selected index with the intended query. This is a static reason to test tie handling, not an observed assertion that the native neighbor delegate always selects the wrong row.~\citep{exec25_otm_imputejl,exec25_otm_choice}

The missing-neighbor threshold uses the original mask and the internal neighbor count. With requested $k=1$, the internal count is two. One missing neighbor gives a fraction $1/2$, which does not exceed a threshold of $1/2$; the selected comparison is strict. Valid donors then receive inverse-distance weights. A valid donor at zero distance produces an infinite inverse weight, and the finite, nonzero total-weight guard prevents the weighted update. An initialized value can consequently remain in the returned table. A diagnostic must distinguish a genuine weighted update from retention after a threshold or weight guard. Reporting only the final percentage of nonmissing cells would lose this distinction.~\citep{exec25_otm_imputejl,exec25_otm_choice}

Marginal random-donor sampling has a different contract. The selected simple-random-sampling routine draws from observed entries and leaves an entirely missing input unchanged. If the observed donor law assigns equal probability to zero and one, its mean is $1/2$ and variance is $1/4$. Those are properties of the sampling law, not a promise that every finite completed sample has exactly those moments. More importantly, suppose the true binary variables satisfy $X=Y$ and the donor is sampled without conditioning on $Y$. Then the imputed probability of $X=1$ given $Y=1$ is $1/2$, whereas the true conditional probability is one. Marginal plausibility does not preserve a conditional law needed by the analysis. Conditioning a donor rule on legitimate pre-decision information is a potential redesign; access to an outcome measured after the decision can instead create leakage.~\citep{exec25_otm_imputejl,exec25_otm_choice}

The selected SVD routine retains the mask, changes the missing entries, and contains explicit rank, iteration and relative-change branches. A returned matrix is not a separate convergence receipt, nor does low reconstruction error establish a valid missingness model. The wrapper should record the rank, initialization, iteration limit, stopping branch and observed-entry invariance before any downstream causal interpretation. Similarly, a threshold based on the missing fraction answers a data-completeness question, not whether an effect is identified. The weighted threshold checks shape and divides missing weight by total weight; admissible weight signs and the zero-total case need an explicit adapter policy. Conditional reuse is appropriate for these numerical operations if their diagnostics survive. Treating their output as a universal correction for missing-not-at-random observations is unsupported.~\citep{exec25_otm_imputejl,exec25_otm_choice}

\subsection{Scala and Spark: fitting a surrogate does not define every transform mask}

Spark's selected Imputer fits numeric surrogates after converting inputs to doubles. During fitting it excludes the configured sentinel and NaN, while the aggregation also excludes nulls. Mean, approximate median and mode follow separate routes. Mode ties select the smallest value. An input column for which no surrogate can be computed is refused. These details matter for a banking pipeline that trains on historical accounts and transforms a later cohort: fitting must use the authorized training population, and the surrogate, configuration and input schema must be retained as part of the model artifact.~\citep{exec25_otm_spark}

The transform branch replaces null and the configured missing-value sentinel, then casts the result back to the original input type. It does not contain the fitting branch's separate unconditional NaN test. With sentinel $-1$, NaN can therefore remain in transformed output even though fitting excluded it. The selected upstream tests explicitly exercise this distinction. An adapter that advertises a single missingness policy must either preserve the difference in its public contract or implement and qualify a deliberate normalization step. It should retain separate counts for original null, NaN, sentinel, replacement and residual missing values; collapsing them into a single completed-row count would obscure which operation took place.~\citep{exec25_otm_spark,exec25_otm_choice}

Type restoration is also substantive. For observed integers $1,2,4$, the arithmetic mean is $7/3$. A truncating cast to the original integer type yields two. The selected implementation documentation warns about integer truncation. Two may be an acceptable count-valued engineering surrogate, but it is not the unchanged real-valued fitted mean. A downstream nuisance model should receive the declared typed transformation, and any financial interpretation should use its actual scale. The public test should compare the real-valued surrogate, its serialized representation, the transformed integer and the subsequent estimator input, rather than merely compare two libraries' display strings.~\citep{exec25_otm_spark,exec25_otm_choice}

Approximate median introduces a third distinction. The documented quantile error concerns rank. For $N=10{,}000$, probability $p=1/2$ and relative rank error $\epsilon=0.001$, the illustrative admissible ranks run from 4,990 to 5,010. A bound on rank does not bound the monetary distance between order statistics: a large gap in account balances can occur inside that narrow rank interval. A value-error guarantee would require additional distributional information. Moreover, the selected \texttt{StatFunctions} path maps zero relative error to maximum integer accuracy and calls an approximate-percentile aggregation. The comment's language about exactness is insufficient to establish mathematical exactness for that selected delegate. Qualification must inspect and test the actual configured path, especially adversarial ties and large value gaps, before describing it as an exact quantile service.~\citep{exec25_otm_spark,exec25_otm_choice}

The integration decision is conditional adoption of fitted numeric preprocessing with explicit training, mask and type contracts. A port that copies only the surrogate numbers while dropping sentinel rules, tie choices or quantile settings would not preserve the reviewed behavior. Keeping the original component behind a typed interface is preferable when its execution model is justified by the data workload; a smaller native implementation is an alternative only after equivalent semantics and costs have been specified and qualified. Neither route turns a marginal surrogate into identification of a target-population causal contrast.~\citep{exec25_otm_spark,exec25_otm_choice}

\subsection{Rust and ordered data: nulls, NaNs, customers and decision time}

Polars provides useful infrastructure precisely because null validity and floating NaN are distinct. In the selected expressions, filling nulls does not fill NaNs, and the NaN-fill expression preserves existing nulls. For the conceptual vector $(1,\mathrm{NaN},\mathrm{null})$, zero-filling nulls yields $(1,\mathrm{NaN},0)$, whereas zero-filling NaNs yields $(1,0,\mathrm{null})$. Applying both yields $(1,0,0)$, but this combines two policy decisions. An invalid arithmetic result and an unobserved customer attribute need not have the same explanation or permissible replacement. The original mask and the reason for each replacement must remain recoverable.~\citep{exec25_otm_polars,exec25_otm_choice}

Selected fill paths can return unchanged data when there are no nulls or when a statistic or propagation strategy cannot fill an all-null series. Mean fill casts to the physical numeric type. Forward and backward limits operate in the supplied series context. These are sensible column operations, yet customer boundaries remain a caller obligation. Consider two ordered rows, customer A with observed value seven and customer B with a missing value. A global forward fill can copy seven into B's row; a within-customer forward fill leaves B missing. The numerical result alone cannot reveal which population partition was intended. The CLI or MCP request should require entity keys and ordering columns whenever a method depends on longitudinal neighbors.~\citep{exec25_otm_polars,exec25_otm_choice}

Impute.jl's forward and backward routines similarly operate on vector order, with limits and boundary behavior. Backward fill and two-sided interpolation use later observations. They may be defensible for a retrospective measurement model under explicit assumptions, but a prospective credit decision cannot silently use information observed after its decision time. A reproducible public fixture should supply event time, availability time and decision time separately. Restricting by event time alone does not prove that a delayed measurement was available when a historical decision was made. This is a proposed information contract, not a claim that a selected package already enforces banking availability rules.~\citep{exec25_otm_imputejl,exec25_otm_choice}

Positional interpolation and coordinate interpolation answer different questions. At times $(0,1,10)$ with values $(0,\mathrm{missing},10)$, equally spaced positional interpolation returns five for the middle row. Linear interpolation in the supplied time coordinate returns one. The difference is exact and does not require a large dataset. Impute.jl's selected interpolation uses position spacing; Polars exposes both positional and coordinate-based routes. The selected positional path preserves leading and trailing nulls and leaves an all-null input unchanged. In the substantive coordinate-interpolation path, null coordinates are refused; the earlier unchanged-input return means this refusal should not be stated as unconditional for every possible input. Unsorted coordinates are sorted by the selected path, while duplicate-coordinate policy and entity partitions still require qualification.~\citep{exec25_otm_imputejl,exec25_otm_polars,exec25_otm_choice}

These operations should be conditionally adopted as typed data infrastructure. They should not be marketed as a causal missing-data model solely because they produce a smooth series. Alternatives include leaving a value missing and refusing an unsupported estimator, fitting an explicitly declared longitudinal observation model, or restricting a claim to the observed population. Each alternative changes the inferential target or assumptions and should be visible to the analyst. A graph-building assistant may propose these alternatives, but cannot infer the missingness mechanism or availability timestamps merely from a completed table.~\citep{exec25_otm_choice}

\subsection{Population consequences and an executable public qualification route}

To quantify why the population contract matters, suppose an identified conditional effect, under separately defended assumptions, is zero in stratum zero and two units in stratum one. A source population with stratum-one proportion $1/5$ has effect $2/5$; a target with proportion $3/5$ has effect $6/5$. Their difference is $4/5$. At USD 10 per unit across 10,000 accounts, the illustrative discrepancy is USD 80,000. These invented populations are an exact design example, not bank observations or a promised benefit. Filling values in either population does not prove the exchangeability, overlap or observation assumptions needed to use the conditional effects in the other.~\citep{exec25_otm_choice}

The proposed public qualification program has independent component branches. First, freeze a small generated law with a target estimand, row identities, observation indicators and a declared decision time. Compare observed-data, complete-data and deliberately misspecified workflows against that known law. Second, replay typed null/NaN/sentinel fixtures across each intended language boundary, retaining the original mask and all casts. Third, qualify neighbor identity, initialization retention, zero-distance ties and donor randomness; do not equate a nonmissing return with a successful conditional update. Fourth, qualify fitted-surrogate isolation, mode ties, integer restoration and quantile rank semantics. Fifth, test entity boundaries, irregular spacing, duplicate times, boundary gaps and future-information use. These branches can proceed independently once their own runtime and rights requirements are met.~\citep{exec25_otm_choice}

The implementation owner should bind each proposed trial to an exact package artifact, dependency set, command, deterministic fixture where appropriate, scientific oracle and refusal oracle. For stochastic donors, retain the random-number scope and assess a distributional statement rather than requiring every run to match a population moment. For iterative completion, retain stopping diagnostics and compare declared tolerances. The request and result schemas should record target population, effect scale, observation mask, entity keys, time semantics, fit/transform partition, selected algorithm, typed failures and total costs. An MCP wrapper must preserve these fields and provenance; transport success is not scientific acceptance.~\citep{exec25_otm_choice}

The selected Impute.jl and Polars declarations are MIT-style, and Spark supplies an Apache 2 declaration with separate binary-dependency material. These observations support further integration analysis, not clearance of every installed artifact or redistribution plan. Complete dependencies, native delegates, wider language coverage, residual search candidates and public execution costs remain open. Unrestricted missing-not-at-random identification, unsupported target populations and arbitrary dependent uncertainty have no universal repair supplied by these libraries. Their resolution requires additional information, defended restrictions or a narrower claim. The proposal can nevertheless advance through the specified public fixtures before expensive bank experiments: a completed cross-language table does not by itself identify the target causal effect.~\citep{exec25_otm_imputejl,exec25_otm_spark,exec25_otm_polars,exec25_otm_choice}
