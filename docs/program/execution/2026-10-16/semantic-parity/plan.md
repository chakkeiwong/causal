# Library, CLI and MCP semantic parity: reviewed proposal plan

Bind the existing local runtime, schemas, adapter sources and historical
examples. Retain distinct library exceptions, CLI exits, MCP protocol/tool
errors and canonical scientific dispositions. A successful transport does not
establish scientific qualification.

1. Inspect the implemented operation map, wrappers and supported schema/protocol.
   Reuse existing historical originals and audits; do not rerun frozen evidence.
2. Freeze a small deterministic successor protocol with complete generated
   requests, independent set/graph expectations, refused/unsupported cases,
   changed-context failure and invalid transport input. Check the existing
   local MCP environment before claiming a real transport run.
3. Run bounded library/CLI/MCP cases sequentially, recording full responses,
   execution identities and actual/static/mock labels. Preserve every failure.
4. Explain agreement and differences, propose concrete semantic/error repairs,
   and state remaining local and external acceptance cases. Integrate any new
   substantive findings into a preserving reader and record this requirement.

Plan review: distinguish a common canonical service from universal parity.
Unsupported operations may be callable through a generic local API yet absent
from the advertised MCP tool list. Graph/set identity, premise status and
diagnostics matter as much as numbers. This is bounded proposal evidence, not
a production implementation or bank acceptance exercise. No sibling changes,
live model calls, new images or external institutional inputs are necessary.
