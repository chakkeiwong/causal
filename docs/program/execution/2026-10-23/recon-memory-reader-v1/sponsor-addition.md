# Memory tests need matched evidence and auditable denominators

RECON supplies a useful public/generated design for testing evidence chains,
retractions, conflicts and alternative timelines before expensive bank trials.
Its 24 cases and 1,604 questions are described as deterministic provenance
structures with LLM narration. The reported main comparison filters 190
questions, leaving 1,414. Provenance correctness and an intervention effect
remain distinct scientific claims. \citep{exec23_recon_original}

Source inspection identifies questions that must be resolved before adopting
its performance rankings. The stated 200-item strict-majority denominator
cannot yield 86.3% rounded agreement; the 60-item human baseline and several
ten-item task percentages also require aggregation records. These are exact
denominator checks, not allegations about how the results were produced.
Scoring, abstention and accuracy can rank systems differently, and a supplied
case-correlation example changes variance from 1/20 to 1/2.
\citep{exec23_recon_reference}

Retain the benchmark design as a candidate. Recover versioned data/code,
per-item and annotator records, matched evidence, index readiness and full
costs before a native trial. Curated human packets, structured Oracle inputs
and self-retrieved model contexts do not isolate the same capability. No
benchmark harness or service was executed here. \citep{exec23_recon_original}

The census records 72 inspected and 41 unread originals, plus four open
crosscutting obligations. This is source-review progress, not native adoption
or final acceptance. \citep{sp23recon_reader,sp23recon_progress}
