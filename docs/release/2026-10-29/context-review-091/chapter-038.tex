\chapter{From a learned graph to a defensible calculation}
A graph becomes useful to a bank when its statistical meaning survives
the next calculation. Directed, partially directed and mixed graphs encode
different information. The Tetrad bridge comparison first follows variable
identity, categories and endpoint marks across languages. Weka and Banjo then
show why a predictive factorization or a lagged search still needs a separate
intervention argument. The remaining studies examine calculations under a
supplied model: libDAI distinguishes conditioning from intervention and
numerical stability from accuracy; aGrUM connects identified formulas to
support and counterfactual coupling; OpenGM distinguishes marginal inference
from joint optimization. Together these comparisons ask which part of a
banking request a numerical result actually answers.

\section{Tetrad across language boundaries: preserving the scientific object}
\label{sec:exec24-tetrad-bridge-reuse}

A bank may want an analyst in Python, a model reviewer in R and an approved
Java discovery engine to discuss the same borrower graph. Calling the same
algorithm name does not ensure that they have supplied the same variables,
categories, missingness policy, background knowledge or statistical test.
Nor does a returned graph identify an intervention merely because a bridge
makes it convenient to query. A useful proposal therefore treats the language
boundary as part of the scientific specification. The inherited restricted
Java PC/Fisher-Z candidate remains distinct from the Python and R surfaces
considered here.~\citep{exec13_tetrad_reuse_decision,exec24_pytetrad_source}

\paragraph{The original design and the pinned implementation.}
Ramsey and Andrews describe a Python interface through JPype, an R interface
through Reticulate and Python, data conversion, endpoint graphs and examples
of background knowledge and resampling. Their 2023 primary paper explains why
access to the underlying Java classes is valuable, while its examples require
deliberate column typing. It is evidence for that architecture, not proof of
compatibility of every later distribution. The Python example declares ten
repetitions whereas the displayed edge-frequency table describes one hundred;
the paper alone does not establish a common request denominator for those
artifacts. We use neither the displayed frequencies as bank graph truth nor
this textual discrepancy as a measured software defect.~\citep{exec24_pytetrad_paper}

The selected bridge revision is the 7 October 2026 commit recorded in the
source audit. Its setup declares version 0.1.2 and Python at least 3.7, whereas
its README asks for Python at least 3.12 and JDK 21 or later. Its packaged JAR
is described as a released version or a version with adjustments. The tree
records a 56,587,560-byte JAR, but the binary has not been acquired or executed
here. Consequently the Java revision previously inspected, the bridge commit,
the package version and the bundled binary are four identities to reconcile.
The bridge's permissive root license does not settle the inherited Java
distribution or embedded third-party terms. The selected R file separately
points to MIT (SEI)-style terms and third-party software; the referenced
\texttt{license.txt} is absent from the selected complete repository tree.
That is a bounded documentary gap, not a legal conclusion.
\citep{exec24_pytetrad_source,exec13_tetrad_reuse_primary}

\paragraph{Types and categories are substantive inputs.}
The selected Python converter treats floating columns as continuous and other
column types as discrete by default. Its optional integer-as-continuous switch
is not passed by the ordinary search constructor. An integer-valued account
balance can therefore enter a different statistical family from the same
values represented as floating point. A worker must require the scientific
type explicitly; storage dtype is an inadequate substitute for units and
measurement meaning.~\citep{exec24_pytetrad_source}

For discrete variables, the converter assigns category numbers in first-seen
order. Consider two branch datasets containing the same categories but starting
respectively with approve then decline, and decline then approve. Independently
generated codes assign approve zero in the first and one in the second. This
does not show that Java necessarily pools them incorrectly: the eventual
delegate could reconcile labels. It shows why a wrapper cannot presume identical
codes merely from identical column names. The conversion also stringifies labels
and column names. The distinct Python objects integer one and string 1
both become the same string; a verified bijection must reject or reversibly
escape this collision before constructing Java variables.
\citep{exec24_pytetrad_source,exec24_pytetrad_choice}

Missingness needs a separate representation. Continuous output is reconstructed
as floating columns and discrete missing output as Python \texttt{None}. On
the forward path, the selected converter enumerates unique discrete values
without an explicit missing-sentinel branch, converts mapped codes to integer
and stringifies category names. This can turn a missing token into a named
category or encounter a mapping/cast failure, depending on the input and
installed pandas behavior. The audit does not claim one universal runtime
outcome. Preserve a typed category dictionary, a missing mask, ordered row and
column identifiers and the requested imputation or deletion policy. A successful
round trip must preserve each of these, including all-missing and mixed columns.
\citep{exec24_pytetrad_source}

The R directory contains more than one interface concept. Its README and the
2023 paper discuss the Reticulate route, while the selected temporary
\texttt{TetradSearch.R} class calls rJava directly. Its converter tests
\texttt{is.numeric} before \texttt{is.integer}, despite a comment recommending
integer columns for discrete data. An independent base-R witness verifies that
an ordinary integer vector satisfies both predicates and therefore takes the
first, continuous branch. This witness executes no Tetrad or rJava code.
Factor codes and Java helper behavior still need their own inspection; the
branch observation is not a finding about every R interface. The accompanying
utility refers to Tetrad 7.6.5 and a moving JDK download, which must not be
silently equated with the Python JAR.~\citep{exec24_pytetrad_source,exec24_pytetrad_choice}

\paragraph{Endpoint matrices are not binary adjacencies.}
Let the ordered variables be $A,Y$, and suppose a graph contains $A\to Y$.
The selected endpoint converter places the endpoint at node $i$ in entry
$M_{ji}$, using three for a tail and two for an arrowhead. Hence
\[
 M=\begin{pmatrix}0&2\\3&0\end{pmatrix}.
\]
Both off-diagonal entries are nonzero because each describes one end of the
same edge. Treating them as independent binary arcs requests both directions.
The selected binary-adjacency converter's comment says entry $B_{ij}=1$
means $j\to i$, while its loop supplies nodes $i,j$ in that order to
\texttt{addDirectedEdge}. For
\[
 B=\begin{pmatrix}0&0\\1&0\end{pmatrix},
\]
the documented convention requests $A\to Y$ and the source loop requests
$Y\to A$. These are static argument-flow findings; no claim is made that a
particular Java graph accepts two opposing arcs. The converter also generates
new names rather than retaining caller labels.~\citep{exec24_pytetrad_source,exec24_pytetrad_choice}

An adapter should expose distinct, validated types for binary adjacency,
endpoint graph, CPDAG, PAG and a deliberately selected DAG. Preserve both
endpoint symbols, row and column names, ordering and graph class. The selected
causal-learn converters map named enum members rather than relying solely on
the numeric comments; their target library must nevertheless be versioned.
A CPDAG-to-DAG convenience call selects an extension. It does not resolve
observational equivalence or authorize a point causal effect.
\citep{exec24_pytetrad_source}

The monetary importance can be demonstrated without fitting software. In one
authored Gaussian model, $A=U_A$ and $Y=\tfrac12 A+U_Y$, with independent
zero-mean noises of variances one and three quarters. In a second, $Y=V_Y$
and $A=\tfrac12 Y+V_A$, with independent noises having the same respective
variances. Both give the observed covariance
\[
 \Sigma_{A,Y}=\begin{pmatrix}1&1/2\\1/2&1\end{pmatrix}.
\]
The causal derivative of the mean of $Y$ with respect to an intervention on
$A$ is one half in the first model and zero in the second. An analyst cannot
choose between them from this observed distribution alone. If an action
increases $A$ by one unit for 200 accounts, each unit of $Y$ is stipulated to
be worth 100 USD, and implementation costs 4,000 USD, the net values are
6,000 USD and minus 4,000 USD respectively. These are exact illustrative
calculations, not an empirical return estimate. A reversed edge or arbitrary
DAG extension can therefore change an investment recommendation while leaving
observational fit unchanged.~\citep{exec24_pytetrad_choice}

\paragraph{Failure, knowledge and process identity.}
The selected search object retains mutable parameters, graph results,
background knowledge and pooled datasets. The PC and FCI methods assign
\texttt{self.java} only after a search returns. A later failed search can
therefore leave the prior graph accessible through an ordinary getter;
\texttt{set\_data} itself does not invalidate that graph. This follows from
the assignment order and is illustrated by an independent state witness,
not an induced failure in downloaded software. New data also do not by
themselves empty the separately stored pooled datasets. A proposed worker
must bind every successful result to its own immutable request, input hashes,
parameter snapshot, knowledge and execution generation. It must never publish
a previous graph as the result of a failed new request.
\citep{exec24_pytetrad_source,exec24_pytetrad_choice}

Several smaller source observations reinforce the need for interface fixtures.
The mixed-variable polynomial setter calls the discretization parameter setter
without passing the requested value. Several explicit-graph getter branches
invoke converters without returning their result; the explicit graph-to-matrix
branch also drops custom endpoint codes. A bootstrap index check permits an
index equal to the number of stored graphs before indexing. These are selected
source-level mismatches, not a claim that every wrapper method fails. Test
default and explicit arguments separately, compare echoed effective parameters,
and make missing, stale, nonfinite, cancelled and unsupported results distinct.
The R knowledge-tier helper catches and prints errors; a worker needs a
machine-readable failure and a check of the effective constraints.
\citep{exec24_pytetrad_source}

JVM startup introduces a further shared-state boundary. The translation and
missing-data modules start a JVM at import when needed, and otherwise reuse
the already running process without a local equality check of the loaded JAR.
The G-regression module has its own startup path with different flags. A caught
startup exception followed by imports is not a structured job receipt. Use an
isolated worker whose Java version, binary hash, classpath and flags are fixed
before importing the bridge; fail closed if they cannot be attested. The setup
declares NumPy, pandas and JPype but the main search module also imports
NetworkX. Inspecting that fact and the G-regression delegate does not complete
the native dependency closure.~\citep{exec24_pytetrad_source}

The missing-data helper delegates auditing, imputation and pooling by edge
frequency to Java. Checking for a class name does not establish the delegate's
scientific assumptions, calibration or identity. Likewise the G-regression
wrapper passes a supplied graph into an effect and bootstrap delegate; its
source comments about identification and prior parity tests are not new
verified results in this proposal. Preserve graph selection, missingness,
resampling units and all failures as separate uncertainty dimensions. A pooled
edge frequency is not automatically a posterior probability of a bank cause,
and fixed-graph effect uncertainty need not cover graph selection.
\citep{exec24_pytetrad_source}

\paragraph{A bounded reuse choice and qualification route.}
Retain the bridge and original paper as references. Consider an isolated
Python/Java integration only after its actual artifact, grants, dependency
closure and semantic fixtures are reconciled with a selected scientific
profile. Whole-package adoption is deferred; a port of the discovery engine
has no demonstrated advantage over maintaining a small explicit boundary.
Porting selected converters is a separate option requiring rights review and
independent graph/type tests. Reject loss of endpoint information, implicit
category meaning, stale-result publication and unsupported conversion of an
equivalence class into an identified effect; these rejected behaviors do not
justify discarding every Tetrad candidate.~\citep{exec24_pytetrad_choice}

The scientific owner specifies target, observation law, measurement, temporal
knowledge and graph-class assumptions. The adapter owner maintains bijections,
missingness, request generations, result/refusal states and cancellation. The
platform and rights owner locks actual binaries and notices; the evaluation
owner predeclares public known-law and negative cases with complete task
denominators. Include setup, conversion, successful and failed computation,
review, correction and maintenance in costs. For an authored 6,000 USD trial
with 300 submitted, 240 completed and 200 qualified requests, the costs are
20, 25 and 30 USD per respective denominator. Completion must not replace
qualification in the investment case.~\citep{exec24_pytetrad_choice}

The next evidence is concrete: authentic binary/source reconciliation;
category, missingness and endpoint round trips; explicit-argument and
failed-second-request fixtures; knowledge and pooling checks; and restricted
native comparisons using public or generated data. Full G-regression and
imputation delegates, separate R terms, support and actual costs remain open.
No public trial can recover an unknown bank assignment mechanism merely by
running this bridge. The source comparison does not establish an executed integration; independent validation is still needed.

\section{Weka Bayesian networks as predictive references and causal comparators}
\label{sec:exec24-weka-reuse}

A bank can use a Bayesian-network classifier to predict a borrower's observed
repayment while still lacking an answer about what a servicing intervention
would change. Both tasks may display a directed graph and probability tables,
yet they condition on different information and impose different scientific
requirements. Weka is consequently useful to the proposal as a concrete
predictive comparator and software reference. Its selected classifier must not
inherit causal-discovery or intervention guarantees merely from the words
Bayesian network. The earlier Java and temporal surveys remain distinct
evidence, with their original limitations.~\citep{exec13_java_weka,exec15_javatemporal_weka,exec24_weka_source}

\paragraph{A historical source identity rather than an invented current release.}
The inspected GitHub mirror ends at a pinned 10 August 2022 revision. Its
README explicitly directs users to the official Waikato Git service and says
the mirror is no longer updated. The source resource says
\texttt{3-8-7-snapshot}, and the build descriptor says 3.8.7-SNAPSHOT. These
declarations agree on a development identity; they do not establish a published
2026 distribution. The official successor's cutoff identity is unresolved in
the present source collection. The build declares GPL terms and Java profiles
alongside numerical, parser and runtime dependencies. Actual binary identity,
complete notices, support and distribution arrangements need separate review;
neither a historical snapshot nor process isolation clears those obligations.
\citep{exec24_weka_source}

\paragraph{What the default classifier actually learns.}
The selected BayesNet source initializes K2 structure search and a simple
conditional-probability estimator. Its training path removes rows whose class
is missing, applies supervised discretization to non-nominal predictors and
fits a replacement filter for missing predictors. The structure-search base
class initializes a naive-Bayes graph by default, with arrows from the class
to every other variable and a one-parent limit. K2 puts the class first in
its ordering and searches only earlier candidate parents. With these defaults,
the initial class parent already fills the one-parent budget for each other
variable. This is a source-level description of a classifier configuration;
it cannot be interpreted as a finding that future default status causes a
borrower's previously measured characteristics.~\citep{exec24_weka_source}

Changing the initialization, parent bound, search family or class column
changes the procedure. The selected conditional-independence search compares
local scores with and without a parent; it is not the Fisher-Z test with a
declared significance level used by the earlier restricted Tetrad candidate.
An optional classifier correction can add arrows to connect variables to the
class's Markov blanket. The randomized K2 order also constructs a new random
generator in its selected path without a locally supplied seed argument.
Consequently an adapter needs an explicit algorithm, effective settings,
ordering, randomization and output-class contract. An algorithm label is
insufficient for either scientific comparison or reproducibility.
\citep{exec24_weka_source}

\paragraph{Conditioning does not perform an intervention.}
For a discrete network with parents $\operatorname{pa}(j)$, the selected
estimator forms a joint factorization
\[
 \widehat p(x)=\prod_j\widehat p_j(x_j\mid x_{\operatorname{pa}(j)}).
\]
Its class-probability routine evaluates that product for each candidate class
value and normalizes across classes. With observed predictors $X=x$, the
result represents a fitted $\widehat p(Y=y\mid X=x)$. It does not delete the
treatment-assignment factor or justify invariance of the remaining mechanisms.
For a causal DAG under appropriate structural assumptions, an intervention
would instead replace the action mechanism and use the corresponding truncated
factorization. Those assumptions and the identification step are additional
inputs, not consequences of conditional-probability normalization.
\citep{exec24_weka_source,exec24_weka_choice}

An exact authored example makes the distinction operational. Let an unobserved
binary borrower type $U$ have probability one half. Let success be $Y=U$,
and let action $A$ be assigned with probabilities $4/5$ when $U=1$ and $1/5$
when $U=0$. There is no arrow from action to outcome. Bayes' rule gives
\[
 P(Y=1\mid A=1)=4/5,\qquad P(Y=1\mid A=0)=1/5,
\]
whereas replacing the action assignment leaves
\[
 P(Y=1\mid\operatorname{do}(A=1))=
 P(Y=1\mid\operatorname{do}(A=0))=1/2.
\]
All treatment levels have positive probability in both type strata; the failure
is uncontrolled confounding, not zero exposure probability. If 1,000 accounts
are each worth 100 USD per incremental success and the action costs 10,000 USD,
misreading the conditional difference as a causal effect gives a net 50,000 USD.
The stipulated true causal value is minus 10,000 USD. A well-fitted classifier
can reproduce the observational conditionals perfectly and still give no
justification for the first investment calculation.~\citep{exec24_weka_choice}

\paragraph{Smoothing and weights change the statistical object.}
The selected estimator initializes each category count to $\alpha$, defaulting
to one half, and then adds instance weights. If a parent configuration $j$
has weighted counts $n_{jk}$ for $K$ categories, its fitted table is
\[
 \widehat p_{jk}=\frac{n_{jk}+\alpha}
 {\sum_{\ell=1}^{K}n_{j\ell}+K\alpha}.
\]
For binary counts $(0,1)$ the result is $(1/4,3/4)$. Multiplying the data
weights by ten while retaining the same prior gives $(1/22,21/22)$.
An unobserved binary row returns $(1/2,1/2)$ under the default positive prior.
Finite probabilities in such a row do not create observed treatment support
or validate a transport assumption. The worker must retain prior strength,
category dictionary, support counts and the meaning of weights.
\citep{exec24_weka_source,exec24_weka_choice}

The inspected plain local-score path increments integer counts once per row,
whereas the simple CPT estimator uses each instance's weight. Two category
observations with weights one and nine therefore contribute counts $(1,1)$
to that selected search-score path and $(1,9)$ to CPT estimation. With the
same half-count smoothing, the corresponding probability illustrations are
$(1/2,1/2)$ and $(3/22,19/22)$. The first is an illustration of the score's
row-count sufficient statistics, not a claim that this score outputs a
probability vector. The mismatch requires an explicit weight contract and a
native fixture; it is not resolved by the classifier declaring a weighted-data
interface. Other search and ADTree paths need separate qualification.
\citep{exec24_weka_source,exec24_weka_choice}

\paragraph{Preprocessing defines the target population and information clock.}
The supervised discretizer chooses cut points using class counts and entropy.
Fit it only within the permitted training split and retain its boundaries when
processing a held-out borrower. Choosing cut points with evaluation labels
would leak outcome information. Even when correctly split, a category produced
by this procedure is a data-dependent measurement transformation; its meaning
must be reconciled with any causal estimand stated for the original continuous
quantity. A predictive cut point does not supply a bank intervention rule.
\citep{exec24_weka_source}

Removal of missing-class rows can also change the population. In an authored
example, success has population probability one half, success labels are always
observed, and failure labels are observed with probability one quarter. Among
observed labels, success then has probability
\[
 \frac{(1/2)\cdot1}{(1/2)\cdot1+(1/2)\cdot(1/4)}=4/5.
\]
This is a selected sample, not a newly discovered improvement in borrower
quality. The source does not by itself correct the selection mechanism. A
proposal must state the label clock, selection probabilities or assumptions,
target population and necessary sensitivity analysis before extrapolation.
\citep{exec24_weka_choice}

The replacement delegate computes weighted modes and means from its fitted
batch, excludes the class from replacement, and reuses the fitted values on
later instances. In its standalone numeric branch, a column without observed
weight retains the initialized zero replacement; in a nominal column with
declared categories and no observations, all-zero counts select the first
category through the maximum-index helper. The full BayesNet pipeline
discretizes non-nominal predictors before this delegate, so these primitive
branches must not be conflated with every end-to-end outcome. Missing masks
and all-missing warnings remain necessary. Single replacement values neither
integrate missing-value uncertainty nor establish a missing-at-random law.
\citep{exec24_weka_source}

\paragraph{Graph import and output validation.}
The selected initial-BIF path matches a node by name but bounds its parent loop
using the original dataset index rather than that matched source index. For a
source ordering $[A,B]$ with $A\to B$ and a dataset ordering $[B,A]$, the first
node's requested parent count is zero although $B$ has one parent; the second
uses a count of one for a node with no parents. This is an exact index witness
for the selected source statements. It does not assert the exception type or
runtime outcome of a compiled import. Require permutation-equivariant node and
category mappings and compare the complete imported parent sets and tables.
The warning that an unknown parent is ignored must become an explicit rejected
or incomplete request when graph preservation is required.
\citep{exec24_weka_source,exec24_weka_choice}

The class-probability routine computes in log space and subtracts the largest
log score before exponentiating. This improves ordinary numerical scaling,
but it is not a guarantee that every input yields a valid probability vector.
Its normalization helper rejects a zero or NaN sum, and the selected caller
catches that exception and returns an all-zero vector as a missing prediction.
Such a vector sums to zero, not one. A downstream decision rule must not read
it as zero risk or a confident class. Validate dimensions, labels, finiteness,
nonnegativity and unit sum; retain the distinct failure state and its cost.
The generic inherited classifier test does not establish any causal calibration
or these complete integration conditions.~\citep{exec24_weka_source,exec24_weka_choice}

\paragraph{Disposition and a concrete public qualification.}
Retain the pinned classifier and source as a historical reference and a
conditional predictive comparator. Defer unrestricted adoption until a
permitted official successor identity, selected scientific task, full rights
and reproducible environment are established. An isolated Java integration
could be economical when it preserves typed inputs, preprocessing, ordering,
weights and complete failure semantics. Porting a Bayesian-network engine
creates new search, probability and maintenance obligations without a measured
benefit here. Reject using this classifier graph as an automatically identified
causal model; retain separately specified causal and predictive alternatives.
\citep{exec24_weka_choice}

The scientific owner defines prediction versus intervention, observed-label
selection, support and temporal split. The adapter owner validates imports,
preprocessing state, output simplex and failures. The platform and rights owner
resolves actual artifacts, notices and maintenance; the evaluation owner
predeclares generated confounding, selection, empty-row, weight-rescaling,
node-permutation and numerical-refusal fixtures. A 7,200 USD authored trial
with 360 submitted, 300 completed and 240 qualified tasks costs respectively
20, 24 and 30 USD per task. Include failed fits, analyst correction, upgrades
and review rather than reporting successful-call runtime as investment value.
\citep{exec24_weka_choice}

Known routes exist for official source access, artifact and license inspection,
typed native public fixtures and fair predictive comparison. Unknown bank
assignment, missing-label truth and causal sufficiency require new information
or defensible restrictions; a software wrapper cannot manufacture them. The
reference decision gives no native, causal or economic qualification.
Independent validation remains outstanding.

\section{Banjo: temporal network search, observation clocks and a bounded reference choice}
\label{sec:exec24-banjo-reuse}

A bank may seek a temporal graph linking servicing actions, balances and later
repayment. The useful question is whether changing an action changes repayment,
not merely whether yesterday's recorded action predicts tomorrow's label.
Banjo supplies a concrete reference for discrete Bayesian-network search with
lag restrictions. The acquired implementation is a gene-network application
derivative, however, and its inferred cellular pseudotime is not a bank's
physical decision clock. Its selected source can inform a proposed worker
contract without establishing an operational banking implementation.
This comparison preserves the earlier Java and temporal surveys and extends
their analysis of identity, preprocessing, search and graph output
\cite{exec13_java_banjo,exec15_javatemporal_banjo,exec24_banjo_source}.

\subsection{Which artifact, which permission, which proposed use?}
The selected repository is \texttt{daniel-315/slingshot-modified-banjo}, pinned
to its 13 August 2026 commit. Twenty-one selected original files authenticate
against the complete pinned tree through Git blob identity and full-byte
SHA-256. They include application settings, the score and observation
implementations, graph management, search, proposal and cycle checks,
discretization, and the graph comparator. Source constants identify Banjo
2.2.0 with the date 15 April 2008; that declaration does not authenticate an
official distribution, describe all derivative changes or establish current
maintenance. The selected compile script targets Java 8 bytecode; the script
has been inspected but not executed. Neither successful native compilation nor
the identity of a distributed binary is claimed \cite{exec24_banjo_source}.

The source notice reserves rights to Duke University and Alexander Hartemink.
It says that noncommercial use may be licensed and directs commercial users
to contact the rights holder. A possible license is not a granted license.
The official-source identity attempt was refused by the fixed collector's
host policy before an HTTP response, so the evidence does not show that the
official site is unavailable. The actual grant, complete terms, derivative
permissions and dependency inventory remain unresolved. A banking product
cannot infer commercial reuse permission from public source visibility
\cite{exec24_banjo_source,exec24_banjo_choice}.

Reference use is therefore the present proposal decision. Direct adoption and
porting are deferred pending authentic rights and a measured benefit.
A separate Java worker is a candidate integration route after rights, artifact
identity and public fixtures are qualified. Rewriting the search is an
alternative only if its scientific and maintenance costs justify a separate
implementation. Rejecting automatic causal interpretations or silent
conversion loss does not require rejecting every predictive comparison.
The source review establishes this bounded choice, not an admitted native
capability \cite{exec24_banjo_choice}.

\subsection{Lag windows, discretization and support must share a clock}
Let $X_{i,t}$ be variable $i$ in an observation file and let $L$ be the maximum
lag. Each scored row pairs current variables with their preceding $L$ rows.
For valid file lengths $T_f>L$, the number of available windows is
\[
 N=\sum_f(T_f-L).
\]
The selected observation implementation constructs windows within each file,
so it avoids a transition from the end of one file to the beginning of the
next. Two files of lengths four and three with $L=1$ supply five windows.
Concatenating them first supplies six and creates one false cross-file
transition. The application setting of 959 observations with lag one yields
958 available windows in one file; the requested count is capped at the
available count. A file boundary is consequently part of the statistical
input, not merely a storage optimization. A proposed bank adapter must retain
entity boundaries, calendars, missing intervals and the meaning of a row
\cite{exec24_banjo_source,exec24_banjo_choice}.

By contrast, the discretization map is fitted to all combined loaded raw
observations before those observations are mapped back to their files.
The selected interval discretizer uses the observed range and a requested
number of bins; when the number of distinct values does not exceed the bin
count, it assigns successive category labels. It is not an equal-frequency
rule. In the authored two-bin witness, training values $0,1,2$ map to
$0,1,1$. Adding a held-out value of $100$ changes their mapping to $0,0,0$.
This is a precise reason to declare the fit split before preprocessing.
It is not evidence that every exploratory use of combined observations is
leakage. A future predictive evaluation requires training-only fit, retained
cutpoints and a declared out-of-range policy. The selected value-lookup path
throws when a value has no stored mapping; an adapter must not assume that
an arbitrary new observation is automatically classified by a frozen
threshold model \cite{exec24_banjo_source,exec24_banjo_choice}.

A second boundary concerns a category present only in the initial lag rows.
The selected cardinality routine scans current slices of usable windows and
takes one plus each variable's largest code. For a coded sequence $(1,0,0)$
with lag one, current slices contain only zero but the first lagged parent is
one. The authored witness compares a current-only cardinality of one with a
lag-inclusive cardinality of two. The score's parent-configuration count uses
these declared cardinalities, while its indexing reads lagged values. This
is a conditional inconsistency requiring an end-to-end fixture, not an
observed Java crash. Earlier validation or a different runtime path could
refuse the input. The product contract should verify every current and lagged
code against its declared domain before search, and preserve a refusal rather
than quietly renumbering the data \cite{exec24_banjo_source,exec24_banjo_choice}.

\subsection{What the score establishes, and what it does not}
For node $i$, let $r_i$ be its number of states, $q_i$ the product of its
parents' state counts, $N_{ijk}$ the count for parent configuration $j$ and
child state $k$, and $N_{ij}=\sum_kN_{ijk}$. With positive equivalent sample
size $\alpha$, the inspected evaluator implements the local log score
\begin{align*}
 s_i={}&\sum_{j=1}^{q_i}\left[\log\Gamma(\alpha/q_i)
                  -\log\Gamma(\alpha/q_i+N_{ij})\right]\\
 &+\sum_{j=1}^{q_i}\sum_{k=1}^{r_i}
       \left[\log\Gamma(\alpha/(q_ir_i)+N_{ijk})
                  -\log\Gamma(\alpha/(q_ir_i))\right].
\end{align*}
Zero-count terms cancel. The source has compact-array and legacy observation
paths, increments integer counts for the selected rows and can precompute
log-gamma values. Its input validation requires a positive equivalent sample
size. These facts identify the selected computation; they do not prove that
successive bank windows are independent or that a chosen discrete model is
correct \cite{exec24_banjo_source}.

The exact authored oracle evaluates the same finite rising-factorial
expression without executing Banjo. For binary parent and child, counts
$(2,0)$ and $(0,2)$ and $\alpha=2$ give a conditional marginal factor $9/64$.
The no-parent counts $(2,2)$ give $1/30$, so their ratio is $135/32$.
Repeating each observation twice changes that ratio to $385875/8192$.
The extra apparent strength is produced by count duplication; it does not
manufacture independent information. The local ratio conditions on the
specified domains, prior and models, with common terms held fixed. It is
not a posterior probability of a causal edge. The oracle also checks the
log-gamma representation numerically against the exact rational results
\cite{exec24_banjo_choice}.

Lag order alone does not resolve this causal distinction. Consider two
authored mechanisms for an action $A_{t-1}$ and outcome $Y_t$. In the first,
a hidden fair binary variable $U_{t-1}$ determines both
$A_{t-1}=U_{t-1}$ and $Y_t=U_{t-1}$. In the second,
$A_{t-1}$ is fair binary and $Y_t=A_{t-1}$. Both observational laws place
probability one half on $(0,0)$ and $(1,1)$, yet their intervention contrasts
are respectively zero and one. Time direction excludes a future-to-past
arrow but does not exclude the hidden common cause. A hypothetical campaign
covering 1,000 accounts, valuing a successful outcome at 50 USD and costing
10,000 USD therefore has net value of either $-10{,}000$ or $40{,}000$ USD
under these two mechanisms. Neither number is a bank forecast. Additional
assignment knowledge, measured confounders, interventions or a justified
restricted causal model is needed to decide between them
\cite{exec24_banjo_choice}.

\section{libDAI: exact factor meaning before approximate computation}
\label{sec:exec24-libdai-reuse}

A bank may need probabilities from an already specified causal model before
it compares interventions. A discrete inference engine can compute those
probabilities, but it cannot supply missing causal assumptions merely by
returning normalized beliefs. libDAI is a useful reference for that boundary:
its factor representation, exact enumeration, junction-tree computation and
belief propagation expose different mathematical and operational contracts.
The earlier combined C++ comparison remains intact; this review separates
libDAI's concrete reuse decision from OpenGM and examines the selected
implementation rather than treating a feature list as qualification
\cite{exec13_cxx_inference,exec24_libdai_source}.

\subsection{A historical paper and a later source revision}
Mooij's five-page JMLR paper describes version 0.2.7, released under GPL v2 or
later. Its factor-graph formulation, available inference tasks and interface

worker. The genuine publisher PDF is retained and inspected, including its

configurations. The paper says that not every method implements every task;

\cite{exec24_libdai_paper}.

The selected source is the \texttt{dbtsai/libDAI} mirror at its 16 May 2012
revision. Its README declares version 0.3.0, dated 12 July 2011, and its
license grants redistribution under two-clause BSD conditions. Those later

selected files authenticate against the complete pinned tree, including
factor and probability primitives, indexing, factor-graph operations, exact
inference, belief propagation, junction-tree construction and build settings.
The mirror is not authenticated as an official current distribution. The
official-source attempt was rejected by the collector's fixed host policy,
which is not evidence of an unavailable server
\cite{exec24_libdai_source,exec24_libdai_choice}.

The Linux template links GMP and GMPXX and names Boost libraries. Its SWIG

The platform-independent configuration enables debug checks, while the

library has been executed for this review \cite{exec24_libdai_source}.

The preceding bridge and discovery examples concern the interpretation of a
graph inferred or supplied by an analyst. Even after a causal model is
accepted for a particular calculation, its probability representation can
change at the next boundary. Factor ordering, normalization and the operation
used to encode an intervention therefore require their own comparison.

\subsection{Factor meaning is a typed conversion contract}
Let the finite variables be $X_V=(X_i:i\in V)$ and let each nonnegative factor
$f_I$ depend on variables $X_{N_I}$. The represented probability law is
\[
 p(x_V)=\frac{\prod_I f_I(x_{N_I})}{Z},\qquad
 Z=\sum_{x_V}\prod_I f_I(x_{N_I}).
\]
This requires finite nonnegative entries and $0<Z<\infty$. A Bayesian network
can be represented using one conditional-probability factor per variable.
That conversion preserves a probability law only if category meaning,
variable identity, dimensions and entry ordering are also preserved
\cite{exec24_libdai_paper,exec24_libdai_source}.

The source orders variables by ascending numeric label and uses the first
variable as the fastest-changing index. With binary $X$ followed by
three-state $Y$, the index is $x+2y$. Assigning weights $(1,2,3,4,5,6)$ in
that order yields $p(X=1)=4/7$. Reading the same vector as a row-major table
with index $3x+y$ instead yields $5/7$. Both outputs normalize and can look
plausible; a probability-simplex check cannot detect this error. One factor
constructor accepts a variable set and copies entries, whereas the ordered
variable-vector constructor explicitly permutes entries. A proposed adapter
must select the correct contract and retain category labels and the
permutation as auditable input \cite{exec24_libdai_source,exec24_libdai_choice}.

The variable comparison operators use labels for identity; matching labels
with different state counts trigger checks only under the selected debug
conditional. The adapter should always reject conflicting domains before
construction, regardless of the native build. The linear-index routine also
defaults unspecified variables to state zero. A missing business observation
must therefore be represented as missing evidence, not passed as an omitted
state that silently becomes the first category. The marginal routine
intersects the requested variable set with the factor's domain; the caller
must verify that every requested variable was actually represented. These
are distinct identity, missingness and query-completeness tests
\cite{exec24_libdai_source}.

\subsection{Clamping evidence does not perform a causal intervention}
The inspected factor-graph clamp multiplies neighboring factors by a
single-state indicator. This conditions the original distribution on an
observation. In a causally justified Bayesian network, an intervention
instead replaces the factor governing the action by the specified assignment
mechanism, while retaining the other mechanisms. The factor graph alone
does not say which table was an action's causal mechanism. That provenance
must survive compilation \cite{exec24_libdai_source,exec24_libdai_choice}.

An exact authored example makes the distinction observable. Let $U$ be fair
binary, let $P(A=U\mid U)=4/5$, and let $Y=U$. Then
$P(Y=1\mid A=1)=4/5$, while
$P(Y=1\mid\operatorname{do}(A=1))=1/2$ and the intervention contrast is zero.
The conditioning calculation retains $p(A\mid U)$; the intervention
calculation replaces it. This example supplies the causal model explicitly.
It does not infer that model from the observed distribution
\cite{exec24_libdai_choice}.

Nor is making a cavity a generic intervention implementation: the selected
method replaces every factor touching a variable with ones, which can erase
outcome mechanisms as well as the assignment mechanism. Backup and restore
operations can retain earlier factors, but the worker must verify recovery
under failed or cancelled requests. In the selected clamp, the initial
guard permits an index equal to the number of states, whereas valid indices
are strictly smaller. The subsequent setter has a debug-only bounds check.
This is a conditional source boundary requiring a native fixture, not an
observed memory fault. The proposed API rejects every index outside
$0\leq x<r_i$ before calling the library
\cite{exec24_libdai_source,exec24_libdai_choice}.

\subsection{Exact inference has numerical and resource conditions}
The selected exact enumerator multiplies factors into a full joint table,
computes its sum and normalizes marginals. Its algorithmic exactness is
conditional on the supplied finite model; it does not imply exact arithmetic.
For two singleton factors with entries $(10^{-200},2\cdot10^{-200})$, the
mathematically normalized product is $(1/5,4/5)$, but both binary64 products
underflow to zero in the independent witness. A log-scale calculation with
maximum subtraction recovers the intended normalized ratio. An exactly zero
normalizer instead denotes an impossible or invalid query and must be
refused. Scaling factors and tracking their scales can preserve normalized
beliefs, but the scales must also be restored when reporting $\log Z$.
The inspected probability primitive explicitly refuses a zero norm;
finite, nonnegative inputs and finite outputs require additional checks
\cite{exec24_libdai_source,exec24_libdai_choice}.

Resource use is another part of the result. A full joint table on thirty
binary variables has $2^{30}$ entries: eight-byte entries alone require
8 GiB, before containers and intermediate products. Junction-tree inference
can exploit structure, but its clique tables may still be large. The
selected constructor chooses an elimination heuristic and applies a memory
estimate with a documented heuristic multiplier. An estimate is not an
operating-system resource limit. A proposed worker needs its own memory,
time, cancellation and output limits, and must report when a requested
exact calculation was refused or replaced by an explicitly approved
approximation \cite{exec24_libdai_source,exec24_libdai_choice}.

\subsection{A zero convergence residual can coexist with a wrong marginal}
Belief propagation iterates messages, with configured update order, damping,
log-domain arithmetic, tolerance and iteration/time bounds. The selected
implementation returns the largest change in beliefs; a nonconvergence
warning is conditional on verbosity. It explicitly omits NaN checks in the
iteration loop. A worker must inspect residuals, iteration counts, finite
values and termination conditions independently of textual logs. Even a
finite residual below tolerance does not bound marginal error
\cite{exec24_libdai_source}.

Consider an authored triangle of binary variables with edge factor three
when neighboring states agree and one when they disagree. Uniform messages
remain uniform after a belief-propagation update, giving zero residual.
The resulting edge belief assigns agreement probability $3/4$. Exact
enumeration gives two all-equal states of weight 27 each and six other
states of weight three each, hence $Z=72$. For a fixed edge, the agreeing
weight is 60, so its true agreement probability is $5/6$. The error is
$1/12$ despite the fixed point. Single-variable marginals are one half in
both calculations, so inspecting only those marginals would miss the
discrepancy \cite{exec24_libdai_choice}.

This is a mathematical witness for the proposed diagnostic, not a native
libDAI benchmark. It distinguishes iterative stability, approximation error
and statistical uncertainty. Under a hypothetical decision coefficient of
120,000 USD, an error of $1/12$ translates into 10,000 USD of value error.
A small residual cannot justify that monetary exposure. Public qualification
should compare exact and approximate results on declared finite regimes,
measure query-specific errors and refuse unsupported accuracy claims.
Sampling uncertainty and uncertainty about the causal model remain separate
\cite{exec24_libdai_choice}.

and conditional candidate for an isolated C++ inference worker. Direct
adoption of a general causal platform is rejected because the selected

\subsection{Graph identification and numeric support are different predicates}
The selected causal formula tests identification by the presence of an
abstract-syntax-tree root. Its evaluation method refuses a missing root and
otherwise evaluates that tree against the observational Bayesian network.
These are useful distinctions, but a present root is not a certificate of
positive observational support for every conditional term. The source also
checks that queried variables are observed and that outcome, intervention
and conditioning sets do not overlap. A caller must preserve those
preconditions rather than reducing every failure to an empty numeric answer
\cite{exec24_agrum_source}.

The selected division node evaluates its children and invokes tensor
division. For dense arrays, the inspected dispatch reaches ordinary
elementwise division; generic dispatch similarly invokes the registered
operator. No support-zero refusal is introduced along those selected
numeric branches. Scalar and empty-tensor branches also divide directly.
This is a bounded source finding: it does not establish that every
high-level query reaches a zero denominator, or that every scalar type and
runtime reports the same result. It defines concrete zero-over-zero,
positive-over-zero and nonfinite fixtures for native evaluation
\cite{exec24_agrum_source,exec24_agrum_choice}.

Ordinary tensor normalization leaves a zero-sum tensor unchanged. By
contrast, conditional-probability-table normalization throws for a zero-sum
conditioning row. These methods therefore have different contracts.
A returned all-zero vector is not a normalized distribution and cannot be
read as zero risk. A proposed wrapper must check finite nonnegative entries,
required support, dimensional completeness and the appropriate normalizer
for its query. It should return a typed refusal or an explicitly justified
identified set; adding a small denominator is a modeling change, not an
innocuous formatting repair \cite{exec24_agrum_source,exec24_agrum_choice}.

For an exact authored example, let a binary covariate $Z$ have probability
one half in each stratum. Suppose action $A=1$ is observed only when $Z=0$,
where the mean outcome under that action is one half. Under the specified
adjustment model, the supported contribution to the population mean is
$1/2\cdot1/2=1/4$. The unobserved mean for $Z=1$ can be any $m\in[0,1]$,
so the compatible intervention means form
\[
 \mu(1)=\frac14+\frac12m\in\left[\frac14,\frac34\right].
\]
The formula's unsupported conditional term corresponds to a zero-over-zero
ratio in the observed distribution. Replacing it by zero selects the lower
endpoint; replacing it by one half selects the midpoint. Neither operation
identifies the missing mean. Publicly generated data can test whether the
worker preserves this refusal or set, but recovering the actual missing
bank response requires additional information or a justified restriction
\cite{exec24_agrum_choice}.

\subsection{Counterfactual abduction must preserve a joint posterior}
The selected counterfactual builder starts from the observational Bayesian
network, identifies parentless variables excluding intervention and declared
latent variables, computes their individual posteriors given the profile,
and fills their separate root tables with those marginals. This preserves
each updated root marginal. It need not preserve dependence induced between
the roots by conditioning on their common descendant. The earlier
identification review already flags this boundary; the present decision
retains it as a prerequisite for a native, query-specific comparison
\cite{exec19_cxx_identification_source,exec24_agrum_source}.

Consider independent fair binary roots $U,V$, an action $A$, a factual
observation $E=\mathbf1\{U=V\}$, and deterministic potential outcome
$W(a)=a\mathbin{\mathrm{xor}}U\mathbin{\mathrm{xor}}V$.
After observing $E=1$, the joint posterior places one half on $(0,0)$ and
one half on $(1,1)$. Both individual root marginals are still fair binary.
Under $\operatorname{do}(A=1)$, preserving the joint posterior gives
$P(W(1)=1\mid E=1)=1$. Replacing it by the product of its marginal
posteriors assigns probability one quarter to all four root pairs and gives
one half instead. This is an exact finite structural example, not a claim
that a particular installed aGrUM build returned the latter value
\cite{exec24_agrum_choice}.

The difference has a concrete decision interpretation. For a hypothetical
1,000-account cohort, 80 USD per successful outcome and a 30,000 USD
campaign cost, the two calculations give 50,000 and 10,000 USD net value.
The 40,000 USD discrepancy comes from discarded posterior coupling, not
from Monte Carlo error. A valid restricted use may prove that the factual
profile leaves relevant roots independent, or may preserve a joint
abduction distribution in another representation. A general counterfactual
claim instead requires structural mechanisms and cross-world coupling that
an observational Bayesian network does not supply automatically
\cite{exec24_agrum_choice}.

Graph identity also matters during reconstruction. The constructor from an
observational network differs from the copy constructor of the full causal
model. The selected counterfactual path uses the former, so added latent
descriptors and causal annotations need an explicit preservation test.
The output adapter maps variables back to the original network by name and
fills the resulting tensor. Domain labels, order and retained annotations
must be checked together; equal displayed names alone are insufficient

\subsection{Tensor identity and language wrappers are scientific interfaces}
The inspected dense and generic binary-operation templates compare shared

displayed name. Higher-level construction may impose further checks; this
review does not claim that every Python object with a repeated name silently

An authored probability witness explains why that fixture matters. Two

and normalize to $(4/7,3/7)$. If an adapter instead treats them as distinct
variables, it produces an outer-product joint distribution whose
probability that the two states disagree is $13/20$. That is a different
model, even though both outputs are normalized. Variable identity, not only
numeric values, belongs in the round-trip contract
\cite{exec24_agrum_choice}.

The selected Python convenience method standardizes string queries into

returned tensor and returns \texttt{None} for an unidentified formula.
The inspected SWIG extension also documents special constructor and lifetime
handling. These source observations do not settle every exception,
temporary-object, serialization or cancellation path. A CLI or MCP response

invalid domain, runtime failure and successful qualified value. Serializing

\section{OpenGM: preserving the question across optimization and inference}

libDAI, graph-cut libraries, HDF5 and Python bindings. The inspected defaults
disable the command-line build and Python wrapper. A list of supported
interfaces therefore does not establish what an installed artifact contains.
The selected source's build requirements and declarations are evidence for
a proposed artifact inventory; no downloaded code or build script has been
executed \cite{exec24_opengm_source}.

The proposal retains OpenGM as a reference and leaves a narrowly specified
isolated worker as a conditional integration option. Direct adoption of the
whole solver catalogue is deferred because its algorithms have different
domains, rights and result contracts. Porting is deferred until a measured
need justifies maintaining model encodings, numeric behavior and solver
interfaces. The unmaintained declaration increases the importance of an
identified maintenance owner and a supported build, but is not by itself a
proof that every bounded use is unsuitable \cite{exec24_opengm_choice}.

\subsection{The algebra is part of the business query}
Let $V$ be finite variables, $F$ factors, $x$ a joint labeling, and
$\phi_f(x_{N(f)})$ a factor on its ordered neighborhood. OpenGM separates
the operation that combines factors from the operation that accumulates
over labelings. For a probability model, an unnormalized weight is
\[
 w(x)=\prod_{f\in F}\phi_f(x_{N(f)}),\qquad
 Z=\sum_x w(x),\qquad p(x)=w(x)/Z,
\]
provided the factors give finite nonnegative weights and $0<Z<\infty$.
For an energy model, $E(x)=\sum_f e_f(x_{N(f)})$ may instead be minimized.
The library paper formalizes these as different algebraic choices. It also
explicitly warns that not every algorithm supports every choice. Selected
source implements separate addition, multiplication, minimization and
maximization operations. A type name or successful generic serialization
cannot replace the algorithm-specific compatibility check
\cite{exec24_opengm_paper,exec24_opengm_source}.

An exact authored example makes the distinction operational. Suppose two
binary labels have joint probabilities
\[
 p(0,0)=0.35,\quad p(0,1)=0.25,\quad p(1,0)=0,\quad p(1,1)=0.40.
\]
The most probable joint labeling is $(1,1)$, but $P(X=0)=0.60$. Under
unit loss for an incorrect prediction of $X$, choosing its marginal mode
has expected loss $0.40$, whereas taking the $X$ component of the joint
mode has loss $0.60$. For 10,000 hypothetical cases at 100 USD per error,
that substitution adds 200,000 USD expected loss. The solver could have
correctly solved its stated joint optimization problem while the business
adapter answered the wrong question \cite{exec24_opengm_choice}.

Even correct probability inference does not identify an intervention.
Let an unobserved fair binary $U$ determine $Y=U$, and let the assigned
action equal $U$ with probability $4/5$. Then $P(Y=1\mid A=1)=4/5$, while
both intervention means are $1/2$ and the effect of changing $A$ is zero.
Conditioning a factor graph on $A=1$ preserves the selection association;
it does not remove the assignment mechanism. A causal worker needs an
identified model and a declared mechanism transformation before numerical
inference is meaningful \cite{exec24_opengm_choice}.

\subsection{A normal return does not certify exhaustive search}
The selected brute-force routine enumerates configurations with variable
zero changing fastest. It updates an incumbent through the chosen ordered
accumulator, invokes a visitor, and stops if the visitor requests it. Both
visitor stopping and exhaustion reach a final \texttt{NORMAL} return.
The separate visitor protocol distinguishes, for example, a time-limit stop
from a bound-based stop, but that distinction is not preserved in this
routine's return code. Its \texttt{arg} method supports the first stored
labeling and returns \texttt{UNKNOWN} for a requested higher rank. These
are concrete source contracts, not a report from an installed worker
\cite{exec24_opengm_source}.

For a two-variable authored energy table, let the enumeration order
$(0,0),(1,0),(0,1),(1,1)$ have energies $5,4,3,0$. Stopping after two
visits produces incumbent $4$; complete enumeration produces $0$.
The four-unit difference is known because this tiny example has an exact
oracle. In a larger case, \texttt{NORMAL} alone does not supply either an
exhaustion certificate or a finite optimality gap. The proposed response
must therefore include the visited/requested state counts where meaningful,
visitor stop reason, incumbent, independently valid bound and algorithm
configuration \cite{exec24_opengm_choice}.

The inherited base inference interface further returns an inverse-neutral
value for its default bound when the accumulator has an ordering, and a
not-a-number value when it does not. For floating-point minimization,
the selected inverse neutral is negative infinity. The brute-force class
does not override that bound in the inspected header. Exhaustion may justify
an exact result under valid arithmetic, but merely reading its default bound
does not yield a useful finite certificate. Unsupported marginals return
\texttt{UNKNOWN} in the base interface. A uniform response schema must
preserve those distinctions instead of manufacturing a probability or gap
\cite{exec24_opengm_source}.

\subsection{Hard constraints and shared factors require numerical contracts}
A second boundary appears in the concrete move-making delegate. For a
multiplicative model it recomputes the destination objective. For other
operators it updates the previous value by combining a new factor value
and removing the old one. With finite exact arithmetic this is a useful
incremental calculation. With infinite penalties it can have a different
numeric contract \cite{exec24_opengm_source}.

Consider an additive unary energy whose initial label has positive infinite
penalty and whose other label has zero penalty. The exact constrained
optimum is the feasible second label. Along the inspected incremental
update, the arithmetic expression is $+\infty+0-(+\infty)$, which is
not-a-number under the independently tested binary64 arithmetic. This is a
conditional source witness: no native OpenGM failure was observed, and
other algorithms or encodings may follow different paths. It motivates
fixtures for initially infeasible states, infinite penalties, NaNs and
finite substitutes. Replacing infinity by an arbitrary large constant is
not automatically valid; the constant must dominate a proved objective
range without creating unacceptable numeric error
\cite{exec24_opengm_source,exec24_opengm_choice}.

Function sharing saves representation space but does not remove repeated
factors. An authored unary factor with weights $(2,1)$ gives probability
$2/3$ to its first label after normalization. Adding the same factor twice
multiplies its contribution twice and yields $4/5$, a change of $2/15$.
That may be the intended model, or it may double-count one observation.
The adapter must distinguish shared storage identity from independent
evidence provenance \cite{exec24_opengm_paper,exec24_opengm_choice}.

Variable order is another semantic input. The inspected factor constructor
requires strictly increasing variable indices using runtime checks that
remain active when ordinary debug assertions are disabled. Other label
checks are assertions, and one direct-evaluation label check is commented
out in the selected source. This does not prove every invalid call lacks
validation; it requires entrypoint-specific tests. Sorting variable indices
must also permute factor axes. For a binary table with weights
$w(0,0)=1,w(0,1)=2,w(1,0)=3,w(1,1)=4$, the correct $P(X=1)$ is $7/10$.
Transposing its semantic axes changes the reported event probability to
$3/5$. Both tables normalize, so a sum-to-one check cannot detect the
meaning change \cite{exec24_opengm_source,exec24_opengm_choice}.

\subsection{A bounded public qualification route}
The proposed qualification suite starts with tiny fully enumerated models,
where energy optima, partition functions and marginal probabilities have
separate exact oracles. It varies semiring, solver, factor and variable
order, shared function identity, numeric type, constraint encoding and
early visitor stops. It tests valid inputs and typed refusals separately.
Even 40 binary variables have $2^{40}=1{,}099{,}511{,}627{,}776$ joint
assignments; finite representability is not a practical exhaustive-search
guarantee. Sparse or shared functions can reduce storage while leaving
the search combinatorics difficult \cite{exec24_opengm_choice}.

An isolated CLI or MCP worker should declare its exact artifact, enabled
solver dependencies, model algebra, supported factor class and requested
result. Its output distinguishes model rejection, unsupported algorithm,
timeout, incomplete incumbent, numeric failure and qualified result. A
timeout must preserve request identity and partial-result status; a retry
must not duplicate a business action. These are proposed adapter contracts,
not verified OpenGM integrations \cite{exec24_opengm_choice}.

Scientific ownership covers causal meaning and loss; numerical ownership
covers algebra, domain and valid bounds; adapter ownership covers ordering,
termination and request recovery; platform ownership covers maintenance,
rights and complete cost. A hypothetical 18,000 USD over 600 submitted,
450 completed and 300 qualified requests gives 30, 40 and 60 USD per request
under the respective denominators. Actual current support, compatibility,
prices and decision value remain unknown. Public tests can resolve bounded
implementation questions before expensive bank experiments. Hidden
assignment, unrestricted causal identification and arbitrary uncertainty
cannot be supplied by a general factor-graph solver. Package execution and
independent validation remain to be performed
\cite{exec24_opengm_choice}.

The chapter's comparisons locate several different causes of an apparently
successful but unusable answer. A bridge can change variable meaning, a
predictor can answer a conditional rather than interventional question, and
an inference engine can solve the wrong numerical objective. Even the right
objective may have unsupported probability terms or an inadequate numerical
approximation. The shared service must preserve the question at each of
these steps. The authoritative software choice in
Chapter~\ref{scisyn:software} therefore remains selective reuse with explicit
scientific and numerical boundaries; these examples explain the obligations
behind that choice.
