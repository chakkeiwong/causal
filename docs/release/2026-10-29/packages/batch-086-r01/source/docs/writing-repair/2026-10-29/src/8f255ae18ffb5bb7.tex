\section{NumPyro: preserving the experiment through handlers and compiled inference}
\label{sec:exec23-numpyro-worker}

NumPyro is a plausible Python worker when a bank can state a probabilistic model and wants to explore a JAX-based computational route. Its role begins with that supplied model. It does not determine whether a servicing action is manipulable, whether an unrecorded customer state confounds treatment, or whether a financial reporting field was available when the decision was made. These scientific choices must enter the model contract before a sampler can answer the intended question. The pinned source examined here declares version 0.22.0 at revision \texttt{033f7e2e57bd0396fba8493ae246debe52f2c973}, committed on 5 October 2026. This is a source declaration at a revision within the literature cutoff, rather than an assertion that an independently acquired release artifact has identical contents. The root license is Apache-2.0, the Python requirement is at least 3.11, and the direct numerical requirements include JAX and jaxlib at least 0.7.0. Device-specific extras and the additional Funsor inference route require their own artifact and rights review. \citep{exec23_numpyro_sources}

The comparison with PyMC is therefore a comparison of proposed worker contracts. PyMC's inspected route transforms a graph and controls predictive freezing and regeneration; NumPyro's inspected route applies handlers to executions of a stochastic function and passes arrays through compiled inference. Neither representation supplies missing assignment information. Both need the same banking estimand, information clock, outcome units and refusal semantics. Their different defaults make a transparent adapter more useful than a wrapper that merely gives identically named commands. \citep{exec23_pymc_sources,exec23_numpyro_sources}

\subsection{Conditioning, intervention and the meaning of an execution trace}

In the inspected handler implementation, \texttt{condition} sets a matched sample value and marks the site observed. \texttt{substitute} can replace several kinds of primitive, including deterministic values, without making the same observation declaration. \texttt{replay} takes matched sampled values from an execution trace, checks the sampled-versus-observed role and leaves already observed target sites alone. Thus matching a site name is a mechanism for moving values; it is not evidence that two models describe the same financial experiment. An adapter must bind the model, data and site roles as well as their array shapes. \citep{exec23_numpyro_sources}

The \texttt{do} handler makes an especially consequential distinction. It creates a fresh sample site with the original name whose value does not propagate to descendants, then sends the supplied intervention value down the original computation. A returned treatment value and a recorded sample under the original treatment name can consequently differ by design. The upstream counterfactual tests explicitly distinguish the model's returned values from the trace values, including when observation and intervention are composed. Those tests describe intended behavior; they have not been executed in this proposal. A converter that extracts the original-name trace entry and calls it the administered action could misreport the experiment even when the handler follows its own contract. Multiple intervention handlers at the same site also require attention to the inspected warning and handler order. \citep{exec23_numpyro_sources}

The causal distinction can be checked without a numerical backend. Let an unobserved binary type $U$ have probability $1/2$, let a binary action $A$ agree with $U$ with probability $3/4$, and set the response to $Y=2A+4U$. Enumeration gives
\begin{equation}
 \mathrm{E}(Y\mid A=0)=1,\qquad
 \mathrm{E}(Y\mid A=1)=5,\qquad
 \mathrm{E}\{Y\mid\operatorname{do}(A=a)\}=2a+2.
\end{equation}
The association is four response units and the intervention contrast is two. This is the same deliberately confounded law used in the PyMC comparison, recalculated by an independently authored finite enumeration here. It supplies a common semantic oracle: conditioning an action and cutting its assignment mechanism have different answers. Neither backend acquires identification simply by returning one of these numbers. \citep{exec23_pymc_reference,exec23_numpyro_reference}

Composing handlers also does not make every customer-specific counterfactual identified. To see the extra requirement, let $Y^0$ and $Y^1$ denote binary responses under two actions. One structural model has $(Y^0,Y^1)=(U,U)$ for $U\sim\mathrm{Bernoulli}(1/2)$; another has $(Y^0,Y^1)=(U,1-U)$. Both have
\begin{equation}
 \Pr(Y^0=1)=\Pr(Y^1=1)=\tfrac12,
\end{equation}
but $\Pr(Y^1=1\mid Y^0=1)$ is one in the first model and zero in the second. Equal single-world intervention marginals leave this cross-world quantity undetermined. A shared-noise construction or another justified restriction can define a model-specific answer, and sensitivity across these constructions can expose the ambiguity. A model proposed by an LLM must state that construction explicitly; handler composition cannot verify it. This example is an authored identification witness, not an upstream software failure. \citep{exec23_numpyro_reference}

\subsection{Prediction must preserve which latent variables are regenerated}

The inspected \texttt{Predictive} implementation substitutes supplied posterior values, then executes the model. By default it ignores stored deterministic values during substitution and recomputes them from their parents. Setting \texttt{condition\_deterministic=True} instead permits those stored values to be substituted. Output selection through \texttt{return\_sites} has a separate role. As a simple arithmetic check, equal-weight parent values $(1,2)$ give a stored-square mean of $5/2$ and a recomputed-cube mean of $9/2$. Keeping the old deterministic values after changing the expression answers a different question from recomputation. NumPyro's default and PyMC's inspected predictive controls should therefore be represented by explicit regeneration choices in a common interface. One cannot infer equivalence from matching output names. \citep{exec23_numpyro_sources,exec23_pymc_sources,exec23_numpyro_reference}

Posterior substitution also fixes supplied stochastic sites. Including such a site among requested outputs does not ask the model to redraw it. Conversely, an absent latent site is not automatically inferred from an observed response during ordinary forward execution. The inspected \texttt{infer\_discrete} path invokes additional enumeration and posterior-sampling machinery; ordinary prediction uses a different masking and execution path. The documentation further requires clearing an observed response to generate a new realization of that response. Leaving an old observation attached can preserve that value rather than create a new future outcome. A bank worker must distinguish parameter draws learned from historical data, historical customer states, states to infer from new evidence and genuinely new outcomes. \citep{exec23_numpyro_sources}

A servicing example shows why this is an economic distinction. Suppose a hidden type $U=1$ has prior probability $1/3$, and an alert $S=1$ has probabilities $3/4$ under type one and $1/4$ under type zero. The alert probability and posterior type probability are
\begin{equation}
 \Pr(S=1)=\tfrac{5}{12},\qquad
 \Pr(U=1\mid S=1)=
 \frac{(1/3)(3/4)}{(1/3)(3/4)+(2/3)(1/4)}=\tfrac35.
\end{equation}
Let an additional action have stipulated net payoffs USD 100 for type one and USD $-200$ for type zero; taking no additional action pays zero. Averaging over the posterior gives
\begin{equation}
 V(1\mid S=1)=\tfrac35(100)+\tfrac25(-200)=-20.
\end{equation}
Replacing the type distribution by its most probable state instead reports USD 100 and selects the action, with an actual expected loss of USD 20 under the specified posterior law. Ignoring the alert and drawing the type from its prior gives yet another action value, USD $-100$. Posterior averaging, MAP substitution and unconditioned regeneration are three different procedures. These exact, stipulated amounts motivate the adapter's uncertainty contract; they are not measured returns from a bank or observed package behavior. \citep{exec23_numpyro_reference}

\subsection{Discrete inference and continuous sampling have separate contracts}

For enumerable latent sites, the inspected model utilities prepare parallel enumeration, with plate dimensions controlling the tensor arrangement. The Funsor contribution is an additional dependency and is labelled experimental by its import path. The inspected discrete handler accepts temperature one for posterior sampling and temperature zero for MAP-style decoding; other temperatures are rejected. Its source also warns that inferred-trace log probabilities are not meaningful. A downstream likelihood audit must not reuse those trace log probabilities as an ordinary fitted likelihood. Likewise, a MAP path is not a collection of posterior paths and cannot propagate hidden-state uncertainty in the servicing example. The scan boundary needs more careful qualification: the handler documentation says the scan primitive is unsupported, whereas the selected tests include scan hidden-Markov examples of lengths one and two and mark length ten as expected to fail because of a Markov sum-product adjoint limitation. This documentation/test tension justifies a registered length- and construction-specific trial, not a blanket assertion of support or a reproduced failure. None of those upstream tests has been run here. \citep{exec23_numpyro_sources}

NumPyro also exposes composable Gibbs and HMC-within-Gibbs routes. The inspected discrete selector distinguishes enumerable sites being updated from sites already marked for marginalization. The proposal must record that choice, support sizes, block structure and proposal settings. The inspected composition rejects some configurations, including subsample plates and value-dependent supports across blocks; the HMC-within-Gibbs entry rejects a bare potential-function model. These restrictions do not establish that a different kernel can repair the case. Native qualification should compare a small hidden-state model against complete enumeration and retain separate acceptance for marginal likelihood, posterior state probabilities and policy value. A state decoder agreeing with one selected path cannot satisfy all three. \citep{exec23_numpyro_sources}

A continuous reference can be equally transparent. With a $\mathrm{Beta}(2,3)$ prior and four successes plus one failure, the likelihood gives a $\mathrm{Beta}(6,4)$ posterior. Ratios of its normalizing integrals yield mean $3/5$ and variance $6/275$. This provides a check of both location and spread without treating an optimizer's answer as a posterior. A later registered trial can assess chains against those moments, finite-sample Monte Carlo tolerances and diagnostic behavior. Passing that trial would qualify this numerical construction under its declared law; it would not identify a confounded action or validate an unknown causal model. \citep{exec23_numpyro_reference}

\subsection{Devices, random keys, diagnostics and restart identity}

The inspected MCMC interface requests parallel chains by default but falls back to sequential chains with a warning if too few devices are available. Vectorized chains are another declared route. Device count, execution method and actual array precision must therefore enter a run identity; a requested GPU or parallel configuration is insufficient evidence that it was used. The source utilities expose platform and 64-bit configuration, and the host-device-count helper carries its own configuration caveat. These are controls to test, not measured throughput or a general speed advantage over PyMC. \citep{exec23_numpyro_sources}

Randomness needs equally explicit treatment. The seed handler carries a mutable random key and documents a closure pattern to avoid leaking this state through JAX transformations. MCMC splits a single key for multiple chains; it also accepts a supplied batch of keys. An adapter should preserve how chains and prediction tasks receive keys and check the intended independence or deliberate coupling. Four exact copies of a Bernoulli$(1/2)$ draw have average variance $1/4$; four independent draws have average variance $1/16$. Labelling copies as independent would understate variance by a factor of four. This is an authored dependence counterexample, not a finding that NumPyro's scalar-key splitting duplicates chains. Deliberately coupled random numbers for a paired comparison can be legitimate, but their covariance must be represented. \citep{exec23_numpyro_sources,exec23_numpyro_reference}

The inspected HMC state includes trajectory and divergence information, while the default collected fields retain samples and divergences. Further quantities need explicit collection. Summary functions use split R-hat and effective sample size with declared chain/draw axes and minimum draw requirements. Their names do not establish identity with another package's diagnostic implementation. The proposed worker must distinguish an unavailable diagnostic, a nonfinite value, an adverse diagnostic and a satisfactory result under predeclared criteria. None of these outcomes certifies assignment truth, graph identification or repeated-sampling calibration of a causal policy interval. \citep{exec23_numpyro_sources}

For continuation, \texttt{last\_state} and \texttt{post\_warmup\_state} expose more information than saved posterior draws. The documented continuation route reuses the final state and its random key; warmup behavior changes when a post-warmup state is supplied. This is a useful interface for a future recovery design, but not evidence of durable serialization, crash consistency or compatibility across changed models. A restart contract must bind the complete sampler state, model/data identities, transformations, adaptation, random-key lineage, numerical environment and publication boundary. Local fault injection must then show whether uninterrupted and interrupted executions meet the registered comparison rule. Timing must also account for JAX's asynchronous dispatch, which the MCMC documentation expressly notes; elapsed Python submission time alone is not complete computational cost. \citep{exec23_numpyro_sources}

\subsection{A concrete reuse decision and a bounded qualification route}

The appropriate disposition is to retain NumPyro as a source-qualified reference for a future native Python worker. Direct use would preserve its handler, enumeration and numerical semantics within a pinned environment. A general R, Java or C++ port would duplicate those semantics and the compiler boundary without demonstrated benefit; a process interface is the more defensible candidate until conversion costs are measured. PyMC remains a substantive alternative for graph transformation and posterior prediction, while exact finite and conjugate calculations remain independent semantic references. Selection between workers should use matched supported models, accepted uncertainty output, full compilation and warmup costs, effective sample production, prediction, memory, serialization and recovery. No hardware performance ranking follows from the source review. \citep{exec23_numpyro_sources,exec23_pymc_sources,exec23_numpyro_reference}

Library, CLI and MCP entrypoints should preserve one model and experiment identity: observation versus intervention, factual versus cross-world target, fixed versus regenerated sites, posterior averaging versus MAP decoding, units and clock, chain layout, precision and diagnostic availability. An LLM can propose these declarations, retrieve the supporting assumptions and explain refused requests; the model owner must justify their scientific meaning. A maintainer must bind the selected NumPyro, JAX, jaxlib, Funsor and device artifacts and their rights. An operator must set budgets, verify actual device execution and test durable recovery. The pinned metadata names a license-file path that differs from the inspected root filename, so a release trial must inspect the actual distributed notices rather than infer their custody from a classifier. None of these owner roles is filled by an API response. \citep{exec23_numpyro_sources}

Before integration approval, a registered native trial should exercise the finite confounding and cross-world witnesses, compare posterior averaging with discrete decoding, check deterministic substitution under changed inputs, validate the conjugate moments, inspect invalid supports and dimensions, verify diagnostic availability and test interrupted continuation. Whole-environment rights, numerical reliability and the causal assumptions remain separate acceptance questions. The exact examples demonstrate why those experiments have merit before costly bank validation; general causal identification and bank adoption remain open. \citep{exec23_numpyro_sources,exec23_numpyro_reference}
