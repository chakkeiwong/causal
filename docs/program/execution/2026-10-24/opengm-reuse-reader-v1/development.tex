\section{OpenGM: preserving the question across optimization and inference}
\label{sec:exec24-opengm-reuse}

A bank allocating a servicing budget may need the least costly joint action,
the probability that a particular account responds, or the effect of changing
the assignment policy. These are different questions even when their data
can be represented by the same factor graph. OpenGM is a useful historical
reference for separating model representation, algebra and algorithms. Its
generality makes the adapter's declaration of the requested operation more
important, not less. A most probable joint configuration is not a vector of
marginal probabilities, and neither is automatically a causal intervention
\cite{exec24_opengm_paper,exec24_opengm_source,exec24_opengm_choice}.

\subsection{A historical original with a conditional integration route}
The selected repository is \texttt{opengm/opengm}, pinned to its 26 July
2019 revision. Its README explicitly labels the project unmaintained, while
the inspected CMake file declares version 2.3.1. The README links manuals
for other versions; those labels must not be silently treated as the
selected artifact. This is a bounded historical-source comparison, not a
claim that every later fork or commercial support arrangement has been
surveyed. The five-page 2012 library paper is a genuine retained original.
Its design argument is inspected directly, while its historical performance
comparisons are not imported as current measurements
\cite{exec24_opengm_paper,exec24_opengm_source}.

The root license grants MIT-style permissions with notice retention. That
does not determine the complete rights of a binary containing optional
solvers. CMake exposes separate switches for, among others, CPLEX, Gurobi,
libDAI, graph-cut libraries, HDF5 and Python bindings. The inspected defaults
disable the command-line build and Python wrapper. A list of supported
interfaces therefore does not establish what an installed artifact contains.
The selected source's build requirements and declarations are evidence for
a proposed artifact inventory; no downloaded code or build script has been
executed \cite{exec24_opengm_source}.

The proposal retains OpenGM as a reference and leaves a narrowly specified
isolated worker as a conditional integration option. Direct adoption of the
whole solver catalogue is deferred because its algorithms have different
domains, rights and result contracts. Porting is deferred until a measured
need justifies maintaining model encodings, numeric behavior and solver
interfaces. The unmaintained declaration increases the importance of an
identified maintenance owner and a supported build, but is not by itself a
proof that every bounded use is unsuitable \cite{exec24_opengm_choice}.

\subsection{The algebra is part of the business query}
Let $V$ be finite variables, $F$ factors, $x$ a joint labeling, and
$\phi_f(x_{N(f)})$ a factor on its ordered neighborhood. OpenGM separates
the operation that combines factors from the operation that accumulates
over labelings. For a probability model, an unnormalized weight is
\[
 w(x)=\prod_{f\in F}\phi_f(x_{N(f)}),\qquad
 Z=\sum_x w(x),\qquad p(x)=w(x)/Z,
\]
provided the factors give finite nonnegative weights and $0<Z<\infty$.
For an energy model, $E(x)=\sum_f e_f(x_{N(f)})$ may instead be minimized.
The library paper formalizes these as different algebraic choices. It also
explicitly warns that not every algorithm supports every choice. Selected
source implements separate addition, multiplication, minimization and
maximization operations. A type name or successful generic serialization
cannot replace the algorithm-specific compatibility check
\cite{exec24_opengm_paper,exec24_opengm_source}.

An exact authored example makes the distinction operational. Suppose two
binary labels have joint probabilities
\[
 p(0,0)=0.35,\quad p(0,1)=0.25,\quad p(1,0)=0,\quad p(1,1)=0.40.
\]
The most probable joint labeling is $(1,1)$, but $P(X=0)=0.60$. Under
unit loss for an incorrect prediction of $X$, choosing its marginal mode
has expected loss $0.40$, whereas taking the $X$ component of the joint
mode has loss $0.60$. For 10,000 hypothetical cases at 100 USD per error,
that substitution adds 200,000 USD expected loss. The solver could have
correctly solved its stated joint optimization problem while the business
adapter answered the wrong question \cite{exec24_opengm_choice}.

Even correct probability inference does not identify an intervention.
Let an unobserved fair binary $U$ determine $Y=U$, and let the assigned
action equal $U$ with probability $4/5$. Then $P(Y=1\mid A=1)=4/5$, while
both intervention means are $1/2$ and the effect of changing $A$ is zero.
Conditioning a factor graph on $A=1$ preserves the selection association;
it does not remove the assignment mechanism. A causal worker needs an
identified model and a declared mechanism transformation before numerical
inference is meaningful \cite{exec24_opengm_choice}.

\subsection{A normal return does not certify exhaustive search}
The selected brute-force routine enumerates configurations with variable
zero changing fastest. It updates an incumbent through the chosen ordered
accumulator, invokes a visitor, and stops if the visitor requests it. Both
visitor stopping and exhaustion reach a final \texttt{NORMAL} return.
The separate visitor protocol distinguishes, for example, a time-limit stop
from a bound-based stop, but that distinction is not preserved in this
routine's return code. Its \texttt{arg} method supports the first stored
labeling and returns \texttt{UNKNOWN} for a requested higher rank. These
are concrete source contracts, not a report from an installed worker
\cite{exec24_opengm_source}.

For a two-variable authored energy table, let the enumeration order
$(0,0),(1,0),(0,1),(1,1)$ have energies $5,4,3,0$. Stopping after two
visits produces incumbent $4$; complete enumeration produces $0$.
The four-unit difference is known because this tiny example has an exact
oracle. In a larger case, \texttt{NORMAL} alone does not supply either an
exhaustion certificate or a finite optimality gap. The proposed response
must therefore include the visited/requested state counts where meaningful,
visitor stop reason, incumbent, independently valid bound and algorithm
configuration \cite{exec24_opengm_choice}.

The inherited base inference interface further returns an inverse-neutral
value for its default bound when the accumulator has an ordering, and a
not-a-number value when it does not. For floating-point minimization,
the selected inverse neutral is negative infinity. The brute-force class
does not override that bound in the inspected header. Exhaustion may justify
an exact result under valid arithmetic, but merely reading its default bound
does not yield a useful finite certificate. Unsupported marginals return
\texttt{UNKNOWN} in the base interface. A uniform response schema must
preserve those distinctions instead of manufacturing a probability or gap
\cite{exec24_opengm_source}.

\subsection{Hard constraints and shared factors require numerical contracts}
A second boundary appears in the concrete move-making delegate. For a
multiplicative model it recomputes the destination objective. For other
operators it updates the previous value by combining a new factor value
and removing the old one. With finite exact arithmetic this is a useful
incremental calculation. With infinite penalties it can have a different
numeric contract \cite{exec24_opengm_source}.

Consider an additive unary energy whose initial label has positive infinite
penalty and whose other label has zero penalty. The exact constrained
optimum is the feasible second label. Along the inspected incremental
update, the arithmetic expression is $+\infty+0-(+\infty)$, which is
not-a-number under the independently tested binary64 arithmetic. This is a
conditional source witness: no native OpenGM failure was observed, and
other algorithms or encodings may follow different paths. It motivates
fixtures for initially infeasible states, infinite penalties, NaNs and
finite substitutes. Replacing infinity by an arbitrary large constant is
not automatically valid; the constant must dominate a proved objective
range without creating unacceptable numeric error
\cite{exec24_opengm_source,exec24_opengm_choice}.

Function sharing saves representation space but does not remove repeated
factors. An authored unary factor with weights $(2,1)$ gives probability
$2/3$ to its first label after normalization. Adding the same factor twice
multiplies its contribution twice and yields $4/5$, a change of $2/15$.
That may be the intended model, or it may double-count one observation.
The adapter must distinguish shared storage identity from independent
evidence provenance \cite{exec24_opengm_paper,exec24_opengm_choice}.

Variable order is another semantic input. The inspected factor constructor
requires strictly increasing variable indices using runtime checks that
remain active when ordinary debug assertions are disabled. Other label
checks are assertions, and one direct-evaluation label check is commented
out in the selected source. This does not prove every invalid call lacks
validation; it requires entrypoint-specific tests. Sorting variable indices
must also permute factor axes. For a binary table with weights
$w(0,0)=1,w(0,1)=2,w(1,0)=3,w(1,1)=4$, the correct $P(X=1)$ is $7/10$.
Transposing its semantic axes changes the reported event probability to
$3/5$. Both tables normalize, so a sum-to-one check cannot detect the
meaning change \cite{exec24_opengm_source,exec24_opengm_choice}.

\subsection{A bounded public qualification route}
The proposed qualification suite starts with tiny fully enumerated models,
where energy optima, partition functions and marginal probabilities have
separate exact oracles. It varies semiring, solver, factor and variable
order, shared function identity, numeric type, constraint encoding and
early visitor stops. It tests valid inputs and typed refusals separately.
Even 40 binary variables have $2^{40}=1{,}099{,}511{,}627{,}776$ joint
assignments; finite representability is not a practical exhaustive-search
guarantee. Sparse or shared functions can reduce storage while leaving
the search combinatorics difficult \cite{exec24_opengm_choice}.

An isolated CLI or MCP worker should declare its exact artifact, enabled
solver dependencies, model algebra, supported factor class and requested
result. Its output distinguishes model rejection, unsupported algorithm,
timeout, incomplete incumbent, numeric failure and qualified result. A
timeout must preserve request identity and partial-result status; a retry
must not duplicate a business action. These are proposed adapter contracts,
not verified OpenGM integrations \cite{exec24_opengm_choice}.

Scientific ownership covers causal meaning and loss; numerical ownership
covers algebra, domain and valid bounds; adapter ownership covers ordering,
termination and request recovery; platform ownership covers maintenance,
rights and complete cost. A hypothetical 18,000 USD over 600 submitted,
450 completed and 300 qualified requests gives 30, 40 and 60 USD per request
under the respective denominators. Actual current support, compatibility,
prices and decision value remain unknown. Public tests can resolve bounded
implementation questions before expensive bank experiments. Hidden
assignment, unrestricted causal identification and arbitrary uncertainty
cannot be supplied by a general factor-graph solver. Native qualification,
independent review, visual and final acceptance remain open
\cite{exec24_opengm_choice}.
