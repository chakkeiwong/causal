\section{Reusing DAGMA without changing the scientific question}
\label{exec16:dagma-reuse}

A bank considering a new servicing action may first want to learn which
observed variables could mediate its response. Continuous structure learning
offers a computational route to candidate graphs, but its output must survive
several distinct interpretations: numerical optimization, graph topology,
structural assumptions and the intervention being contemplated. DAGMA is a
useful case because the original Python implementation exposes a compact
linear optimizer and a nonlinear alternative, while its acyclicity argument
has a precise domain. The proposed reuse decision is to retain this original
implementation as a reference and a candidate for a later isolated adapter.
The current evidence does not justify wholesale adoption or a port into the
core library. The selected source revision dates from January 2024; it is
distinct from translations of the method in other software.
\citep{exec16_dagma_primary}

\subsection{A domain theorem is not a numerical acceptance test}

Write $W_{ij}$ for the weight from parent $i$ to child $j$, and let
$S=W\circ W$ denote its entrywise square. The inherited characterization
uses
\begin{equation}
 h_s(W)=-\log\det(sI-S)+d\log s,
 \qquad s>\rho(S),
 \label{exec16:dagma-domain}
\end{equation}
where $d$ is the number of variables and $\rho$ is the spectral radius.
Within this nonsingular M-matrix domain, $h_s(W)$ is nonnegative and vanishes
exactly for a DAG. The primary paper separately assumes that the chosen
statistical model identifies the graph. Its central-path result concerns
the limiting optimization scheme, not every finite sequence of approximate
gradient steps. Neither statement supplies an effect confidence region for
a graph selected from a finite banking sample.
\citep[Section 2, Theorem 1 and Lemma 6]{exec13_pydisc_dagma2022}

An independent two-variable calculation provides a useful behavioral oracle.
For $W_{12}=a$, $W_{21}=b$ and zero diagonal,
\begin{equation}
 h_s(W)=-\log\{1-(ab/s)^2\},\qquad |ab|<s.
\end{equation}
Differentiating this scalar expression, or using
$\nabla h_s(W)=2W\circ(sI-S)^{-\mathsf T}$, gives an independent check of
the original module's derivative. At $a=0.2$, $b=0.3$ and $s=1.3$, its value
is approximately $0.00213244957$. The inspected original module agrees with
the scalar expression; central finite differences at step $10^{-6}$ agree
with its derivative to a maximum absolute discrepancy below $4\times10^{-11}$
in this example. This is a numerical identity check at a declared point,
not an estimate of graph recovery or a uniform numerical guarantee.
\citep{exec16_dagma_exact}

The domain cannot be omitted from that oracle. For
$W=\operatorname{diag}(\sqrt{2},\sqrt{2})$ and $s=1$, the determinant is
one, although the graph contains two self-loops and $\rho(S)=2$.
The original helper returns a value near zero outside its theorem domain.
For a two-cycle with $a=2$, $b=1$ and $s=1$, the determinant is $-3$;
the helper's log-absolute-determinant expression gives $-\log3$.
These are direct calls to the numerical helper. They do not show that the
optimizer admitted those matrices during fitting: the optimization loop
contains separate inverse-matrix domain checks. They show why a consumer
cannot certify a DAG by accepting an isolated small residual. A future
adapter must inspect domain validity and the returned graph's actual support,
including self-loops and directed cycles.
\citep{exec16_dagma_primary,exec16_dagma_exact}

\subsection{What the executed source module requires of an adapter}

The bounded execution used the unchanged saved linear module with Python
3.11.15, NumPy 2.1.3, SciPy 1.17.1 and tqdm 4.70.0. It did not install the
complete DAGMA distribution. Seven deterministic input cases exercised the
least-squares path with four inner iterations and one outer stage. These
small budgets deliberately expose interface boundaries; the resulting
observations are not a performance or accuracy study.
\citep{exec16_dagma_runtime}

The first boundary is ownership of observations. In the least-squares path,
the module centers the caller's array in place. Integer input raises a
NumPy casting exception. A service that retains the original observations
for another estimator therefore needs its own floating-point copy, a record
of the removed means and a stable mapping between columns and variable
identities. Copying data is also a real memory and transfer cost. It should
appear in a matched workflow comparison rather than disappear outside the
timed optimizer.
\citep{exec16_dagma_primary,exec16_dagma_runtime}

The second boundary concerns scientific constraints. The signature describes
edge collections as optional lists, while the inspected implementation
recognizes tuples of tuples. For the same four-row input, excluding edge
$(0,1)$ as \texttt{((0,1),)} produced a zero in that matrix entry. Supplying
\texttt{[(0,1)]} instead left an entry approximately $0.039991$.
The invalid branch constructs a \texttt{ValueError} without raising it.
An empty tuple raises an indexing exception. A requested included edge also
remained absent on a zero-signal input, consistent with the upstream warning
that inclusion is not guaranteed. These findings call for an explicit
distinction between hard exclusions, soft inclusion preferences and hard
required edges. A scientific constraint cannot silently become a preference
because a serialization library changed a tuple to a list.
\citep{exec16_dagma_primary,exec16_dagma_runtime}

The third boundary is the identity of the diagnosed result. With no weight
threshold, the deliberately short run returned a cyclic matrix, including
self-loops. With a threshold of $0.3$, the same optimization returned the
empty graph. The saved prethreshold residual remained approximately
$0.003200116$, although the returned graph's residual was zero. The stored
least-squares score was approximately $2.693174$, while evaluation on the
returned graph gave $3.125$. Neither value is intrinsically misleading if
its matrix is named. A wrapper becomes misleading when it attaches one
matrix's diagnostics to another matrix without saying so.
\citep{exec16_dagma_runtime}

A proposed adapter should retain the raw and thresholded matrices, the
original and effective optimization settings, the observation transform and
diagnostics recomputed on each reported object. Its runtime bound must cover
the upstream retry loop as well as the nominal iteration counts. Malformed
inputs, singular solves, nonfinite values, exhausted budgets and cyclic
outputs need distinct error or incomplete dispositions. Silently deleting
an edge to obtain a DAG changes the reported procedure; any such repair
would require its own explicit rule and qualification. These are concrete
requirements for a future wrapper, not capabilities established by the
reference module's execution.
\citep{exec16_dagma_primary,exec16_dagma_runtime}

\subsection{Units and nonlinear weights can reverse a banking interpretation}

For a stipulated linear structural model written with row observations,
$X=XW+E$, a change of measurement units $Z=XD^{-1}$ gives
$W_Z=DW D^{-1}$, where $D$ is a positive diagonal scale matrix. In a DAG,
the total directed-path coefficient matrix is
\begin{equation}
 K=(I-W)^{-1}-I=W+W^2+\cdots+W^{d-1},\qquad
 K_Z=DKD^{-1}.
\end{equation}
This algebra describes a change of units in an already stipulated structural
model. It does not prove that a fitted graph has a causal interpretation or
that a penalized optimizer is invariant to rescaling its data.
\citep{exec16_dagma_exact}

For example, suppose an authored three-variable model has
$W_{12}=2$, $W_{23}=3$ and $W_{13}=1$. Its total first-to-third coefficient
is $1+2\times3=7$. With $D=\operatorname{diag}(10,1,100)$, the transformed
edge weights are $20$, $0.03$ and $0.1$, and the transformed total coefficient
is $0.7$. Both describe the same stipulated mechanism in different units.
A raw threshold of $0.5$ retains all three original edges but only one
transformed edge. Thus a threshold needs an explicitly declared scale;
``the same threshold'' is not a scientifically matched comparison across
arbitrarily standardized borrower measures. Fitting, thresholding, refitting
and any subsequent uncertainty calculation must be treated as a whole
procedure.
\citep{exec16_dagma_exact}

The nonlinear alternative has a different problem. The inspected
\texttt{fc1\_to\_adj} routine takes a norm of first-layer weights and returns
nonnegative entries. It does not return signed intervention derivatives.
Consider two authored one-parent response functions,
\begin{equation}
 f_+(x)=4\sigma(2x)-2,\qquad
 f_-(x)=-4\sigma(2x)+2,\qquad
 \sigma(u)=\frac{1}{1+e^{-u}}.
\end{equation}
Their first-layer norm is the same, namely two, and both have baseline zero.
Since $\sigma'(0)=1/4$, their derivatives at zero are $+2$ and $-2$.
In a stipulated servicing illustration with USD~100 per outcome unit and
USD~20 marginal cost per unit of action intensity, the local net-value
derivatives are USD~180 and USD~$-220$. The same nonnegative adjacency
weight is consistent with opposite local recommendations. These are exact
derivatives of declared functions; they are neither finite-action effects
nor results of executing the nonlinear PyTorch implementation.
\citep{exec16_dagma_primary,exec16_dagma_exact}

An intervention calculation therefore needs the fitted structural functions,
the intervention definition, units and assumptions that justify using those
functions causally. A graph-only export loses that information. For
equivalence-class, latent-variable or temporal questions, the reviewed
constraint-based and temporal routes remain substantive alternatives. A
convenient DAG representation cannot substitute for their different
information and uncertainty contracts.

\subsection{The reuse choice and the evidence that would change it}

The inspected repository carries Apache~2.0 terms. Redistribution requires
the license, relevant retained notices and marked modifications, together
with applicable NOTICE obligations. That root license does not settle the
terms of every dependency or of a different implementation. The package
metadata declares NumPy, SciPy, torch, tqdm and igraph without version bounds,
although the narrow linear source path imports only the first, second and
fourth. Its version configuration refers to \texttt{src/VERSION}, absent
from the inspected pinned tree. This is a concrete build-identity issue to
resolve against a selected release, not grounds to invent a release number
or declare that every published package is broken. Saved examples and the
inline demonstration function also do not establish a supported build or
passing continuous integration.
\citep{exec16_dagma_primary}

Reference use is consequently justified now. Conditional integration of a
selected linear path is a plausible next prototype: establish a complete
permissible build, implement the stated conversion and failure contract,
and replay the boundary cases with independent graph and numerical oracles.
Direct adoption leaves those obligations with the caller. Porting adds
floating-point, solver, threshold and maintenance differences before any
measured need for a port has been demonstrated, so it is not selected here.
NOTEARS supplies a meaningful numerical comparator under matched model and
output assumptions, while PC, FCI or temporal alternatives answer different
questions where sufficiency, hidden causes or time order matter.

The initial evaluation should use generated mechanisms with known truth and
public inputs with declared limits. It should predeclare identifiable and
observationally equivalent cases, unit transformations, graph-error and
downstream decision criteria, and retain failed or incomplete requests in
the denominator. The prototype maintainer owns build reproducibility and
failure semantics; the scientific reviewer owns assumptions and any later
effect-identification argument. Full costs include copying, serialization,
optimization, diagnostic review and dependency maintenance. Their actual
prices and a banking return remain unknown. A validated wrapper and useful
matched public or generated results would justify reconsidering integration
and the expense of independent and bank-specific trials.
\citep{exec16_dagma_primary,exec16_dagma_runtime,exec16_dagma_exact}
\label{exec16:dagma-reuse-end}
