## Java planning and learning require distinct investment cases

Three source profiles distinguish supplied-model planning, compact tabular updates and historical deep reinforcement learning. BURLAP supports a conditional finite-model or linear-feature worker proposal; Chen's routines are useful arithmetic references with adoption deferred pending terminal and discount qualification; the inspected RL4J artifact is explicitly historical and requires a maintained distribution and backend decision before adoption. The original LSPI article supports sample reuse within its stated MDP, projection and approximation conditions, not a confidence guarantee for arbitrary bank logs. \citep{exec24_policyjava_burlap,exec24_policyjava_chen,exec24_policyjava_rl4j,exec24_policyjava_lspi}

Exact authored examples distinguish a zero nominal Bellman residual from a 10 USD model error, Q-learning from Sarsa and terminal updates, unclamped targets from training labels, and information-seeking from fully observed continuation. In the small hidden-state example, ignoring the value of information loses 3.50 USD. These examples were reproduced without running upstream code. A bounded search is not a complete Java inventory. \citep{exec24_policyjava_comparison}

The next investment gate is a public or generated prototype with an exact oracle, pinned worker, valid state/history and clock conversion, declared logging/support, full failure and refusal counts, and measured complete costs. Native runtime, transitive rights, arbitrary hidden-state identification, calibrated selected-policy uncertainty and actual bank economics remain separate obligations. The proposal neither substitutes planning output for causal evidence nor treats source review as implementation acceptance. \citep{exec24_policyjava_comparison}
