# Bounded C++ IV/RD candidate inspection

The cutoff-bounded GitHub repository search found two candidates in four queries: one dynamic-system instrumental-variable project, one regression-discontinuity running-variable measurement-error package, and no results in the generic two-stage-least-squares and instrumental-forest queries. Queries admitted repositories created before 8 October 2026 and returned at most 30 results each. This is a documented discovery slice, not an exhaustive search or evidence that other C++ methods do not exist. Both selected revisions predate the 7 October client cutoff. Repository metadata establishes identity and date only; the conclusions below come from the pinned README, manual, source and headers.

`kota7/rddsigma` is an R package with Rcpp/C++11 components, not a standalone C++ causal estimator. Its pinned 6 June 2025 commit declares package version 0.2.0 and `MIT + file LICENSE`. The README and manual define a narrow sharp-RD measurement-error problem: observed running variable and binary assignment are supplied, and the output estimates the error standard deviation, with latent running-variable and error distributions restricted to the documented parametric families. No outcome is an input to `estimate_sigma`; it therefore does not estimate a discontinuity in an outcome or a local causal treatment effect. At most, the Rcpp code is an auxiliary component for a future measurement-error workflow whose identifying assumptions and effect estimator remain separately supplied.

The inspected implementation offers a two-step Gaussian method and an EM parametric method with Gaussian latent running variable and Gaussian or Laplace measurement error. The R boundary drops rows with missing assignment or running variable, requires more than one remaining row and binary assignment, and uses a random `runif(1) * sd(w)` initial value when `init_sigma` is absent. The EM code returns estimates, standard errors and convergence status; a finite estimate without a successful status cannot by itself certify a completed optimization. The C++ Gaussian path also changes integration tolerance and performs recovery steps if an EM increment is negative. These are estimation details for the error scale, not checks of RD continuity, no manipulation, treatment compliance or a causal effect.

One inspectable numerical concern merits a future native/reference test. In `tsgauss`, the code forms `sd_w = sd(w) * (n-1) / n` and comments that the maximum-likelihood estimate divides by n. If `Q` is the centered sum of squares, R's sample standard deviation is `sqrt(Q/(n-1))`; the maximum-likelihood standard deviation is `sqrt(Q/n)`. The implemented multiplier produces `sqrt(Q*(n-1))/n`, not `sqrt(Q/n)`. This is an algebraic comparison of the inspected formula, not a claim about measured downstream bias or a particular package output. The result is subsequently used in variance and likelihood expressions, so a future test should determine its effect before considering reuse. The package source and selected examples have not been compiled or run in this review.

The second candidate, `PatrykKot/Leasts-squares-algorithm-and-instrumental-variables-algorithm-to-dynamic-system-identification`, is an academic embedded-system project. Its README says it identifies discrete transfer-function models using recursive least squares and recursive instrumental variables. The source keeps input/output lag buffers, recursively updates parameter and covariance matrices with a forgetting factor and supplies a rank-search wrapper using an AIC-like residual criterion. The RIV source builds the instrument vector from lagged input samples. This is system identification for an input/output process; it does not specify the economic or banking treatment, an excluded exogenous assignment instrument, an exclusion restriction, monotonicity, a complier population, weak-IV robust inference or a causal estimand. A coincident acronym is not an IV causal method.

Static review exposes reasons not to port this embedded project into a bank causal library. Both recursive update paths replace a zero update denominator by `0.0001`, hiding a singular/unsupported update instead of returning a typed weak-information result. The rank wrapper writes to a fixed sample array and tests `currentIndex > maxSamplesNumber` only after storing and incrementing; at the first call after the configured capacity, it can write one element past the allocated array before setting `finished`. The repository metadata has no license classification, and the inspected tree contains no license file. No build, execution, memory-safety test or permission to redistribute is claimed.

The bounded disposition is to exclude the academic dynamic-system project as a causal IV estimator and retain it only as an adjacent embedded-systems lead. Do not integrate or port it into the causal proposal. Retain `rddsigma` only as a documented R/Rcpp measurement-error reference; defer any adapter until its likelihood calculation is reconciled with an independent reference, missing-data and random-start behavior are made explicit, convergence failures are tested, exact licensing is reviewed and a separate RD effect estimator is paired with it. Compare causal RD and econometric IV candidates on their own estimands, assumptions and uncertainty contracts. In particular, a C++ implementation should not be accepted merely because its name says “instrumental variables.”

The searches did not target package registries, papers, vendor catalogs or every repository spelling; they omit source-code search and non-English candidates. Commercial market coverage and causal IV/RD sources in R, Python, Java, and other languages are separate obligations. No universal absence, executable compatibility, effect validity, calibration, price, deployment or bank-value conclusion follows from this cell review.
