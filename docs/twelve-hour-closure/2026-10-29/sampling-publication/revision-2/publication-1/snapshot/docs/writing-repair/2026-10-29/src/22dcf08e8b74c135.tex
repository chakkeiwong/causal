The chapter compares three ways to obtain the missing trajectory: constrained
donor matching, augmentation beyond the donor hull, and model-based
reconstruction. It first distinguishes the commercial host from the estimator
it runs and examines how panel wrappers define the target. Detailed R method
studies then precede the wider R, Python and cross-language comparisons.
The question throughout is whether the same donor information, intervention
clock and uncertainty reach the bank's decision after fitting and conversion.

\section{A commercial host does not settle synthetic-control semantics or rights}
\label{exec19:synth-scope}

A bank comparing a treated regional portfolio with other regions needs a
credible untreated path, not merely an optimizer that returns donor weights.
A commercial statistical host may run a community estimator, a vendor-native
command or a general optimization routine. These are different implementation,
support and rights arrangements. The proposed common service should compare
those arrangements explicitly while preserving donor eligibility, timing,
missingness, pre-fit and the uncertainty protocol.

The selected Synth-for-Stata repository is an author-maintained community
implementation inside the commercial Stata host. Its inspected command identifies
version 0.0.8 and declares Stata version 13.0. The selected commit,
\texttt{ae99fd1ed100e8f5ea38386f18f02e61a90956e6}, is dated 30 April 2026.
Twelve authenticated texts cover its command, help, loss helper, package
manifest, optimizer interface, component notices and selected test artifacts.
No Stata executable, plugin binary or compiled Mata library was run here.
A host compatibility declaration is not a verified installed edition,
entitlement or vendor-supported causal capability.~\citep{exec19_synth_stata_source}

\subsection{Freeze the donor universe and information used to select weights}
\label{exec19:synth-donors}

The selected help describes a convex weighted donor combination. Donors default
to all panel units other than the treated unit; an explicit donor list must
contain at least two units. That syntactic rule cannot establish that another
region is unaffected by the intervention, has comparable measurement or supplies
a credible untreated trajectory. Predictor averages ignore missing entries,
while a wholly missing predictor is rejected. Consequently, two units can
contribute averages over different observed dates. Predictor-specific windows
can also override the common predictor period.~\citep{exec19_synth_stata_source}

Consider an authored regional-portfolio example, with outcomes measured in
thousands of USD. Two donors and the treated region have trajectories
\begin{equation}
 D_1=(90,110,120),\quad D_2=(110,130,140),\quad T=(100,120,150).
 \label{exec19:synth-paths}
\end{equation}
The first two dates precede intervention. Equal donor weights reproduce both
preperiod treated values exactly and predict 130 at the third date. Stipulate
that this donor average is the treated region's true untreated path. The
corresponding treatment effect is then 20, or USD 20,000. This truth is an
assumption of the example, not something established by pre-fit alone.
\citep{exec19_synth_contract_reference}

Now suppose the second donor also receives a spillover of 20 at the final date.
Its observed final value becomes 160. The same weights predict 140 and the
apparent treated gap falls to 10. Alternatively, selecting weights using the
treated postintervention outcome can choose $1/4$ for the first donor and $3/4$
for the contaminated second donor. The selected synthetic path is then
\begin{equation}
 \widetilde T=(105,125,150),\qquad T_3-\widetilde T_3=0.
 \label{exec19:synth-leakage}
\end{equation}
The intervention has not disappeared from the stipulated world; contamination
and postoutcome selection have changed the comparison. A lower postperiod gap
cannot certify a better causal counterfactual.~\citep{exec19_synth_contract_reference}

The source makes this timing check operationally relevant. Default predictor
and MSPE periods precede treatment. For an explicitly supplied MSPE period,
however, the inspected command checks that the requested dates occur in the
panel, without imposing a separate before-treatment inequality in that branch.
The help allows later predictor dates only under a substantive unaffectedness
condition. The proposed adapter must therefore declare and check the scientific
window; passing a command's membership validation is a narrower result.
\citep{exec19_synth_stata_source}

\subsection{Keep optimizer settings and failure states attached to the result}
\label{exec19:synth-numerics}

The selected help and code disagree on two defaults. The help gives constraint
margin 0.05 and precision parameter 7, whereas the command syntax uses 0.005 and
12. A reproducible comparison must record explicit supplied values and the
actual source or binary rather than rely on an unqualified default. The source
also computes RMSPE before calling a compiled Mata rounding routine on the
weight vector. The routine's body has not been inspected, so its precise
rounding rule and the resulting relation between displayed weights and the
reported pre-fit score remain open.~\citep{exec19_synth_stata_source}

More directly, the inspected C wrapper assigns the return status from
\texttt{pr\_loqo}, stores the primal vector and returns zero without branching
on that optimizer status. The associated header distinguishes optimal,
suboptimal, iteration-limit and infeasible outcomes. A successful wrapper return
therefore cannot, on this source evidence alone, be interpreted as an optimal
feasible synthetic control. Future native conformance should inspect the actual
binary, status propagation, constraint residuals and support of the returned
weights before reporting scientific results. These are static observations,
not measured failure frequencies or proof that every invocation fails.
\citep{exec19_synth_stata_source}

Source criticism also requires avoiding false defects. The nested loss helper
returns negative squared error to a maximizer. Selecting the larger log
objective among alternative starts is consistent with minimizing the underlying
squared error. A nearby comment about the \emph{lowest loss} does not justify
reversing the comparison signs. The relevant object is the implemented objective
and its sign, not the variable name alone.~\citep{exec19_synth_stata_source}

\subsection{A placebo count needs its own sampling and selection argument}
\label{exec19:synth-inference}

The selected help says the estimator can support placebo and permutation
analyses, but that does not supply a universally calibrated test for a bank's
regional intervention. The protocol must identify which units could have been
treated under the null, how pre-fit filters and donor eligibility were chosen,
whether the treated region enters the reference set, the tail direction and
which tuning steps are repeated for every placebo. Donor and time dependence
also remain substantive assumptions.

A purely arithmetic illustration makes the denominator visible. One equally or
more extreme statistic among five eligible statistics, including the treated
unit, yields $1/5$. Retaining only two statistics yields $1/2$. Neither fraction
is automatically a valid $p$-value: the assignment or exchangeability argument
and the rule selecting retained cases still need justification. The finite count
is an authored reference, not a theorem attributed to an uninspected original
or an inference result from the vendor engine.~\citep{exec19_synth_contract_reference}

The proposed common output should keep donor weights, balance, outcome paths,
pre-fit diagnostics, optimizer status and any separately justified inference
object distinct. A trajectory difference must not become a confidence interval
or policy value merely because downstream software expects a scalar.

\subsection{Preserve unresolved component notices and comparison breadth}
\label{exec19:synth-rights}

The pinned README states GPL version 2 or later, while the bundled optimizer
source and header retain proprietary notices, including a restriction on
unauthorized commercial use. This discrepancy is an unresolved rights record.
It is not a finding of lawful distribution, an accusation of infringement or
permission to embed the component. Authoritative clarification for the exact
distribution is required before an adoption decision. The commercial host,
community code, compiled plugin, Mata library and any hosted service must each
retain their own scope.~\citep{exec19_synth_stata_source}

The broader comparison remains inconclusive. Stata, EViews, SAS, IBM,
MathWorks and commercial hosted open-source frontends remain separate candidate
families; only the selected community implementation has matching technical
originals in this tranche. Generic regression, optimization, synthetic-data or
control-arm descriptions cannot establish a donor-weighted comparative panel
estimator. Uninspected sources and failed acquisition routes likewise cannot
establish product absence. Prices, entitlements, full native alternatives and
applicable automation or redistribution rights remain unresolved.

For the prototype proposal, retain the community estimator as a documentary
comparator and defer executable admission until the rights conflict, binary
correspondence and numerical contract are resolved. Compare transparent exact
examples and separately reviewed open-source estimators under the same donor,
clock and inference specification. Public evidence can establish that design
before a paid vendor trial; it cannot substitute for institutional assignment
truth or realized banking value.
