## Python policy components must share a scientific target

The reviewed Python portfolio spans four different roles: OBP for selected contextual-bandit estimators, SCOPE-RL for selected sequential scores and evaluation, d3rlpy for policy learning and fitted-Q evaluation, and POMDP-Py for planning within supplied hidden-state models. A common programming language does not make their values comparable. The proposed product must bind the population, action/history schema, logger and support, policy identity, clock, episode ending, monetary transformation and uncertainty target before choosing a worker. \citep{exec23_obp_sources,exec23_scope_rl_sources,exec15_d3rlpy_package,exec23_pomdppy_sources}

Prior exact examples show why this is material: a randomized policy can be worth USD 8 while its greedy version is worth USD 10; a done convention can retain USD 2 instead of USD 10; and a cumulative reward transformation can require USD 28 rather than a naive USD 23.50 inversion. These are authored semantic witnesses, not measured bank or package performance. Score bootstrapping, policy selection and hidden-model uncertainty require separate arguments. \citep{exec15_d3rlpy_exact,exec23_scope_rl_reference,exec15_d3rlpy_value}

The recommended path is conditional original workers with package-specific conversion tests, independent finite oracles and frozen public/generated evaluations, including complete failures, correct refusals and full costs. The inherited ten-result bibliographic search is not a software census; other families, delegates, method originals, exact environments and rights remain open. This synthesis supplies a coherent qualification route while retaining inconclusive Python coverage and withholding native integration or bank-value claims. \citep{exec15_d3rlpy_contract,exec23_obp_sources,exec23_scope_rl_sources,exec23_pomdppy_sources,exec24_policiespython_comparison}
