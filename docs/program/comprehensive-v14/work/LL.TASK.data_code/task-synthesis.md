# Data and code agents for causal banking analysis

This operation develops the data and code handoff as a proposal and research decision. The integrated reader section is `docs/program/execution/2026-10-13/data-code/chapter.tex`; its review and source audit are under `docs/program/execution/2026-10-13/data-code/`. It is a scholarly and architectural result, not an installed agent, a live-model trial, or a bank-data validation.

The banking question is whether an early arrears-review offer improves discounted net recovery over 180 days for accounts eligible at their first qualifying arrears date. The offer, subsequent acceptance and final restructuring terms are different actions. The account, not its customer, branch or contact row, is the declared unit. A positive effect can justify the offer only after offer cost, alternative actions and the actual eligible population are stated. A field whose event time precedes the offer but whose availability time follows it cannot be a feature of the operational policy at the offer instant. A date-10 offer therefore rejects a field delivered on date 11, even when the event occurred earlier. This clock check is independent of whether the field predicts recovery retrospectively.

The fixed non-agent baseline is an analyst interview, versioned data dictionary, reviewed code and deterministic numerical fixtures. An agent can propose field mappings, retrieval passages, graph alternatives, code patches and diagnostic explanations. The project controller accepts only a typed declaration, exact source/input hashes and a caller-granted fixed operation. A patch or notebook is a development artifact for review, never an executable instruction carried by a retrieved document or agent message. An unsupported target or missing backend remains a failure/refusal; an empty JSON object is not a successful estimate.

The exact target oracle uses two equally common strata, propensities 0.2 and 0.5, and conditional effects 0 and 10. The population mean and uniformly averaged retained-population mean are 5. Conventional overlap weighting uses e(x)[1-e(x)] and yields 250/41, about 6.09756. The arithmetic independently detects a report that calls a trimmed uniform AIPW result ATO. The observation law, potential outcomes and prices are stipulated; these numbers do not measure a bank or a fitted model.

The primary literature gives distinct favorable and adverse evidence. Zhu et al.'s CausalAgent uses processing, structure-learning and reporting agents with MCP tooling and a Sachs demonstration, while quantitative effect and counterfactual modules are future work. Chou et al.'s oci-agent gives a human principal inspectable specifications, notebooks and diagnostics with reported public ACIC/LaLonde evaluations, but target changes after trimming still require explicit review. Leban et al.'s CausalDS benchmark separates causal scenes, observations, private ground truth, identification and scored abstention; its scorer and metadata branches need guarded adaptation. Babaei Giglou et al.'s OntoLearner provides ontology-loading and relation-learning components but source-code pinning alone does not pin downloaded ontology bytes. Zheng et al. position agents around data inspection, assumption elicitation, formal discovery and interpretation, while CPDAG/PAG ambiguity must remain visible. All five original PDFs are authentic, locally hash-bound, and inspected at the anchors in `source-audit-v2.json`.

The pinned source paths sharpen the decisions. The selected CausalAgent MCP server calls an OLC function not imported or defined in its inspected module; its parser returns `{}` on malformed JSON. The oci-agent notebook runner uses `NotebookClient` with `timeout=-1`, and the selected ATO notebook branch uniformly averages retained AIPW pseudo-outcomes. OntoLearner's `hf_hub_download` calls omit a revision argument. CausalDS distinguishes nullable identification results from false and grants abstention credit only for explicitly abstainable tasks, while missing metadata and invalid interval branches need guards. These are source-level observations at selected commits; none of these packages was installed or run here. Prior search metadata found many broad data/LLM works but was not an exhaustive census; code-paper alignment, transitive dependencies and source-specific licenses remain scoped in the existing package register.

The first prototype should adapt OCI's specification, review and report artifacts behind fixed operations; reject unbounded notebook execution; use locally versioned ontology bytes if OntoLearner concepts are adopted; retain malformed, unknown, unsupported and nonidentifiable as different states; and assess CausalDS as a benchmark after scorer and original-data checks. The existing local controller passed 80 conformance checks with six synthetic path exports and zero live model calls. It has a 16-operation cap, ten-second workers and a one-GiB worker address-space ceiling; local replay rechecks byte identities. These checks do not establish live model accuracy, authenticated adversarial security, distributed exactly-once effects, bank causal truth or production acceptance.

The next bounded study can freeze a public/generated task set with briefs, response rubrics, controls, timings, adverse cases, fixed prompts/splits, a deterministic baseline and a stopping rule. It should score target preservation, invalid clock use, unsupported certainty, graph ambiguity and complete failure accounting. A live provider evaluation additionally needs named model/version, custody, prices and independent reference judgments. Authentic bank experiments remain conditional on a prototype and a decision-relevant value of information.
