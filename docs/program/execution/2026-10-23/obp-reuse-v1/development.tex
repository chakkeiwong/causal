\section{Contextual bandit reuse requires a different contract from sequential servicing}
\label{exec23:obp-scope}
A one-time offer allocation and a sequence of collection decisions are different
causal products. Open Bandit Pipeline (OBP) is a useful comparator for the former:
the inspected core organizes logged contextual-bandit observations, target
action distributions, propensity-weighted estimators, response regressions and
evaluation wrappers. It does not convert repeated customer histories into a
qualified longitudinal policy analysis merely because each history can be
flattened into rows. The selected revision is dated 5 November 2022, declares
version 0.5.5 and is the revision returned by the cutoff query. Eleven authentic
source/declaration files support this profile; slate, continuous-action,
multiple-logger and action-embedding estimators need separate review.
\cite{exec23_obp_sources}

\subsection{Logging probabilities, clipping and replay change what the number means}
\label{exec23:obp-target}
For one decision, let $X$ denote information available before choosing action
$A$, let $R$ be the subsequent reward, and write $b(a\mid x)$ and
$\pi(a\mid x)$ for the logging and target action probabilities. Under a common
context population, a stable conditional reward law, truthful logging and
support wherever the target acts, the target is
\[
 V(\pi)=\mathbb E_X\sum_a\pi(a\mid X)q(X,a),
 \quad q(x,a)=\mathbb E[R\mid X=x,A=a],
 \quad \mathbb E_b\!\left[\frac{\pi(A\mid X)}{b(A\mid X)}R\right]=V(\pi).
\]
The last equality follows by cancelling $b$ in the conditional sum over $a$.
Its causal interpretation requires that the reward mechanism remains valid
under the proposed assignment; observed association alone is insufficient.
If action effects persist, affect future eligibility or alter later information,
this single-decision target must not replace a sequential target.

The inspected IPW estimator selects supplied or estimated propensity scores
according to an explicit flag, forms the observed-action ratio and applies an
optional clipping threshold. The doubly robust estimator combines a
target-weighted regression prediction with a clipped weighted residual. Its
calculation can be represented as
\[
 \widehat V_{\rm DR}=\frac1n\sum_i\left\{
 \sum_a\pi(a\mid X_i)\widehat q(X_i,a)
 +\min(W_i,c)\big(R_i-\widehat q(X_i,A_i)\big)\right\},
 \qquad W_i=\frac{\pi(A_i\mid X_i)}{\widehat b(A_i\mid X_i)}.
\]
The default unbounded threshold and a finite clipped threshold are distinct
estimating rules. With an exact conditional-mean regression the residual has
zero conditional mean, but arbitrary estimated regressions, fitted propensities
or clipping need their own bias and uncertainty analysis.
\cite{exec23_obp_sources}

Consider two equally common customer types. For type zero, the logging
probability of offer one is $1/4$ and rewards under offers zero and one are
$(0,2)$. For type one, the logging probability is $3/4$ and rewards are $(1,5)$.
The target always gives offer one. Its value is $7/2$, and exact weighting
recovers that value. Clipping the importance ratio at two gives $3$; substituting
a uniform logging probability gives $17/4$. At ten dollars per reward unit and
a stipulated offer cost of 32 dollars, the respective margins are $3$, $-2$ and
$10.50$. An exact response regression restores the DR population value in this
constructed law even with the specified clipped residual. This illustrates
conditional mechanisms; it is not a finite-sample guarantee or an observed
package benchmark.\cite{exec23_obp_reference}

The replay estimator has another contract. It keeps observations whose
observed-action target probability equals exactly one and normalizes by the
sample match rate. Under unequal contextual logging, the matched contexts have
different frequencies from the target population. In the preceding example,
the limiting matched reward is $17/4$, not $7/2$. Appropriate uniform
randomization or another justified replay design is therefore substantive.
For a fully stochastic target with both action probabilities $1/2$, no exact-one
match exists; the selected source leaves an all-zero score vector when there
are no matches. A product must expose unavailable replay evidence rather than
reporting a zero policy value as a scientific result.
\cite{exec23_obp_sources,exec23_obp_reference}

\subsection{A validated array is not a validated causal request}
\label{exec23:obp-uncertainty}
The core expects target probabilities with dimensions round, action and
position. The inspected validator checks the action-axis sum and position/action
indices, and rejects nonpositive supplied propensity values. Its array helper
checks array type and dimension, not general finiteness. The target-distribution
check does not separately impose nonnegative entries: the row
$(-1/10,11/10)$ sums to one but is not a probability law. A nonfinite propensity
also needs an explicit finite-value check; a comparison with zero is not a
complete validator. These are scoped source findings. The proposed adapter
must independently verify common row identities, action/position vocabulary,
finite values, valid probabilities and their scientific provenance.
\cite{exec23_obp_sources,exec23_obp_reference}

The regression wrapper defaults to one fold, fitting and predicting on the
same contexts. Its multi-fold branch uses shuffled row K-fold splits. Such
splits do not preserve customer groups or forward calendar separation by
construction. Missing propensities are replaced with a uniform distribution
inside this regression-preparation path. That fallback does not authenticate a
bank logging policy, especially for importance-weighted or MRDR fitting. The
adapter must bind whether the quantities are true logs, estimates or explicit
design inputs, and justify both the fitting loss and the evaluation law. An
out-of-fold prediction flag alone is not an uncertainty theorem.
\cite{exec23_obp_sources}

Basic estimator intervals first calculate round-level scores and then bootstrap
those fixed scores. The common helper takes percentile endpoints and reports
the mean of bootstrap means. It does not repeat response fitting, propensity
estimation or hyperparameter selection in the selected call. Self-normalized
IPW inherits this interval path, so fixed-score resampling and re-estimating the
normalization are different procedures, as the preceding sequential-library
example already shows. The proposal must state the conditioning argument and
retain the actual number of replications and seed, rather than describing all
such output as full-pipeline uncertainty.
\cite{exec23_obp_sources}

Tuning is another layer. The source offers an estimated-MSE route and a
stability-comparison route, chooses a threshold from candidate scores, and
stores the selected threshold on the estimator object. Later calls reuse it
when the attribute already exists. This may be deliberate state reuse, but an
adapter must distinguish a frozen tuning choice from a new-data tuning request.
The interval call fixes the chosen threshold; it does not repeat the selection
for every bootstrap sample. The scope of the MSE/bias helper also needs its own
source-theorem review before a guarantee is attributed to it.
\cite{exec23_obp_sources}

One apparent defect illustrates why complete argument tracing matters. The
tuned interval constructs a base estimator without forwarding the estimated-
propensity flag. However, it has already selected the intended propensity
array into a local variable and passes that array as the base estimator's
ordinary propensity argument. The selected base interval reads that argument
under its default flag. Thus the inspected chain does not establish a
known-versus-estimated propensity substitution error. The audit retains this
rejected concern, while keeping actual fitting and selection uncertainty open.
Similarly, OBP's Student helper returns a \emph{one-sided} lower bound, so its
$1-\delta$ quantile should not inherit the symmetric-endpoint criticism from
the preceding library. Contract differences must be reviewed individually.
\cite{exec23_obp_sources,exec23_obp_reference}

\subsection{Public benchmark evidence and a deployable worker are separate assets}
\label{exec23:obp-decision}
The inspected dataset class reads campaign data, sorts by timestamp, maps the
position coding, extracts click rewards and supplied propensity columns, and
prepares features before its optional chronological train/test slicing. The
on-policy comparison is the empirical reward mean of the selected logged
policy's full or test sample. It is useful observed benchmark evidence, with
sampling uncertainty and a particular campaign population, not an exact
counterfactual oracle or a bank outcome. Feature vocabularies derived before
the split must be disclosed; timestamp sorting does not by itself establish
training-only preprocessing or independent observations. No dataset was loaded
or executed in this review, and its complete data rights remain unqualified.
\cite{exec23_obp_sources}

The source-level reuse decision is \emph{reference}. An isolated Python worker
could preserve the selected estimator and preparation semantics after a frozen
environment and native qualification, but full adoption would admit unreviewed
families and dependencies. A port to R, Java or C++ currently lacks a measured
benefit that justifies duplicating action-position conversion, nuisance fitting,
tuning state and bootstrap semantics. A minimal independent reference is a
useful oracle, not a full replacement. The selected artifact contains Apache
2.0 text; full dependency/data rights remain a separate obligation. The
Poetry file specifies Python below 3.10 and pins some scientific libraries,
whereas setup metadata uses broader minimum versions. Those declarations need
a concrete resolution, not an assumption of compatibility with the most recent
environment. Named authors and the selected revision do not establish a current
maintenance promise.\cite{exec23_obp_sources}

The proposed request contract carries context and action clocks, immutable row
and customer IDs, the outcome window and monetary units, action/position
mapping, target and logging provenance, fitted-model identities, split design,
clipping rule and tuning state, bootstrap unit and seed. Library, CLI and MCP
must return the same target, denominator, unavailable-result reasons and
qualification limits. A conversational agent may translate a business request
into these fields, but must not invent missing logging truth or treat a
schema-valid probability array as sufficient evidence.

Public qualification should begin with the exact contextual law above, then
vary logging imbalance, stochastic targets, zero matches, clipping, position
permutations, invalid probabilities, nuisance estimation, repeated customers
and temporal drift. Reuse of a tuned object must be compared with a deliberately
fresh object, and score-only intervals with the scientifically justified
resampling procedure. Actual native outputs, refusals and costs must be
measured after environment and source custody are complete. This route can
justify a prototype without claiming that public e-commerce logs already
validate a bank intervention.
