41.1      An operation is defined by its mathematical output
A bank may ask a single software team to discover a graph, identify an effect and estimate
the value of an offer. Those requests have different outputs. Discovery can return a selected
directed graph, an equivalence class or a set of candidates. Identification can return an
expression in the observed law or a nonidentification result. Estimation can return a number
with a sampling uncertainty claim. A shared product becomes misleading when it places all
three behind a field named “causal effect” without preserving these types.
  Consider a renewal offer A, retained balance Y and customer characteristics X available
before the offer. A point-treatment question might be

                                       θ = E{Y (1) − Y (0)}.

Here the expectation is over a declared eligible population, not automatically over the customers
who accepted an offer. A discovery algorithm can help propose relationships among X, A, Y ,
but a graph proposal does not by itself establish that Y (a) is identified. Even after identification,
numerical uncertainty depends on how customers were sampled and whether branch, household
or calendar dependence matters. Software comparison must preserve each stage.
   The selected source paths considered here make these differences concrete. DirectLiNGAM
exposes a functional discovery construction; y0 exposes symbolic identification; delicatessen
exposes estimating equations; and statsmodels exposes fitted treatment-effect operations with a
joint GMM representation. These are useful components of a workflow, with different scientific
contracts. The source inspections establish the specific interfaces and branches described below.
They do not establish execution speed, numerical agreement or empirical coverage for this
bank. (LiNGAM project, 2026b; y0 project, 2026b; delicatessen project, 2026b; statsmodels
project, 2026b)

42.1      A graph representation carries a scientific commitment
A funding analyst may represent the offer rate, customer response and retained balance by
three columns in a matrix. The columns are measurements; the graph and structural equations
give those measurements causal meaning. An adapter must preserve both. A correctly sized
matrix can still encode every arrow in the wrong direction, and a software object called a mixed
graph can still contain a directed cycle that is inadmissible for the requested identification
algorithm. These errors arise before questions of estimation accuracy.
  The inspected LiNGAM base class stores a coefficient in Btarget,predictor . It fits each variable
against eligible variables earlier in its selected causal order, optionally removing predictors
excluded by the prior-knowledge matrix. The adaptive-Lasso branch and ordinary regression
branch therefore share an orientation convention. A conversion to an edge list must interpret
a nonzero Bjk as k → j. (LiNGAM project, 2026a)
  For a stipulated banking example, let F denote a funding change, A an offer adjustment
and Y the balance response, in declared normalized units:
                           A = 0.4F + εA ,      Y = 0.1F + 2A + εY .
Holding the disturbance law fixed, a one-unit intervention on F changes A by 0.4 and Y by
0.1+2(0.4) = 0.9. The latter consists of the direct path and the mediated path. Transposing this
coefficient matrix produces a different acyclic graph with no path from F to Y ; its corresponding
total effect is zero. Shape checks and acyclicity checks both pass. An asymmetric intervention
example, rather than a symmetric matrix fixture, detects the semantic error. The arithmetic
is an original project example, not a fit to a bank dataset. (Causal banking research project,
2026d)
   LiNGAM’s inspected estimate_total_effect method regresses the target on the source
and the source’s estimated parents. If the requested target is earlier than the source in the
selected causal order, the method warns and continues. The numerical coefficient remains an
output; the warning records a reason its causal interpretation may be inappropriate. A service
that records only the returned floating-point number would lose that distinction. It should
carry the order, adjustment variables, warning and fitted graph together, and state whether
the request falls within the admitted functional model. (LiNGAM project, 2026a)
