# Commercial computation and workflow: source preflight

Continue the eligible commercial computation/workflow lane independently of
the partial frontier census. The banking use is a restarted causal batch:
preserve its input vintage, causal target, estimator/covariance configuration,
code/environment, numerical tolerances, failed and completed requests, and
the complete cost of recovery.

The initial frame includes Databricks Lakeflow Jobs (AWS), Snowflake task
graphs, Azure Machine Learning pipelines (API v2), Dataiku DSS scenarios,
AWS Step Functions, SAS Viya orchestration, Domino and Posit Workbench/Connect.
These are candidate identities, not capability findings. The frame is bounded
and complementary market discovery remains necessary. Product aliases,
deployment editions and exact historical versions must be resolved before
coverage or absence conclusions.

1. Preserve six fixed official manual requests, with transport/format outcomes,
   exact local bytes and SHA-256. Inspect the repair, retry, reuse, ordering and
   failure semantics. Never execute downloaded code or start a vendor trial.
2. Separate a job being repaired from scientific replay. Ask whether partial
   recovery changes data vintage, selected population, code or environment;
   whether native retries duplicate side effects; and whether cached outputs
   still answer the same causal question. Read actual manual text before
   making each vendor claim.
3. Audit identity, edition/date limits, inspected anchors and supported claims.
   Acquisition on 22 October does not authenticate exact 7 October bytes.
   Preserve failures and unread leads in the omissions register. Runtime,
   commercial terms and prices remain unverified where no evidence exists.
4. Prepare a connected comparison and a matched public known-law replay
   protocol. Use synthetic failures and public data before expensive bank
   experiments. Treat commercial runtime qualification as later work, while
   completing source-based proposal analysis now.
5. Checkpoint the actual source progress with an exact next action, yield the
   active lane for paired-release/program/Git preservation, and retain the
   complete operation contract. Do not mark coverage complete or turn a
   checkpoint into a user permission gate.

Requests have two concurrent connections, 45-second transport timeouts and a
16 MiB per-file bound. Sandbox connection failures receive a separately
recorded elevated retry. A source failure affects that source; independent
lanes remain eligible. No sibling repository, credentials, settings or remote
service state is changed.
