# Resolve the native grf reuse choice

The native seed and the inherited R-package entry point to the same upstream
grf implementation. Review the pinned source, license, dependency declarations,
maintenance identity, previously reviewed adapter contract and exact boundary
references. Do not count these entries as independent engines or inherit
runtime acceptance from a passing design.

Choose the initial route on the evidence already acquired: preserve the
maintained R preprocessing, forest, score and average-effect path; reject a
direct native embedding or algorithm port for the initial prototype. State
what evidence could reverse that choice. This decision can finish without
granting integration_allowed, installing a package or running a new study.

Review challenges: a GPL declaration is not a complete distribution/dependency
audit; a dated commit is not a support SLA; a project C++ arithmetic oracle is
not a vendor forest run; a CATE prediction is not an ATE and its variance is
not the average-effect variance. Match the decision to the integrated chapter
already covering these issues. Record the criterion outcome and continue the
next eligible lane.
