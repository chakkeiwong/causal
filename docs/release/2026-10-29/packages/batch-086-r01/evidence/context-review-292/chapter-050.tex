\chapter{Choosing repeated actions}




% SOURCE docs/release/2026-10-29/source/docs/writing-repair/2026-10-29/src/4723b53203c50569.tex CHAR 0
A repeated servicing decision changes both cash flows and the information
available for later decisions. Choosing software therefore begins with the
policy question: evaluate a fixed rule from logged experience, learn a rule
and evaluate it separately, or plan within a supplied model. A numerical
answer can be accurate for one of these questions and misleading for another.

The chapter first examines learned policies and their evaluation populations,
then R methods for learning and evaluating dynamic rules. The detailed Python
comparisons distinguish sequential scores, one-time offers and hidden-state
planning before bringing those choices together. Java and C++ provide
contrasting learning, inference and planning implementations. The final Julia
studies connect interface semantics to concrete model evaluation and
partial-history weighting. Their worked examples keep policy selection,
information loss, monetary scaling and uncertainty visible throughout.

\section{d3rlpy: learning a policy without losing its evaluation target}
\label{exec15:d3rlpy-contract}

A collections team wants to choose the next contact, restructuring offer or
referral from a borrower's history. A library that learns actions from logged
episodes is an attractive challenger to a manually specified rule. The
proposal must nevertheless say which policy is evaluated, whose starting
states define value, when money is received, and which unobserved alternatives
the historical data can support. These choices belong to the scientific
interface. They cannot be delegated to an algorithm name.

The selected d3rlpy source is revision \texttt{38c34b6f99fd}, dated
10 September 2025 and declaring version 2.8.1. It supplies offline and online
reinforcement-learning interfaces, episode and transition objects, and fitted
Q evaluation (FQE). The separately observed PyPI release also has the label
2.8.1; a matching label alone does not establish equality between a released
distribution and a later repository snapshot. The proposal selects these
pinned interfaces as a reference and prospective challenger. An enabled bank
adapter remains conditional on the concrete acceptance cases developed here.
\citep{exec15_d3rlpy_package,exec15_d3rlpy_value,exec15_d3rlpy_contract}

\subsection{From a loan history to a value target}

Let \(H_t\) contain information available before action \(A_t\), and let
\(S_t=f(H_t)\) be the state supplied to a learner. Let \(R_{t+1}\) be net
cash flow from that decision interval, including contact cost and any
specified credit loss. For a policy \(\pi\), a starting distribution \(\mu\),
and a declared period discount \(\gamma\), the proposed target is
\[
 V^{\pi}(\mu)=E_{S_0\sim\mu}^{\pi}
       \left[\sum_{t=0}^{T-1}\gamma^t R_{t+1}\right].
\]
This is a definition of the desired policy value. Recovering it from logs
requires that the state/history and observation process support the relevant
conditional transitions and rewards, that action assignment is adequately
accounted for, and that the policy does not require unsupported histories and
actions. A convenient compressed state need not preserve these conditions.
A feature constructed from a later recovery cannot be included in a state
available to an earlier collections decision. The adapter therefore needs
timestamps, lineage and a declared information set as well as arrays.
\citep{exec15_d3rlpy_contract}

FQE fits a separate action-value approximation for a supplied policy. In
the selected implementation, the update obtains the next action through
\texttt{predict\_best\_action}, passes the observed terminal indicator to the
Q-loss calculation, and discounts a transition spanning \(k\) intervals by
\(\gamma^k\). The public learner distinguishes a greedy prediction from a
sampled action. That distinction matters: the inspected FQE update does not
average its continuation over the actions of an arbitrary randomized policy.
No claim about all possible custom implementations follows from this selected
path. \citep{exec15_d3rlpy_value}

Consider a one-decision model with stipulated rewards USD~2 and USD~10 for
actions zero and one. A policy choosing these actions with probabilities
\(1/4\) and \(3/4\) has value USD~8. A deterministic policy always choosing
action one has value USD~10. Evaluating the latter cannot certify the former,
even if both are stored in the same learner object and agree on which action
has the largest score. The proposed contract must freeze whether deployment
uses a greedy rule, a sampled rule, an exploration mixture or a constrained
postprocessor. For a stochastic target, it must either supply a verified
policy-integrated Bellman update or refuse this FQE route. These are exact
target distinctions, not empirical claims about learner quality.
\citep{exec15_d3rlpy_exact,exec15_d3rlpy_contract}

\subsection{Ending an episode changes which observations are learned from}

The pinned episode generator separates terminal flags from timeout flags.
If both are set, it gives priority to termination by setting the overlapping
timeout entries to zero. The source assignment modifies the supplied timeout
array. It then emits episodes at marked boundaries. If no termination or
timeout is present it raises an assertion; if a final segment after an earlier
boundary is unclosed, that segment is not emitted. The selected episode
representation counts all rows as transitions when terminated and one fewer
when truncated. A basic terminal transition receives a zero successor, whereas
a nonterminal transition needs the next stored observation.
\citep{exec15_d3rlpy_episode}

These conventions are reasonable only after mapping the bank's observation
scheme. A default may be terminal for a loan-lifetime objective; an extract
ending on a reporting date is not evidence that no later recovery will occur.
A refinancing event may end one contract while preserving a customer-level
relationship. Each target needs an explicit event dictionary. Treating all
extract boundaries as terminal substitutes zero future value for an unresolved
continuation. Treating an actual end as truncation can omit the final reward.
\citep{exec15_d3rlpy_contract}

For an exact row-accounting example, three stored rows provide three
transitions when the episode is terminal but only two when it is truncated:
the latter's final observation can be a successor, while its final action and
reward have no successor transition in the basic picker. In a six-row input
with a timeout only at row index two, the generator emits indices zero through
two and leaves indices three through five outside emitted episodes. The
adapter should retain the original six-row count, identify this final segment
and require a declared disposition. Silently relabelling the tail as a
completed episode would conceal missing information. A separate boundary
fixture with both flags true must verify the declared precedence and preserve
the caller's original arrays. \citep{exec15_d3rlpy_exact,exec15_d3rlpy_contract}

The inspected upstream test has an additional qualification limit. Its
parameter named ``overlap'' sets timeout flags, but the assignment to terminal
flags occurs only in the separately named terminal branch. Consequently that
parameter does not exercise simultaneous true flags. This is a direct
source-control-flow observation, not an upstream test execution or a claim
that the precedence code fails. A prototype must construct an actual overlap,
check input immutability at the wrapper boundary and verify row disposition
across terminal, truncated and unclosed episodes. The presence of a suitably
named test is insufficient evidence that the intended case is covered.
\citep{exec15_d3rlpy_episode,exec15_d3rlpy_contract}

\subsection{An initial-state score must actually use the initial population}

The selected \texttt{InitialStateValueEstimationEvaluator} is documented as
averaging value at initial states. Its implementation iterates through batches
of each episode and takes the first observation of every batch. The batch
window is 1,024 rows. For sufficiently long episodes, later batch starts
therefore enter the reported mean. Episode duration also changes the number
of contributions. This cannot be treated as one starting observation per
borrower merely because of the evaluator's name.
\citep{exec15_d3rlpy_value}

Take two terminated episodes with 2,048 and one rows. Stipulate predicted
values USD~10 and USD~30 at the long episode's first and second batch starts,
and USD~20 at the short episode's initial state. Equal weighting of the two
initial borrowers gives
\[
   \widehat V_{\mathrm{starts}}=(10+20)/2=15.
\]
The literal selected batching calculation gives
\[
   \widehat V_{\mathrm{batch}}=(10+30+20)/3=20.
\]
The five-dollar difference arises even when every supplied prediction is
exact. It is population substitution, not approximation error. This exact
control-flow reference has not executed the native package.
\citep{exec15_d3rlpy_exact}

A repaired wrapper should extract exactly the declared start state for every
eligible target unit and average with prespecified population weights. It
should separately report exclusions and zero-transition episodes, including
batch-boundary tests at 1,023, 1,024, 1,025 and 2,048 rows. A continuing
portfolio might instead require a calendar-date state distribution; that is
a valid different target and needs an explicitly different scorer. The
package's average-value metric over logged transitions is useful as a scale
diagnostic, while its SoftOPC score contrasts values in episodes selected by
a return threshold with values across all episodes. Neither is automatically
the requested incremental collections value.
\citep{exec15_d3rlpy_value,exec15_d3rlpy_contract}

\subsection{Calendar time and monetary units survive preprocessing}

The basic transition picker assigns interval one. The multistep picker uses
row offsets to discount intervening rewards and to construct the continuation
interval. A physical calendar is not supplied by those row offsets. If a
state is recorded monthly until delinquency and daily thereafter, identical
row discounts express different economic preferences in the two regions.
The contract must choose a fixed grid or a verified clock-aware conversion;
the learner and evaluator must then use the same convention.
\citep{exec15_d3rlpy_episode,exec15_d3rlpy_contract}

Suppose cash flows USD~10 and USD~20 occur at months zero and two, with a
stipulated monthly discount of 0.9. The calendar value is
\(10+0.9^2(20)=26.2\), whereas treating the second stored record as the next
month gives \(10+0.9(20)=28\). This discrepancy is deterministic. More
training cannot resolve a clock the input has failed to represent.
\citep{exec15_d3rlpy_exact}

Reward preprocessing raises a related issue. The selected source includes
clipping, affine standardization and scaling by a range of episode returns.
The public \texttt{predict\_value} applies observation and action
transformations but does not apply an inverse reward transformation.
A transformed Q-value must therefore retain its transformed-objective label.
Moreover, applying a one-step inverse to a cumulative value is generally
incorrect when preprocessing shifts rewards. If \(r'=a r+b\), then
\[
 V'^{\pi}=a V^{\pi}+b E^{\pi}
                 \left[\sum_{t=0}^{T-1}\gamma^t\right].
\]
The additional term depends on the discounted horizon and potentially the
policy. A shift can change preferences when policies alter episode length.
This equation is an authored algebraic identity for the declared transform,
not a theorem about a fitted neural approximation.
\citep{exec15_d3rlpy_value,exec15_d3rlpy_exact}

For two adjacent periods with rewards ten and twenty, \(\gamma=0.9\), and
\(r'=(r-5)/5\), the original value is USD~28 and the transformed value is
3.7. Applying the one-step inverse gives \(5(3.7)+5=23.5\). The correct
horizon-aware inversion gives \(5(3.7)+5(1+0.9)=28\). Clipping is more
severe: rewards one hundred and one thousand both become one at an upper
clip of one. No inverse call can recover their original magnitudes from that
output alone. The original cash-flow records must remain available for
evaluation. If a return-range scaler has an equal minimum and maximum, the
selected division also needs an explicit invalid-scale outcome rather than a
nonfinite monetary score. \citep{exec15_d3rlpy_value,exec15_d3rlpy_exact}

\subsection{Conservative learning cannot create missing intervention evidence}

The discrete CQL path combines its temporal-difference loss with a penalty
formed from log-sum-exp action values minus the logged-action value. This is
a specified learning objective. Its name and penalty do not establish the
bank's action-assignment mechanism, recover omitted confounders or turn a
never-observed action into an identified policy comparison.
\citep{exec15_d3rlpy_value}

In a one-state example, suppose logging always chooses action zero and
observes reward zero. Two admissible models agree on every logged record.
Under action one, their rewards are respectively USD~100 and minus USD~100.
The value of always taking action one is different in these models, although
no observed-data fitting criterion can distinguish them using the specified
logs alone. A conservative learner may prefer the supported action; that is
a defensible decision rule under additional preferences or ambiguity
restrictions. It is not recovery of the missing reward. The proposed output
should retain unsupported action mass and any imposed structural assumptions,
and refuse an unconditional causal-value certificate.
\citep{exec15_d3rlpy_exact,exec15_d3rlpy_contract}

Evaluation requires a further separation among sources of uncertainty. A
return distribution describes variation in what happens under a fixed policy
and model. Variation among fitted critics or random seeds describes another
object. Neither automatically supplies sampling coverage for an estimated
mean, uncertainty from unsupported actions or the effect of searching over
many policies. The selected FQE configuration exposes a critic count, but the
inspected update is not by itself an inference procedure for all those
targets. \citep{exec15_d3rlpy_value,exec15_d3rlpy_contract}

For example, a return equally likely to be zero or one hundred has mean fifty
and variance 2,500 square dollars. Under an explicitly independent sample of
one hundred such returns, the sample mean has variance twenty-five and
standard error five dollars. The return standard deviation is fifty dollars.
Reporting one as the other confuses individual risk with precision of a mean.
If two equal-value policies instead receive independent, unbiased score
errors of plus or minus ten, selecting the larger score gives errors
\(-10,10,10,10\) across the four equally likely possibilities: expected
optimism is five dollars. These stipulated calculations motivate customer-level
evaluation splits and selection-aware protocols; they are not measured FQE
coverage or a prediction of a particular bank's bias.
\citep{exec15_d3rlpy_exact}

\subsection{A bounded reuse decision and its next experiment}

The root source has an MIT license with notice-retention and warranty terms.
Its package declaration requires Python at least 3.9 and eleven direct
dependencies, including PyTorch at least 2.5, Gym at least 0.26 and Gymnasium
exactly 1.0.0. Several other requirements are unpinned. The inspected CI
configuration uses Python 3.10 on Ubuntu and macOS and temporarily omits
Windows from its active matrix. These are declared inputs and configuration,
not a resolved installation, a successful CI observation or a commitment to
future support. A deployment decision also needs dependency notices,
checkpoint compatibility and a reviewed update policy.
\citep{exec15_d3rlpy_package}

Direct adoption is deferred. Narrow integration is a plausible later route
because it can retain upstream learners while making population, episode,
policy, clock, scale and failure semantics explicit. Porting the neural
learners is not selected: it would create a second implementation and its
numerical-equivalence burden without a demonstrated benefit. Rejecting all
reference use is also unwarranted; the identified issues admit specific
constraints, fixes and generated acceptance cases. The detailed SCOPE-RL and
Open Bandit Pipeline reviews in Sections~\ref{exec23:scope-rl-scope}
and~\ref{exec23:obp-scope} retain reference dispositions, with native workers
conditional on their own qualifications. This reference does not qualify
those engines or their different sequential and contextual-bandit targets. \citep{exec15_d3rlpy_contract}

The next justified experiment is a small generated environment with an exact
tabular value and direct independent rollouts. It should first verify the
native observations and repaired conversions above, then compare learned
policies against the tabular reference while removing an action from logging
support. Training, tuning and final evaluation should have explicit episode
identities; repeated configurations, failed fits, unsupported requests and
nonfinite scores stay in the denominator. Runtime, review time, data
reconstruction and maintenance cost belong beside performance. Bank-specific
losses, authentic customer validation and measured return on investment are
later inputs. This sequence permits a concrete product proposal now while
making the evidence required for a future adapter precise.
\citep{exec15_d3rlpy_contract}

\section{R policy learning: what is optimised, what is evaluated, and what remains unknown}
\label{sec:exec24-policies-r}

A servicing policy should be judged by the value of the decisions it will make after selection.
Consider a bank choosing between a reminder, a payment holiday and ordinary servicing at
successive monthly decisions. A shallow decision tree can describe an interpretable allocation;
a backward regression can construct a sequence of actions; and a policy evaluator can estimate
the value of a supplied rule. These are related services, but they have different targets and
failure modes. This section compares policytree, DynTxRegime, DTRreg and polle at pinned
commits preceding 7 October 2026. It develops conditional original-R-worker choices from
inspected technical sources. Native behaviour, the original methodological papers referenced
by those packages, complete rights and exhaustive R coverage remain separate obligations.

\subsection{Three targets that an interface must distinguish}
Let $H_t$ be the information available before the stage-$t$ action $A_t$, and let
$d=(d_1,\ldots,d_K)$ be a policy with $A_t=d_t(H_t)$. For a stipulated utility $U$,
write $V(d)=\mathbb E[U^d]$. The value of a fixed rule $d$, the value of a
data-selected rule $\widehat d$, and the best value
$\sup_{d\in\mathcal D}V(d)$ over a declared policy class $\mathcal D$ are different
objects. Exact empirical optimisation within shallow trees establishes neither
population optimality nor optimality over unrestricted policies. An estimated value
for rules trained on subsets also need not be the value of the final rule refitted
on all observations. The request must identify which of these is intended.

Selection alone can create apparent value. Suppose two policies each have true value
zero, and their independent development-value errors are equally likely to be minus
one or plus one dollar. Selecting the larger estimate has development expectation
$\mathbb E[\max(\epsilon_1,\epsilon_2)]=1/2$ dollar: the maximum is minus one
only when both errors are negative, with probability $1/4$. The selected policy's
fresh expected value is still zero in this stipulated law. No defect in the optimiser
is needed. A held-out evaluation or a justified design for adaptive-policy evaluation
addresses a different question from improving the empirical search.
\citep{exec24_policiesr_reference}

The familiar one-stage augmented score also exposes the assumptions that a software
label can hide. For action $a$, define
\begin{equation}
 \Gamma_a=m_a(X)+\frac{\mathbf1\{A=a\}}{\widehat e_a(X)}
                      \{Y-m_a(X)\}.
\end{equation}
Conditional on $X$ and fixed fitted nuisance functions, let $e_a=\Pr(A=a\mid X)$
and $\mu_a=\mathbb E[Y\mid A=a,X]$. Direct conditioning gives
\begin{equation}
 \mathbb E[\Gamma_a\mid X]-\mu_a
 =\left(1-\frac{e_a}{\widehat e_a}\right)(m_a-\mu_a).
\end{equation}
Thus either correct nuisance function removes this conditional mean error, where
the propensity denominator is positive and the expectations exist. Interpreting
$\mu_a$ causally still requires the relevant consistency and exchangeability
conditions. Conditioning on fixed nuisance fits is also not a licence to reuse
the same observations adaptively without further analysis. With $\mu_a=10$,
$m_a=8$, $e_a=1/4$ and $\widehat e_a=1/2$, the expected score is nine, not ten;
correcting either nuisance gives ten in this exact example.
\citep{exec24_policiesr_reference}

When an action has no logging support, neither optimisation nor a fitted propensity
creates evidence for its reward. A logger that always takes action zero with reward
zero is compatible with both minus ten and plus ten dollars under action one.
These worlds have the same observed data but different optimal decisions. A bank
must supply additional justified structure, new information or an experiment;
there is no universal software repair for this unrestricted gap.

\subsection{policytree: a useful optimiser with an upstream score obligation}
The inspected policytree declaration is version 1.2.5, requiring R at least 3.5.0,
with MIT plus its licence file and dependencies including grf and Rcpp. Its main
interface accepts a feature matrix $X$ and an action-reward matrix $\Gamma$. The
documentation describes exhaustive shallow-tree search and explains the substantial
dependence on depth, feature count and distinct feature values. The optional
\texttt{split.step} skips candidate splits; hybrid search builds a deeper tree using
limited lookahead. The latter is a different optimisation procedure, not an
unqualified certificate of the same global optimum.
\citep{exec24_policiesr_policytree}

The inspected R wrapper checks numeric matrix/data-frame inputs, missing entries,
matching row counts, nonnegative depth and positive integer split and node-size
controls. It passes the matrices to an Rcpp binding, which invokes the C++ tree
search. The inspected leaf routine maximises sums of supplied rewards, retaining
the earlier action on exact reward ties because its update uses a strict greater-than
comparison. Recursive paths check interrupt requests and split eligibility. These
details make an original R worker a plausible proposal choice, but they do not
establish runtime bounds on an arbitrary input or causal validity of the supplied
reward matrix. The wrapper needs explicit finite-value, depth/resource and action-ID
policies, with native tests of the exact entrypoint before admission.
\citep{exec24_policiesr_policytree}

The binary causal-forest score adapter constructs the two conditional mean estimates
from forest predictions and forms the augmented scores using observed treatment
propensities. In the inspected function, the inverse propensity is calculated
directly; support and any upstream grf safeguards therefore need to be matched
explicitly. An adapter should record whether the supplied scores are out-of-sample,
which nuisance version produced them and which observations were used to select
the policy. It should not label an arbitrary matrix as doubly robust evidence.
The package's train/test example is useful documentation, but a complete learning
procedure must also account for nuisance and feature-selection dependencies.
\citep{exec24_policiesr_policytree}

Prediction adds a mundane but material banking risk: feature meaning can change
without changing matrix dimensions. The R method checks the column count, while
its documentation requires the training order. The C++ prediction path follows
numeric split-column positions. A CLI/MCP worker should bind names, order, units
and preprocessing to the fitted artifact, and refuse a schema mismatch. Action
indices similarly need a stable mapping to reminder, holiday and ordinary servicing.
The proposed choice is to integrate the original optimiser behind a schema-aware
worker and an independently qualified scoring/evaluation layer. A whole C++ port
is unnecessary unless a measured deployment constraint justifies its maintenance.
\citep{exec24_policiesr_policytree}

\subsection{DynTxRegime and DTRreg: sequential structure is an explicit modelling choice}
DynTxRegime's pinned 4.16 declaration identifies Q-learning, interactive Q-learning,
weighted learning and value-search families, with GPL-2 licensing and dependencies
including modelObj, kernlab and optimisation packages. Its \texttt{qLearn} interface
performs a single backward step. A numeric response starts the recursion; a prior
\texttt{QLearn} object passes the preceding estimated value into the next step.
The inspected dispatch verifies model objects, the data frame, response and feasible
action-set interface, then delegates regression and prediction. A sequence of calls
therefore needs a declared stage order, available histories and reward convention;
the existence of the object hierarchy does not prove that the chosen regression
models identify the bank's optimal strategy. The documented training-set value
must be kept distinct from an external evaluation of the resulting rule.
\citep{exec24_policiesr_dyntx}

This is a reasonable original-R-worker candidate where its model and action-set
interfaces match the question. The alternatives are to use a different qualified
sequential estimator, to retain it as a mathematical/design reference, or to defer
a family whose delegates and assumptions have not been inspected. The package-level
listing of methods must not close every method-specific coverage cell. In particular,
the selected Q-learning dispatch does not establish a universal outcome-weighted,
value-search or hidden-state capability.

DTRreg version 2.4 declares GPL-2 and provides dynamic weighted least squares,
G-estimation, Q-learning and survival-related families. The inspected DTRreg
documentation specifies treatment, treatment-free and blip models at each stage;
it restricts continuous-treatment blips to a quadratic form. Its direct consistency
claims depend on model conditions and should be assessed against the methodological
originals before inheritance as a theorem. In the inspected dispatcher, multinomial
G-estimation is explicitly rejected. Backward stage fitting is followed by forward
recalculation of selected treatments and renewed pseudo-outcome construction.
That is a substantive sequential algorithm, not a collection of unrelated stagewise
regressions.~\citep{exec24_policiesr_dtrreg}

The continuous-action domain illustrates why an apparently precise optimum can
exceed the evidence. For a stipulated benefit $u(a)=8a-2a^2$, the nonnegative
unrestricted optimum is $a=2$ with value eight. If observed actions cover only
$[0,1]$, the supported optimum is $a=1$ with value six. A second response curve
can equal this quadratic on $[0,1]$ and continue as $6-100(a-1)$ beyond one;
the observed action range cannot distinguish it, but its optimum remains one.
Choosing the first curve's extrapolated optimum requires the quadratic restriction
outside support. Clipping a recommendation is a policy constraint, whereas asserting
the extrapolated optimum is an identification claim.~\citep{exec24_policiesr_reference}

DTRreg's inspected weight dispatcher distinguishes inverse probability, capped inverse
probability, overlap and other paths. The capped path uses the empirical 99th
percentile. Trimming can control extremes, but it changes the estimating expression
and does not restore unsupported actions. In an exact four-stage example with
probability $1/10$ of the required action at each stage, the target path occurs with
probability $1/10{,}000$ and has inverse weight $10{,}000$. With unit reward and a
cap of one hundred, the expectation of the capped path contribution is $1/100$
instead of one. This is an authored illustration of the tradeoff, not a benchmark
of DTRreg's default settings.~\citep{exec24_policiesr_dtrreg,exec24_policiesr_reference}

Its selected bootstrap resamples participant rows, reconstructs the object and
reruns the stage procedure. An interruption returns an explicit aborted result;
NA parameter draws trigger an error before covariance construction. An optional
tail replacement modifies bootstrap draws before variance calculation. These
are observable source contracts that a worker should preserve. They do not
establish finite-sample coverage, justify treating correlated bank accounts as
independent, or remove nonregularity near tied optimal actions. The documentation
warns about nonunique optimal treatment only when a variance-estimation option is
selected; absence of that warning otherwise is not evidence of a unique optimum.
\citep{exec24_policiesr_dtrreg}

\subsection{polle: separating training, evaluation and history restrictions}
The pinned polle 1.6.5 declaration describes policy learning and evaluation, requires
R at least 4.1 and lists an Apache License at version two or later. Its dependencies
include policytree, DynTxRegime, survival and targeted; this declaration is not
transitive rights clearance. The inspected evaluator accepts either a fixed policy
or a learner, and distinguishes value evaluation from a restricted single-stage,
binary-action subgroup effect. It accepts separate action, outcome, censoring and
terminal-outcome models. Source checks request censoring models when relevant
censoring events occur and a terminal-outcome model for the specified missing
terminal-utility case. These are useful refusal semantics for a proposed worker.
\citep{exec24_policiesr_polle}

The default evaluator has \texttt{M=1}. In that branch, training and validation
objects are the same. For \texttt{M>1}, the inspected routine constructs folds,
splits by the policy-data IDs and passes distinct training and validation objects
to the evaluation function. That function sends the training object to
\texttt{fit\_functions}; when no fixed policy is supplied, the inspected delegate
invokes the learner on that training object before evaluating on validation data.
This establishes a concrete source path for outer evaluation separation. It does
not by itself prove independence of related accounts, prevent leakage through
externally supplied fitted nuisance objects, or validate every delegated learner.
The choice of a fixed policy, training algorithm, training sample size and final
refit must appear in the reported target.~\citep{exec24_policiesr_polle}

History compression is another explicit restriction. The inspected interfaces have
separate full-history flags for action, outcome and censoring models and for the
policy itself, with state-like histories as defaults. In a stipulated example,
an earlier binary observation $H$ is fair, the present state is constant, and utility
is $\mathbf1\{A=H\}$. A rule retaining $H$ achieves value one; every fixed action
using only the constant state achieves one half. A smaller state representation is
not harmless merely because an API accepts it. The bank must explain why the
retained state suffices for the causal and decision questions, or preserve the
history and evaluate the larger model.~\citep{exec24_policiesr_polle,exec24_policiesr_reference}

The learning interface offers distinct Q-learning, doubly robust Q-learning, tree
and weighted-learning choices, with method-specific restrictions and delegates.
Nested nuisance-fitting folds and outer policy-evaluation folds are different
controls. An adapter must preserve both, record any supplied prefit models and
avoid translating a method name into a blanket calibration claim. The
outcome-weighted delegate supplies a concrete reason to preserve the resolved
solver and dependency versions as well.~\citep{exec24_policiesr_polle}

The pinned polle wrapper selects \texttt{ipop} by default and passes that
choice to DTRlearn2. Inspection of DTRlearn2 2.1 and WeightSVM 1.7-16
traces the alternative \texttt{svm} route beyond the warning in polle's
comments. WeightSVM converts the signed binary responses to factor codes.
Its native classifier orders classes by first appearance and gives the
first class the positive decision-function sign. The special native rule
for literal signed labels does not apply after this factor conversion.
DTRlearn2 copies the returned support-vector coefficients into its own
decision function without translating the returned class order back to the
signed response. Positive output can consequently refer to the opposite
action from the one its downstream threshold assumes.
\citep{rel15policydelegates}

An exact project witness isolates the convention. Take two one-dimensional
points at -1 and +1 with matching signed labels, positive unit weights and
unit penalty. The stipulated hard-margin solution has dual weights 1/2.
When the negative observation appears first, the native convention gives
the negative class a positive score; importing its coefficients without
the class translation gives slope -1 and, under the inspected bias
reconstruction, intercept zero. The returned action labels are reversed.
Reversing the row order gives slope +1. This is an algebraic witness using

\section{Policy evaluation software must preserve the decision and its uncertainty}
\label{exec23:scope-rl-scope}
A servicing team may use an offline policy evaluation library to compare a
sequence of reminders, forbearance offers and escalations. The useful output is
the value of a specified feasible policy under an information clock, together
with defensible uncertainty. A function returning a ranking is only one part of
that task. SCOPE-RL provides a particularly useful proposal comparator because
its selected discrete estimators, interval helpers and policy-selection paths
make several boundaries explicit. This review concerns version 0.2.1 at the
immutable 1 December 2023 revision returned by the cutoff query. Eleven
authenticated source and declaration files support the following observations;
the continuous-action, distributional and density-learning families have not
received equivalent inspection. No upstream program was executed.
\citep{exec23_scope_rl_sources}

\subsection{An episode, a propensity and a policy are substantive inputs}
\label{exec23:scope-rl-target}
Let a customer episode have $T$ decisions. At decision $t$, $H_t$ is all
information available before the action, $A_t$ the action, and $R_t$ the
subsequent monetary reward. Write $b_t(a\mid H_t)$ for the actual logging
probability and $\pi_t(a\mid H_t)$ for the policy being evaluated. For a declared
initial population and discount $0<\gamma\leq1$, the proposed target is
\[
 J(\pi)=\mathbb E_\pi\!\left[\sum_{t=0}^{T-1}\gamma^tR_t\right],
 \qquad
 W_{it}=\prod_{s=0}^{t}
 \frac{\pi_s(A_{is}\mid H_{is})}{b_s(A_{is}\mid H_{is})}.
\]
The elementary change-of-measure argument needs the logging probabilities to
describe the actual action mechanism, support for every target action-history
pair, and the same conditional transition/reward law under the intervention.
Multiplying the logging trajectory density by $W_{i,T-1}$ then replaces each
action factor by its target counterpart. For a reward observed by time $t$,
future action factors integrate to one, which explains the per-decision form.
An omitted private distress signal or a post-action feature can invalidate this
argument even if every probability row sums to one. The independent-episode
sampling condition used for the simple uncertainty examples below is additional
to this identification argument.

The inspected implementation reshapes flattened records into equal-length
episodes, cumulatively multiplies action probabilities, and either repeats the
final weight or retains the prefix weights. Its two scores therefore correspond
to
\[
 Z_i^{\rm TIS}=W_{i,T-1}\sum_t\gamma^tR_{it},
 \qquad Z_i^{\rm PDIS}=\sum_t\gamma^tW_{it}R_{it}.
\]
The interface checks dimensions, row counts, divisibility by the horizon and
target probability normalization. Such checks cannot establish truthful
logging, temporal ordering or common episode membership. The probability
validator is called with a zero lower limit; the discount expression divides a
cumulative product by $\gamma$ while its scalar check also uses a zero lower
limit. A proposed adapter must enforce finite, strictly positive observed-action
denominators and an explicitly supported discount domain before these calls.
This is a static source finding, not an observed runtime failure.
\citep{exec23_scope_rl_sources}

An exact two-period example clarifies why two estimators can disagree without
targeting different policies. Let both logging actions be independent fair
coins and both target actions have probability $3/4$ of action one. Set
$R_0=2A_0$, $R_1=4+4A_1$ and $\gamma=1/2$. Direct enumeration of all four
trajectories gives $J(\pi)=5$. Both importance scores average to five under the
logging law. On the particular two-episode sample $(1,0),(0,1)$, however, TIS is
$3$ and PDIS is $15/4$. Neither sample result proves bias or superior precision.
The project's rational-arithmetic reference enumerates the complete finite law
and distinguishes this population calculation from the illustrative sample.
\citep{exec23_scope_rl_reference}

The inspected doubly robust score adds a fitted state-value term and subtracts
the fitted action value, with current and previous prefix weights:
\[
 Z_i^{\rm DR}=\sum_t\gamma^t
 \{W_{it}(R_{it}-\widehat Q_t(H_{it},A_{it}))
       +W_{i,t-1}\widehat V_t(H_{it})\},\quad W_{i,-1}=1.
\]
Its source calculation is useful for conversion tests, but the label does not
prove robustness to an arbitrary hidden logging signal, an estimated policy,
or dependent customers. The input builder defaults to one fitted-Q fold; its
multi-fold branch excludes contiguous groups of whole trajectories. It caches
fitted models by policy name. Therefore episode grouping, calendar dependence,
policy identity and changes to training settings must be bound explicitly.
Repeated calls with a reused name are not evidence of a fresh fit. The d3rlpy
delegate and a full frozen environment remain native qualification obligations.
\citep{exec23_scope_rl_sources}

\subsection{Terminal rewards and uncertainty cannot be inferred from names}
\label{exec23:scope-rl-uncertainty}
The high-level evaluator defaults to disabling rewards after a done flag. The
actual mask is the cumulative product of $1-d_t$, including the current row.
If a dataset defines $d_t$ as indicating that the transition just produced the
terminal reward, this removes that terminal reward as well. A different
pre-transition convention could justify the mask; the adapter must state and
test the convention. With undiscounted rewards $(2,8)$ and flags $(0,1)$, the
literal mask leaves value $2$, whereas retaining the terminal receipt gives
$10$. At a stipulated servicing cost of six dollars, the margins are $-4$ and
$4$. These are authored examples, not measured bank returns or observed
package outputs. The dataset documentation separately describes episode end
and maximum-step termination, while the fitted-Q dataset call passes the done
array as its terminal argument. A conversion must resolve both meanings.
\citep{exec23_scope_rl_sources,exec23_scope_rl_reference}

The basic estimator's interval method first calculates one score per trajectory
and delegates the resulting vector to a common interval helper. The bootstrap
helper samples those fixed scores with replacement, takes percentile endpoints,
and reports the mean of bootstrap means. Its signature defaults to 100
replications although its parameter prose says 10,000, and it requires an
explicit random seed. Neither this helper nor the selected call refits the
value model, estimates new logging propensities or repeats policy learning in
each bootstrap sample. Whether conditioning on those fits is scientifically
appropriate needs a separate argument; it is not supplied by the word
bootstrap. \citep{exec23_scope_rl_sources}

This distinction already matters without a learned nuisance. For a
self-normalized weighted mean, let two episode weights be $(1,3)$ and returns
$(0,4)$. Ignoring the implementation's tiny denominator stabilizer solely for
this exact algebraic illustration, the estimate is $3$ and the precomputed
normalized scores are $(0,6)$. The four equally likely size-two bootstrap index
pairs produce means $(0,3,3,6)$ if these scores are fixed, but ratios
$(0,3,3,4)$ if the denominator is recalculated. Their bootstrap variances are
$9/2$ and $9/4$. This is not a coverage assessment of either procedure; it shows
that they are different resampling targets. The selected self-normalized class
inherits the score-based interval path and uses a $10^{-10}$ denominator
stabilizer. A native test must retain that stabilizer, distinguish ratio
recalculation from score resampling, and state which procedure is justified.
\citep{exec23_scope_rl_sources,exec23_scope_rl_reference}

Three analytic interval helpers need particularly careful admission. The
Hoeffding-named helper computes the radius
\[
 \max_i z_i\sqrt{\log(2/\alpha)n/2},
\]
whereas its adjacent displayed formula places $n$ in the denominator. Parsing
the expression as inert syntax confirms multiplication by $n$; at $n=20$ the
source radius is twenty times the expression with the same logarithm and $n$
in the denominator. More fundamentally, an observed sample maximum is not a
known population range. For independent Bernoulli rewards with mean $1/100$,
all twenty observations are zero with probability $(99/100)^{20}>0.8$. The
source Hoeffding and Bernstein expressions then both give zero radius despite
the positive mean. A constant negative sample also makes the first radius
negative and reverses its endpoints. No concentration guarantee follows from
these helper names for unrestricted banking rewards.
\citep{exec23_scope_rl_sources,exec23_scope_rl_reference}

The Bernstein-named helper also differs from its printed variance expression:
the executable expression divides the variance contribution by $n-1$, while
the prose display includes $n(n-1)$, and a supplied sample maximum again replaces
a declared range. These observations warrant explicit comparison of definitions
and sample-variance conventions, not a silent formula patch. The Student helper
uses the $1-\alpha$ quantile and returns symmetric endpoints labelled
$100(1-\alpha)$ percent. Under the exact nondegenerate normal-sample model in
which the usual Student pivot has a symmetric continuous law, those endpoints
have central probability $1-2\alpha$: $90$ percent at $\alpha=0.05$. This
algebra does not establish a distributional approximation for importance
scores. Positive sample sizes, finite values, signed rewards, degenerate
samples, alpha endpoints and valid simultaneous coverage must all be explicit
adapter contracts. \citep{exec23_scope_rl_sources,exec23_scope_rl_reference}

\subsection{A selection benchmark is not an offline safety certificate}
\label{exec23:scope-rl-decision}
The inspected lower-bound selector obtains on-policy selection results before

evaluation metrics. The called routine rejects a missing on-policy return
array. This is a concrete benchmark-data requirement: a logged-only banking
request generally cannot furnish those counterfactual returns. Missing truth
must lead to a refusal or a separately designed selection path, never fabricated
on-policy values. The selected call forwards the same alpha to each candidate
and estimator; no multiplicity adjustment appears in this path. Even twenty
independent tests with individual false-admission probability $0.05$ have
probability $1-0.95^{20}$, approximately $0.642$, of at least one false admission.
That hypothetical example is not a measured SCOPE-RL error rate. A candidate
policy learned or selected on the evaluation histories requires its own
selection-aware design. \citep{exec23_scope_rl_sources,exec23_scope_rl_reference}

The ground-truth lower-quartile output also needs a name/value fixture. The
source sorts the policy-value array before deriving a lower-quartile name
ordering, then sorts lower-quartile values separately. In input order A, B,
give A returns $(-10,-10,40,40)$ and B returns $(4,4,4,4)$. Their means are
$15,4$, but lower quartiles are $-10,4$. The selected expressions pair the
unchanged name order A, B with descending values $4,-10$, rather than the

\citep{exec23_scope_rl_sources}

\section{Contextual bandit reuse requires a different contract from sequential servicing}
\label{exec23:obp-scope}
A one-time offer allocation and a sequence of collection decisions are different
causal products. Open Bandit Pipeline (OBP) is a useful comparator for the former:
the inspected core organizes logged contextual-bandit observations, target
action distributions, propensity-weighted estimators, response regressions and
evaluation wrappers. It does not convert repeated customer histories into a

flattened into rows. The selected revision is dated 5 November 2022, declares

multiple-logger and action-embedding estimators need separate review.
\citep{exec23_obp_sources}

\subsection{Logging probabilities, clipping and replay change what the number means}
\label{exec23:obp-target}
For one decision, let $X$ denote information available before choosing action
$A$, let $R$ be the subsequent reward, and write $b(a\mid x)$ and
$\pi(a\mid x)$ for the logging and target action probabilities. Under a common
context population, a stable conditional reward law, truthful logging and
support wherever the target acts, the target is
\[
 V(\pi)=\mathbb E_X\sum_a\pi(a\mid X)q(X,a),
 \quad q(x,a)=\mathbb E[R\mid X=x,A=a],
 \quad \mathbb E_b\!\left[\frac{\pi(A\mid X)}{b(A\mid X)}R\right]=V(\pi).
\]
The last equality follows by cancelling $b$ in the conditional sum over $a$.
Its causal interpretation requires that the reward mechanism remains valid
under the proposed assignment; observed association alone is insufficient.
If action effects persist, affect future eligibility or alter later information,
this single-decision target must not replace a sequential target.

The inspected IPW estimator selects supplied or estimated propensity scores
according to an explicit flag, forms the observed-action ratio and applies an
optional clipping threshold. The doubly robust estimator combines a
target-weighted regression prediction with a clipped weighted residual. Its
calculation can be represented as
\[
 \widehat V_{\rm DR}=\frac1n\sum_i\left\{
 \sum_a\pi(a\mid X_i)\widehat q(X_i,a)
 +\min(W_i,c)\big(R_i-\widehat q(X_i,A_i)\big)\right\},
 \qquad W_i=\frac{\pi(A_i\mid X_i)}{\widehat b(A_i\mid X_i)}.
\]
The default unbounded threshold and a finite clipped threshold are distinct
estimating rules. With an exact conditional-mean regression the residual has
zero conditional mean, but arbitrary estimated regressions, fitted propensities
or clipping need their own bias and uncertainty analysis.
\citep{exec23_obp_sources}

Consider two equally common customer types. For type zero, the logging
probability of offer one is $1/4$ and rewards under offers zero and one are
$(0,2)$. For type one, the logging probability is $3/4$ and rewards are $(1,5)$.
The target always gives offer one. Its value is $7/2$, and exact weighting
recovers that value. Clipping the importance ratio at two gives $3$; substituting
a uniform logging probability gives $17/4$. At ten dollars per reward unit and
a stipulated offer cost of 32 dollars, the respective margins are $3$, $-2$ and
$10.50$. An exact response regression restores the DR population value in this
constructed law even with the specified clipped residual. This illustrates
conditional mechanisms; it is not a finite-sample guarantee or an observed
package benchmark. \citep{exec23_obp_reference}

The replay estimator has another contract. It keeps observations whose
observed-action target probability equals exactly one and normalizes by the
sample match rate. Under unequal contextual logging, the matched contexts have
different frequencies from the target population. In the preceding example,
the limiting matched reward is $17/4$, not $7/2$. Appropriate uniform
randomization or another justified replay design is therefore substantive.
For a fully stochastic target with both action probabilities $1/2$, no exact-one
match exists; the selected source leaves an all-zero score vector when there
are no matches. A product must expose unavailable replay evidence rather than
reporting a zero policy value as a scientific result.
\citep{exec23_obp_sources,exec23_obp_reference}

\subsection{A validated array is not a validated causal request}
\label{exec23:obp-uncertainty}
The core expects target probabilities with dimensions round, action and
position. The inspected validator checks the action-axis sum and position/action
indices, and rejects nonpositive supplied propensity values. Its array helper
checks array type and dimension, not general finiteness. The target-distribution
check does not separately impose nonnegative entries: the row
$(-1/10,11/10)$ sums to one but is not a probability law. A nonfinite propensity
also needs an explicit finite-value check; a comparison with zero is not a
complete validator. These are scoped source findings. The proposed adapter
must independently verify common row identities, action/position vocabulary,
finite values, valid probabilities and their scientific provenance.
\citep{exec23_obp_sources,exec23_obp_reference}

The regression wrapper defaults to one fold, fitting and predicting on the
same contexts. Its multi-fold branch uses shuffled row K-fold splits. Such
splits do not preserve customer groups or forward calendar separation by
construction. Missing propensities are replaced with a uniform distribution
inside this regression-preparation path. That fallback does not authenticate a
bank logging policy, especially for importance-weighted or MRDR fitting. The
adapter must bind whether the quantities are true logs, estimates or explicit

\citep{exec23_obp_sources}

estimation or hyperparameter selection in the selected call. Self-normalized

\citep{exec23_obp_sources}

stability-comparison route, chooses a threshold from candidate scores, and

\citep{exec23_obp_sources}

\section{A hidden-state planner consumes a model; it does not identify one}
\label{exec23:pomdppy-scope}
Servicing decisions may depend on financial distress that is only partially
observed through payments, calls and other signals. POMDP-Py offers useful
interfaces for describing such states, transitions, observations, rewards,
beliefs and online planners. The inspected revision, dated 28 October 2025,
declares version 1.3.5.1. Thirteen authenticated source/declaration files cover
selected histogram and particle beliefs, POUCT/POMCP planning, finite policy
trees and an alternative small-state value routine. This is a reference for
proposed architecture and numerical qualification. Supplied-model planning
does not establish that a latent banking model is identified, that its observation
law is truthful, or that the value of a learned optimal policy has a calibrated
confidence interval. \citep{exec23_pomdppy_sources}

\subsection{Belief and value require a declared information experiment}
\label{exec23:pomdppy-belief}
Let $S_t$ be the latent state, $A_t$ the chosen action, $O_{t+1}$ the subsequent
observation and $b_t(s)$ the posterior state probability given available
history. For supplied transition and observation laws $T(s'\mid s,a)$ and
$L(o\mid s',a)$, Bayes' rule gives
\[
 \widetilde b_{t+1}(s')=L(o\mid s',a)\sum_sT(s'\mid s,a)b_t(s),
 \qquad b_{t+1}(s')=\frac{\widetilde b_{t+1}(s')}
 {\sum_u\widetilde b_{t+1}(u)}.
\]
The denominator is the probability of the new observation under the supplied
model. It must be positive for this conditional update. A service cannot
replace a zero denominator with an arbitrary posterior and claim the same
information experiment. Model estimation, hidden-state identification,
distributional uncertainty and approximation error are separate from this
conditional algebra.

An exact banking example shows what is at stake. Suppose distress has prior
probability $1/4$. A diagnostic signal is positive with probability $3/4$ under
distress and $1/4$ otherwise. The positive-signal probability is $3/8$, and
posterior distress probabilities are $1/2$ after a positive signal and $1/10$
after a negative one. A rescue action pays a net $35$ dollars in distress and
loses $15$ otherwise; declining has value zero. Acting without information has
value $-5/2$. Under the supplied sensor, acting only after a positive signal
gives expected value $15/4$ before a two-dollar diagnostic cost, hence net
$7/4$. If the actual signal instead has probability $1/2$ in either state,
the same proposed rule has net $-13/4$. A more accurate search of the wrong
sensor model cannot repair this gap. All values are stipulated, exactly
enumerated project examples rather than measured bank or package results.
\citep{exec23_pomdppy_reference}

The histogram update follows the displayed transition-observation product and
allows a static-transition shortcut or a supplied next-state set. It normalizes
only when total mass is positive; an impossible observation therefore leaves
an all-zero histogram. The histogram constructor checks for a dictionary, not
a positive normalized probability law. Restricting the next-state set also
changes what is normalized: if the predicted masses are $1/5$ on distress and
$4/5$ on healthy but only healthy is enumerated, the returned normalized belief
places mass one on healthy. Such restriction is valid only if the discarded
mass is truly impossible or the changed conditioning target is intended.
The adapter must report unsupported observations and omitted support explicitly.
\citep{exec23_pomdppy_sources,exec23_pomdppy_reference}

Particle updating has different failure semantics. The explicit updater samples
a transition and observation from each current particle, retains exact
observation matches, and reinvigorates the survivors. An empty set raises
particle deprivation; otherwise resampling and an optional state transform
restore the requested count. Repeating survivors does not create new
independent evidence, and a transform changes the approximation law unless
justified. Exact observation equality also needs a declared discrete or
otherwise appropriate observation representation. The source marks the explicit
updater as untested. POMCP performs a related tree-based update and raises
deprivation when an anticipated observation child is absent. History, tree and
belief updates must be coordinated, with no double update or invented recovery
posterior. \citep{exec23_pomdppy_sources}

The weighted representation needs its own identity fixture. Its probability
query averages weights among repeated equal values before normalization,
whereas its sampling method weights every entry. For entries $(D,1),(D,1),(H,1)$,
the query gives probability $1/2$ to $D$, while entry-weighted sampling gives
$2/3$. This is a documented average-weight convention in one path and a
different sampling construction in the other; an adapter must not silently
treat them as a single empirical measure. Ordinary unweighted Particles
overrides the histogram and sampling methods and gives frequency $2/3$ in
this example. The defect must therefore not be attributed indiscriminately to
all particle classes. \citep{exec23_pomdppy_sources,exec23_pomdppy_reference}

\subsection{Planning budgets and reward clocks need native qualification}
\label{exec23:pomdppy-planning}
POUCT samples belief states, explores action-observation branches, and returns
the action with the highest current tree value. A positive simulation count
takes precedence over the time budget in the inspected stopping rule; when
both defaults are negative, a one-second planning duration is selected.
Elapsed-time and completed-simulation fields are useful observations, not
accuracy certificates. The stop test runs between simulations. It cannot
interrupt a single nonterminating model or rollout call. The adapter therefore
needs an independently enforced execution deadline and a durable refusal result.
Random sources, model delegates, action ordering, initial values and planning
history must be recorded for replay. \citep{exec23_pomdppy_sources}

A concrete progress edge appears with options that consume no primitive steps.
The model sampler returns duration zero when an option is not initiable.
The tree simulation branch explicitly handles zero duration, but the selected
rollout loop only adds duration to depth and repeats while depth is below its
limit. Repeatedly selecting such an option can leave depth unchanged forever.
This is a static control-flow witness, not an executed hang. Similarly, the
tree recursion stops at depth greater than the limit while rollout uses depth
strictly less than the limit. Horizon-zero, horizon-one, terminal and option
fixtures must establish the actual reward count rather than infer it from a
parameter name. \citep{exec23_pomdppy_sources,exec23_pomdppy_reference}

Option rewards introduce a second clock. The general sampler accepts an
internal discount argument defaulting to one; the selected POUCT calls omit
that argument, then discount the continuation by $\gamma^{\text{duration}}$.
For a two-step option with rewards two and eight dollars, continuation value
twenty and $\gamma=1/2$, the resulting expression is $2+8+(1/2)^2 20=15$.
Applying the primitive-step discount throughout gives
$2+(1/2)8+(1/2)^2 20=11$. Either a macro-action reward convention or a
primitive-step convention can be declared, but they are different targets.
The adapter must bind the chosen convention and test model delegates, rather
than silently adjusting rewards after planning.
\citep{exec23_pomdppy_sources,exec23_pomdppy_reference}

The source black-box interface documents a three-component sample, while the
general sampler's contract and selected planner unpack four components,
including duration. That boundary needs an explicit adapter and conformance
test. The reward model permits stochastic sampling; a call to its sample method
is not automatically the expected reward needed by an exact dynamic program.
The small-state value routine explicitly describes deterministic rewards, and
its qualification must preserve that restriction or supply justified reward
expectations. \citep{exec23_pomdppy_sources}

\subsection{Exact references must be checked against each other}
\label{exec23:pomdppy-decision}
The policy-tree value-iteration source warns of unpruned tree growth and is
restricted to enumerable actions, states and observations. Its recurrence uses
$\gamma^{\text{depth}}$ when multiplying a child value. At three stages with a
single state/action/observation, deterministic reward one and $\gamma=1/2$, that
expression yields $1+\gamma(1+\gamma^2)=13/8$. The ordinary one-step Bellman
recurrence yields $1+\gamma+\gamma^2=7/4$. The separate Python value routine
multiplies each next-horizon expectation by one factor of gamma and provides
a useful comparison target under its declared finite deterministic regime.
Neither routine has been executed here. Source-to-oracle tests must resolve
the recurrence and horizon semantics before either is labelled an exact
product backend. \citep{exec23_pomdppy_sources,exec23_pomdppy_reference}

The proposal disposition is \emph{reference}. Model/agent/planner separation
and the explicit supplied-model computations are valuable design examples.
An isolated original Python/Cython worker is a candidate after the named belief,
clock, horizon, timeout and protocol defects are reviewed and native fixtures
pass. Full adoption would include substantially more model and planner behavior
than this profile covers. Reimplementing the planner family in R, Java or C++
would also duplicate stochastic-state, belief and maintenance obligations with
no measured benefit yet demonstrated. Independent finite-state oracles should
remain independent, not be relabelled ports of the complete library.

The pinned artifact contains MIT license text and names its author. Its build
requires setuptools, wheel and Cython at least 3.0.8, and selected runtime

locked compiler/ABI/runtime or transitive rights clearance. An executable worker
must bind those identities, its imported native binaries and model code. The
scientific owner must justify state, observation and intervention meaning; the
maintainer must resolve actual numerical and lifecycle contracts; the operator
must measure search, conversion, memory and recovery cost.
\citep{exec23_pomdppy_sources}

A proposed library/CLI/MCP request should bind model revision, initial belief,
state/action/observation vocabularies, decision history, reward and option clocks,
horizon, random seeds and both simulation and wall-time limits. The response

deprivation or timeout, and any separately justified uncertainty statement.
An LLM can help articulate candidate states and diagrams, but a fluent
description cannot authenticate the latent observation law. Public qualification

bank identification, general POMDP uncertainty and institutional adoption open.

\section{Choosing a Python policy component by the question it can answer}
\label{sec:exec24-policies-python}

A bank comparing Python policy tools must first decide whether it is evaluating
a single offer, a sequence of servicing decisions, a newly learned rule, or a
plan conditional on a supplied hidden-state model. These questions need different
information and different validation. The preceding original-source profiles
provide four contrastive choices: Open Bandit Pipeline (OBP), SCOPE-RL, d3rlpy
and POMDP-Py. Their common Python interface does not make their policy-value
outputs interchangeable. This synthesis uses the exact previously inspected
revisions and their original source records; it adds no assertion of a newer
release or a native comparison.~\citep{exec23_obp_sources,exec23_scope_rl_sources,
exec15_d3rlpy_package,exec23_pomdppy_sources}

\subsection{Four questions, four input contracts}

For a one-time offer with pre-action context $X$, action $A$ and subsequent net
reward $R$, the contextual target is
\[
 V(\pi)=E_X\sum_a\pi(a\mid X)q(X,a).
\]
OBP's inspected round-level estimators are a candidate for this contract when
the logging probabilities, action and position identities, and reward mechanism
are justified. A repeated customer table does not become a one-time randomized
offer study by deleting customer and time columns. Earlier offers may change
eligibility, information and subsequent rewards, which changes the target.
OBP's selected replay path also requires exact-one matches with the evaluation
policy and returns its initialized zero vector when no matches exist. A wrapper
must distinguish absence of replay evidence from a genuine zero value.
\citep{exec23_obp_sources}

For sequential servicing, use histories $H_t$ available before action $A_t$,
actual logging probabilities $b_t$, and a declared horizon and discount:
\[
 J(\pi)=E_\pi\sum_{t=0}^{T-1}\gamma^tR_t,
 \qquad W_t=\prod_{s=0}^{t}\frac{\pi_s(A_s\mid H_s)}{b_s(A_s\mid H_s)}.
\]
SCOPE-RL's inspected trajectory and per-decision scores expose this distinction
through products of observed-action ratios and episode-level sums. Its equal-length
reshape makes episode identity and chronology an upstream obligation. A probability
row that sums to one cannot verify that the actual bank used that logger, that
an action was supported, or that the observed history excludes future information.
The native path also needs explicit finite positive denominators and a supported
discount domain. These are source-based admission requirements, not observed
runtime failures.~\citep{exec23_scope_rl_sources}

d3rlpy supplies learning and fitted-Q evaluation interfaces, allowing a proposed
policy to be trained and then scored under a declared state representation.
Its inspected FQE update takes the next action from a best-action call. A bank
deploying a randomized rule must therefore establish that the evaluator targets
that rule, rather than silently substituting its greedy action. In the earlier
exact example, rewards USD 2 and USD 10 with action-one probability $3/4$ give
value USD 8; always choosing action one gives USD 10. The two-dollar difference
is a target difference even before approximation or sampling error.
\citep{exec15_d3rlpy_value,exec15_d3rlpy_exact}

POMDP-Py occupies a different role. Its belief update consumes a transition law,
observation law and prior belief; its planner searches within that supplied
model. It can support an architectural or numerical comparison when those laws
are specified, but cannot by itself identify them from partially observed logs.
The inspected histogram update normalizes only when its total mass is positive.
An impossible observation must be exposed as such, rather than relabeling a
zero-mass output as a valid posterior. Belief, model and planner errors require
different diagnostics.~\citep{exec23_pomdppy_sources}

This gives a practical selection rule. Use a contextual estimator for a justified
single-decision target; use sequential scores for a supported logged trajectory
target; consider a learner and its matching evaluator for a frozen learned policy;
and use a hidden-state planner for a justified supplied-model planning target.
When the substantive assumptions fail, switching packages is not a repair. The
request should instead return an identified set, a sensitivity result, a need for
additional information, or a refusal with its reason.

\subsection{Evaluation of a learned rule differs from learning its value}

Let $D_{\rm train}$ be the data used to choose $\widehat\pi$, and let
$D_{\rm eval}$ be an evaluation sample under a justified logging and sampling law.
Conditional evaluation asks for $J(\widehat\pi)$ given the trained rule. Assessment
of the learning algorithm averages over possible training samples. The value
$\sup_{\pi\in\Pi}J(\pi)$ of a policy class, or an unrestricted optimum, is a third
target. Neither a large fitted value nor a winner among estimated values equates
these objects. A comparison must freeze which target it reports, including the
policy's randomness, constraints, postprocessing and version.

This matters when combining the libraries. SCOPE-RL's selected input machinery
delegates fitted-Q work and caches models by policy name. The standalone d3rlpy
revision reviewed here is not automatically the exact delegate imported by that
SCOPE-RL environment. Matching a package name is insufficient: the dependency
version, artifact and selected calling path need their own binding. The policy
name should also not be the sole identity of a retrained rule. A proposed value
artifact should bind policy bytes, preprocessing, feature order, fitting data,
hyperparameters, stochastic deployment rule, evaluator and target population.
\citep{exec23_scope_rl_sources,exec15_d3rlpy_contract}

Uncertainty needs the same precision. The selected OBP and SCOPE-RL interval
paths resample already calculated scores. They do not thereby repeat all nuisance
fitting, normalization and policy selection. Conditioning on fitted functions can
be valid in a justified design, but must be the actual scientific claim. In the
earlier exact self-normalization example, fixed-score bootstrap means are
$(0,3,3,6)$ while recalculated weighted ratios are $(0,3,3,4)$. These define
different resampling distributions. Neither list alone establishes coverage.
The source-specific distinctions among one-sided and symmetric bounds also
prevent copying a criticism or guarantee between packages merely because the
helpers share a statistical name.~\citep{exec23_obp_sources,
exec23_scope_rl_sources,exec23_scope_rl_reference}

For banking data, customer clustering and shared calendar shocks additionally
govern valid splits and uncertainty. Shuffled rows can place the same customer's
history in training and evaluation, or mix earlier and later information. A
target-specific comparison should preserve units and clocks, define whether
training is external or refitted, and justify its dependence assumptions. The
reviewed software is useful for implementing selected calculations, not for
manufacturing these missing premises.

\subsection{A shared data adapter must preserve money and endings}

A single adapter that flattens histories and passes arrays to each package is
insufficient. SCOPE-RL's inspected done mask includes the current transition,
whereas a dataset may attach the terminal reward to that same transition. The
earlier $(2,8)$ reward example then changes retained value from USD 10 to USD 2.
d3rlpy distinguishes termination, truncation and an unclosed tail, with different
transition counts. POMDP options can consume multiple primitive time steps and
need a consistent convention for internal rewards and continuation discounts.
These are distinct contracts to test, not evidence that one package is globally
better.~\citep{exec23_scope_rl_sources,exec23_scope_rl_reference,
exec15_d3rlpy_episode,exec23_pomdppy_sources}

Money also survives only if its transformation is preserved. Under an affine
reward transform $r'=ar+b$, a cumulative value obeys
\[
 V'^\pi=aV^\pi+bE^\pi\sum_{t=0}^{T-1}\gamma^t.
\]
A one-step inverse is generally insufficient, particularly when the policy
changes the horizon. The previously derived two-period example converts a
transformed value $3.7$ back to USD 28 with the correct discounted shift, but
only USD 23.50 with a one-step inverse. Clipping can destroy invertibility
altogether. Preserve original cash flows and declare the objective used for
learning separately from the monetary objective used for evaluation.
\citep{exec15_d3rlpy_value,exec15_d3rlpy_exact}

The common CLI/MCP request can therefore bind the population, history and action
schemas, assignment mechanism, policy identity, observation and reward clocks,
ending conventions, monetary transformation and scientific target. Each worker
then applies a package-specific conversion with a reversible provenance record
where reversibility is possible. Its result should include accepted units,
excluded and unresolved tails, failures and refusals, support diagnostics,
uncertainty scope and actual computational cost. A returned scalar cannot
substitute for this contract.

\subsection{Reuse choices and the remaining search}

The four prior decisions favor source-qualified references and conditional
original workers, not unconditional adoption. The detailed SCOPE-RL review
in Section~\ref{exec23:scope-rl-uncertainty} identifies interval expressions
and endpoint conventions that require explicit qualification; its selected
lower-bound selector also requires on-policy returns that an ordinary
logged-only bank request cannot supply. These restrictions survive this
comparison. OBP's one-sided bound has a different contract, and its replay
and tuning limitations require their own checks. The POMDP-Py review in
Section~\ref{exec23:pomdppy-decision} likewise withholds an exact-backend claim
until the competing horizon recurrences and the belief and clock conversions
are resolved. A common wrapper must preserve these different refusal reasons. OBP and SCOPE-RL declare Apache
2.0 licenses in the inspected roots; d3rlpy and POMDP-Py have inspected MIT
declarations. Full dependency, data, compiler and distribution obligations
remain specific to the chosen artifacts. POMDP-Py's Cython components require
native-binary and ABI custody; Python packaging alone does not remove that duty.
The existing conversion contracts explain why a wholesale cross-language port
would duplicate scientific, numerical and maintenance responsibilities without
an established benefit. Small independent oracles remain valuable because they
can expose semantic disagreement without inheriting the same implementation.
\citep{exec23_obp_sources,exec23_scope_rl_sources,exec15_d3rlpy_package,
exec15_d3rlpy_contract,exec23_pomdppy_sources}

The next inexpensive comparison should use finite generated laws with known
policy values and public logged tasks whose provenance and rights are inspected.
It should distinguish genuine propensities from fitted or invented ones, supported
from unsupported actions, greedy from stochastic deployment, pre-terminal from
post-terminal reward flags, and fixed-policy from selected-policy uncertainty.
Retain zero-match replay, impossible observations, nonfinite inputs, timeouts
and unresolved tails in the request denominator. Measure conversion, fitting,
search, evaluation, repair and review costs per scientifically accepted artifact,
with correct refusals separate. No such native comparison is claimed here.

Coverage is still incomplete. The inherited cutoff-filtered bibliographic query
returned ten records from 2,527 reported matches, and is not an exhaustive software
or alias census. Its methodological leads need genuine originals before their
technical results enter this proposal. Broader continuous-action, distributional,
slate and multiple-logger families, complete learning delegates, and alternative
implementations remain explicit follow-up. The justified contribution of this
comparison is a coherent selection and qualification route across four inspected
families. It does not close Python policy coverage, unrestricted hidden-state
identification, calibrated optimal-policy inference or bank adoption.
\citep{exec24_policiespython_comparison}

\section{Java policy systems: planning, fitted control and the missing evaluation contract}
\label{sec:exec24-policies-java}
A bank comparing Java policy tools must first decide whether its question is about a supplied model, a policy learned from experience, or the value of an intervention in the population represented by a logging process. The same customer-servicing action can occur in all three problems, but the evidence supporting its value changes. Consider a loan account for which the bank can wait, offer a restructuring or obtain additional information. The observed balance is not automatically a Markov state: unrecorded affordability, previous contact, calendar shocks and the timing of a consent response may matter. A simulator can accept a proposed state and action without establishing that these are the variables on which the bank's historical assignment was conditionally unconfounded. This distinction governs the following comparison of BURLAP, Chen's Java reinforcement-learning library and an explicitly historical RL4J artifact. It also explains why an off-policy learning label is insufficient for causal off-policy evaluation.~\citep{exec24_policyjava_burlap,exec24_policyjava_chen,exec24_policyjava_rl4j,exec24_policyjava_comparison}

\subsection{What a small Bellman residual actually establishes}
Write a supplied finite discounted model as $(\mathcal S,\mathcal A,P,r,\gamma)$, with $0\leq\gamma<1$. For a fixed randomized policy $\pi$, its Bellman operator is
\[
 (T^\pi v)(s)=\sum_a\pi(a\mid s)\left\{r(s,a)+\gamma\sum_{s'}P(s'\mid s,a)v(s')\right\}.
\]
BURLAP's selected evaluator discovers reachable states using the supplied full model and updates their values using the fixed policy's action probabilities. It stops after a configured iteration limit or a sufficiently small observed change. Its reachability cache depends on state identity and prior expansion. A changed transition model or meaning of state identifiers therefore requires deliberate reset and re-enumeration. A changing customer population cannot silently inherit an old graph of reachable states.~\citep{exec24_policyjava_burlap}

Under the declared discounted finite model, the contraction inequality yields
\[
 \|v-V^\pi\|_\infty\leq
 \frac{\|T^\pi v-v\|_\infty}{1-\gamma}.
\]
Indeed, add and subtract $T^\pi v$ in $v-T^\pi V^\pi$ and move the term $\gamma\|v-V^\pi\|_\infty$ to the left. This is a project derivation about a residual computed over the required state space. The implementation's in-place iteration change is not automatically that full residual, and reaching an iteration cap does not prove either quantity small. More fundamentally, the bound concerns the supplied $P,r$. In an authored one-state example, $r=1$ USD and $\gamma=0.9$ give $v=10$ USD with zero nominal residual. If the true reward is 2 USD, the true value is 20 USD. Exact solution of the declared equations leaves a 10 USD model error.~\citep{exec24_policyjava_comparison}

State identity is part of this contract. The selected hashing factory defaults to object-identifier independence and documents identifier-dependent treatment for relational domains. Two records with equal displayed balances need not be equivalent when their links to a household, guarantor or intervention history change feasible actions or transitions. The adapter must justify the equivalence relation it uses; an ordinary hash collision and a deliberate semantic aggregation are different issues. This review does not assert that a native collision was observed.~\citep{exec24_policyjava_burlap}

\subsection{Least-squares policy iteration and the conditions behind sample reuse}
The genuine 2003 Lagoudakis--Parr article supplies the mathematical background. For a linear action-value approximation $Q_w(s,a)=\phi(s,a)^\top w$, a fixed target policy and transition samples $(s_i,a_i,r_i,s'_i)$, LSTDQ forms
\[
 A_D=\sum_i\phi_i(\phi_i-\gamma\phi'_i)^\top,
 \qquad b_D=\sum_i\phi_i r_i,
 \qquad A_Dw=b_D,
\]
where $\phi'_i=\phi(s'_i,\pi(s'_i))$. The paper explains why the same transitions can be reused across target policies: the policy changes the next-state feature term. It also explicitly describes the sampling distribution's role in the projected fixed point. State-action samples must represent the intended projection weighting, and next states must come from the appropriate conditional transition law. Uneven coverage and unvisited important states remain problems; the phrase arbitrary sample collection does not remove them. The finite MDP and linear approximation assumptions must accompany this result.~\citep{exec24_policyjava_lspi}

The article's approximate-policy-iteration guarantee is conditional on a uniform bound on value-function approximation error over iterations. It does not make a small empirical weight change into an estimated uniform error bound or a bank confidence interval. Its discussion allows convergence or oscillation within an error-controlled region and identifies basis choice and sample distribution as central. Its chain examples illustrate selected behavior; they do not certify the current bank state abstraction. The original code-distribution footnote refers to noncommercial use of that distribution, which must not be confused with the separately inspected BURLAP license. No original experiment or original code distribution was executed here.~\citep{exec24_policyjava_lspi}

BURLAP's inspected LSTDQ routine builds next features using a greedy policy, initializes an inverse matrix to a scaled identity, then applies a rank-one inverse update. The default inverse scale is 100; interpreting it as the same value of a ridge coefficient reverses the matrix relationship. For $B=A^{-1}$, the selected update denominator is
\[
 d=1+(\phi-\gamma\phi')^\top B\phi.
\]
The inspected loop divides by $d$ without a denominator guard in that path. In an exact scalar witness, $B=100$, $\phi=1$, $\gamma=1/2$ and $\phi'=101/50$ give $d=0$. The corresponding updated regularized scalar matrix is also zero. This is a mathematical input witness for a necessary diagnostic, not a reported native failure or a claim that every input fails. A wrapper must detect singularity and conditioning before admitting a value; an SVD fallback would require an explicit changed-estimator contract.~\citep{exec24_policyjava_burlap,exec24_policyjava_comparison}

The selected SARS tuple carries state, action, reward and next state, without a separate terminal flag in that representation. Its LSTDQ loop still constructs next features. The class documentation itself warns about terminal-state handling and proposes offsetting continuation through rewards. That workaround is not automatically equivalent to a bank's absorbing default or contractual settlement. A correct episodic adapter must therefore bind a terminal feature or equivalent absorbing-state convention; it must not infer it from an account disappearing from a file. Greedy ties also matter: the inspected policy randomizes uniformly over exact maximizing ties, including when constructing next-state actions. A deterministic first-action port changes that policy. With equal estimated Q values but true action values 10 and 0 USD, uniform tie-breaking has value 5 USD while always choosing the first has value 10 USD. These authored values show target sensitivity, not the relative quality of either implementation.~\citep{exec24_policyjava_burlap,exec24_policyjava_comparison}

\subsection{Tabular updates, comments and missing terminal information}
Chen's Q-learning update uses the maximum next-state Q value, while its Sarsa update uses the supplied next action. An inherited comment in the latter mentions a maximum, but the executable expression reads the specified action's value. The distinction is substantive. With old Q equal to 4 USD, reward 2 USD, learning rate 0.1, discount 0.7, maximum next Q equal to 8 USD and selected next-action Q equal to 1 USD, the updates are 4.36 and 3.87 USD respectively. Both inspected signatures lack a terminal argument. If the transition is terminal, the appropriate zero-continuation update in this example is 3.80 USD. An absorbing state with correctly zeroed values can implement that convention; retaining the model's generic nonzero initialization cannot be assumed to do so.~\citep{exec24_policyjava_chen,exec24_policyjava_comparison}

The actor-update path has another boundary: its literal temporal-difference expression is $r+V(s')-V(s)$, although the constructor stores a discount parameter. In the same reward/value example, the literal error is 6 USD; inserting discount 0.7 would give 3.60 USD. The reviewed path may suit a different convention, but calling it a discounted implementation without an explicit translation would be unjustified. The method accepts an external value function; it does not independently establish the critic's identification or accuracy. The selected epsilon-greedy strategy also copies its random-generator reference. A clone is therefore not evidence of independent random streams. Its returned action/value pair does not by itself preserve the historically realized assignment probability.~\citep{exec24_policyjava_chen,exec24_policyjava_comparison}

These findings favor using the compact routines as transparent teaching and arithmetic references until terminal handling, discount convention, action constraints, random streams and data lineage are qualified. A direct port is not automatically easier: reproducing a comment instead of the expression changes Sarsa; silently adding a discount changes the actor path. Any deliberate repair must be named and compared against an independent oracle.

\subsection{Historical deep learning: targets, clamping and experience identity}
The historical RL4J DQN path separates the online and target networks. For nonterminal transitions, StandardDQN uses the largest next target-network value; DoubleDQN selects an action using the online network and evaluates that action using the target network. Both selected methods use the immediate reward alone for a terminal transition before an optional label clamp. With reward 2 USD, discount 0.9, online next values $(9,8)$ and target next values $(1,10)$, the two targets are 11 and 2.90 USD. These are different learning labels, not two interchangeable off-policy value estimates.~\citep{exec24_policyjava_rl4j,exec24_policyjava_comparison}

The common computation can clamp a label around the current action value. If that value is 4 USD and the clamp width is 1 USD, the two labels become 5 and 3 USD; even the terminal reward label 2 becomes 3 USD. This can be an intentional training device, but a clamped training label must not be returned as an unclamped monetary estimand. The inspected source defaults the clamp to disabled through a NaN setting. The adapter must bind the actual configuration rather than infer it from a default in one class.~\citep{exec24_policyjava_rl4j,exec24_policyjava_comparison}

The replay handler links a pending transition to its next observation before storing it. Episode-end processing supplies the final observation; reset drops a pending transition. The replay buffer samples distinct stored indices within a batch, caps batch size by current storage size and duplicates selected transitions. None of these operations converts dependent customer histories into independent evaluation observations or reconstructs missing assignment probabilities. The target computation builds next-observation features before terminal target suppression, so a zero-continuation target does not justify omitting the final observation object. The selected feature builder arranges recurrent observations using the order it receives; a random replay batch must not be relabelled a customer's chronology. These are interface constraints for a future conformance test, not measured native outcomes.~\citep{exec24_policyjava_rl4j}

\subsection{Information acquisition is not fully observed continuation}
BURLAP's selected QMDP approximation averages fully observed action values over a belief and assumes the future information advantage of the fully observed problem. Its available actions are obtained from one sampled underlying state, making common action feasibility a condition to inspect. A bank may instead be choosing whether to learn something. Consider a hidden binary affordability state with equal probabilities. Today it can pay 1 USD to reveal that state or wait for free. Tomorrow it chooses the matching treatment and earns 10 USD if correct, zero otherwise; $\gamma=0.9$. The true values are 8 USD for revealing and 4.50 USD for waiting. A fully observed continuation credits waiting with 9 USD, so this approximation chooses waiting and loses 3.50 USD relative to revealing in the authored finite law.~\citep{exec24_policyjava_burlap,exec24_policyjava_comparison}

The repair is not to attach a confidence label to that approximation. A full belief-state model must represent what each action reveals, with justified observation and transition models and a feasible belief-dependent action set. Exact enumeration of a small supplied model can test that translation; larger models require declared approximation and numerical error. Whether the bank's latent model is identified from logged data is a separate scientific question. No surveyed planner supplies a universal answer to unrestricted hidden-state identification.

\section{C++ policy systems: logged decisions, supplied models and learned control}
\label{sec:exec24-policy-cxx}
A banking team choosing a C++ policy engine must first decide which quantity the engine is expected to compute. Estimating the cost of a fixed servicing policy from logged randomized actions is different from evaluating that policy inside a supplied transition model. Both differ from training a controller to maximize rewards in a simulator. Vowpal Wabbit, AI-Toolbox and mlpack provide concrete implementations relevant to these roles, but their shared policy vocabulary does not make their outputs interchangeable. The following comparison uses cutoff-pinned source, three genuine method or software papers and exact authored witnesses. No downloaded code, native build or bank experiment is run.~\citep{exec24_policycxx_vw,exec24_policycxx_aitoolbox,exec24_policycxx_mlpack,exec24_policycxx_comparison}

\subsection{A bounded ecosystem comparison with explicit identities}
The selected Vowpal Wabbit revision is dated 28 September 2026 and its version file declares 9.11.9. The selected AI-Toolbox revision is dated 18 March 2025. The selected mlpack revision is dated 6 October 2026; its version header declares 4.8.1 while its README names 4.8.0 as the stable download. These are inspected revision identities, not evidence that a particular installed binary equals the source or that every package is a released distribution.~\citep{exec24_policycxx_vw,exec24_policycxx_aitoolbox,exec24_policycxx_mlpack}

The repository search is bounded and cannot establish ecosystem completeness. One literal off-policy-evaluation query returns no matches, whereas a broader reinforcement-learning query returns many candidates, including RLLib, OpenSpiel, rl-tools, smarties and other specialized systems. A search miss is not absence: names, language tags, bindings and repository descriptions can obscure relevant methods. Those candidates, registries, maintained forks and additional planning families remain explicit survey work. The present comparison supplies three substantive profiles without calling the C++ coverage cell complete.~\citep{exec24_policycxx_comparison}

Direct license texts also differ: the selected Vowpal Wabbit and mlpack sources carry BSD-style terms, while AI-Toolbox carries GPL version 3. These declarations need to be bound to the intended distribution and dependencies before a reuse decision. A process boundary is a useful engineering choice but is not, by itself, a conclusion about licensing obligations. \subsection{Vowpal Wabbit: action-dependent feedback and the logging contract}
The inspected action-dependent-feature reduction includes inverse-propensity, direct-regression and doubly robust cost transformations. It exposes a probability-clipping option with zero as its default. The inverse-propensity delegate divides an observed cost by the clipped reported probability; a separate safety helper warns and substitutes 0.001 for nonpositive inputs. The label parser also has explicit handling for invalid and test probabilities. These branches are not a proof that every malformed record reaches the safety helper. They show why a scientific adapter must validate logging probabilities before it chooses a learning or evaluation path.~\citep{exec24_policycxx_vw}

Let $h(a\mid x)$ be the actual logging probability, $\pi(a\mid x)$ a fixed target policy and $C$ the observed cost. Under the required observation and causal assumptions, a single-step target value can be represented by
\[
 V_C(\pi)=E_h\!\left[\frac{\pi(A\mid X)}{h(A\mid X)}C\right].
\]
The logging probability is part of the experiment. Replacing a missing or zero number with a small positive number cannot establish support or truthful randomization. If an action is never observed, two worlds that agree on all logged outcomes can assign that action costs of zero and 100. No arithmetic convention selects the correct world.~\citep{exec24_policycxx_cs2021,exec24_policycxx_anytime2024,exec24_policycxx_comparison}

An authored two-action example makes clipping concrete. Let $h=(0.8,0.2)$, $\pi=(0.2,0.8)$ and deterministic costs $(20,100)$ USD. The target cost is 84 USD. Ordinary inverse weighting has expectation 84. Replacing each logging denominator by $\max(h,0.4)$ gives 44 USD. With a regression prediction $(10,80)$, the ordinary doubly robust expression
\[
 \sum_a\pi(a)q(a)+\frac{\pi(A)}{h(A)}\{C-q(A)\}
\]
also has expectation 84, whereas clipping the correction denominator gives 76. The examples quantify a target change under stipulated inputs; they are not measured behavior of a native worker or a claim that clipping can never be justified. A justified bias bound or a different target must accompany the choice.~\citep{exec24_policycxx_comparison}

The inspected code paths also separate cost-sensitive training labels from reporting estimates. A declaration that a training option is enabled does not demonstrate that every reporting or evaluation function applies the same transformation. A proposed CLI response should identify the estimator, cost sign, clipping rule, regression fit, target-policy bytes and logging probabilities actually used. It must retain rejected records and reasons instead of silently treating them as valid observations.~\citep{exec24_policycxx_vw,exec24_policycxx_comparison}

\subsection{Time-uniform inference has scientific premises}
The original off-policy confidence-sequence paper provides a useful baseline: an identified contextual-bandit value, a target policy supported by the logging policy, bounded rewards and weights in its central construction, and predictable bets produce a nonnegative martingale. Inverting the corresponding wealth processes gives confidence sets valid uniformly over time. The proof permits optional stopping under its premises; it does not authorize changing the target policy after looking at the same data without further justification.~\citep{exec24_policycxx_cs2021}

The inspected 2024 author version of the later anytime-valid paper expands the framework to predictable adaptive logging, settings without a known uniform upper bound on importance weights, and separately defined time-varying targets. Individual ratios must still be finite. Its fixed-value theorem requires a constant conditional target mean and bounded rewards; the time-varying results concern a time average, not automatically the latest value. A two-period authored example with target means 0.2 and 0.8 has average 0.5 and latest value 0.8. Calling an interval for one quantity an interval for the other would be a reporting error.~\citep{exec24_policycxx_anytime2024,exec24_policycxx_comparison}

The paper's contextual process permits exogenous temporal dependence but distinguishes it from actions that change later contexts or rewards. Its potential-outcomes appendix states consistency, exchangeability and positivity requirements for a causal interpretation. A servicing action can alter later balances, customer contact and eligibility. In that setting, a sequence of immediate bandit evaluations does not by itself identify the value of replacing the entire longitudinal policy. A sequential model, appropriate histories and a separate identification argument are required.~\citep{exec24_policycxx_anytime2024,exec24_policycxx_comparison}

These papers support a mathematical route, not certification of the selected C++ implementation. The source contains distinct confidence-sequence and robustness classes, numerical root searches and reward-range handling. One inspected update clips rewards when adjustment is disabled; another expects rewards in $[0,1]$. To use monetary losses, define and justify any normalization and transform the reported interval back to dollars. Independently test numerical boundaries, alpha allocation, reward limits, persisted state, dropped observations and the exact theorem-to-code mapping. An asymptotic empirical-likelihood component and an anytime-valid construction must not be conflated merely because both produce intervals.~\citep{exec24_policycxx_vw,exec24_policycxx_cs2021,exec24_policycxx_anytime2024,exec24_policycxx_comparison}

\subsection{AI-Toolbox: evaluation conditional on a supplied world}
The AI-Toolbox paper distinguishes planning with a known model from learning through interactions. It describes MDP, POMDP and factored components and Python bindings. Those are historical architectural claims. The paper describes C++17, while the inspected later CMake file requests C++20 and declares Boost, Eigen and LpSolve requirements. The change illustrates why a paper's environment cannot stand in for the selected source contract.~\citep{exec24_policycxx_aitoolbox_paper,exec24_policycxx_aitoolbox}

The inspected policy-evaluation routine repeatedly computes action values under the supplied transition/reward model and averages them using the supplied policy. It stops at the configured horizon or tolerance. With tolerance disabled it returns zero in the variation field, as a reporting convention; that zero is not a measured infinite-horizon error. In a one-state authored model with reward 10, discount 0.9 and zero initial value, one iteration returns value 10 while the infinite-horizon value is 100. The error is 90 and the Bellman residual at the returned value is nine. In this contraction example the residual bound $9/(1-0.9)=90$ is exact.~\citep{exec24_policycxx_aitoolbox,exec24_policycxx_comparison}

The statistical uncertainty of an estimated model is separate from numerical iteration error. Even a perfectly solved supplied model can be the wrong banking world. The adapter should therefore bind transition, reward and observation identities and label values conditional on that model. For a fixed policy choosing next actions with probabilities $(1/4,3/4)$ and continuation values $(20,4)$, the expected continuation is eight; maximization gives 20 and changes the target.~\citep{exec24_policycxx_comparison}

ImportanceSamplingEvaluation uses target-to-behavior probability ratios to discount traces. The surrounding update has no explicit terminal flag, so absorbing-state conventions, values and trace clearing must be established by the caller. With reward 10, discount 0.9 and an erroneously retained next value 50 at termination, the update target is 55 rather than ten. The control variant also deserves a targeted check: its inspected next-state maximization passes the maximizing action index into the trace-probability expression evaluated at the current state. When the maximizing action differs between those states, the literal expression need not equal a current-state epsilon-greedy ratio.~\citep{exec24_policycxx_aitoolbox,exec24_policycxx_comparison}

For an exact authored witness, current-state action values are $(10,0)$ and next-state values are $(0,10)$, with epsilon 0.1 and behavior probability 0.5 for current action zero. Using the next-state maximizing index in that expression gives ratio 0.1; using the current-state maximizing index gives 1.9. This is a static conformance question for the selected branch. We have not executed the library or established the consequences for an entire learning run. Preserve the observation and test it against the declared algorithm before admitting that branch.~\citep{exec24_policycxx_aitoolbox,exec24_policycxx_comparison}

Partial-observation planning needs an equally explicit boundary. QMDP constructs belief-space action planes from a fully observable MDP solution; the observation-space size participates in the output representation, not a newly learned observation model. POMCP instead uses a supplied generative model and sampled beliefs, with the inspected implementation documenting particle depletion as a concern. Neither solves the inverse problem of identifying a hidden banking state from an arbitrary observational history. Conditional original-worker reuse is preferable to an unreviewed whole-library port when model semantics and rights are accepted.~\citep{exec24_policycxx_aitoolbox,exec24_policycxx_comparison}

\subsection{mlpack: learned control, replay and distributional targets}
The inspected mlpack Q-learning code distinguishes online and target networks, supports a double-Q action selection branch, and suppresses continuation on a stored terminal indicator. Its ordinary target discounts by $\gamma^{n}$ using the replay object's step count. The returned episode score, however, sums the observed rewards without discounting. These outputs serve different purposes; the score is not automatically the discounted value being trained.~\citep{exec24_policycxx_mlpack}

Random replay draws transition indices from a stored buffer; priority replay uses sampling weights tied to priority and a training correction. Neither set of weights is the action propensity needed for causal off-policy evaluation. The inspected transition schema stores states, action, reward, next state and termination, without a logging-probability field. A product requiring causal evaluation must retain that information elsewhere and prove the join and sampling semantics. Shuffling dependent transitions does not create independent banking customers or remove policy-selection bias.~\citep{exec24_policycxx_mlpack,exec24_policycxx_comparison}

Two source-level boundary cases need explicit conformance tests. First, the categorical target branch uses a single discount factor while the ordinary branch uses the replay step count. With a three-step accumulated reward of three, discount 0.9 and continuation ten, the corresponding scalar targets are 10.29 and 12. This difference requires a documented restriction or a reviewed repair when multistep replay is combined with the categorical branch. Second, the literal projection coefficients are zero when the transformed return falls exactly on a support atom, unless another step supplies the missing mass. The inspected projection loop does not show such a step. An authored unit mass at that atom therefore produces zero under those literal coefficients instead of one. These are reproducible algebraic witnesses, not an observed native benchmark failure.~\citep{exec24_policycxx_mlpack,exec24_policycxx_comparison}

The replay implementation waits for a full multistep buffer and truncates reward recursion at a stored terminal event. How the final short tail is delivered, how multiple episodes are separated, and whether sampling can occur before enough entries exist are part of the caller contract to verify. Reward support limits and projection behavior need particular care when the target is denominated in dollars: clipping a training distribution to chosen bounds is not evidence that tail losses are absent.~\citep{exec24_policycxx_mlpack,exec24_policycxx_comparison}

\section{A Julia planning interface must preserve a single decision experiment}
\label{exec23:pomdpsjl-scope}

A bank considering Julia for sequential servicing needs to decide which part
of a planning system it is buying into. POMDPs.jl supplies a common vocabulary
for a model, solver, policy, belief updater and simulator. These interfaces are
valuable because the same declared problem can be presented to different
algorithms, but the interface itself neither identifies that problem from
observations nor proves the returned policy optimal. The root package at the
selected 8 June 2026 repository revision declares version 1.0.0. Sixteen
authenticated source and documentation files support the present inspection.
The root MIT license explicitly warns that other packages in the organization
can have different licenses. POMDPTools and individual solvers therefore need
their own source, rights and numerical reviews. Section~\ref{sec:exec24-policies-other}
develops that review for selected POMDPTools evaluation and simulation delegates;
its source findings do not constitute native qualification or coverage of all
solvers. The organizational name cannot stand in for a concrete adoption decision.
\citep{exec23_pomdpsjl_sources}

The model contracts distinguish a state space, an action space, a transition
distribution, an observation distribution, reward and discount. Let
$S_t$ be the account state before decision $A_t$, $S_{t+1}$ the resulting state,
$O_{t+1}$ the information released after that decision and $R_t$ its reward.
For a declared initial belief $b$ and policy $\pi$, a finite-horizon target is
\[
 V_H^\pi(b)=E_{b,\pi}\!\left[\sum_{t=0}^{H-1}\gamma^tR_t\right].
\]
This expression defines our supplied-model target. A causal interpretation
also needs a justified intervention law for $A_t$, sufficient state and an
honest observation clock. Merely writing a transition method does not supply
those premises. Moreover, the dynamic decision network used internally to
generate variables is a computational dependency graph; it is not a graph
discovered from bank data or an identified causal equivalence class.
\citep{exec23_pomdpsjl_sources,exec23_pomdpsjl_reference}

\subsection{Joint generation is an event, not three independent API calls}
\label{exec23:pomdpsjl-generation}

POMDPs.jl permits explicit distributions as well as a joint generator returning
a named tuple with next state, observation and reward. The documented caller
uses the \texttt{@gen} interface. Its inspected implementation invokes the
joint generator once for that invocation, takes supplied fields and fills
missing fields using transition, observation and reward methods in dependency
order. A POMDP observation can depend on both the old and new state, and the
reward fallback can depend on the observation as well. An adapter that calls
the generator separately for each output can change the joint experiment even
if every output retains the correct marginal distribution.
\citep{exec23_pomdpsjl_sources}

Consider a stipulated one-step distress event $U\sim\mathrm{Bernoulli}(1/4)$.
Set $S_{t+1}=U$, release alert $O_{t+1}=U$, and return reward $-40$ in distress
or $8$ otherwise. A coherent event has expected reward $-4$, always agrees
between state and alert, and has probability $1/4$ of an alert accompanying a
loss. If a wrapper independently regenerates the state, alert and reward,
the marginals survive, but state and alert agree with probability only $5/8$
and alert with loss occurs with probability $1/16$. The difference is material
to a policy: a subsequent rescue worth $35$ in distress and $-15$ otherwise,
taken only on an alert, has expected incremental value $35/4$ under the coherent
law and $-5/8$ under the split law. These are exact authored counterexamples
to a conversion strategy, not observed failures of the Julia package.
\citep{exec23_pomdpsjl_reference}

The proposed boundary therefore transports one event identifier and one
joint transition result, with model revision, state/action identifiers,
observation release time and reward units. A random seed alone does not define
equivalence across wrappers: the requested fields and invocation order also
determine how a joint generator consumes its random stream. Reproducibility
requires the concrete random-number implementation, serialized state or seed
protocol, call schedule and worker environment. The source exposes an explicit
random-number argument and a default when omitted; it does not provide the
bank's complete replay protocol.
\citep{exec23_pomdpsjl_sources}

\subsection{Observation, reward and termination need compatible signatures}
\label{exec23:pomdpsjl-contracts}

An observation method depending only on action and next state automatically
supports the fuller old-state signature through fallback. The reverse need
not hold. Suppose two accounts both reach state zero after the same action,
but an alert reports whether the previous state was one. Then the two histories
require alert probabilities zero and one, although action and next state are
identical. A solver requesting only those latter arguments cannot represent
both laws. The documentation explicitly acknowledges that some solvers require
the narrower signature. The repair is to select a compatible solver, augment
the modeled state with a justified sufficient history, or refuse the conversion;
silently dropping the old state changes the model.
\citep{exec23_pomdpsjl_sources,exec23_pomdpsjl_reference}

Reward conversion has a similar obligation. A solver asking for
$\bar r(s,a)$ needs the appropriate conditional expectation of a transition
reward, including the observation when relevant:
\[
 \bar r(s,a)=\sum_{s',o}T(s'\mid s,a)Z(o\mid s,a,s')r(s,a,s',o)
\]
in a finite explicit model. A joint generator can instead define the joint law
directly, in which case the expectation must follow that law. The inspected
documentation requires consistency between reward signatures. For the
two-outcome example, weighting by the declared probabilities gives $-4$;
averaging the two reward values uniformly gives $-16$. Returning a convenient
number from the narrower method is not enough.
\citep{exec23_pomdpsjl_sources,exec23_pomdpsjl_reference}

Terminal value is zero after termination in the model contract. That does not
erase the reward on the transition into the terminal state. A settlement
paying $12$ on entry has value $12$ with zero subsequent continuation; a wrapper
that masks the transition reward by destination terminal status reports zero.
This parallels the episode-clock issue in other sequential packages, without
asserting that the inspected Julia simulator implements that erroneous mask.
The root default marks no state terminal. A concrete bank model and simulator
must therefore bind terminal behavior, horizon, per-step discount and any
variable-duration convention explicitly. The inspected standard generator
fields do not by themselves establish a semi-Markov discount contract.
\citep{exec23_pomdpsjl_sources,exec23_pomdpsjl_reference}

\subsection{Belief meaning and a conditional Julia worker route}
\label{exec23:pomdpsjl-decision}

The library deliberately uses \emph{belief} broadly: it can be a posterior,
particles, a partial history or another policy information state. Its
initialization contract allows lossy conversion and has a pass-through default;
the history contract permits a partial suffix, and the default current
observation reads the last history item. Thus a successful initialization call
does not certify posterior normalization, sufficiency, nonempty history or an
independent snapshot. A wrapper must identify the representation and supported
operations, copy or serialize mutable state when isolation is required, and
refuse claims that exceed the retained information. State/action/observation
objects also require stable equality and identity: the model guide warns
against mutating objects used as dictionary keys or retained in histories.
\citep{exec23_pomdpsjl_sources}

The present disposition is a reference for interface design, with a conditional
future Julia worker. Full adoption is premature because an abstract
\texttt{solve} or \texttt{simulate} declaration is not an audited solver or
an executed experiment. A blanket port to R, Python, Java or C++ is also
unjustified: it would duplicate dispatch, distribution and stochastic-event
semantics before demonstrating a benefit. An independent finite-state oracle
remains useful precisely because it checks the intended experiment separately
from the chosen implementation.
\citep{exec23_pomdpsjl_sources,exec23_pomdpsjl_reference}

A prototype can proceed once it pins Julia and all dependency artifacts,
selects and reviews one concrete solver/updater/simulator combination, and
registers conformance cases for joint outputs, asymmetric transitions,
old-state observations, reward expectation, terminal entry, history loss,
state mutation and randomness. Measure offline preparation and online action
latency separately, along with compilation, serialization, memory, recovery
and numerical error at the required accuracy. The same target, information
clock, diagnostics and refusal must survive library, CLI and MCP use.
An LLM may help draft a model or map a business question into these contracts,
but a plausible generated method cannot authenticate a latent state or its
intervention law. Native integration, scientific qualification and institutional
adoption remain open.
\citep{exec23_pomdpsjl_sources}

\section{Julia policy evaluation: a supplied model and logged experience answer different questions}
\label{sec:exec24-policies-other}

A servicing team may want to compare a fixed contact rule with today's practice,
choose a better rule, or value the best rule available with information that
will actually arrive before each action. Those questions require different
experiments. The existing POMDPs.jl review establishes a root planning interface,
not a statistical identification result. We now inspect its concrete
POMDPTools 1.1.0 evaluation and simulation delegates at the same 8 June 2026
revision. Separately, a bounded Julia search identifies Hu and Wager's
partial-history importance-weighting research code and its genuine May 2023
author original. The first route evaluates a supplied transition model; the
second learns a stationary policy value from logged trajectories under explicit
assignment and mixing restrictions. Neither route alone qualifies a learned
bank policy or an arbitrary latent-state business process.
\citep{exec23_pomdpsjl_sources,exec24_policyother_tools,exec24_policyother_ope,exec24_policyother_original}

\subsection{A linear solve is conditional on the model and the policy}
For a fixed Markov policy $\pi$, a finite-state transition matrix $P_\pi$ and
expected one-step reward vector $r_\pi$, discounted value solves
\[
 v_\pi=r_\pi+\gamma P_\pi v_\pi,
 \qquad v_\pi=(I-\gamma P_\pi)^{-1}r_\pi.
\]
A stochastic transition matrix and $0\leq\gamma<1$ supply a standard sufficient
condition for invertibility; a finite-horizon problem instead needs a finite
recursion, and an undiscounted recurrent problem requires a different
argument. The inspected \texttt{evaluate} method is an MDP method. It forms
separate policy transition and reward objects and solves the linear system.
Its matrix has current states in rows and successor states in columns;
terminal rows and their subsequent reward are zero. This is source evidence
for a concrete computation, not evidence that bank transition probabilities
are causally identified or that the model's uncertainty is calibrated.
\citep{exec24_policyother_tools}

Suppose an unsettled account receives expected reward 6 each step, remains
unsettled with probability one half and otherwise terminates, with discount
0.9. The supplied-model infinite value is $120/11$, while the two-step value
is 8.7. A settlement reward of 12 earned on entry to a terminal state remains
12; zero continuation after settlement does not remove it. These exact
examples distinguish horizon, reward timing and model semantics without
claiming a Julia execution. Transition rows, reward units, terminal flags and
the policy information set belong in the CLI/MCP request and response.
\citep{exec24_policyother_contract}

The inspected matrix and reward builders call \texttt{action(policy,state)}
separately. A deterministic state-to-action policy is straightforward. A
policy whose call samples a fresh action needs an explicit construction of
its action mixture before this calculation can be interpreted as that
randomized policy's value. Consider an action that gives zero and stays,
and another that pays 10 and exits, selected with equal probability at each
step. Its value is $100/11$. If transition and reward are assembled from
independent single action draws, the four possible scalar solves give
$0,10,0,100$, whose mean is $55/2$. This is an authored warning about an
unqualified stochastic-policy conversion, not a claim that every stochastic
policy object behaves this way. Audit the concrete dispatch or explicitly
average over the action law, then verify against an independent finite oracle.
\citep{exec24_policyother_tools,exec24_policyother_contract}

\subsection{The simulator's information and stopping rules are part of the target}
The partially observed rollout with an explicit updater acts on its initialized
belief, generates a joint next-state/observation/reward event, accumulates
reward and updates the belief. The inspected convenience overload receiving
a POMDP and an initial state instead converts to \texttt{UnderlyingMDP}.
A wrapper must therefore bind the method signature, not infer the information
set from the word POMDP in the model type. In a one-step authored example,
a fair hidden binary state and constant observation give value zero when
matching the state pays 10 and a mismatch loses 10. A policy allowed to see
the state earns 10. That difference is information leakage relative to the
partially observed target; it is not evidence of a superior deployable policy.
\citep{exec24_policyother_tools,exec24_policyother_contract}

The rollout stops at terminal state, its explicit maximum number of steps,
or a discount-weight threshold. Its defaults permit a very large horizon
and zero threshold. A threshold on $\gamma^t$ is not a dollar error bound.
If $|R_t|\leq R_{\max}$ and $0\leq\gamma<1$, truncating after $H$ steps leaves
an absolute tail bounded by
\[
 R_{\max}\frac{\gamma^H}{1-\gamma}.
\]
At $R_{\max}=10$, $\gamma=0.9$ and $H=5$, that bound is 59.049. A wrapper must
return the chosen horizon, residual bound and timeout status; finite output
is not sufficient evidence that a requested infinite-horizon precision was
met. The history recorder computes a threshold-related horizon using
logarithms, so zero/one discounts and nonpositive thresholds need explicit
input-domain tests rather than assumptions borrowed from a different method.
\citep{exec24_policyother_tools,exec24_policyother_contract}

Failure status changes interpretation. With exception capture enabled,
\texttt{HistoryRecorder} returns the accumulated prefix together with the
exception and backtrace. The inspected default batch processor reduces a
history to discounted reward, and that reward accessor sums the recorded
rewards without checking the exception field. Thus an adapter using this
composition must preserve exceptions itself. A prefix reward of 5 does not
establish full value 5; if a stipulated missing continuation is minus 100,
the complete value would be minus 95. In real failed requests that continuation
is unknown and must not be imputed. Return episode length, stopping reason,
exception, partial reward and completion flag, retain all requested episodes
in the denominator, and supply a custom batch processor. No native failure
frequency or performance claim is inferred from static composition.
\citep{exec24_policyother_tools,exec24_policyother_contract}

\subsection{Partial histories can identify a different, stationary value}
Hu and Wager study a partially observed Markov process with observed state
$X_{it}$, hidden state $H_{it}$, action $A_{it}$ and reward $Y_{it}$. Their
behavior policy $\pi_0(a\mid X_{it})$ is known and depends only on the observed
state. It cannot additionally depend on the hidden state after conditioning
on that observed information. The target policy also maps observed state to
action probabilities. Their finite-state stationary target $V_i(\pi)$ is the
mean reward for unit $i$ under the target policy's stationary law; the
population target averages over independently sampled heterogeneous units.
It is not the discounted finite-initial-belief value in the preceding subsection.
\citep{exec24_policyother_original}

For a history length $k$, their estimator is
\[
 \widehat V(\pi;k)=\frac1n\sum_{i=1}^n\frac1{T-k}
 \sum_{t=k+1}^{T}\left\{\prod_{s=0}^{k}
 \frac{\pi(A_{i,t-s}\mid X_{i,t-s})}
      {\pi_0(A_{i,t-s}\mid X_{i,t-s})}\right\}Y_{it}.
\]
The product includes $k+1$ actions, including the current action. It is not
self-normalized by the sum of the weights. The inspected simple-example
implementation uses this rolling product and averages the aligned weighted
rewards; its $k=-1$ branch returns the unweighted mean. For importance ratios
$(2,0,2,2)$ and rewards $(1,2,3,4)$, our exact outputs are 4 for $k=0$,
$16/3$ for $k=1$ and zero for $k=2$. These finite values are arithmetic
witnesses, not a statement that one window identifies the bank target.
\citep{exec24_policyother_original,exec24_policyother_ope,exec24_policyother_contract}

The paper requires a uniform contraction bound on the joint observed/hidden
state law under the policies considered, a bounded action-density ratio,
reward moment restrictions and stationary initial behavior distributions
for its main theorem. Its contraction requirement is stronger than merely
asserting asymptotic mixing. Longer histories reduce the retained-initial-law
bias but increase the weight variability. With fair binary logging and a
deterministic target, a matching window has probability $2^{-(k+1)}$, weight
$2^{k+1}$ and weight second moment $2^{k+1}$. A zero estimate from windows
with no matches does not demonstrate zero policy value. The proposal must
include support and weight diagnostics, admissible histories and an honest
refusal or inconclusive result when the data cannot support the target.
\citep{exec24_policyother_original,exec24_policyother_contract}

The paper distinguishes the average value of sampled units from population
value. Between-unit heterogeneity adds a sampling term that longer trajectories
cannot remove. Its unequal-length expression averages unit-specific estimates,
not all visits equally. Two units with values 10 and zero observed for two and
eight visits have equal-unit average 5 and pooled-visit average 2. For banking,
the unit must be an independently justified customer or cluster, and the
population weighting must match the investment question. Common calendar shocks
or cross-customer interference are not covered by labeling visits independent.
\citep{exec24_policyother_original,exec24_policyother_contract}

The paper's central limit theorem adds growth and nondegeneracy restrictions
and centers the estimator on its expectation. Its text cautions that an
MSE-motivated window need not satisfy that theorem's growth condition, while
its simulations show less Gaussian behavior at large windows and small sample
sizes. The inspected tuning code uses one estimated standard-error interval
as an overlap rule; the paper also states that its experimental multiplier is
one. Neither observation supplies a nominal 95 percent interval for a
bias-affected, adaptively selected target. Separate fixed-window uncertainty,
remaining truncation bias and tuning or policy-selection effects. An estimated
logger and dynamic policy learning are explicit extensions beyond the original
paper's stated known-logger evaluation setting.
\citep{exec24_policyother_original,exec24_policyother_ope}

\subsection{Research scripts need a reproducible target before reuse}
The cutoff-pinned research repository contains ten files: a README and Julia/R
simulation and aggregation scripts for two simple examples and a synthetic
mobile-health example. Its complete selected tree has no license declaration,
\texttt{Project.toml} or \texttt{Manifest.toml}; this observation does not settle
rights outside that tree. The scripts use absolute output paths and choose a
random seed before setting it. The README directs repeated runs with different
seeds, and the aggregator reads available output files without an independent
manifest of expected completed requests. A prototype needs documented rights,
an exact environment, caller-supplied seed schedule, portable paths, run identities
and expected/failed/completed counts before any reproduction claim.
\citep{exec24_policyother_ope}

The synthetic mobile-health scripts also illustrate why a literature result
and its numerical implementation need separate comparison. The paper's reward
categories include boundary values 70, 80 and 150; the selected source's strict
comparisons return zero at those three exact boundaries instead of the paper's
$-3,-1,-1$. The estimator's glucose feature uses the stored previous value,
whereas the current value is a distinct field. A previous value of 120 and
current value of 130 produce different decisions at threshold 125. These
are source-to-definition and information-clock questions, not clinical advice
or an asserted native benchmark defect. Resolve the intended indexing and
units before transporting a target or comparing a reference reward. The
published example is simulated from a stated model, not authentic bank or
clinical outcome validation, and no numerical study has been rerun here.
\citep{exec24_policyother_original,exec24_policyother_ope,exec24_policyother_contract}

The appropriate proposal disposition is a conditional POMDPTools worker for
supplied-model finite or justified discounted evaluation, and a research
reference for partial-history weighting under a justified known logger.
Do not inherit the root interface's rights across packages, infer a native
capability from static review, port an entire ecosystem without a demonstrated
benefit, or translate stationary mean rewards into discounted bank cash flows
without an explicit horizon model. POMDPTools declares its own MIT license
and Julia/dependency compatibility; its complete installed dependency closure,
solver choices and operating costs still require review.
\citep{exec24_policyother_tools,exec24_policyother_contract}

A public/generated qualification can freeze model and policy identities,
information clock, discount/horizon, logger and support, window/tuning rule,
seed list, exact finite oracles, failure policy and held-out scenarios. Compare
both the ordinary and adverse cases: randomized policies, state leakage,
terminal-entry rewards, threshold/domain limits, captured exceptions, zero
matching windows, unknown logging and nonstationarity. Measure compilation,
model audit, computation, serialization, rights review, recovery and maintenance.
Illustrative cost 2,400 USD across 100 requests, 80 conformant outputs and
60 useful outputs gives 24, 30 and 40 USD per denominator; these are not measured
prices. The current bounded Julia/Rust discovery query and selected source
reviews do not close every other-language candidate or establish an absence
of Rust software. Search tails, concrete solvers, native experiments and
unsupported scientific regimes remain explicit obligations.
\citep{exec24_policyother_contract}

Across the chapter, a useful comparison preserves the decision before comparing
algorithms. A fitted controller, a value under a supplied model, an estimate
from logged actions and a stationary population value answer different
questions. The source-specific counterexamples show why state sufficiency,
policy randomness, episode endings, support and reward clocks must survive
conversion. The preferred route is consequently narrow reuse with explicit
qualification and independent finite references; neither a language change nor
a more elaborate optimizer supplies missing causal information. The next
chapter turns to comparisons across institutions and time, where assignment,
shared shocks and the choice of comparison group impose a different set of
requirements.
